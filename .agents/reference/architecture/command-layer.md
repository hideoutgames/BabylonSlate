# Command Layer

Undo/redo, dirty state, autosave and the crash-recovery journal for authored documents, plus the editor document pipeline that drives them.

`DocumentProvider`'s hooks register their effects where it calls them, and React runs and cleans up effects in that order, so each call stays at its commented position; `useDocumentStateSlices` comes last so its layout effect publishes to subscriptions after the others. Each hook returns its actions as one memoised group of stable callbacks, and the provider spreads the groups into the single `actions` object it creates once.

The undo boundary is exactly the asset-file boundary. Editing surfaces never mutate document models directly; every accepted edit goes through `applyGraphChange` / `applySceneChange` / `applyAssetDocumentChange`. The only Scene write without a command is the open-time prefab sync.

## Command contract

```ts
interface EditCommand<TDoc = unknown> {
  readonly type: string;
  readonly mergeKey?: string;          // coalesce one continuous gesture
  apply(doc: TDoc): TDoc;              // pure replacement; never mutate input
  invert(): EditCommand<TDoc>;
  coalesce?(next: EditCommand<TDoc>): EditCommand<TDoc> | undefined; // first `from`, last `to`
  readonly byteSize: number;           // retained cost, measured lazily; required
}
```

- Prefer deltas; snapshot a subtree only when a compact inverse is impractical. Every command reports `byteSize` (the interface requires it, so none is free history): a lazy, memoised getter, never an own field, so the journal's field spread never copies or measures it. Small fixed-field commands use `retainedFieldBytes(this)` ([`snapshot-bytes.ts`](../../../packages/edit/src/snapshot-bytes.ts)); `from`/`to` commands memoise each side and carry measured sides through `invert` and `coalesce`, so a scrub measures only each new `to`. `PatchTilemapDocumentCommand` measures each chunk patch once (a `WeakMap` keyed by patch identity), so a folded stroke measures only the chunks its newest sample touched.
- Commands are serialisable (`type` + fields) for the journal. Every `SCENE_COMMAND_TYPES` entry needs a reviver (`journal.test.ts` enforces it).
- Commands copy what they add or set (independent snapshots), and `apply` returning its input means no-op (`history: "unchanged"`; Redo kept). Reorders move only from the recorded `from` index.
- `diffSceneCommands` / `diffGraphCommands` derive commands from before/after snapshots. `planSceneChange` replays the deltas and falls back to one `ReplaceSceneCommand` when they do not reproduce the target (safety net for fields without a delta).
- `ReplaceSceneCommand` rejects values JSON would lose (undefined, non-finite, `-0`, sparse arrays, runtime objects, cycles).

## Stacks and budgets

- One `DocumentEditStack` per document id, never a global stack. Chrome Undo/Redo act on the active document only.
- `HistoryOutcome`: `recorded` | `cleared` (edit larger than the budget still applies, history is cleared) | `cleared-gesture` (rest of that gesture) | `unchanged`.
- Caps from Engine Settings ([`packages/vfs/src/app-settings.ts`](../../../packages/vfs/src/app-settings.ts)): `undoHistoryLength` default 50 (1–1000); `undoByteBudget` default 16 MiB (1–1024 MiB). Oldest entries drop first; `EditSession.configure` reapplies to all stacks.
- `applyWithHistoryAdmission`: both directions must declare finite integer byte costs that fit before `apply` runs; otherwise `history-budget` / `invalid-byte-size` with nothing changed. Used by Simulation Keep ("Apply Simulation Changes").
- Merge: equal `mergeKey` on the top entry coalesces. `applyBatch(…, { mergeKey, amend })` wraps a change in a keyed `CommandBatch`, whose `coalesce` concatenates the next keyed batch (Undo reverts and Redo replays both). Batches of one gesture share append-only part storage, so a coalesce, its `invert` (each part inverted once) and its `byteSize` (each part measured once) cost only the new parts; a batch whose storage was already extended or handed out copies first. A batch's inverse costs what its forward batch costs, since it retains the same snapshots. Stacks keep running byte totals, so budget checks never rescan history; `amend` joins the top entry of the same key even after its gesture ended. `applySceneChange(id, next, { mergeKey })` always amends: a placement (`place:<actorId>`) and its later rest on a surface are one step unless another edit lands between them. Keys: `move:<nodeId>`, `data:<nodeId>`, `function-graph:<name>`; multi-actor transforms become one `SetActorsTransformsCommand`. A keyless multi-command edit gets one key for its set of command keys when every command is a field edit: `graphEditMergeKey` (node data) and `sceneEditMergeKey` (actor rename, transform and properties; component property and transform), so a multi-selection scrub coalesces as one item's does. Hosts pass stable per-field keys for scrubs; gesture boundaries (new pointer gesture, Enter, blur, discrete key) end a merge group.
- History outlives the tab for the project session: a clean close keeps it with a `documentContentIdentity` hash; reopen resumes only when the content identity matches. Discarded edits, deleted paths, external changes and project open/close drop history. Renames move history with `EditSession.rekeyDocument`; a stack already under the new id is dropped, never inherited.

## Dirty state and saving

- Forward edits mark dirty without hashing. Undo, Redo and journal replay compare against the last saved/loaded baseline (Scenes structurally, others by content identity), so undoing to saved content is clean.
- Autosave runs `ProjectSettings.autoSaveIntervalMs` (default 120000) after the first edit; later edits do not reset the timer. `ProjectSettings.autoSave` (default on) is checked in `scheduleDebouncedSave` only: off drops a waiting interval and starts none (the setting change itself lands there), its timer re-checks it before saving, and turning it on starts an interval through the same settings-change schedule. Failures keep documents dirty. `compileOnSave` defaults true. Play is an explicit save + compile trigger.
- `setAutoSavePaused(true)` holds the timer while an Unsaved Documents close prompt is open (tab close, Close Project, exclusive Scene open), so Discard drops what the prompt lists; resuming starts a new interval when anything is unsaved. The prompt lists live dirty state and closes without asking when everything listed was saved by a save already in flight; an exclusive Scene open then continues through `openDocument`, not Discard, so a Scene the replace gate's stop leaves dirty asks again.
- Under an authoring lock `DocumentService.assertDocumentCanClose` refuses a dirty document or a Scene, and `closeDocument` throws that refusal synchronously when no session gate waits. The editor route closes tabs one at a time, still closes the rest and reports the first refusal in **Could Not Close Documents**. A refusal after an async session gate (the session source whose stop fails, or a close that throws after the stop) is not reported in that dialog.
- Only dirty documents write. Queued writes resolve the asset's current path from its guid, so a queued save cannot resurrect a moved or deleted path.
- `lockAuthoringWrites(reason)` closes project-write admission (Save All, autosave, registry, blob, extension writes) and its lease's `ready` resolves after admitted operations drain. Simulation preparation takes its baseline behind it.
- Save All writes each dirty document from its snapshot only while the tab still has that path: a Content Browser delete or move landing between two writes would otherwise recreate the file at its old path. `markAllClean` skips the same documents, so a moved one stays dirty for the next save.
- `runSaveAll` returns a `SaveAllOutcome`: `saved`, `locked` (everything written but documents someone else has locked), `authoring-locked`, `recovery-pending` or `no-document`; every caller branches on it (Auto-Save, Save All, Play, Preview Build, the close prompts, the exclusive Scene open, the Pull / Switch Branch / Revert unsaved step). Source control locks: [source-control.md](source-control.md#saving-under-someone-elses-lock).
- Save All settles each document as soon as its file is written: `markAllClean([doc])`, then `journalDiscardLine` when it is clean (an edit landing during the save keeps it dirty and its records). So a later document's failure (a full disk, a lock refusal) never leaves a written one dirty with records a crash would replay onto its saved file; the failure path refreshes the mtime snapshot for what was written. The journal is truncated only when nothing is left unsaved. A storage-full failure (`isStorageFull`: `QuotaExceededError`, `ENOSPC` / `EDQUOT`, the iOS and Android out-of-space messages, [`storage-full.ts`](../../../apps/editor/src/lib/storage-full.ts)) rethrows as `STORAGE_FULL_MESSAGE`, which the Save All button and Auto-Save show as their `… Failed:` text. Reloading a document from disk (`applyOpenDocuments`: external change reload, a pull's reload, the rewrite flows' Discard, Save Failed's Discard Changes) appends one for it too.
- Save All holds the editor viewports' frames (`withEditorViewportFramesHeld`, [render.md](render.md)) from its turn in the project write queue until it settles, whether it saves, throws or is refused there (authoring lock, missing project); the authoring-lock refusal before queueing takes no hold. Nothing it awaits needs an editor viewport frame: Auto Bake On Save waits for browser frames (`waitPaintedFrame`), collects through `EditorSceneSync` and already runs under its own Dialog's obstruction; the audio reverb flush yields to `requestAnimationFrame` and bakes in workers; model thumbnail jobs and `onSceneSaved` are dispatched synchronously and never awaited. A Save All during Play holds only the editor viewports, which Play already pauses or releases; one during Simulation is refused by its authoring lock.
- Every `project.json` write the editor makes outside Save All (Class reference replacement and delete repair) goes through the same project write queue (`saveProjectNow`), so it lands after a Save All already running instead of being overwritten by its older document.

## Journal format

- Path: `derived/{projectGuid}/journal/00000000.jsonl`, `00000001.jsonl`, … in app-private derived storage. Segments roll at `JOURNAL_SEGMENT_MAX_CHARS` = 64 KiB (append rewrites only the tail segment).
- `journal/sealed.json` (`{"through": N}`) marks segments `0..N` as sealed: records of an earlier session awaiting the recovery decision. Append never rewrites a sealed segment; it starts the next one.
- No marker (or no journal folder), or one that does not parse, seals nothing. A marker that exists but cannot be read (any failure other than `StorageNotFoundError`, a directory at its path included) never counts as unsealed for a caller that would then remove or rewrite records: `truncateJournal` rejects with the read error and removes nothing (Save All and Close Project fail as on any journal storage failure), and a session's first append rejects (`JournalBuffer` reports it and keeps the lines for its next flush). The recovery offer (`readSealedJournalLines`) and `discardSealedJournal` treat it as sealing nothing and leave every segment in place, so opening a project never fails on it.
- Line: `{"v":1,"docId":"…","at":"ISO-8601","command":{"type":"…",…}}`. Multi-command actions are one `edit.batch` record; an unsupported child skips the whole batch.
- Markers: `document.repath` (`docId` = new id, `from` = old id; `resolveJournalLines` follows chains), `document.discard` (close drops earlier edits), `document.checkpoint` (Class rename snapshot of open referrers, flushed before the rename writes; a referrer the rename leaves clean then gets a `document.discard`, flushed before the rename returns, so a reload right after a saved session is offered nothing).
- `JournalBuffer` writes at most `JOURNAL_FLUSH_DELAY_MS` = 150 ms after the first record, and flushes on Save, close, `pagehide` and backgrounding. Edits inside that window can be lost on a crash.
- A rolling append that stored some segments before one failed rejects with `JournalAppendError` (`journalLinesCommitted`): `JournalBuffer` keeps only the records not stored, so a retry stores none twice. Journaling of a project pauses (`onPausedChange`; the status bar's **Crash Recovery Paused — Use Save All**, and the floating `JournalPausedNotice` once per pause on every layout, since phones hide the status bar) after `JOURNAL_STORAGE_FULL_FAILURES` (3) storage-full writes in a row or past `MAX_UNWRITTEN_JOURNAL_LINES` (4,000) waiting records: waiting records are dropped and new ones ignored, so what is stored stays a prefix of each document's edits and a crash recovers up to the pause. It resumes only when a Save All cleared the journal and nothing is unsaved in that tick, or a project open sealed it, so it never journals an edit without the ones before it.
- `coalesceJournalLines` folds one gesture (first `from`, last `to`) only for commands whose replay writes just `to`. `byteSize` never enters journal payloads.
- Replay: `replayJournalLines` → `reviveCommand` → `apply`. Malformed lines return in `malformed`, throwing records in `skipped`; neither is dropped until Save or clean close.
- Recovery lifecycle: opening a project calls `sealJournalForRecovery`, which seals every segment written so far; the modal **Recover Unsaved Edits?** (`RecoveryDialog`, `editor-route.tsx`) shows before editing starts while the sealed records resolve to any edit (none: the sealed segments are discarded). Records from a session that never reached Recover or Discard (a crash in between) are sealed again with the rest. Replay reads only the sealed segments, so edits made after the reopen are never replayed. A journal that cannot be sealed or read (an I/O failure, a folder at a segment or marker path) never blocks the open: it is removed (`removeJournal`; storage has no rename to quarantine it) and `recoveryNotice` `unreadable` tells the user. Either way the session's `JournalBuffer` resumes for the project.
  - Pre-open records replay only onto the saved base. At open `noteRecoveryBase` records each target's registry entry (entries are replaced, never mutated, and kept when a file is indexed again unchanged). `replayRecoveryJournal` stops before changing anything and answers `changed` (`recoveryNotice`, **Replace Changes Since Opening?**) when a target is dirty or its entry differs; with `replaceChanged` a dirty target is reloaded from its file first and a rewritten one's records are dropped (its base is gone).
  - Replayed documents lose their `EditSession` history (written by `updateScene` / `updateGraph` / `updateAssetDocument`, so recovered edits cannot be undone). When the replay ends at the saved content with nothing skipped, `discardSealedJournal` drops the sealed records. Otherwise each recovered document gets a `document.checkpoint` record (its whole content) in the live journal, flushed before the sealed records are discarded (or unsealed, when some could not be replayed): a crash recovers the sealed records or the checkpoint, and no record written since the open replays ahead of or onto them. A checkpoint that cannot be written leaves the sealed records sealed. Discard calls `discardSealedJournal`. All of this runs in the tick that applies the replay, so no save sits between.
  - While the choice is pending nothing writes project documents, so the base cannot move: `runSaveAll` refuses before queueing and again in the queue (`recovery-pending`: a shortcut, Play's save or any background caller), Auto-Save's timer defers (no error status) and starts a fresh interval after Recover or Discard (`resumeAfterRecovery`), and background Texture encodes pause (`setEncodeQueuePauseReason("recovery")`). Open-time automatic updates (a Prefab sync) stay in memory until then. The provider's `recoveryPendingRef` is set with `recoveryAvailable` in one call (`setRecoveryPending`).
- `truncateJournal` removes only the live segments (those after the sealed ones). A Save All that leaves nothing unsaved (and so autosave and Save & Play) truncates them; clean and forced Close Project truncate them too. Sealed records survive all of these and a document close (`document.discard` is a live record and does not reach sealed ones); only Recover or Discard ends them. Project Settings are not journaled. `v` exists for future journal migration.
- The status bar shows `Unrecovered Edits` while the recovery choice is pending; Save All behaviour does not change.

## Document revisions and subscriptions

- Documents mutate in place; `DocumentService.getRevisions()` keeps one revision per document kind, drawn from one service-wide sequence.
- Components read the narrowest hook: `useDocumentActions()` (stable for the provider lifetime), `useOpenDocument(id)`, `useDocumentDirty(id)`, `useOpenDocumentsOfKinds(kinds)`, `useOpenDocumentTabs()`, `useRegistryState()`, `useSaveState()` and the other state slices. Thumbnail versions are a store, not a value (`useThumbnailVersions()`, a `ThumbnailVersions` from `@haptic/editor-kit` that keeps its identity): readers subscribe per asset with `useThumbnailVersion(store, guid)` or per list with `useThumbnailVersionsKey(store, guids)`, so a thumbnail write renders only the views showing that asset (a closed picker, a mounted Content Browser tile, a shown card list), never the provider, the shell slice (`useEditorShellState()`: prompts, recovery, Homepage lists, the Thumbnails setting) or a Content Browser whose mounted tiles it does not touch. There is no aggregate hook: a component calls one hook per piece of state it renders, so it re-renders only when that state changes.
- Memos that read the registry key on `[assetRegistry, registryEpoch]`; memos that read other open documents key on `useOpenDocumentsOfKinds`. Edits never advance `registryEpoch`.
- A catalog that merges registry headers with open tabs splits into a header part keyed on the registry and an overlay of the open tabs, so an edit parses no header: `useClassGraphs` ([`use-class-graphs.ts`](../../../apps/editor/src/lib/use-class-graphs.ts); every Class graph by class id, the open Class tabs laid over a fresh copy of the header graphs, which callers copy before adding to) and the Function Library and Scene parts of `useGraphPanelCatalogs`. An open Scene counts in the Scene palette through its actor and component lists, and in the Timeline index through its clip list, so other Scene edits keep both.
- Code that runs after render (handlers, async work) reads `getOpenDocuments()` at call time, never a render snapshot.

## Document tab lifecycle

| State | Tab | Content + history | DockView / Babylon |
| --- | --- | --- | --- |
| Mounted-warm | Open | Yes | Yes (hidden + frozen when inactive) |
| Idle-unmounted | Open | Yes | No; remount from `layout.json` + session view state |
| Closed | Gone | Clean history kept for same-content reopen | Gone |

- `DOCUMENT_IDLE_UNMOUNT_MS` = 120_000, `MAX_WARM_DOCUMENT_WORKSPACES` = 3 ([`document-working-set.ts`](../../../apps/editor/src/lib/document-working-set.ts)); named constants, not settings. Open Scenes, and the source document of every open Text Editor tab (`keepMounted`), stay mounted and count toward the cap.
- Three tab categories ([`document.ts`](../../../packages/core/src/document.ts)): asset documents (`AssetDocumentKind`, `isAssetDocumentKind`: content, dirty state, save, reload, file operations, reference repair); pinned chrome tabs (`ChromeDocumentKind`, `isChromeDocumentKind` / `isChromeDocumentId`: Content Browser and Source Control, never closed, not sortable); transient tabs (`TransientDocumentKind`, `isTransientDocumentKind` / `isTransientDocumentId`). A check that means "has an asset behind it" uses `isAssetDocumentKind`; one that means "pinned" uses the chrome helpers, so a transient tab is closable, sortable and counts for Close All.
- **Text Editor tab** (`text-editor`, the only transient kind): an Inspector field's value full size ([`text-editor-workspace.tsx`](../../../apps/editor/src/components/text-editor-workspace.tsx), lazy-loaded; a plain page, not a DockView document). Id `text-editor:<session>`, the session id `<sourceDocumentId>#<fieldKey>` carried in `ref.path`. `DocumentService.openTransientDocument` opens it synchronously with no content; it is never dirty or saved, `buildLayouts` leaves it out of `tabOrder`, `documents`, `panelPlacements` and `assetGuids` (an active one saves its source document, else the Content Browser, as active), and `parseDocumentId` returns null so a saved id never restores. Closing it returns to its source document.
- Its session ([`text-editor-sessions.ts`](../../../apps/editor/src/services/text-editor-sessions.ts), an external store) is owned by the field: `useTextEditorTab` ([`use-text-editor-tab.ts`](../../../apps/editor/src/lib/use-text-editor-tab.ts)) keeps its value, read-only state, completion names, error and `commit` (the field's latest `onChange`) current. The tab lives exactly as long as the field: the field unmounting (selection change, deletion, its document or the project closing) removes the session and closes the tab one task later, cancelled when the same field remounts; closing the tab removes the session; `initializeFromProject` clears every session; a tab without a session closes itself. Edits commit through the field's own document-scoped `onChange` (the Inspector's `DocumentWorkspaceProvider` id, never the active tab), with the same draft contract as `MultilineTextField`, plus a commit when the tab stops being active. Save All (`saveAll`: the Mod+S keybind, the toolbar, Save before Play) calls `flushTextDrafts()` synchronously before queueing the save, and every field `onChange` writes `DocumentService` synchronously, so text still being typed is saved; auto-save does not flush.
- The project owns one Engine on a hidden canvas; viewports are `registerView` clients. Closing a Scene tab releases its leases but never disposes the project Engine. Closing or replacing the Scene a Play/Simulate/Preview session started from stops that session first.
