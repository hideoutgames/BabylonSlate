# Source Control

Built-in Git (Integrated mode: clone, publish, commit, pull, push with Git LFS, behind the [Git core](#git-core)) and optional Git LFS file locking (every mode; Manual leaves sync to another Git app): the `LockProvider` port and LFS client, device credentials with GitHub and GitLab device sign-in, the host REST clients, the pinned Source Control tab (Changes, History, Locks, and the [asset diffs](#asset-diffs): Actors, Diff, Revert Asset), branches, the status bar and external-change detection by mtime.

This file describes what is built. What remains (the iPad benchmark and its native streaming decision) is in [source-control-plan.md](../source-control-plan.md).

## Decisions

- Per project, `ProjectSettings.sourceControl.mode`: `off` (default), `integrated`, `manual`. **Off costs nothing**: `SourceControlService.configure` and `SourceControlSyncService.configure` return before loading credentials, HTTP, the Git core or timers and emit nothing, and no tab, banner, phone button, lazy chunk or polling exists. Any other mode on a source-control host is *active* (locks).
- **Manual**: another Git app (Working Copy, a desktop client) syncs; Haptic implements Git LFS locking only. It reads no git state beyond the `.git/config` prefill, shows no git status, loads no Git core and never adds `lockable` to `.gitattributes`.
- **Integrated**: Haptic is the folder's only Git client ([Integrated mode](#integrated-mode)). **One Git client per folder**: `project.json` is committed and records the team's mode, so a stored `integrated` reaches folders another client owns; `integratedBlocker` (`lib/source-control-mode.ts`) decides from platform, test mode, storage tier, a readable `.git/HEAD` and the folder's adoption whether the Git core may run: not on a host without source control, not without `.git`, not in a chosen (`external`) folder on iOS or Android (`other-git-client`), and on desktop not in a working copy this device has not adopted (`not-adopted`). **Adoption** (`asksAdoption`: Electron, not test mode, `.git`) is asked once per desktop working copy with the one-Git-app warning, since any Git app (GitHub Desktop, the git CLI) may own it, and kept in that copy's own `.git/config` as `haptic.integrated = true` ([Git core](#git-core)): per working copy, never committed, surviving a reinstall. Clone and Publish adopt the copies they make; iOS and Android app storage has only Haptic as its Git client, so it is never asked. Test mode always runs (`FakeSync`, no `.git`). A blocked Integrated project keeps its locks and shows the reason in Changes and Project Settings.
- No source control on production web: GitHub's LFS and REST endpoints send no CORS headers and a proxy is out of scope. Native hosts bypass CORS (`CapacitorHttp`, Electron `net.fetch`). Test mode uses `FakeLockProvider`, in-memory credentials and `FakeGitHost`.
- Locks are **advisory** and failure never blocks editing. Release is explicit only (per lock, **Release All My Locks**, **Release Pushed Locks**, or an Integrated push with **Release Locks After Push**, which Haptic made), never on a timer, close or heuristic.
- Credentials are **per device and host origin**, never per project and never in `project.json` or Git. Clerk's GitHub sign-in cannot supply them (Clerk keeps provider tokens server-side), so host sign-in is separate from the Haptic account.
- Every link (device sign-in or saving a token) shows the use-at-your-own-risk warning first; **Decline** stores nothing; acceptance is never remembered.
- Lock paths are repository-relative and the project folder is the repository root; Release Pushed Locks compares local and remote files on that assumption.
- No Haptic-run server or client secret: OAuth device flow with public clients. Client ids are build variables (`VITE_GITHUB_CLIENT_ID`, `VITE_GITLAB_CLIENT_ID`, read only in [`source-control-client-ids.ts`](../../../apps/editor/src/lib/source-control-client-ids.ts)); without one that host's Sign In is hidden and a pasted token still works. Test mode supplies a fixed id.
- External change is detected by file mtime on foreground, not by git. A pull's reload classifies by the same rule ([pull](#integrated-mode)).
- `project.json` is committed: `ProjectService.saveProject` leaves it untouched (its `updatedAt` too) when the payload would differ only in the stamp, so a Save All that changes nothing is no Git change and no teammate conflict.
- **The checked-out branch is device state**, Git's HEAD (`SyncPort.branch`; `FakeSync` keeps it per working copy), never `project.json`. `sourceControl.branch` is the team's default branch (Project Settings shows it as **Default Branch** in Integrated mode; Manual mode's locks and Release Pushed Locks use it, Integrated mode's locks the checked-out branch, [Port and client](#port-and-client)). Why: `project.json` is committed and differs per branch, so a branch recorded there would be a change on every switch, carried into commits and merges, and overwritten by the other branch's own `project.json` the moment it is checked out; a changed `project.json` also reloads the whole project. HEAD is per working copy already (as the adoption answer lives in `.git/config`), survives the checkout and is what every other Git app reads. So a switch writes no `project.json`, the sync's client identity is folder and repository only, and Clone of a non-default branch leaves `project.json` as it is.

## Loading

- The startup path imports only the `@haptic/source-control` barrel (provider, credential store, scheduler, types, `SyncPort`'s small pure helpers, the `.blobs` path rule `lfsObjectId`), the sync service, the mode and change helpers, the status bar and the actions provider. Device sign-in, token refresh, the host REST clients, the comparator, the fake host, the Git core (`./git`, with isomorphic-git), `./fake-sync` and `./git-benchmark` are subpath exports kept out of the barrel, so the bundler splits them. The Git core installs the `buffer` package as `globalThis.Buffer` (isomorphic-git reads the global; WKWebView and Electron renderers have none) only when a repository opens; its `sha.js` dependency resolves the same package.
- The device accounts module loads on the first configure of an active project or with a Source Control settings page; the Engine Settings page, the Project Settings account rows, the Sign In dialog, the Locks, Changes and History windows (`lazyPanel`), the Pull, Revert and Switch Branch flows, the New Branch dialog, Clone, Publish, New Project's Remote fields (with the accounts module, once Remote is chosen) and the Git client module (`source-control-sync-port.ts`, which imports `./git` or `./fake-sync` dynamically) load on first use: an Integrated configure, a clone, a publish, or accepting the one-Git-app warning on desktop (Mode's switch writes the adoption, through the Git core, while the saved mode is still Off or Manual). The Remove Unused Files flow loads with the Changes window and its scan module with its first run. The Actors and Diff windows are in the same lazy family; the diff loader, its worker client and the worker load with the first diff a window shows (the worker ends when the diff closes or `DIFF_IDLE_MS` after its windows were last on screen), and the graph canvas with the first graph diff; a Material, Particle Graph, Behaviour Tree or State Machine canvas loads with its family's editors (`shell/asset-panels/rendering.ts`, `animation-ai.ts`, through `lazyPanel`), never with the Diff window. The actions provider holds only `SourceControlDiffService` (no decode code) and the toolbar pickers; the branch menu items load with the status bar. `boot-imports.test.ts` pins this.

## Port and client

- `LockProvider`: `create(path)`, `verify({ branch? })` → `{ ours, theirs }`, `unlock(id, { force? })`. `LockError.kind` is `conflict` (409 with the existing lock), `offline`, `unauthorized`, `unsupported` or `http`. `FileLock.lockedAt` is `""` when the server omits it (Unknown Age).
- **Create is the race-free check**: 201 holds the lock. A 409 carries no ours/theirs, so `create` then verifies: a path in `ours` is returned as held; otherwise it is a theirs conflict. If verify fails, the 409 stays a conflict.
- Calls go to `{lfsBase}/locks` with `application/vnd.git-lfs+json` and Basic `<credential.username>:<token>`: `POST /locks`, `POST /locks/verify` (cursor pagination), `POST /locks/:id/unlock`. `ref.name` is `refs/heads/<branch>`, the branch read on every request (`GitLfsLockProviderOptions.branch`, `SourceControlService.lockBranch`), so a host that scopes locks by ref checks the branch being pushed:
  - Integrated mode: the working copy's checked-out branch (the sync snapshot's `branch`, followed by `setCheckedOutBranch`; a move verifies again and lets auto-lock try each path again), for create, verify and unlock (Lock, Unlock, Release Locks After Push); the pre-push check (`locksBlockingPush`) verifies the branch the push sends (`SyncPort.branch` when it runs), which a switch moved before the snapshot did.
  - Manual mode (another Git app owns HEAD) and Release Pushed Locks: the default branch.
  - No branch checked out (`""`: an open that failed or has not finished, a blocked folder; a detached HEAD refuses to open): the default branch, not a refusal. No push can run then, and locks stay advisory and keep working. An empty branch never makes `refs/heads/`: the provider falls back to the default (`main` unless set).
- **Missing lock support:** GitHub and GitLab (`github`, `gitlab`, `gitlab-token` credentials) always have the locking API, so there a 404 or 501 from create or verify is an `http` error, **Repository Not Found Or No Access** (a token that cannot see the repository), and checks continue on the normal schedule. On any other host it is `unsupported`: the service stops polling and auto-lock, and the Locks window shows **This Host Does Not Support File Locking.** Saving a different credential tries again. An unlock 404 is always an `http` error (the lock is gone).
- Lock state comes only from verify. A malformed verify body or a repeated `next_cursor` is an `http` error, so a refresh keeps the last known locks.
- `parseRepositoryUrl` maps the **configured** repository URL (HTTPS, SSH or scp-style) to an HTTPS origin and path; `http://` is upgraded and an `ssh://` user and port are dropped, as git-lfs does. The origin is the credential key.

## Credentials

- One `HostCredential { origin, username, token, kind, account?, refreshToken?, expiresAt? }` per HTTPS origin, all under the single SecretStore key `source-control:credentials` (one read lists them). `CredentialStore` caches reads, but every change (`update`) re-reads the stored secret, applies the change and writes, serialized in the process, so another window's write is never lost to a stale cache.
- `kind` and Basic username: `github` (device sign-in) `x-access-token`; `gitlab` (gitlab.com device sign-in) `oauth2`; `gitlab-token` (self-managed GitLab personal token) the fixed `haptic`; `token` (any other host) `x-access-token`. Only `github`, `gitlab` and `gitlab-token` have a host REST API (pickers, Release Pushed Locks).
- **Origin rule** (`authorizedHttp`): a token goes only to its own origin, plus `https://api.github.com` for a `https://github.com` credential (the one exception; GitLab's API shares its origin). Any other URL is refused before a request. Every credentialed request sets `disableRedirects`: Electron's `lfs:fetch` never follows redirects (`redirect: "error"`) and CapacitorHttp gets `disableRedirects`, so a 3xx comes back unfollowed. Git and LFS use Basic, REST APIs Bearer.
- Requests take their credential from a `CredentialSource` (`current`, `renew`); a 401 renews it and retries once.
- **Refresh** (`RefreshingCredentials`, owned by the accounts module): GitLab sign-in tokens expire (about 2 h) and come with a refresh token. A token within 2 min of `expiresAt` is refreshed before use, and a 401 refreshes once: `POST https://gitlab.com/oauth/token` with `grant_type=refresh_token`, `refresh_token`, `client_id` (non-confidential app, no secret). One refresh per origin is in flight. It first re-reads the stored credential and uses another window's refresh if there is one (GitLab spends the old refresh token). A rejected refresh, or a build without the GitLab client id, removes the credential (compare-and-remove on the refresh token), so the sign-in banner returns; a refresh that cannot reach the host keeps the credential and fails that request. The service keys its provider on the account, so a refreshed token keeps the provider and its locks. GitHub OAuth App tokens do not expire and are never refreshed.

| --- | --- | --- |
| iOS / Android | Keychain / Keystore via the first-party `BabylonSlateSecrets` plugin (not Preferences); the Swift file must be in the App target and `packageClassList` | `CapacitorHttp` |

## Device sign-in

- GitHub: `POST https://github.com/login/device/code` (`client_id`, `scope=repo read:org`: `repo` for Git, LFS, locks and repositories, `read:org` for the organizations Publish lists), poll `POST https://github.com/login/oauth/access_token`; user `GET https://api.github.com/user` (`login`). gitlab.com: `POST https://gitlab.com/oauth/authorize_device` (`scope=api write_repository`), poll `POST https://gitlab.com/oauth/token`; user `GET https://gitlab.com/api/v4/user` (`username`). Polls use the device-code grant; errors are read from 200 (GitHub) and 400 (GitLab) bodies.
- Each poll waits the code's interval (5 s default) first; `authorization_pending` continues, `slow_down` adds 5 s, and `expired_token`, `access_denied`, the code's own expiry and cancellation stop. The clock is injected (`DeviceClock`).
- The verification page is hard-coded per host (`https://github.com/login/device`, `https://gitlab.com/oauth/device`), never taken from the response. Desktop admits exactly these two pages in `externalOpenUrl`; every host opens them with `window.open(…, "_blank")`, which Electron hands to `shell.openExternal` and the mobile WebViews to the system browser.
- Returning from the browser fires the mobile Homepage session check, which unmounts dialogs, so `useHostLink` holds `holdSessionCheck` from **Accept** until the Sign In dialog closes.
- Self-managed GitLab needs its own app registration, so it takes a personal token instead.

## Settings and UI

- `sourceControl: { mode ("off"), repositoryUrl (""), branch ("main"), autoLockOnEdit (true), releaseLocksAfterPush (true, Integrated only) }`. Unknown modes normalize to `off`; other fields are dropped. Polling uses the fixed `LOCK_POLL_INTERVAL_MS` (60 s). Changing repository or branch drops the old provider's locks and every read-only state.
- **Project Settings → Source Control:** Mode (**Off** / **Integrated** / **Manual**; `offeredSourceControlModes`: Integrated only for a project that has it, or for a folder with a readable `.git` Haptic may run Git in: on desktop after the **Use Haptic As This Folder's Git App?** warning, whose acceptance adopts the folder before the mode is saved, and in iOS and Android app storage, where Haptic is the only Git client, with no warning (a copy whose branch's `project.json` left Integrated mode is never stranded; an Off copy there with an interrupted Publish's `.git` is offered both), **Publish Project…** (`canPublishProject`: Off, no `.git`, app storage or desktop), Repository, Branch, Account, **Auto-Lock On First Edit**; **Release Locks After Push** shows only for Integrated. A blocked Integrated project shows the sync snapshot's `integratedBlockerLabel` under Mode (the sync is the one place that decides it; the page reads only `blocked` and `active`). **Git App** row, desktop Integrated only: **Use Haptic's Git Here** while `not-adopted` (the warning; **Cancel** stores nothing and nothing asks again by itself) or **Stop Using Haptic's Git Here** while the client runs in a folder `asksAdoption` covers (clears the adoption on this device; `project.json` stays Integrated, so the blocker returns). Both go through `setSourceControlAdoption` → `SourceControlSyncService.setAdopted`. In Integrated mode Repository and **Default Branch** are read-only (no pickers): the repository belongs to the working copy (`origin`; the sync opens a new client for a new one), and the branch is the team's default, apart from the working copy's checked-out branch ([decision](#decisions)). Adopting a desktop folder takes `origin` and the checked-out branch from the `.git` prefill as the default. Choosing Manual or Integrated with an empty repository reads the `.git/config` prefill first and otherwise shows a field error; turning Off asks first. While the mode is not Off, the account-aware rows replace the URL field with a picker of every API account's repositories (plus **Use Typed URL**), and the branch field with the host's branches when the repository's host has an API credential.
- **Engine Settings → Source Control** (Projects group; hidden where source control is unavailable): Accounts (GitHub and GitLab rows, shown when signed in or when the client id exists), Self-Managed GitLab, Other Git Hosts.
- **Sign-in prompt:** an active project whose repository origin has no credential shows one banner above the documents (`SourceControlSignInBanner`); the service builds no provider and requests nothing until the accounts module reports a saved credential, and a removed credential drops the provider and brings the banner back. Sign In runs device sign-in for github.com and gitlab.com and opens Engine Settings → Source Control otherwise.
- **Saved layouts:** `DockviewShell` drops panels its kind's catalog no longer lists (function graph tabs excepted) and the groups and splits they leave empty before `fromJSON`, which otherwise rejects the whole layout for an unknown component.
- **Source Control tab:** the `source-control` chrome document (`SOURCE_CONTROL_ID`, a `ChromeDocumentKind` beside `content-browser`): non-closable, never persisted in `tabOrder`, pinned last (`pinStickyTabs`), drawn at the right end of the tab bar left of **Open Documents**; on phones a **Source Control** button beside the Content Browser button opens it. It exists only while the service is active (`DocumentService.setSourceControlTab`; `initializeFromProject` keeps it only for a project not Off). It is a DockView document whose catalog holds **Locks** (Manual) or **Changes** with **History** and **Locks** tabbed in it (Integrated, `DockWindowOptions.sourceControlIntegrated`); the open document carries `sourceControlIntegrated`, and a mode change starts its layout afresh (the shell remounts by that key). The shell sits in a `DocumentWorkspaceProvider` for its id, so `useDockPanelShown` counts its windows hidden while another tab is in front (it stays mounted, and dockview still calls them visible). No asset document lists Locks or Changes.
- **Release Pushed Locks** (Manual, API hosts only): one remote listing per check (GitHub: the whole tree in one `GET /repos/{path}/git/trees/{branch}?recursive=1`; GitLab, which has no single-request tree: `GET /projects/:id/repository/tree?ref=…&path=<folder>` for each folder holding an own lock, paged only until that folder's wanted paths are found, a 404 folder holding nothing pushed), then each own-locked file hashed once: normal files by Git blob SHA-1, `**/.blobs/<sha256>` LFS objects by the blob SHA-1 of their pointer text from name and size. A path missing from the listing (or cut short) is Not Pushed. The Locks window checks when the set of own locks changes and on Refresh; the action re-checks and skips documents with unsaved edits. Own rows show **Pushed** / **Not Pushed**.

## Integrated mode

- **Sync service** (`SourceControlSyncService`, one per provider): `configure` returns at once for Off and Manual; for Integrated it checks `integratedBlocker` (where `asksAdoption` holds it first reads the folder's adoption through `SyncPortFactory.readAdoption`, which loads the Git core as opening would, so only an Integrated desktop project with `.git` pays for it), then opens one `SyncPort` per folder and repository through the lazily loaded `SyncPortFactory` (Git core on devices with the device's credential for the repository's origin and native HTTP wrapped by `monitoredHttp`, on the branch the copy's HEAD names; test mode `FakeSync`, one remote per normalised clone URL and one working copy per folder for the page, so unpushed commits and the checked-out branch survive a reopen) and then reads status and fetches. The request's branch only starts a new copy (Clone, Publish, a test-mode copy's first open). An open that fails (the adoption read included) resets the identity, so **Refresh**, foreground or the next configure opens again. A blocked folder keeps its identity, so `setAdopted(input, adopted)` does the rest itself: `stop()`, `settled()` (no operation of the client runs while `.git/config` changes), `SyncPortFactory.setAdoption` (no credential or network), then for an Integrated input `stop()` and `configure` again in a `finally`, so the folder's own answer decides even when the write failed (it rejects then); a Manual or Off input (Mode's switch, which adopts before saving Integrated) only writes.
- **Operations belong to their project.** They run one at a time in a queue. Each port gets a `folderBoundStorage` view of the project folder (storage adapters bind one folder at a time and the next project re-points the same adapter), which refuses every call once another folder is bound. `stop()` (close, mode change, Publish, dispose) is synchronous: it bumps a revision and aborts the running operation's `AbortSignal`, passed to the port's fetch, pull, push, outgoing and a deepening log. Work writes the snapshot only through an `update` that checks its revision, and the push after a commit, the steps after a push and Release Locks After Push run only while the revision is still the one that started them. `settled()` resolves once the queue drains (Publish's init is queued too): Close Project calls `stop()` then awaits `settled()` inside the project write queue, just before `closeProject()` releases the folder (a pull ahead in that queue finishes first). Every project open starts from Home, after that close, so this also covers a project switch.
- **Snapshot** (`getSnapshot`/`subscribe`, read with `useIntegratedSyncState()`): `active`, `blocked`, the checked-out branch (the port's, from the open and every status; `""` while the open failed, never the default branch, which the menus show as **No Branch Checked Out** (`branchLabel`) with the open failure's message, Commit and Pull disabled: a detached HEAD still refuses to open), `head` and `remoteHead` (commit ids from the status and the remote state, for diff refs), change rows, `ahead`/`behind`, newest incoming commits, last fetch time, the running operation's kind and the last problem (title, message, `SyncError` kind and code, lock holders). It is replaced only when something changes, so lock polls, edits and transfer bytes re-render none of its readers. The running transfer's bytes live in `service.transfer` (`TransferBytes`: published at most every `TRANSFER_PUBLISH_MS`, 100 ms, reset when an operation starts), read only by the transfer labels (status bar, Changes status line, Pulling step); transfers carry whole bodies, so progress is bytes and an indeterminate bar, never a percentage. Clone's progress uses its own `TransferBytes`.
- **Problems:** a run's failure becomes the problem under its title; its success clears a problem with that same title; starting a commit, pull, push or publish clears any problem (a fetch keeps it). A push refused by others' locks fails with the holders (`LockedByOthersError`), so it stays until a later push or commit.
- **When it reads:** status is stat based (unchanged files are never read): once `STATUS_DEBOUNCE_MS` (800 ms, a one-shot timer) after editor saves (`afterEditorSave` in the provider: Save All, Auto-Save, `saveProjectNow`, renames) and registry changes (new assets, imports, moves, deletes, Texture encodes), and on foreground. A remount that only re-read the files marks the registry epoch it reached (`noteRegistryReread`: the foreground rescan and a pull's reload), and that epoch schedules none, since the foreground refresh or the pull reads the status itself; any other advance notes (on open the sync has no port yet, so the note does nothing). While `editorQuiet` or the app is hidden (`setHidden`, from the provider's lifecycle) a due status holds no timer and runs once on return. Fetch runs on opening the project, on foreground, on **Refresh** and after a push. Nothing polls.
- **Changes** (`groupChanges`): a row per changed `.hasset`, carrying the changed `.blobs/<sha256>` files its registry header references (no file is read), and a row per other file (`project.json` as **Project Settings**, folder markers by folder name). Blobs are never rows, and are matched by full path: each content root has its own blob folder (`contentRootBlobFolder`: `assets/.blobs`, `plugins/<name>/assets/.blobs`; a copy between roots writes the blob into the destination's), so `registryChangeLookup` gives an asset the paths in its own root's folder, and the same blob in two roots is two files. A commit (`commitPaths`) writes the chosen rows' files and every changed blob a chosen asset references (also one another row lists). A changed blob no chosen asset references is never committed: an edit's blob a revert abandoned, an undone import's, or a deleted one an unchanged asset may still use; it stays an untracked file in the working copy (no checkout deletes one, a switch or pull to a tree without it included; **Remove Unused Files** does), so no dead LFS object is pushed. The chosen assets' blobs come from their own headers, read from the working copy at commit time (`withWorkingHeaders`, `assetBlobFolder` by path; the commit reads those files anyway), not from the registry's last index, so an asset the registry does not index (a disabled plugin's, an Editor Only extension's) or indexed before its last write never goes without them; a file that is no readable asset keeps the registry's answer. One row count feeds the tab badge, **N Changes** and **Commit N Assets**. The window's rows are a `WindowedList` first in their own `ScrollArea` (with Incoming after them), and the commit box is its own component holding the message, so typing re-renders no row.
- **After a commit, pull or push**, the changes and counts come from local refs (`status` and `remoteState`, no network) as their own step, **Could Not Read Changes**, so it never reports the operation before it as failed.
- **Commit author** (`commitAuthorFor`, in the package): the credential's account name (`Haptic` without one). A GitHub or gitlab.com sign-in keeps the account's numeric id (`accountId`) and commits as the host's private no-reply address (`<id>+<login>@users.noreply.github.com`, `<id>-<username>@users.noreply.gitlab.com`), which links the commit to the account without exposing its email; tokens commit with an empty email.
- **Missing LFS rule:** a commit refused with `lfs` / `missing-lfs-rule` shows **Add Git LFS Rule**, which writes `withLfsRule(.gitattributes)` and commits only that file.
- **Push:** `outgoing({ signal })` (the paths the push sends, measured against the remote's branches as they are now, so a teammate's force-pushed or deleted branch hides none) → `SourceControlService.locksBlockingPush(paths, port.branch)` (a fresh verify of the pushed branch; empty without a provider or on a host without the locking API, so locking never blocks a push it cannot judge; a failed verify refuses) → refusal naming the holders, or `push()`. A push refused or failed still reads the counts from local refs (its `outgoing` brought the remote branches up to date). After a push that went through, each step has its own title, so none reports the push as failed: the local read above → with **Release Locks After Push**, `releaseOwnLocks` on pushed paths that have no remaining change, skipping documents with unsaved edits (**Could Not Release Locks**; skipped when the local read failed) → fetch (**Could Not Check For Changes**).
- **Remove Unused Files** (`source-control-unused-files-flow.tsx`, Changes' **More Actions** menu, so Integrated only): refused while authoring is locked or any document or Project Settings is unsaved (checked again on **Remove**); `SourceControlSyncService.findUnusedFiles` (queued, problem title **Could Not Find Unused Files**) → a warning confirmation with the count and size → `withProjectWrites(removeUnusedFiles(paths))` (queued, **Could Not Remove Unused Files**, then a status) → what it removed. A `.blobs` file is removed only when every rule lets it go:
  - **Git:** untracked, and held by no commit of any local branch that the remote-tracking branches lack (`SyncPort.removableLfsObjects`: an unpushed commit's objects exist only in the working copy, and its push uploads them from these files). Pushed means a remote-tracking ref as last fetched reaches the commit, from local refs (no network): a push uploads objects before it moves the ref, and a stale ref only keeps more. Tracked files are never touched.
  - **Headers:** directly in a content root's blob folder (any other `.blobs` file is left alone) and referenced by no `.hasset` header on disk whose root loads from that folder (`assetBlobFolder`: project, plugin and extension roots, indexed or not, move backups included). Only the headers of roots holding a candidate are read, by range (`readAssetCatalog`), never a chunk or blob. A `.hasset` outside every root (a plugin's settings) keeps its names in every folder; one whose header cannot be read keeps its whole folder.
  - **Open documents** need nothing else: a save encodes the document chunk from memory and writes its blob when the file is missing (`createVfsBlobStore.writeBlob`), so Undo back to a version whose blob went still saves; every other chunk is carried from the header on disk (`keptChunksFor`), which the header rule keeps. The unsaved refusal is on top of that.
  - **Order:** the Git answer is read in the queued operation (only this queue's own operations change it), then the headers are read again and the files removed as the project's only writer (`input.exclusiveWrites` → `ProjectService.withExclusiveWrites`: new writers refused with **Read-only while removing unused files**, admitted ones (saves, imports, copies, encodes, each admitted for its whole span) drained first, refused while another lock such as Simulation's holds writes, the wait and every step ending at the operation's abort), so an asset written since the confirmation keeps its blob. Only the confirmed paths are candidates.
- **Rewrite flows** (Pull, Switch Branch, Revert) share one slot in `SourceControlActionsProvider`: a request of any of them while one is mounted is ignored (Pull Conflicts' non-modal Compare leaves the status bar, branch menus and Revert Asset reachable, and a new flow would drop the conflicts under the old hold). They share `useRewriteFlow` (`source-control-rewrite.tsx`): refused while authoring is locked (and again if a lock arrived before they run), the unsaved-documents step (`UnsavedDocumentsDialog`: every unsaved document and Project Settings, or Revert's one asset; **Save All**, or **Discard** reloads them from disk; an Auto-Save that lands moves on), the confirmation, and the `AuthoringHold` from the confirmation until the files are reloaded, released on done or unmount.
- **Pull** (`source-control-pull-flow.tsx`): refused while authoring is locked (Play stopped at a breakpoint, Simulation); unsaved documents are saved (**Save All**) or discarded (reloaded from disk) first; a warning confirmation (not undoable). From the confirmation, the flow holds `lockAuthoring("Read-only while pulling")` (an `AuthoringHold`: the release and the lock state right after it) behind the modal **Pulling From {branch}** step (no close; bytes, then **Loading The Pulled Files…**): edits are refused, and `requestPlay` and `requestPreviewBuild` refuse Play, Simulation and Preview Build while documents are read-only, naming the reason in the Output Log. In one project write-queue turn (`withProjectWrites`: debounced save cancelled; nothing in the reload enqueues a project write, so no deadlock) `pull()` (no fetch after it: the pull fetched, and the counts come from the local read) → fast-forward, merge, or **Pull Conflicts** (`groupConflicts`: one row per asset, **Keep Mine** / **Take Theirs**, **Apply And Finish Pull** disabled with the first unchosen asset named; **Cancel Pull** changes nothing; every apply recomputes the conflicts; the hold stays through it) → `applyPulledChanges(changedPaths, hold)`: remounts the registry and classifies against the mtime snapshot with `classifyExternalChanges`, as the foreground rescan does, with the pull's own `.hasset` paths and `project.json` always counted as changed (a foreground rescan during a long pull may already hold their times); reads the project (`reload-project` while no open document or Project Settings is unsaved: a project reload replaces every document and resets the save state) or the clean changed documents under the hold; then, only if the lock state is still the hold's, releases the hold and applies them in the same synchronous step (no Play or edit can start in between), installs the new snapshot (a document that could not be read keeps its old mtime) and leaves dirty changed documents, and a project reload withheld for unsaved edits, to the external-change prompt (raised there, since the snapshot moved on). If another lock arrived, nothing is applied and the snapshot stays, so the next foreground rescan reports the pull. A queued Save All runs after the reload and finds the reloaded documents. External reloads read every document first and apply them in one step (`readOpenDocuments`, `applyOpenDocuments`).
- **Branches:** `BranchMenuItems` (Changes' branch picker in place of its label, the status bar's **Switch Branch** submenu, More Tools) reads `localBranches` and `remoteBranches` when its menu opens (the remote's may fail; this copy's still list), the checked-out branch marked, then the remote's other branches. **Switch Branch** (`source-control-branch-flow.tsx`): the shared rewrite steps, then the modal **Switching To {branch}** step and, in one `withProjectWrites` turn, `SourceControlSyncService.switchBranch` (operation `switch`, title **Could Not Switch Branch**, rejects) → `applyPulledChanges(changedPaths, hold)`. In the same queued operation, before anything is checked out, it reads the target's `project.json` at its tip (`SyncPort.branchCommit`, then `readFile`) and refuses with `branchSettingsRefusal`'s message unless that keeps Integrated mode with the same repository (`sameRepository`): the reload installs the target's settings, and Manual, Off or another repository would stop the client in this copy, on iOS and Android with no way back; the local counts follow at once and a fetch is queued without holding the reload. An `uncommitted-changes` refusal names the assets (`groupChanges` over the error's `paths`) and changes nothing. **New Branch…** (`source-control-new-branch-dialog.tsx`, disabled before the first commit): no file changes, so no unsaved step or hold; refused, with the lock's reason, while authoring is locked (subscribed, and checked again on create: a branch checked out under Pull Conflicts would make **Apply And Finish Pull** pull the new branch); a name invalid by `isValidBranchName` or taken here or on the remote (when its list could be read) is refused as typed; `createBranch` checks it out.
- **History** (`panels/history-panel.tsx`, `history` window tabbed with Changes and Locks): **This Asset** (`SourceControlActions.historyPath`: the last `.hasset` `openDiff` showed, or the active tab's on **Open History**; never Project Settings or a folder marker, `isAssetPath`) or **All Assets**; **Uncommitted Changes** first (the snapshot's rows); pages of `HISTORY_PAGE` (50) from `SourceControlSyncService.history` (`SyncPort.log`) in a `WindowedList`, through `sync.commitHistory` (`CommitHistory`: one list per asset and one for every asset, keyed by path, branch and HEAD, read on the first ask from History or a picker and again once the key moves or after a failed first page; the eight last used kept), so the Diff's pickers list the same commits without reading the log again. **Load Older History** (or the pickers' **Load Older**) reads the next page with `skip` and `deepen`, in the operation queue (a deepen writes `.git` and moves the remote-tracking branch, so Close waits for it and cancels its download; problem title **Could Not Load Older History**), then the counts from local refs; plain pages are read outside the queue. After a page that ended at the shallow boundary it reads the pages again with a larger limit, since a deepen can show the boundary commit did not change the asset. The chosen commit shows its message, author, time and short id (**Copy Commit Id**), in **This Asset** only **Compare With Working Copy** (`openDiff` with a `commit` base) and **Revert To This Version** (`requestRevert` with a commit ref), and its assets (`commitChanges`; each opens its parent → commit diff; a shallow boundary commit says to load older history).
- **Status bar** (Integrated and `active` only; Off, Manual and blocked keep the save-state bar): a branch menu (**Commit…**, **Pull**, **Push**, **Refresh**, **Switch Branch**, **New Branch…**, **Open Source Control**, **Open History**), **N Changes** (opens the tab), **Pull N** / **Push N** when non-zero, replaced by the running pull, push, publish or switch, and the last problem's title (it opens the tab, whose Changes window shows the message and lock holders); a small **Saved** on the right unless a save problem takes it. Phone: the same actions in **More Tools** (`SourceControlPhoneTools`), which open the tab when one fails. `SourceControlActionsProvider` (editor route) shares the actions and mounts the lazy Pull flow.
- **Clone** (Homepage **Clone**, hidden where `isSourceControlHost` is false): GitHub / GitLab (`hostApiFor(...).repositories()`, `branches()`) or a typed URL (any host with a saved credential), **Branch**, **Project Name** (taken names refused). `ProjectService.cloneProject` opens a new app-storage folder (`openOwnedDocumentsProject`), clones into it under `scaffoldOwnedProject` (a failure or cancel deletes it; `cloneRepository` adopts the copy, so desktop never asks for it), refuses a branch without `project.json`, writes Integrated with the repository (the cloned branch as its default) into `project.json` unless it already names the repository in Integrated mode (`sameRepository`; another branch writes nothing), and releases the folder; the Homepage then opens it as a listed project. **Cancel** aborts the clone's `AbortSignal` (`cloneIntoFolder` → `cloneRepository` / `FakeSync.clone`), which ends it as a `cancelled` `SyncError`; `cloneProject` checks the signal again at the end of its scaffold, so a cancel that lands after the files arrived still removes the folder. The dialog shows no error for `cancelled`. The mobile session check is held during a clone.
- **Publish** (Project Settings, Off only): `HostApi.owners()` (user, then GitHub organizations or GitLab groups with Developer access; only a failed `/user` fails it, a refused organization or group listing leaves the user alone, as GitHub answers `/user/orgs` with 403 for a token without `read:org` or `user`, or where an organization restricts OAuth apps), Repository Name (`repositoryNameFor`), **Private** / **Public**, a summary (`summarizeProject`: `.hasset` count, bytes, `.blobs` bytes; `.git`, the creation marker and Publish's ignored names left out); refused while documents are unsaved. One path for Publish and a Remote New Project, `publishToNewRepository` (lazy `source-control-publish.ts`, through the provider's action of that name, which never rejects once a project is open and resolves `published`, `local` (still Off: nothing created, or the working copy never started) or `integrated` (Integrated mode saved, the first commit or push unfinished)): the host API from this device's credential for the request's origin (`hostApiForOrigin`), `canPublishProject` before anything is created, `HostApi.createRepository` (empty: no README; a name refused (`http`) because a repository with no branches has it gives that repository, read from the host, and one with branches is refused with **already exists and is not empty**, so Publish never pushes into a repository that holds work) → `writePublishFiles` (`withLfsRule`, `withIgnoreEntries`) → `SourceControlSyncService.publish`: `initRepository` / `FakeSync.init` held as the folder's client (`initRepository` adopts it), then `beforeCommit` saves `project.json` in Integrated mode (the settings effect's configure finds the same identity and keeps the client), commits every changed file and pushes; the local read and fetch after it are their own steps. A failed commit or push still reads the counts from local refs (as a refused push does), so the unpushed commit counts as ahead and the status bar's Push is enabled. A failure after the repository exists leaves it; Push or the dialog's message says what remains. **Interrupted Publish:** `.git` exists before Integrated mode is saved, so a failure or a killed app between them leaves an Off project with `.git`. In app storage on iOS and Android (`publishReplacesRepository`: `.git`, tier not `external`, not Electron) only Haptic runs Git, so `canPublishProject` offers Publish again and `init({ replace: true })` removes that `.git` first. On desktop any Git app may have made it: nothing is deleted, and Mode offers Integrated as for any folder with `.git`. A retry under the same repository name takes the repository the first attempt created while it has no branch (its push never happened); the emptiness check is the host's branch listing, and only an answered empty listing counts.
- **Remote New Project** (Homepage New Project, **Hosting** **Local** / **Remote**, a `ToggleGroup` over an options list so a later choice slots in; shown where `isSourceControlHost`, never when editing a project): the lazy Remote fields list this device's credentials that have a host API (`credentialHasHostApi`: GitHub, gitlab.com, self-managed GitLab), with Owner (`useHostOwners`, shared with Publish), Repository Name (follows `repositoryNameFor(project name)` until edited) and Visibility, or **Sign In To GitHub / GitLab** through `useHostLink` without leaving the dialog; Create waits for a complete request. The repository is created **after the project opens**, through the same `publishToNewRepository` as Publish: Publish needs the open project (its settings save, the sync input and the provider's settings effect, which disposes the sync while no project document is set), so a pre-open path would be a second Git path beside Clone's, and the project still opens once. The provider's create actions run `publishCreatedProject` after the lifecycle's create resolves: only a project this create scaffolded is published (`ProjectService.createEmptyProject`'s `created` is false for a picked folder that already held a project, which opens as it is), the launcher phase moves to `source-control` first, and a `local` outcome sets `publishNotice` (shown above the documents by `SourceControlPublishNotice` until dismissed or the project closes, with the reason and where Publish is); an `integrated` outcome shows only as the snapshot's **Could Not Publish** problem, as after Publish. Nothing deletes project files. On iOS and Android Remote disables **Choose Folder** (a chosen folder is `other-git-client`) and switches Location back to App Documents; desktop keeps it (Publish's init adopts the folder). The last choice and host origin are app settings (`newProjectHosting`, per device), read when the dialog opens and written on Create; a remembered host that is no longer signed in falls back to another signed-in one, or to the sign-in entry.

## Asset diffs

Integrated mode only; the Source Control tab's **Actors** (`diff-actors`) and **Diff** (`diff`) windows, right of Changes. Diffs open inside the tab, never as document tabs.

- **Open diff** (`SourceControlDiffService`, one per editor route, in `SourceControlActionsProvider`; `useSourceControlDiff`, `useSourceControlDiffState`): the target (path, name, type), `base` and `compare` `DiffRef`s (`working`, `head`, `remote`, or a `commit` id), the chosen item and the loaded `AssetDiff`. A Changes row (anything but its checkbox) opens HEAD against the working copy (`openDiff`); Pull Conflicts' **Compare** opens `remote` (the incoming version the pull fetched) against the working copy; the toolbar pickers change either side. A ref resolves to a commit from the sync snapshot (`head`, `remoteHead`) when the diff loads. The diff loads again when a version it shows moves: the commit a ref names, or, for a working side, the asset's own files. Each load first takes their stat stamp (`SourceControlSyncService.workingStamp`: size and time of the `.hasset` and the changed blobs its row carries, never their bytes); each new status compares a fresh stamp, so a save of another asset reloads nothing and a second save of an already modified asset does. A stamp whose newest time is within `RACY_MS` (2 s) of when it was taken counts as changed once more (coarse file clocks, as Git's racy check); storage without times reloads on every status. It waits for `whenEditorAwake`, aborts a load a newer one replaced, and closes (worker terminated) when the sync goes inactive. It loads only while the Actors or Diff window is on screen (`watch`, from `useDiffWindowShown`: `useDockPanelShown`, so the window's dock tab shown and the Source Control tab in front): a load asked for while none is waits for one, and a status or commit move while none is only marks it stale, compared (commits, then the stamp) when one is shown again, so an Auto-Save of a large Scene with the tab hidden reads nothing. `DIFF_IDLE_MS` (60 s) after the last window went, the worker, its decoded versions and the loaded result go (target and selection stay; showing it loads again).
- **Reads, never of unchanged files:** only the chosen asset, at the two versions. The working copy through the sync's folder-bound storage (`readWorking`); a commit through `SyncPort.readFile`; a blob chunk from the asset's own root's `.blobs` folder (`assetBlobFolder`): the working copy's file, or for a commit `readLfsObject` (downloaded when the copy lost it, never written).
- **Model** (pure, `packages/assets`, no React or Babylon): `diffAssetVersions(path, base, compare, cache)` reads each version through an `AssetVersionSource` and decodes lazily (`AssetVersion`): the header always, a chunk only when its view needs it, and a chunk both versions hold with the same digest once (the document of an unchanged Scene is decoded from one side). Container level first: header rows (name, type, parent class, the header payload when the document has its own chunk) and every chunk by digest (never decoded for this). Views by type: Scene and Scene Layer (`diffSceneDocuments`: the Outliner tree of both versions by actor id, removed actors where the base had them; property groups (Actor, Transform with Euler rotation, each component by id) only for actors that are not unchanged; Scene fields; the Scene Script as a graph diff), graphs (`diffGraphDocuments(base, compare, type)`: each family's reader (`asset-diff-graph-families.ts`; Material and Material Function, Particle Graph, Behaviour Tree, Animation Graph 2D and 3D, else any document storing a script's `nodes` and `edges`) reads a version into a `GraphSource`: its graphs (`GraphSourceSection`: compared nodes and wires, the `GraphCanvasKind` that draws it, the graph as stored), members, items and other fields, titling nodes and naming pins from the family's catalog (`@haptic/shader-graph/catalog`, `@haptic/particle-graph/catalog`, `@haptic/behaviour-tree/catalog`); `diffGraphSources` compares each graph by node id, wires by their ends so a remade wire is no change, pin values from `default:<pin>` fields and a node's other fields (a task's settings by key); members by group (`memberGroups`: Variables, Parameters, Inputs, Outputs, Functions, Events And Dispatchers); items (an Animation Graph transition's settings) and fields as property groups; a changed graph's both versions as stored, for its canvas. A Class has its Event Graph and function graphs; an Animation Graph its State Machine (states and State Aliases as nodes, transitions as wires, stored without their graphs), each state's and rule's graph and the Animation Object's; a Material, Particle Graph or Behaviour Tree one graph (a tree's parent-to-child links as wires, positions from `editorPositions`)), Texture (Size, File Size (the `.hasset` plus its blob chunks), Source (the `source` or `pixels` chunk: format, size, digest), Usage, Compression, Downsample; both rasters, one decode when unchanged), anything else by top-level field (`documentGroups`). Values format as the Inspector shows them (`On`/`Off`, `#RRGGBB` for color tuples, two decimals, a minus sign).
- **Worker:** `AssetDiffClient` runs the model on one long-lived module worker (`asset-diff-worker.ts`) and answers its reads on the main thread (storage and Git live there). A source that marks itself `owned` (the working copy: each read is a fresh file read) has its bytes transferred as they are; a commit's are copied first, since a Git object cache or `FakeSync` may hold them. The worker keeps decoded commit versions in an `AssetVersionCache` keyed `path@commit`, so a base is read and decoded once while saves reload the working side; the working copy is never cached. The cache is bounded by bytes, `DIFF_CACHE_BYTES` (64 MiB: the open diff's base and remote side and the last versions History browsed, a few large Scenes' documents; it shares the device's memory with the editor): each version counts its `.hasset` and its parsed document at the document chunk's length, and after each diff (`trim`, once the decodes it needed are known) the least recently used go until the rest fit, so one larger than the budget is used and not kept. Rasters (a Texture's `source` or `pixels`, up to 64 MiB at 4K) are never kept: each diff reads its own (a blob as read, an inline chunk copied out of the `.hasset`), and the reply transfers their buffers with no second copy; the cost is that a Texture diff reloaded after a save reads (and, when the copy lacks it, downloads) the base raster again. A cached version reads its blobs through the source of the diff asking (a cancelled diff's reads go nowhere), and a shared decode that failed is run again by the next diff. Errors cross with their code (`lfs-object-missing`). Without `Worker` (unit tests) the same handler runs on the main thread.
- **Windows:** Actors is a `TreeView` (windowed) of the view's items with status letters and tints (`tone`), unchanged items muted, node and member summaries as row previews, counts (`DiffCountBadges`) and search (matches with their ancestors). Its first row is the asset itself (`ASSET_ITEM`: header rows, chunks and the document-level groups); the selection is that, an actor id, a graph id, `<graph>/<node>`, `member:<id>` or a group. A diff opens on its first changed actor or graph. Diff shows, by view: properties (`PropertyDiffTable`: Property, Base (ref label) and compare columns grouped, changed cells tinted, **Side By Side** / **Inline**, **Changed Only**; a Scene's chosen actor, or the asset summary and Scene fields), the graph canvas (`diff-graph-view.tsx`, lazy; every graph family, the Scene Script included: **Overlay**, **Base** or the compare version of the chosen graph, with the changed graphs as buttons above it. One shared canvas (`DiffGraphCanvas`, `diff-graph-canvas.tsx`) mounts one read-only `GraphEditor` whatever the mode, so a large graph mounts only the nodes in view (`graph-virtualize.ts`), and only while the Diff window is shown (`useDiffWindowShown`); `diffCanvasDocument` (`diff-graph-canvas-model.ts`, pure) builds what it draws from both versions as the family's editor draws them: each version's changed nodes tagged (`__diffStatus`, and on a changed node `__diffChanges`: pin values and fields, old struck through beside new), and for **Overlay** the compare version plus the base's removed nodes and the base wires it lacks by their ends. Its wrapper of every node type outlines changed nodes warning, added success, removed destructive and dashed, each with a tag, and lists the changed values in a pin node's body (`renderNodeBody`, after the family's own) or below a family's card. A family supplies only a `DiffCanvasFamily`: `toGraph(stored)` (its editor's hydration: `scriptDiffGraph` keeps the pins each node was saved with and gives a node saved without them (a never-edited state, rule or Animation Object graph) the node registry's, `materialDiffGraph`, `particleDiffGraph`, `behaviourTreeDiffGraph`, `animStateMachineDiffGraph`), its node types, node body, edge options and canvas class. `DIFF_CANVAS_KINDS` lists the kinds with a canvas (all five): script graphs draw in the view's own chunk (`ScriptDiffCanvas`); the Material and Particle Graph canvases are exported by `shell/asset-panels/rendering.ts` and the Behaviour Tree and State Machine canvases by `animation-ai.ts`, loaded through `lazyPanel` with those editors, reading the project's Global Parameter Collections as the editors do. A graph whose kind has none (`hasDiffCanvas`) lists each changed node's pin values, fields and wires as property groups. Function Call nodes of a Material draw without pins (no Material Function is loaded for the diff), and State Machine cards name no clip), Texture (`createImageBitmap` of each raster, drawn at most 1024 px for **RGB** / **Alpha**, **Side By Side**, **Swipe** (clip) and **Difference** (per-channel absolute difference); no preview where the browser cannot decode the raster; Materials and Material Instances whose header lists the Texture). An undecodable version shows its error. **Open <Kind>** opens the document (`documentKindForAssetType`).
- **Pickers:** `SourceControlDiffPickers` in the global toolbar's document slot while the Source Control tab is active and a diff is open: Working Copy, HEAD, the remote branch, and the asset's commits from `CommitHistory` (History's list of the asset, loaded when a menu opens unless History already read it) with **Load Older** (History's paging, the menu kept open) while more may come; past the first page the commit rows are a `WindowedList` in their own `ScrollArea`.
- **Revert** (`requestRevert({ path, name, ref })`, the lazy `SourceControlRevertFlow`; History's **Revert To This Version** calls it with a commit ref; only a `.hasset`: a reverted `project.json` would reload the whole project, so other paths are ignored): refused under any authoring lock (Play, Simulation, a pull's hold), the asset's own unsaved document saved or discarded first (the shared rewrite steps), a warning confirmation (not undoable), then `lockAuthoring("Read-only while reverting")` behind a modal step and, in one `withProjectWrites` turn, `SourceControlSyncService.revert(path, commit)` (queued with the other operations, problem title **Could Not Revert**) → `applyPulledChanges(written, hold)`. `restoreVersion` reads the asset at the commit, downloads every blob it references that the copy lacks before writing anything, writes blobs before the asset, and removes the asset when the commit has none. **Revert Asset** is disabled when the base is the working copy.

## Editor behaviour

- **Auto-lock** on the first mutating `applyGraphChange` / `applySceneChange` / `applyAssetDocumentChange` per path per session, after the plugin read-only check. Skip create when verify already lists the path as ours. 409 theirs or a network failure still applies the edit and shows a persistent banner.
- **Advisory open** always succeeds. A path locked by someone else opens in edit mode `readonly` (`DocumentLockEditMode`: `editable` / `readonly` / `edit-anyway`) with holder, age and **Edit Anyway**.
- Moves, renames and deletes are path-keyed over every contained asset: ours → lock new, then unlock old (`transferLock`, never releasing first); delete of ours unlocks (`releasePath`); theirs → refuse with the holder before mutating. Copy never transfers locks. A failed transfer is reported and never undoes the file move.
- While a project's mode is not Off, the Texture alignment pass never re-encodes older Textures in the background (it would race a teammate for the file); only user-initiated re-encodes run, and they count as edits for auto-lock. Content Browser tiles expose `data-lock-state` `mine` / `theirs`.
- `LockPollScheduler` ticks on start, then every 60 s; pause/resume follow background/foreground and `editorQuiet`, and ticks never overlap. Failed checks keep the cached list as the last known result; superseded replies never replace current state, and a verify reply that a local create or unlock overtook is requested again before it replaces the list. A refresh asks at most three times; when local lock changes overtake every reply, it keeps the cached list and its previous status and asks the scheduler for another tick, which waits for resume while paused.
- The Locks window re-renders only rows whose lock changed: `locks` is a stable snapshot until the list changes, and rows are memoized with primitive props.

## Git core

Integrated mode's sync, in `packages/source-control/src/git/` (pure: storage, HTTP, credentials and clock injected). isomorphic-git, pinned exactly, does objects, packs, refs, the index and smart HTTP; Haptic's code does LFS, pull and the history walk. Rejected: host REST APIs for sync (per-host code, a hand-made index, no offline commits, request limits on large pushes) and the `git` binary on desktop (a second implementation; iOS has none). `.blobs/<sha256>` files are LFS objects (raw chunk bytes named by their SHA-256, the LFS oid, never rewritten); Git itself carries `.hasset` files (chunks under 64 KiB stay inline), `project.json`, plugin and extension files and `.haptic-folder` markers.

- **Repository:** the project folder is the working tree and `.git` sits at its root beside `assets/`. `GitRepository` runs one operation at a time and keeps isomorphic-git's cache (packs are immutable; the index is re-read when its stat changes). `core.filemode` is false: storage keeps no modes.
- **`StorageFs`** (one per operation) is the `fs` isomorphic-git runs on: stats are storage's size and mtime (mode 100644, ctime = mtime), and a directory listing answers the following stats, so a status costs one storage call per directory and reads only files whose stats differ from the index. A file with no mtime is always content-checked. `rmdir` removes only an empty directory, so checkout never deletes untracked files. A fetch runs inside `objectsFirst`: its writes and removes in `.git` outside `objects/` (the shallow list, refs) wait until it resolves, because isomorphic-git writes them before the pack, and a fetch cancelled or killed in between would leave them naming commits never stored (every later history walk fails); a failed fetch makes none of them, and one that resolved makes them all, even if its signal aborted meanwhile, since its pack is stored. Every method returns a promise, even for a bad argument: isomorphic-git takes anything else for a callback `fs`.
- **LFS** is git-lfs's clean and smudge, inside `StorageFs`, for working tree `**/.blobs/<sha256>` files:
  - reading one answers its pointer (`version …\noid sha256:<name>\nsize <stat size>\n`), so the object is never read or Git-hashed, and status, `git.add` and checkout see the pointer's id;
  - writing a pointer to one keeps the object's file when it is there with the pointer's size (otherwise `lfs-object-missing`; a pointer naming another object is `lfs-object-corrupt`); other bytes are written as they are;
  - so the index holds the real file's stats against the pointer blob, as git-lfs leaves it, and status compares `.blobs` files by name and size;
  - removing one keeps it: there is no `.git/lfs` store and a push uploads from the working file, so it may be the object's only copy (an unpushed commit's). A checkout of a tree without it (switch, pull) only drops its index entry and leaves it untracked, out of `changedPaths`; a later checkout that wants it finds it there by name and size.
  - `removableLfsObjects({ signal })` lists the untracked ones (`statusMatrix` rows with no HEAD and no index entry; untracked files are never hashed) that no commit of any local branch ahead of every remote-tracking branch holds (`relate` without deepening, each such commit's tree read only along the candidates' folders). Remove Unused Files decides from it.
- **Downloads come first:** clone (fetch without checkout, download the head tree's objects, then check out) and pull (the objects of the paths it writes) download only objects whose file is missing or of another size, through the batch API, checked against size and SHA-256 before they are written. Checkout's write of the pointer then finds the file in place.
- **Transfers:** the batch request carries the repository credential (`authorizedHttp`); an action is sent with exactly its own headers (replacing Haptic's whatever their case, less transport framing such as GitLab's `Transfer-Encoding: chunked`, since bodies go whole), plus the credential only when it is on the repository's origin and has no Authorization. Nothing follows a redirect; a non-HTTPS action is refused. Batches hold 100 objects; transfers run one at a time. Smart HTTP requests send `User-Agent: git/isomorphic-git@<version>`, not the WebView's.
- **Clone:** shallow (`DEFAULT_CLONE_DEPTH` 1, or the caller's), single branch, no tags, into an empty folder (creation markers ignored; otherwise `conflict` / `not-empty`); `core.filemode` false and adopted.
- **Init** (Publish): `git.init` on the branch, `origin` set to the HTTPS clone URL, `core.filemode` false, adopted; a folder with `.git/HEAD` is `conflict` / `repository-exists`, unless the caller passes `replace` (it decided the `.git` is an interrupted Publish's), which removes `.git` first. The first push creates the remote branch.
- **Adoption** (`adoption.ts`): `ADOPTION_CONFIG` (`haptic.integrated`) in the working copy's `.git/config`, through `git.getConfig` / `git.setConfig` on a `StorageFs` (never parsed by hand). `readAdoption` is false without the entry or without `.git`; isomorphic-git casts only `core` entries, so it compares the text with Git's true spellings (`true`, `yes`, `on`, `1`). `setAdoption(false)` removes the entry and keeps the rest of the config.
- **Cancel** (`TransferOptions.signal` on clone, fetch, pull, push, `outgoing` and a deepening `log`): once it aborts, `cancellableHttp` refuses the next request and the answer of one in flight (native HTTP cannot stop a request), `StorageFs` refuses working tree writes and removes (checkout starts every write at once, so the rest fail), and `run` reports any failure as `cancelled`, whatever it looked like on its way out. Clone checks the signal again after checkout. `FakeSync` checks it before each step and each file it writes.
- **Status:** `statusMatrix` rows as added, modified and deleted paths; `.gitignore`d untracked files are left out.
- **Commit:** exactly the chosen paths that changed (`git.add`, `git.remove`), signed with the given author at the injected clock. A present `.blobs` file needs the rule `**/.blobs/** filter=lfs` in `.gitattributes` as the commit will hold it (the chosen working file, else HEAD's), otherwise `lfs` / `missing-lfs-rule`, so Publish's first commit may add rule and blobs together. Publish's helpers: `GITATTRIBUTES_LFS_RULE`, `GITIGNORE_ENTRIES` (`layout.json`, `.haptic-*.tmp`, `.haptic-move-*`), `withLfsRule`, `withIgnoreEntries`.
- **Branches:** `openRepository` takes the branch from HEAD (`git.currentBranch`); a detached HEAD is `conflict` / `detached-head`. `localBranches` lists `refs/heads` (no network); `remoteBranches` reads the ref advertisement (`listServerRefs`, protocol v2 `ls-refs` with prefix `refs/heads/`, v1 filtered client-side; one request, any host). `createBranch` (`isValidBranchName`, `invalid-branch-name`, `branch-exists`, refused before the first commit) writes the ref at HEAD and points HEAD at it. `branchCommit` names a branch's commit without checking it out: the local ref, else the remote-tracking ref after the same fetch a switch makes (null when neither has it), so `readFile` can read the target before a switch. `switchBranch`: a branch only the remote has is fetched `DEFAULT_CLONE_DEPTH` deep (with no local ref the fetch has no haves); the files that differ between the two trees (identical subtrees skipped) are checked against the working tree (hashed only when their stats changed): one holding neither branch's version refuses with `conflict` / `uncommitted-changes` and its `paths`, before any write. Otherwise the target's LFS objects for the paths it writes are downloaded, the paths whose working file is not already the target's are checked out (forced, HEAD unmoved), the others only get the target's index entry, then a new local branch and its upstream (`branch.<name>.remote` / `.merge`) are written and HEAD moves; uncommitted changes to other paths stay, and so do `.blobs` files the target lacks, untracked (the LFS filter never removes one). `changedPaths` feeds the reload.
- **A branch the remote lacks** (new, or deleted there): the fetch's `NotFoundError` for its `refs/heads/<name>` is no failure; its remote-tracking ref goes (as `--prune`). It has nothing to pull; ahead, `outgoing` and a push's LFS uploads count against every remote branch this copy fetched (`relate` takes several remote heads; `outgoing` diffs against their merge base), as git-lfs's pre-push does, never the whole history. Its first push sets its upstream, as `git push -u`.
- **Fetch and history:** `relate` paints both sides newest first and stops when every queued commit is common, so it reads only commits since the fork; it gives ahead and behind, each newest first (commit time; commits of one second keep the walk's order), and the merge base. `fetch` also lists the remote-only commits: the first `INCOMING_LIMIT` (50) of `behind`, from the commits the walk already read (one read per commit per operation). `remoteState` gives the same counts and list against the remote-tracking ref as last fetched, from local refs only (no deepen, no network). `outgoing` (the paths a push would change) first brings every remote-tracking branch up to one ref advertisement (`listServerRefs`): one the remote no longer has goes (as `--prune`), one that moved points at its new commit when this copy holds it and is fetched otherwise (a same-named local branch gives the fetch its haves, else `DEFAULT_CLONE_DEPTH` deep); a stale tip would leave out the paths of commits the remote lost, and their locks. It then diffs the merge base of the branch and its remote branch (before its first push, every remote-tracking branch) with the branch (identical subtrees skipped), so a remote that moved on since adds none of its own paths. After every fetch, `.git/shallow` drops the commits that fetch added whose parents this copy holds (`trimShallow`): isomorphic-git checks before the pack is stored, so a branch fetched one deep off a commit this copy has would otherwise stay a boundary that every walk stops at, short of the merge base. A boundary listed before the fetch stays: the objects past it may be a deepen's that never finished (a killed app), with history missing beyond them. A fork older than the shallow history deepens the fetch by 50, 100, 200 and 400 commits, then gives up; a pull with no base is `conflict` / `unrelated-histories`.
- **Pull** (fetch first): the incoming files are those that differ between the merge base and the remote (identical subtrees skipped). Mine is the working tree's file, committed or not (hashed only when its stats changed). `planPull`: a file whose working copy equals the base or the remote's takes the remote's; any other is a whole-file conflict needing `mine` or `theirs`. Without a choice for each, nothing changes and the conflicts are returned; every call recomputes them. Applying checks out exactly the paths taken (forced, HEAD unmoved), then either moves the branch (fast-forward; a kept file's index entry takes the remote's id, so it reads as an uncommitted change) or commits a merge of local and remote from the index (local tree plus the taken paths; a kept path keeps its committed local version). A `.blobs` file the remote removed stays, untracked. `changedPaths` feeds the external-change reload.
- **Push:** the objects introduced by the commits being pushed (each against its first parent; a new remote branch counts from the tracked branch's remote ref) go through a batch `upload`; only objects the server answers with an upload action are sent (then `verify` when given); then the refs. A remote that moved is `conflict` / `push-rejected`.
- **`readFile(path, commit)`** answers the Git blob; for a `.blobs` pointer, the working copy's file of that size (an object never changes under its name) or a download, never written.
- **`readLfsObject(path, size, { signal })`**: the same for an object named by its `.blobs/<sha256>` path and size (a `.hasset` chunk entry gives both), with no commit or tree read; a missing object is `lfs` / `lfs-object-missing`. Never written: the working copy would keep a file none of its assets uses.
- **`log`** walks the branch until the shallow boundary, `skip` commits left out first (read again from the object cache: isomorphic-git walks from HEAD each time) and the page sliced to `limit` (a path's log that stops at `depth` adds the commit it stopped at); `shallow` says the page ended early because the walk from the branch's head reached a commit in `.git/shallow` (whose commit a path's log lists as the one that added the path), never merely that the copy is shallow (a branch fetched one deep leaves it so); only then is `hasMore` true past the page and `deepen` fetches `limit` more commits, once.
- **`commitChanges(commit)`**: the files against its first parent (every file of a root), from the two trees; null for a shallow boundary commit, whose parent this copy lacks.
- **Errors:** `SyncError` with `kind` `auth` (no credential, credential refused, 401/403), `network` (no answer, Git server failure), `conflict`, `not-found` (repository, branch, object), `lfs` or `cancelled` (the operation's signal aborted), and a `code` where the kind alone does not say. Storage failures and bugs pass through untyped.

### Sync port and fake

- `SyncPort` is what the editor uses ([Integrated mode](#integrated-mode)): `branch` (the checked-out one), `status`, `commit`, `fetch` (counts and incoming commits), `remoteState` (the same from local refs), `outgoing`, `pull`, `push`, `readFile`, `readLfsObject`, `removableLfsObjects`, `log`, `commitChanges`, `localBranches`, `remoteBranches`, `createBranch`, `branchCommit`, `switchBranch`; fetch, pull, push, `outgoing`, `removableLfsObjects`, `remoteBranches`, `branchCommit`, `switchBranch` and `log` take `TransferOptions` (`signal`). Clone, open and init are factories (`cloneRepository`, `openRepository`, `initRepository`; `FakeSync.clone`, `FakeSync.init`); clone takes a signal too. Adoption is not part of the port: `FakeSync` has none, as test mode is never asked.
- `FakeSync` (subpath `./fake-sync`) implements it for editor and end-to-end tests: the working tree is real project storage, history lives in a `FakeRemote` shared by every copy (a teammate commits through `FakeRemote.commit`), with full history, no `.git` and `.gitignore` lines as name or path globs. It shares `planPull` and `relate`, and ids content as Git does (`.blobs` by name and size). Its commits hold `.blobs` files as LFS pointers, as Git does: an object's bytes are only in working copies and `FakeRemote.lfsObjects`, so a push uploads the working files of the objects its commits introduce, a checkout (clone, pull, switch) takes the working file or the store's, checked before any write (`lfs-object-missing` when neither has it), and a removed `.blobs` file stays, as in the Git core; with no index, `removableLfsObjects` takes what HEAD lacks as untracked. Each copy keeps its own local branches and fetched remote branches, as `refs/heads` and `refs/remotes` (`outgoing` brings the fetched ones up to the remote first, as the Git core does); `FakeRemote.commit` on a branch the remote lacks starts it from main. `FakeRemote.lfsObjects` is the LFS store (bytes by oid: seeded, or uploaded by a push), so `readLfsObject` finds only what a server would. Its status works from directory listings: `.blobs` files are never read, and other files are hashed only when their size or mtime changed since an earlier hash (trusted only for an mtime older than that hash, as Git's racy check), as the Git core reads only files whose stats differ from its index.
- [`sync-port.contract.test.ts`](../../../packages/source-control/src/sync-port.contract.test.ts) runs every case against `GitRepository` on the test Git server and against `FakeSync`, so the fake cannot drift.
- The test server ([`git-server.ts`](../../../packages/source-control/src/test-support/git-server.ts)) runs the system `git http-backend` as CGI behind Node `http` with no system or user Git configuration, plus the batch API and an object store on a second origin whose actions bring their own Authorization. Tests reach both through an injected `HttpClient` that routes `https://git.test` and `https://lfs-storage.test` to loopback, so the code keeps its HTTPS-only credential rule; the store refuses any other Authorization.

### Binary HTTP

`HttpClient` and `NativeHttp` carry GET, POST and PUT; a body is text or bytes, and `responseType: "binary"` answers `bodyBytes`. Bodies cross whole (no streaming): Electron's `lfs:fetch` takes a byte body as an exact `ArrayBuffer` (POST or PUT, ≤ `MAX_IPC_BYTES`, 512 MiB) and answers binary bodies up to the same limit (text 16 MiB); CapacitorHttp gets base64 `data` with `dataType: "file"` under a Content-Type that is present and not JSON (default `application/octet-stream`; Android reads JSON first) and answers `arraybuffer` as base64 (JSON content types arrive parsed, Android sends error bodies as text, Android's base64 is line-wrapped). Native streaming waits for the iPad benchmark ([plan](../source-control-plan.md#order)).

### Benchmark

- `runGitBenchmark` (subpath `./git-benchmark`): a shallow clone, a status of the unchanged tree (it reports the files it read, which must be none), a one-file commit and its push, then a few large LFS objects (default 3 of 32 MiB) committed, uploaded and downloaded again; each step's time, bytes sent and received and working files read. Its commits go to a new remote branch only.
- Where it runs (`gitBenchmarkAvailable` in `git-benchmark-hook.ts`): iOS and Android, in Debug Mode, in any build. Mobile `DocumentsStorageAdapter` keeps its folder per instance. Not on desktop: Electron's main process keeps one `NodeStorageAdapter` per window (`projects(event)` by sender id) and storage calls carry no folder, so a second renderer storage instance's `openDocumentsProject` and `releaseFolder` would move and then release the open project. Not on the web: no native HTTP.
- Two ways in, one runner (`runGitBenchmarkLazily` loads `git-benchmark-runner.ts` on first call): **Debug > Run Git Benchmark…** (the way in for release builds, which have no Web Inspector) opens `GitBenchmarkDialog`, lazy and kept mounted after its first open so a run and its result survive closing it; and `DiagnosticLogInstaller` puts `hapticGitBenchmark({ repositoryUrl, branch?, blobs?, blobMiB?, depth? })` on `globalThis` for the Web Inspector console. The dialog prefills Repository URL and Branch from the project's `sourceControl` when it names a repository, in any mode (else empty and `main`) and LFS Objects and Object Size from the runner's defaults (`GIT_BENCHMARK_DEFAULT_BLOBS`, `GIT_BENCHMARK_DEFAULT_BLOB_MIB`); while it runs it shows an indeterminate bar only (the runner reports no phase and takes no abort signal, so there is no Cancel); then the unchanged-status gate (no file read, no change found), a timing summary and the result as formatted JSON with **Copy Results**, or the error with **Copy Error**.
- The runner clones into a new Documents folder through its own storage instance with the device's saved credential for the host, pushes `haptic-benchmark-<time>`, logs and returns the result and deletes the folder. The branch and its LFS objects stay on the host.

## External change

- `IndexedAsset.mtime` comes from the registry walk. On foreground the editor rescans and diffs mtimes plus `project.json`. Editor saves recapture the snapshot (`refreshMtimeSnapshotAfterEditorSave`); the registry's own Texture writes fold in through `applyOwnAssetWrite` only if the file still had the snapshot mtime, so a teammate's change still counts.
- ≥ `MANY_EXTERNAL_CHANGES` assets or a changed `project.json` → **Reload Project**; dirty changed/deleted documents → Keep Edits vs Reload From Disk; clean ones → Reload From Disk.
- Reload never drops in-memory locks before the next verify; this covers a Working Copy branch switch while backgrounded.
