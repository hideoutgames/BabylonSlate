# Scene Layers

SceneLayer overlays: unlit 2D documents stacked on a Play session compositor above the single world Scene.

## Product decisions

- A SceneLayer is a HUD overlay. It is not a second world scene, not additive streaming, and not the removed UserInterface / ADT HUD. Never re-add `@haptic/ui-runtime`, UserInterface, WidgetComponent or Babylon GUI.
- Play loads one world Scene at a time; layers live on a session compositor drawn after the world camera and its post-process, so world PP never hits overlays.
- Scene-owned layers spawn from `SceneSettings.sceneLayers` (`{ assetGuid, zOrder, enabled }[]`) and despawn with that world. Graph-created layers (`ownerSceneGuid === null`) survive world travel until Remove / Clear / Stop. One asset may run as several instances.
- Widgets are actor components (`2D*`), not a separate widget asset system.
- Post-processing is one stack for all layers combined, never per layer: Project Settings `sceneLayerPostProcessStack` (`SceneLayerPostProcessEntry`: `normalizeScenePostProcessStack` rules, no `scalable`, since layers always run full resolution) is what Play starts with. A layer document has no passes. The Scene Layer's Inspector shows that Project Setting itself (`PostProcessPassList` in `scene-details-settings.tsx` writing `updateProjectSettings`), not an override, so its edits are Project Settings edits: no document undo entry.

## Document and editor

- Content Browser type `SceneLayer` → document kind `scene-layer`: actors, folders, 2D gravity, `physicsEnabled` (default false), `tickOnPause` (default false: while the game is paused every actor of an instance and its SceneLayerScript keep ticking, whatever the actors' own Tick On Pause), `canvas` (`SceneLayerCanvasDesign`, default Fullscreen, Root Center, Fit To Screen). Always 2D.
- The editor tab converts to a locked 2D `SerializedScene` so Viewport / Outliner / Inspector reuse the scene shell; Save converts back. `physicsEnabled`, `tickOnPause` and `canvas` travel as editor-only `layerPhysicsEnabled`, `layerTickOnPause` and `layerCanvas`; a layer's `cameraBounds2D` is unused.
- The tab is one locked 2D Unlit viewport with an opaque black clear, not the Play compositor; it draws at device pixels and full quality like Play (`fullQuality`). It hides the 3D/2D toggle, Move/Rotate/Scale and shading menu, and omits Default Camera, fog/IBL, lights and the physics-world picker.
- Canvas (`SceneLayerCanvasDesign`: `sizeMode` fullscreen / desired / custom, `customSizePx`, `rootAnchor`, `scaling` fitToScreen / truePixelSize). `sceneLayerCanvasRect` in layer units: Fullscreen is the design resolution (`sceneLayerDesignResolution`: Custom Resolution when on, else 1920 × 1080) over `twoD.pixelsPerUnit`, Custom `customSizePx` over it, both hanging from the origin at `rootAnchor`; Desired is the drawn content's bounds (none without content; Play stands in the Fullscreen canvas, `sceneLayerPlayCanvas`). The orange outline (`sceneLayerCameraFrame` with the project's context; Desired from `EditorTools.visualBounds2D` of every actor) is that rect moved by Camera Location (`cameraLocation2D` in editor, `cameraLocation` on disk, default 0, 0).
- Play view (`sceneLayerView`, what the camera frames at zoom 1 and location 0, 0): `screen` is the output in design pixels (`sceneLayerOutputDesignSize`: an extended pixelated framebuffer itself, else the design resolution widened to the output aspect, so high-density windows count design pixels) over Pixels Per Unit. Fullscreen, and any mode at True Pixel Size, frame `screen`; Custom and Desired at Fit To Screen frame the canvas widened to its aspect (never stretched). The view's centre puts the canvas's Root on the matching screen point (Center: centred). It is a `{ width, height, center }`; the camera sits at `center` + `LayerCameraState` x/y, so scripts' Camera Location is an offset from it. Authoring is WYSIWYG: 12 px text is 12 design pixels.
- Actors with 3D geometry (`SCENE_LAYER_3D_COMPONENT_CLASS_IDS`, `isSceneLayer3DActor`) get 3D Rotation and Scale rows in the Inspector (`TransformRowsMode` `layer3d`) but keep Position XY plus Z-Order; a mixed selection stays 2D. The viewport still uses the 2D box, whose writes replace only euler Z and keep X/Y tilt.
- Selection uses the 2D transform box (`overlay-box`). Resize writes actor XY scale; on 2D Text / Rich Text it writes `wrapWidth` / `wrapHeight` instead. A multi-selection frames the visuals of every selected root in the attached root's space (`selectionBoxVisuals` in `editor-viewport-tools.ts`); the others follow through the gizmo multi-select world delta, which runs before the box re-lays out on each drag step.

## Object model and placement

- `SceneLayer` extends `Object`; `SceneLayerActor` extends `Actor`. Overlay actors live in the same `World`, tagged `sceneLayerId`, so graphs and Get All Actors see them. Change Scene must not destroy them.
- Instance actor guids are `<layer guid>:<authored id>` with references remapped ([object-model.md](object-model.md#guids-and-identity)); component ids stay authored. Repeated actor ids fail to load.
- Every `2D*` component is overlay-only (`SCENE_LAYER_EXCLUSIVE_COMPONENT_CLASS_IDS`); world-only components (Landscape, Foliage, water, Skybox, cameras, lights, fog, streaming, Movement, buoyancy …) are stripped from layers and refused at runtime. `ENGINE_COMPONENT_DESCRIPTORS` decides placement for Add Component, Place Actors, serialization and instantiation.
- Spawn Actor and world instantiation never create `SceneLayerActor`. World Place Actors uses `overlay: false` and never lists overlay stamps.
- A Class or new Prefab with no authored components gets the starter Box only in a 3D world Scene (`defaultPrefabComponents`); overlay placement and 2D Scenes leave it empty, and `spawnPlacedActor` decides at placement time, not the Class. A SceneLayerActor Class with no authored components shows none in its Prefab, thumbnail and member paste target.
- SceneLayerActor Prefab frame: editor-only `SerializedGraph.overlayDesign` (`SceneLayerActorDesign` = `SceneLayerFrameDesign`, the canvas design without `scaling`; default Fullscreen, Root Center), edited by `graph.setOverlayDesign`, never compiled or read by Play. `sceneLayerActorFrameBounds` is `sceneLayerCanvasRect` with the project's design resolution and Pixels Per Unit; Desired is the XY union of drawn visuals (`EditorTools.visualBounds2D`), none without content. The Prefab Root gets no transform box and no pivot write.

## Runtime and render

- Readiness is per layer instance: `sceneLayerLoading` → `sceneLayerRealized` → `sceneLayerReady` for that exact load id. Begin Play, ticks, physics and playback wait for owner readiness; late acknowledgements for removed/superseded ids are ignored. Create Scene Layer resolves when ready (30 s deadline); a failed or cancelled wait removes its layer, except after Stop, which ends the wait quietly (no layer commands, no diagnostic) like other cancelled continuations.
- Each layer camera is an independent orthographic HUD camera 10 units in front of its Layer Camera centre (`(x, y, -10)` looking along +Z), rolled by its rotation (degrees, positive counter-clockwise like actor Z rotation) at `viewBounds.center` + its location with `±viewBounds/2 / zoom` ortho (`SceneLayerView.viewBounds` from `sceneLayerView` on create, resize and a Desired remeasure; the canvas from `sceneLayerCreate.canvas`; `screen` from the host's `screen` option; `cameraState` from `sceneLayerCreate.camera` then `sceneLayerCamera`). Never parent overlay cameras or meshes to the world camera or copy world view/projection; re-bind the pose if another owner changed it.
- The camera is a `LayerCamera` object on the `SceneLayer` instance (`camera`, its `state` starting at the asset's Camera Location), the same class as the main Scene's. Scripts reach it with Get Layer Camera on the layer or on a Scene Layer Actor (never through the Scene Camera Manager) and move it through its Camera Location / Rotation / Zoom variables, Add Camera Offset and the Tween Layer Camera nodes, which all call `setLayerCamera` → `SceneLayers.setCamera`, which emits `sceneLayerCamera` on change. Never saved, excluded from Save Games like the rest of a layer; it reads as destroyed once its layer is. Zoom is floored at `LAYER_CAMERA_MIN_ZOOM`; non-finite values keep the current field.
- Every canvas → layer mapping (compositor picks, scroll targeting and drag, 2D form controls, 2D Joystick, `projectCursorToSceneLayer`) goes through `sceneLayerCanvasToLayer` with the layer's view (size and centre) and camera; never re-derive it from `viewBounds` alone. Wheel steps scale by zoom only (they scroll along the box's axes). Scroll and mask scissors bound all four projected corners, so a rolled camera clips to the upright screen rectangle (an accepted over-draw at the corners: scissors cannot rotate).
- Draw order: world, then layers by `zOrder` (ties by instance id). Without an enabled Scene Layer pass (`SceneLayerCompositor.setPostProcess`, or post-processing off) each layer draws straight into the backbuffer clearing depth only: no extra target or draw. With one, every layer draws through a view (`LayerRecord.view`: an RTT of its own Scene wrapping the shared target's colour (`colorAttachment`) and depth texture, each texture referenced once more) into one shared target (`LayerStack.target`, `createDepthTextureTarget`, device size): the first layer drawn clears it to transparent, the rest clear depth only. The passes' Scene draws it full screen (an unlit plane, `ALPHA_PREMULTIPLIED` over its transparent clear: an exact copy) through its own renderer with the passes attached (`attachLayerPostProcess`) into a colour-only output, which one blit blends over the world as a layer's blit did (targets keep alpha). One target and one chain whatever the layer count. A new pass list replaces only the passes' renderer; a resize, or the stack gaining or losing its passes, replaces the target and every layer's renderer.
- Held image: a frame where a layer fails to draw, or the passes cannot, blits the last composite again; a replaced stack's last composite (`held`) shows until a frame presents without it. A layer still waiting to present (`fallback`) is left out of the shared target rather than holding it.
- Full quality whatever the tier, render scale or device: layers draw into Play's backbuffer, which keeps the view's device pixels (or the locked custom resolution) while only the world graph scales ([render.md](render.md#play-presentation-and-editor-views)); the shared target is the backbuffer's size and the passes ignore the Post Processing `resolutionScale`; the passes' Scene follows the world's settings and keeps full quality (`preparePostProcessScene`); `pinFullRenderQuality` (`render-settings.ts`) pins layer Scenes, and the editor tab's Scene, to the device's highest anisotropy (Ultra's 16), no texture LOD bias and no Auto LOD. Play layers still follow the world view for project settings (`followSceneRenderSettings`: Water).
- Layer Scenes batch their unlit draws where the image cannot change ([render.md](render.md#draw-batching)): the compositor turns it on at `create`; Play's world Scene and the editor tab never batch. A layer Scene's small nearest-sampled images share one page, so visuals of different images batch too. Each pass keeps its batches and fills between frames and reads again only the members the Scene's render change journal names ([render.md](render.md#draw-batching), Retention), so a layer visual's renderer-facing writes must reach the journal: a Babylon write it hooks, or `noteRenderChange` at a Haptic write point. A member named only for its pose or its overlay style (`RenderChange.Style`, which only `applyOverlayVisualStyle` notes) keeps its readiness answer, so a writer that can change a visual's program must note another kind.
- Overlay identity is `sceneLayerId` / `SNAPSHOT_FLAG_OVERLAY` / overlay-only mesh kind. Overlay visuals never instantiate on the world Scene; leftover `actor-*` world copies are disposed. A snapshot apply sweeps for them only when one can exist (`sweepWorldOverlayLeftovers`): its overlay slots changed, the world Scene's mesh count or newest mesh changed or it notified an addition, or the pass migrated or hid a visual. The pass collects its overlay slots in one set the binding keeps (`binding.overlaySlots`), stamped and pruned per pass like `liveSlots` rather than allocated; the sweep copies what it remembers, so nothing else holds the set.
- `2DTexture` / `2DMaterial` share the Engine `ResourceCache`; overlay sampling must not steal a world texture wrapper. Overlay materials compile scene-local unlit (separate cache key).
- A layer's every frame is a strict one (it never draws a Material's previous variant), so its renderer limits a readiness probe to the meshes the changes since its last passing probe named (`scopedStrictProbes`, [render.md](render.md#frame-path)): a spawned visual, or one whose style crosses full opacity (`applyOverlayVisualStyle` names the component's own meshes). A visual that joined while invisible, disabled or without geometry (a runtime component under a hidden actor, an unrealized list row) is probed on the frame it becomes drawable (`followDrawable`), not with the next unrelated change, as is a mesh whose visibility crosses 1 (a rich text glyph's reveal) or whose sub-meshes a text redraw rebuilt. A change that names no mesh probes the whole layer.
- A layer Scene's drawable meshes ([`layer-drawable-meshes.ts`](../../../packages/render/src/layer-drawable-meshes.ts)) are the dispatch order of its retained draw list (below) and, on a frame that takes Babylon's full path, what its mesh loop (`getActiveMeshCandidates`) and its camera's cull read: `scene.meshes` in order less the disabled and invisible ones (hidden actor roots, disabled control parts), so the cull's output is unchanged. Membership follows the render change journal's `Enabled` and `Visibility` notes, the mesh add and remove observers and the mesh count and newest mesh, and is read where it is used (admission, the mesh loop after the before-render observers, the cull). A mesh whose class redefines those writes (`journalFollows` false) stays listed. A hidden root's world matrix is computed with its drawn descendants' (`getWorldMatrix`) or on any read. Every 32nd frame, and every frame under `verifyRetainedOverlayBatches`, a full filter checks and heals it (`layerWork[].drawable`). The frustum test stays: the camera pans, zooms and rolls and content may sit off canvas.
- A layer Scene draws from a retained draw list ([`layer-draw-list.ts`](../../../packages/render/src/layer-draw-list.ts), `keepLayerDrawList` at `create`), so Babylon's per-frame work sees only what the layer draws: its mesh loop gets the meshes the batcher drew last frame (batch meshes and draws made on their own, `SceneDrawBatcher.outputs`), the cull (`CameraOutputCullTask.drawList`) outputs those without testing any, and the objects pass's list preparation puts the retained lists in its rendering groups marked presorted (`setPresortedPass`), which `_RenderSorted` and `TransparentDepthPrePass` hand to the batcher without sorting. Visuals stay in `scene.meshes` (picking, bounds, parenting, probes).
  - Contents: per rendering group the opaque, alpha-tested and blended submeshes exactly as Babylon would hand them over: dispatch order sorted by the group's compare functions with Babylon's stable sort (blended by `alphaIndex`, then back to front from the camera's eye), from each drawable mesh's cull and preparation answer (ready, enabled, visible, `visibility`, layer mask, frustum, not `isRevealPending`, submeshes) and each submesh's list (its Material's blending and alpha testing).
  - Poses: before the list is read, every drawable mesh's `computeWorldMatrix()` runs, as Babylon's mesh loop runs it: Babylon's own test of the mesh's and its ancestors' dirty flags and parent links, so a pose any writer changed (in place, a replaced vector, a pivot, a re-parent, an animation) recomputes exactly the moved meshes and what they move, and notes `Transform`, before the batcher reads world matrices. Write-point notes are deliberately not used: a writer that forgot one would freeze a visual unseen.
  - Upkeep: the render change journal (a named mesh is read again; one only its pose named asks only its scaling and frustum tests again and sets its blended sort keys, a pose moving none of its other answers; `Style` alone changes nothing, since a style crossing full opacity moves `sceneReadinessRevision`), the drawable list's rebuilds (`layerDrawableMeshRevision`), `sceneReadinessRevision`, `revealPendingRevision`, the camera (view, projection, eye, layer mask) and the renderer's and its groups' settings; polled every frame because no write point notes them: each drawable mesh's `alphaIndex`, rendering group, layer mask, `alwaysSelectAsActiveMesh` and alpha-test sort keys, and each drawing mesh's submeshes and which list its Materials put them in. A mesh that was not ready, or that the journal cannot hear (`journalFollows`), is read every frame. A blended list whose moved members each still sit between their neighbours (Babylon's compare, ties by dispatch order) keeps its order; any other change rebuilds that list from dispatch order and sorts it.
  - Fallback to Babylon's full path for the frame (`layerWork[].drawList.fallbacks`): a graph whose cull feeds more than the objects pass (`graph`: post-process geometry, outlines, water, spatial effects, occlusion), no batcher, frozen active meshes, particle systems, renderer settings its preparation reads (`renderer`: custom render functions or lists, bounding boxes, several passes, order-independent transparency, a custom LOD selector), or a drawing mesh with instances, LOD levels, a skeleton, an edges renderer or an opaque or alpha-tested depth pre-pass.
  - Checks: every 32nd layer frame, and every 4th under `verifyLayerDrawLists` (`__hapticPlayTest.verifyLayerDrawLists`, `HAPTIC_PERF_VERIFY_DRAW_LISTS`), takes the full path; the sorted lists Babylon hands the batcher (`observeSortedPasses`) must equal the retained ones, list by list in order. A difference rereads everything on the next frame and counts in `heals` (`mismatches` while verifying), described in `mismatchDetails`; `fullReadReasons` says what sent it down each full read. `drawLayersFullPath` (`__hapticPlayTest.drawLayersFullPath`) puts every layer frame on the full path, counted in `fullPathFrames` (and in nothing else), so the perf route's `HAPTIC_PERF_LAYER_PARITY` can compare the paused picture, redrawn after each switch (`requestPausedRedraw`: a paused Play view holds its picture) until the counters show the frame took its path, and the overlay picks over every interactive control (`SceneLayerCompositor.hitTargets`, `EngineHandle.sceneLayerPickHits`) on both paths. Unheard changes that only these checks catch: a multi-material's sub-material replaced, and bounds replaced without a pose or geometry change.
  - Only Play builds a compositor (`create-engine.ts`, `playMode`), so only Play's layers (the editor's Play and the exported player) draw this way; the editor's Scene Layer tab is an ordinary editor viewport with no batcher, drawable list or draw list.
- Light and shadow admission returns at once for a Scene with no light, a settled empty light block (`sceneLightingSettledWithoutLights`) and no shadow controller or one with nothing to admit (`SceneShadowController.admitsNothing`: no registered light, pending or unseen mesh, map or view (its casters' classification waits for the first sync with a light), and the camera and settings its last sync planned with), as a layer's steady frames are (Play's visual factory gives every Scene with visuals a controller). A light, a caster, a participation change, a new mesh, a joined Material or a lighting or shadow settings change takes the full path on that call.
- `SceneLayerOverlay` re-indexes only when `World.structuralRevision` changes; `SceneLayerLayoutGate` skips layout unless a recorded input changed. A variable write advances its owner's revision whatever it wrote, so the gate compares a written owner by the variables the layout reads ([`scene-layer-layout-inputs.ts`](../../../packages/runtime/src/scene-layer-layout-inputs.ts), which builds the layout's inputs too): a write to any other variable (an animated opacity, a script's counter) re-reads that one owner and leaves the layer unchanged. A variable the layout starts to read must be read there.

## Physics and input

- **SceneLayerScript**: `SerializedSceneLayer.script` (carried through `sceneLayerToEditorScene` / `editorSceneToSceneLayer`, as `timelineClips` is), edited in the tab's Script mode (Scene Layer modes are Design, Script and Timeline). Every instance is created as class `SceneLayer:<asset guid>` (registered on creation; `SceneLayer` is locked, so the script needs the subclass) with `ScriptRuntime.embeddedScriptHooks`: class defaults and interfaces, Begin Play at that instance's readiness (before its actors' Begin Play), Tick while it may run, On Destroyed on remove (actors already gone). Stop does not run it. Contract: [scripting.md](scripting.md#embedded-scene-scripts).
- Physics is opt-in per asset. Each enabled instance gets its own Rapier 2D world, independent of the world and other layers; disabled layers have no world (bodies, colliders and overlap events do nothing).
- Traces, sweeps and overlaps answer from the caller's world; `showcollision` draws layer colliders in that layer's own scene.
- Picking walks layers high → low `zOrder`, honoring Hit Test (Ignore / Block / Pass Through), then the world. `2DButton` opts an actor into pointer events and is the only source of pointer graph events (no `onTouch*` nodes). Engine Settings `touchMinTargetPx` widens pick AABBs, not visuals.
- Focus navigation uses project Input assets; focus state is session-only and never saved. Each tick walks Scene Layers from the top and stops at the first with a live candidate (`SceneLayerFocusNavigation.candidates`), so layers under the owning one cost nothing. A target outside the walked layers still gets its `focused` variable's first value (false) on the tick it can first take focus: the components still without a value are tracked per world structure revision, and one holding a value is not looked at again (nothing may clear `focused` back to undefined).

## Components with fixed contracts

- Desired in Play: the compositor measures the layer Scene's enabled, visible meshes with vertices (`sceneLayerContentBounds`) at preparation and again only after its render change journal notes a Transform, Visibility, Enabled or Geometry change or a mesh is added or removed, so static content costs nothing per frame; a changed view is reported (`onSceneLayerView` → control `sceneLayerView` → `SceneLayerOverlay.setMeasuredView`) for cursor projection and the safe area. The host reports the output in design pixels with `sceneLayerResize` (`outputWidth`/`outputHeight`).
- `2DAnchor` maps from the canvas onto the view `sceneLayerAnchorView` gives: the anchor point moves to the matching view point and the actor keeps its authored distance from it (identity plus offset, never scaled). Desired, and Custom at True Pixel Size, anchor onto the canvas itself (identity): a Desired canvas is measured from content anchors would move. Unanchored actors keep design positions around the centre. The uppermost anchor in a subtree wins; anchors never bake into positions. Anchors and safe-area insets use the default (zoom 1, centred) view and ignore the layer camera, so anchored content moves with the camera; a fixed HUD over a panning layer is a second layer.
- 2D Text / Rich Text use glyph-quad meshes (Bitmap default, MSDF when the Font has both chunks), not Babylon GUI or `TextRenderer`. Size is px / `pixelsPerUnit`. Bitmap glyphs of every text in a layer share that layer Scene's atlas pages, so texts batch together ([render.md](render.md#draw-batching)). In Play a 2D Text whose text alone changes is redrawn with the meshes it has ([render.md](render.md#play-presentation-and-editor-views)); Rich Text and every other change rebuild it.
- Rich Text reveal timing is the runtime's (`Text2DAppearRuntime`, [`text2d-appear-runtime.ts`](../../../packages/runtime/src/text2d-appear-runtime.ts)); renderers only receive `setText2DAppear` progress. The Appear Sound (`appearSound*` properties) is scheduled there too: `text2DAppearSoundPlan` in core gives the timeline seconds of each one-shot (or a loop's start and stop), a forward play runs a sound clock from its current position that outlives the reveal by the offset, and the tick's flush emits ordinary `playSound` / `stopSound` commands with the owner as emitter (the loop's voice id is `<component guid>:appearSound`). Reverse, removal and a plan that no longer loops stop the loop.
- Scripted letters ([`text2d-letter-scripts.ts`](../../../packages/runtime/src/text2d-letter-scripts.ts), owned by `Text2DAppearRuntime`): Appear Modes entries `class:<Class id>` name RichText2DAppearMode Classes and `[fx=<Class id> strength=n key=value…]` tags name RichText2DLetterEffect Classes (`RichTextEffects.custom`: `{ name, strength, attrs }`, `attrs` every `key=value` of the tag as strings with lower-cased keys; runs with different attrs never merge). The runtime keeps one `RichText2DLetter` object per reveal character and one instance per scripted Class and text, rebuilt when the text or the mode list changes. `onLetterAppear` (pins `letter`, `alpha`) runs per letter only when the reveal position changes, from letters at rest; `onUpdateLetters` (pins `letters`, `deltaSeconds`, `strength`) runs every tick the owner ticks, starting from the poses the modes left. Letter Effect keywords: each build calls the instance's **Get Keys** override once (`Text2DLetterScriptsHost.callFunction`, export `jsIdent(name)`, outputs by pin name, a latent result counts as none) and keeps its lower-cased distinct string keys; letters group into one `onUpdateLetters` call per (Class, strength, values of the declared keys), undeclared attrs ignored. Each group's values map is built then; before each call the scripts set it as the current tag (`tagValue`), which `ctx.getRichTextTagValue` (Get Tag Value, `richText.getTagValue`, lineage-gated by `LINEAGE_FUNCTION_NODE_BASES`) reads for `ctx.self`, "" outside the call. The packed poses (`TEXT2D_LETTER_POSE_STRIDE` = 9: offset X and Y in pixels with Y up, scale X and Y, rotation in degrees, opacity, tint R, G and B clamped to 0..1, rest white) go out as `setText2DLetterPoses` only when they change, empty when every letter is at rest, and ride in `text2d.letterPoses` of the assignment so a rebuilt visual starts posed. A letter's Tint variable is a script colour (`{ x, y, z, w }`, alpha unused; rest is one shared frozen white). The renderer adds the poses to the reveal and the built-in effects per glyph (`updateText2DLetterPoses`); tagged glyphs never batch. A tint other than white gives the glyph mesh its own overlay style binding (`setOverlayLetterTint` in [`overlay-visual-style.ts`](../../../packages/render/src/overlay-visual-style.ts)): the component's style × the letter's RGB, recomputed only when either changes and journaled as `RenderChange.Style`; at white the mesh draws through the component's shared binding again, so untinted meshes keep one lookup per draw. Every glyph kind draws it (bitmap, MSDF, inline images, underlines, Text Material through `OverlayStyleBlock`). Scripts never run in the editor viewport. Both bases are lineage-gated native events (`nativeEvents` in the engine script catalog); export packs every Class deriving from either base, since text names them by Class id.
- Rich Text Decorators ([`rich-text-decorators.ts`](../../../packages/runtime/src/rich-text-decorators.ts), owned by `Text2DAppearRuntime`): custom tags expand in the runtime only; core's parser and the renderer handle only built-in tags (`RICH_TEXT_BUILT_IN_TAGS`), and the editor viewport, which runs no scripts, draws custom tags as literal text. Registry: `ScriptRuntime.updateSources` calls `loadRichTextDecorators` right after the easing curve bake on every load; in sorted Class id order each Class deriving from RichText2DDecorator (not the base) gets one instance, kept until the next load or Stop (released then), and its Get Tag runs once (`invokeEngineFunction`, export `jsIdent(name)`); the trimmed, lower-cased result must match `^[a-z][a-z0-9-]*$` and not be built-in (warned), and the first Class of a tag wins (the other is warned with both names); no result skips the Class. Editor Play starts every Decorator Class (`requiredProjectAssets`) and export packs them (`closure.ts`), since text names them only by tag. Authored vs drawn: the `text` variable stays authored (Get/Set Text, On Text Changed, saves); `Text2DAppearRuntime.displayText` / `properties` give the drawn text, which `text2dAssignPayload`, the reveal (duration, sound plan, Letter Shown schedule) and `Text2DLetterScripts` (letters, `[fx]` tags) read. `RichTextDecorators` keeps one `{ source, text }` per component (WeakMap) and expands (`expandRichTextTags` in core) only when the authored source differs from the kept one (first realization, a text write), on Refresh Text (`refreshText`, re-sent through `refreshComponent(component, "text")` only when the drawn text changed) and on a load (every live Rich Text; only changed ones re-sent); never per tick. With no Decorator loaded callers do one `active` check and keep the authored string; a text without custom tags keeps its own string. Expansion: a custom opening tag pairs with the first `[/name]` at its nesting depth; Decorate gets `{ Value, Content (raw), Component }` and returns `Markup`, which replaces the span and is expanded on its own (so it cannot pair with tags outside it); depth limit `RICH_TEXT_EXPANSION_MAX_DEPTH` (8), and the outermost tag being expanded stays literal once the output or the total returned markup would pass `RICH_TEXT_EXPANSION_MAX_LENGTH` (100 000); null markup (none, error, latent, not a string) leaves the opening tag literal. While Decorate runs, Get Tag Value answers from the tag's attrs (`Text2DLetterScripts.withTag`, restoring the previous tag). Re-entrancy: an expansion asked for while the same component expands (Decorate setting its text) answers with the text drawn so far and re-runs after it from the current text, at most 3 times. A drawn-text change without a variable write calls `Text2DLetterScripts.invalidate`.
- Engine overridable functions: `EngineClassScriptApi.overridableFunctions` (name, description, `GraphClassMemberPin` rows with exec rows, never Pure) declares functions a base's Classes override and the engine calls; RichText2DLetterEffect declares Get Keys (`Keys`: String array), RichText2DDecorator declares Get Tag (`Tag`: String) and Decorate (`Value`, `Content`: String, `Component`: object `2DRichTextComponent` → `Markup`: String). The editor's My Class panel and graph editor (`useClassGraphsWithEngineBases`) add one members-only graph per such base, keyed by the engine class id (`withEngineClassGraphs` in [`logic-graph-document.ts`](../../../apps/editor/src/lib/logic-graph-document.ts)), so override rows, parent signatures, inherited rows and symbols read it like a parent Class graph. These keys never reach project services (compile, save, rename, export use `collectClassGraphsForPalette`); Call rows for them are offered only to their own lineage, and an inherited engine row cannot be copied.
- Reveal events: `2DRichTextComponent` fires `onLetterShown` (`index`, `character`), `onAppearFinished` and `onDisappearFinished` on its owner as component events (`ScriptHost.fireComponentEvent`). `Text2DAppearRuntime` builds the Letter Shown schedule (`text2DShownLetters`: non-whitespace reveal characters and images, start `index * appearInterval`) only when a forward play starts and `handlesComponentEvent` says the owner handles it, then advances a cursor as its clock passes each start (the remaining letters at completion); Play Reverse drops it. A finish event is queued only when the play moved the reveal to that end (an instant finish included). Events queue on the reveal state and dispatch from `advance` after the progress and letter poses moved, in order; ones queued during dispatch wait for the next step.
- Style (Opacity / Tint) and component motion travel separately from structural mesh assignments, so tweens never rebuild visuals.
- 2D Painter, Joystick, form controls, virtualized collections and masks are overlay-only; script-generated painter commands are never written back to the project.
- Export collects layer documents from every Play-library scene's `sceneLayers` and graph `assetRef("SceneLayer")` defaults, including RichText `[img=<guid>]` textures inside markup. The Scene Layer post-processing passes' Materials and texture parameters (`sceneLayerPostProcessAssetGuids`, enabled passes only) are project roots that load at startup (`renderAssetGuids`, `startupRequired`), and the stack is written to `game.json` `sceneLayerPostProcessStack`.

## Post-processing runtime

- One `SceneLayerPostProcessing` object per World (`World.sceneLayerPostProcessing`, fixed guid) owns the live stack. `SceneLayers.postProcessing()` fills it from the load's `sceneLayerPostProcessStack` (the Project Setting) the first time it is read, and sends `sceneLayerPostProcess` before the session's first `sceneLayerCreate` and after each Register / Unregister. It is session-scoped like graph-created layers: it survives Scene changes and layer removal, and Stop ends it. Register Scene Layer Post-Processing and Unregister Scene Layer Post-Processing take only a Material; Unregister removes the first matching pass, Project Setting passes included. A Register node's Material (Scene or Scene Layer) is a required dependency of its owner (`asset-dependencies.ts`), since the renderer compiles the pass from its document as soon as the node runs; an Unregister node's only ships.
- Pass Material Objects are `PostProcessMaterialObject`s owned by the stack (`PostProcessOwner` = `Scene | SceneLayerPostProcessing`); owner admission allows them while the session runs. Get Post Process Entry with any ready Scene Layer as Owner reads this stack. Parameter writes go out as `setPostProcessMaterialParameter` owner `{ kind: "sceneLayers" }`; the compositor accepts one only for a pass in its stack (entry id and Material) and replays it when the passes are attached again (`PostProcessParameterState`).
