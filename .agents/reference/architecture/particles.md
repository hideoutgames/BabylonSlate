# Particles

Basic Particle Emitter, Particle Graph and Particle System assets, `ParticleComponent`, and the main-thread `ParticleService` that runs them on Babylon particle systems.

## Decisions

- Wrap Babylon `GPUParticleSystem` / `ParticleSystem` as **billboard quads only** (`isBillboardBased = true`). No custom simulator or tick, thin-instance particles, SPS, points cloud, fluid renderer, mesh particles or second renderer. Never use the Node Particle Editor UI, snippets, `ParticleHelper` or Babylon JSON (`ParticleSystem.serialize()` / `NodeParticleSystemSet.serialize()`) as payloads: those are Babylon-owned formats with unstable block ids.
- Own the schemas Babylon-free (`assets`, `particle-graph`), then **apply** (Basic) or **lower** (Particle Graph) onto a live system in `render`.
- Two emitter kinds: **Basic** is a module stack with no scripting, GPU first; **Particle Graph** is our own node IR lowered onto Babylon Node Particle blocks for custom per-particle logic. A **Particle System** plays up to 8 slots of either kind on one actor.
- GPU/CPU is chosen **per emitter**. Basic uses `GPUParticleSystem` (`emitRateControl: true`) when the owning engine has compute or transform feedback, else CPU capped at 512. Graphs are always CPU: Babylon's node path only builds `ParticleSystem` and the GPU update shader has no custom-code hook. Graph documents never store a backend, so a GPU tier can follow without a format change. Auto-tiering and a custom GPU graph compiler were rejected.
- The look is a **particle-domain Material**; emitters have no Texture field (one look path). Textures are sampled in the Material ([shader-graph.md](shader-graph.md)). No default Material or Texture ships (no generated artwork): an emitter without a usable Material does not render.
- Units are **seconds**: `updateSpeed = PARTICLE_UPDATE_SPEED` (1/60). Babylon's default 0.01 made one unit about 1.67 s.
- Blend and billboard ids map to Babylon constants **by name** in [`particle-render-modes.ts`](../../../packages/render/src/particle-render-modes.ts), never repo-local numbers (an earlier numeric table swapped ONEONE and STANDARD).
- **Versioning**: headers follow the [schema versioning rules](../engine-plan.md#schema-versioning); `schemaVersion` is a payload field. Normalizers read the current shape. Before the first release it changes in place; after it, a normalizer may fill defaults for new optional fields and any other change raises the header version and adds a migration step.
- Lifecycle (Loop, Duration, Pre Warm) belongs to each emitter; the System owns slots, Space and Preview Skybox.
- Out of scope: flow maps, custom emitters, `textureMask`, ramp/remap gradients, a particle-age material node, attractors in Basic, live particles in the edit-mode viewport.

## Basic Particle Emitter

- Stages: Emitter (Material, Capacity, Loop, Duration, Pre Warm) → Spawn (Rate, Bursts) → Shape (Point, Box, Sphere, Hemisphere, Cylinder, Cone) → Initialize (Lifetime, Speed, Size, Color, Scale, Rotation) → Over Life (Speed Over Life, Speed Limit, Drag) → Forces (Gravity) → Render (Blend Mode, Billboard). Toggle modules keep their values while off.
- Values are Constant, Random Range or Curve (colors: Gradient), 2–8 keys. `PARTICLE_VALUE_SPECS` / `PARTICLE_COLOR_SPEC` are the one table of modes, ranges and units the normalizer, plan and editor read. Mode switches keep the look. Random Range fields use the shared editor-kit `RangeField` (PropertyGrid `range` rows), which keeps Min at most Max. Curve and Gradient fields (`CurveField`, `GradientField`) run the shared `CurveEditor` / `GradientEditor` in constrained mode: 0–1 time, end keys locked, Linear, 2–8 keys, 0.01 key gap; particle data keeps its `{ t, value }` / `{ t, color }` shape.
- Rate and Lifetime curves run over the **emitter cycle** and the service writes them each frame; `addEmitRateGradient` / `addLifeTimeGradient` / `addStartSizeGradient` are never called because they throw on looping systems. Other curves run over **particle age** as Babylon gradients. Color is always a color gradient.
- Bursts: Babylon has no schedule, so the emission driver queues `manualEmitCount` after each frame (bursts fire **one frame late**, never during prewarm) and restores `-1` afterwards (`createManualEmission`, shared with graph slots). The plan caps a burst at the running capacity; the stored Count is not capped.
- Scripted bursts (`emitParticleBurst`: Emit Particle Burst, the component's Emit Burst) take the same path: Basic slots queue the count in their driver, graph slots through their own `createManualEmission` with the graph's computed Emit Rate, capped at the slot's capacity, on every slot or the one at `slot`. Only a `playing` bundle bursts; otherwise a `particle.burst_not_playing` note at `verbose` severity (bursts never start systems).
- The GPU system claims its whole slot ring after construction and `reset()` so overlapping bursts do not overwrite live particles; a layout guard throws `Unsupported Babylon GPU particle layout` after an incompatible upgrade (re-derive, never relax). At capacity GPU recycles the oldest, CPU drops new ones.
- Pre Warm is Infinite-only (Babylon advances a Once emitter's stop clock during prewarm): `preWarmCycles = min(60, ceil(s × 30))`.

## Particle Graph

- Document settings (not nodes): `materialGuid`, capacity 16–4096 (no 512 cap; `cpuBudget` warning), loop, duration, prewarm, blend, billboard. No Space, no backend. Exactly one protected **Emitter Output** (never called "System").
- Types: Float, Vector 2, Vector 3, Color, Particle; no Int. Babylon's Float splat is the only implicit conversion.
- **Spine:** Particle pins carry the system Create Particle → Shape → Update → Emitter Output and take one link; a Particle output feeds one input (`spineFanOut`), because a second branch is never built. The canvas rewires rather than refuses.
- Emit Rate has no particle: per-particle reads, Per Particle Random or system positions there are errors (`perParticleInEmitRate`).
- **Angles**: Babylon takes radians, so radian nodes say "(Radians)" and each has a Degrees twin (Angle, Update Angle, Sine … Arctangent) lowered as a composition of Babylon's own Trigonometry blocks (To Radians / To Degrees), never a new block class. Create Particle and Cone Shape carry `angleUnit` (`radians` default, filled by the normalizer); in degrees the angle pin, its Details default and the Cone bounds (0.57°–180°) are in degrees, and lowering inserts a Degrees To Radians operation (`<node id>/angle`) before the block, wired or literal. `angleUnit` is a plan property, so it is part of the compile key; switching it converts the authored default.
- Reserved ids (`PARTICLE_UNSUPPORTED_V1_TYPES`) report `particle.unsupportedNode`, so later versions enable them without renames. Every node carries a `role` for its header colour. `math.floatToInt` stays reserved (no Int type).
- `utility.localVariable` (`scope` `particle` | `loop`) realizes as `SlateLocalVariableBlock`: Babylon 9.29's block keeps one Loop entry per frame forever and lets a second Particle-scope variable replace the first one's reset hook, so ours keeps a per-particle value tagged with the particle id (a reset renews the id) and one Loop value for the current frame; Particle scope read without a particle acts as Loop. `math.nlerp` (Vector 2/3, Vector 3 until wired) is `ParticleNLerpBlock`.
- `update.noise` (Forces; `textureGuid` or null, Strength pin) is `SlateNoiseBlock`, an update-queue step with Babylon's `UpdateNoiseBlock` maths (fixed random coordinates per particle, `(2 × _fetchR − 1) × Strength × _tempScaledUpdateSpeed` added to the direction, so it follows pause and dilation). Babylon's block reads its texture back from the GPU every frame; ours samples CPU pixels from a `ParticleNoiseSource`: null uses `createParticleBuiltinNoise` (seeded tileable value noise, generated once per page), a Texture is acquired through `ParticleService` `acquireTexture`, read back once (`readPixels`) and shared by the service's systems; until it lands the node pushes nothing, and a missing or unreadable Texture uses the built-in noise with `particle.noise_texture_unavailable`. The Texture is a graph dependency (`particleGraphDependencies().textures`, export closure); Previews load its bytes with the Material textures.
- `shape.mesh` (`source` `ownerMesh` | `model`, `modelGuid`, `useMeshNormals`, `useMeshColor`; Direction 1/2 pins) is `SlateMeshShapeBlock` with Babylon's `MeshShapeBlock` sampling (random triangle, random barycentric point, interpolated normal or the face normal, vertex colour that then skips Create Particle's colour). Babylon's block copies vertices when the system is built and transforms them by the mesh's world matrix, which a world-space system transforms again; ours reads a `ParticleMeshShapeSource` each time a particle is born, with geometry in the emitter's space, so it works in World and Local Space and picks up geometry that lands later (until then particles spawn at the emitter). Owner Mesh is the owning actor's first `Mesh` with vertices (`resolveEmitter`), looked up at most once a frame until found and then kept: vertex data, so a skinned mesh gives its bind pose; previews use a unit sphere (`PREVIEW_OWNER_MESH`). Model is the whole Model merged by `cookComplexCollisionMesh` (no mesh-name filter), loaded once per service through `acquireModelGeometry`. A Model that cannot load, or an actor with no mesh after 120 frames, reports `particle.mesh_missing`; Source Model with none picked warns `particle.meshShapeModel`. The Model is a graph dependency (`particleGraphDependencies().models`); Previews load its bytes. `shape.custom` stays reserved.
- `sprite.setup` (Sprite Sheet; `columns`, `rows` 1–64, `startCell`, `endCell`, `framesPerSecond` 0–240, `loop`, `randomStartCell`, normalized by `particleSpriteSheetSettings`) is `SlateSpriteSheetBlock`: it turns on Babylon's animation sheet (`_isAnimationSheetEnabled`, so `ANIMATESHEET`, the `cellIndex` attribute and `particlesInfos` reach the Material's particle effect) and replaces the sheet creation step to set each particle's first cell. Babylon sizes a cell in texels of `particleTexture`, which is the 1 × 1 readiness texture, so a cell is 1 / Columns × 1 / Rows of the Material's particle UV. Babylon's sheet maths assumes a texture not flipped on upload; Haptic's Textures are (invertY, KTX2 through its wrapper), so the Babylon patch flips V after it in the GLSL and WGSL particle vertex shaders: cell 0 is the top left and cells are upright. Node-built systems skip Babylon's own age-based cell update (`noUpdateQueue`), so `update.basicSprite` (Animate Sprite Sheet, `SlateSpriteAnimateBlock`: first cell + ⌊age × Frames Per Second⌋, wrapped or held on End Cell) and `update.spriteCell` (Update Sprite Cell, `SlateSpriteCellBlock`: ⌊Cell⌋ clamped to the grid) are the only cell changes; without a Sprite Sheet on the spine they do nothing (`particle.spriteSheetMissing`), and a second Sprite Sheet is overridden by the one nearer Emitter Output (`particle.multipleSpriteSheets`). Basic emitters have no sprite sheet yet.
- `trigger.spawn` (Spawn Emitter; `emitterGuid` a Particle Emitter or Particle Graph, `limit` 1–64, `minInterval` 0–60 s, `inheritVelocity`, normalized by `particleSpawnSettings`; Condition pin) is `SlateSpawnBlock`, an update-queue step like Babylon's `ParticleTriggerBlock` that fires while Condition is not 0. Babylon's block clones a system with no Material binding or readiness texture and spaces calls in wall-clock milliseconds, so ours hands the particle's world position and velocity and the system's simulated `_actualFrame` to a `ParticleSpawnSink`. `ParticleService.spawnSink` makes one trigger per node per slot (closed with its slot) that applies Limit and Min Interval, holds the spawned emitter's Material lease (instance key per component and emitter, shared by its spawns) and queues requests; after the frame renders each becomes a spawned emitter: the asset prepared through the slot path (`createGraphSlot`/`createBasicSlot`, CPU, World Space) on its own emitter node at the position, started when its Material and build are ready and the service is not halted, moved by the inherited velocity, run for the emitter's Duration, then drained and disposed. Spawned emitters are in `allRecords` (pause, time scale, stats), outlive the parent's drain, never report, and are cut on retire, Restart or a host change. A spawned Particle Graph's own Spawn Emitters spawn too, down to `PARTICLE_SPAWN_LIMITS.depth` (2) levels; deeper ones report `particle.spawn_depth`. Validation: `particle.spawnEmitterMissing`, `particle.spawnEmitterUnknown`, `particle.spawnCycle` (error) and `particle.spawnDepth`, from the editor's registry (a graph's emitter dependencies are its spawns). The emitters are graph dependencies (`particleGraphDependencies().emitters`, so Play and export carry them); previews load them with `loadSpawnedEmittersForPreview`. The Inspector's On Death and On Spawn presets (`withParticleSpawnPreset`) wire Condition to Normalized Age ≥ 1 or Age ≤ Delta Time.
- `lowerParticleGraphDocument` walks back from Emitter Output in catalog pin order. `particleGraphCompileKey` excludes positions, name, `materialGuid` and unreachable nodes. Documents are replaced, never edited in place (the cached lowering depends on it).
- `realizeParticleGraph` builds synchronously inside `ParticleService.prepare`: blocks are constructed with `new` (never `Parse`, snippets, `setToDefault` or `buildAsync`) into one fresh `NodeParticleSystemSet` per slot; settings go on the `SystemBlock` before the build. `SlateSystemBlock` seeds Babylon's uninitialised `_buildId` so shared value nodes build once. `ParticleSystemSet.emitterNode` is never used (its dispose would destroy the actor's emitter mesh).
- Local Space lowers Apply Velocity through `LocalPositionUpdated` (node-built systems skip Babylon's local step). Position, Emitter Position, Attractor and radial shape directions stay world-space.
- Build failures report `particle.compile.{unsupportedNode,typeMismatch,connectionFailed,buildFailed}` anchored to the node; the set and partial system are disposed.

## Parameters

- **Model (bind by name)**: each emitter declares what it reads (a graph's `parameters` `{id, name, type, defaultValue}`; a Basic emitter's `bindings` `{target, parameterName, defaultValue}`, at most 16, one per target). Names are case-sensitive after trimming, unique per emitter, at most 64 characters (`normalizeParticleParameterName`). Types: Float, Vector 2, Vector 3, Color (Basic targets fix their own). A System's set is derived (`particleSystemParameters`): the union by name over its slots; the first slot that declares a name decides its type and a slot that declares another type conflicts (`particle.parameter_type_conflict`) and keeps its own default. The System authors only `parameterDefaults` by name.
- **Precedence per slot** (`particleSlotParameterValues`): component value (runtime set, else override) ?? System default ?? emitter default, resized to the emitter's type.
- **Graph**: `input.parameter` carries `parameterId` and a `valueType` the normalizer syncs from its parameter; a missing id is `particle.parameterMissing`.
- **Graph authoring** (`parameter-nodes.ts`): parameters live through their nodes; there is no list editor. `reconcileParticleParameters(previous, next)` runs on every canvas commit: a node with an empty `parameterId` (the Add Node **Parameter** type entries, `input.parameter:new:<type>`) declares a new parameter; a node with an undeclared id and a `__parameter` snapshot (`{name, type, defaultValue}`, hydrated onto canvas data and stripped on save, so copies carry it) reads the declared parameter of that name and type, else declares it again under that id with a free name; a parameter `previous` read and `next` does not is dropped (never-read parameters stay). `convertParticleConstantToParameter` / `convertParticleParameterToConstant` swap a node's type in place (same id and `out` pin, so wires stay); `bindParticleParameterNode` rebinds and drops the orphan; `withParticleParameter` edits one and retypes its nodes. The editor shows them as the canvas node menu (**Convert to Parameter** / **Convert to Constant**) and the Parameter node's Inspector rows. The compile key includes the id and type but not the name or default (`plan.parameters` carries them outside the hash), so renames and new defaults are live. Lowered to a `ParticleInputBlock`; Babylon 9.29 builds it as `() => this.value`, so writing `block.value` reaches the running system without a rebuild, through downstream math and in Emit Rate. `realizeParticleGraph` returns the blocks by parameter id; the slot keeps its current document to map names.
- **Basic**: `resolveBasicEmitterPlan` stays parameter-free; `applyBasicParameters` returns a scaled plan (rate and burst scales on the driver's schedule, bursts rounded and capped; lifetime, speed and size ranges and the size curve; the tint on every colour key; Gravity replaces the acceleration only while the module is on). Creation applies the scaled plan; later changes write only those targets (`applyBasicParameterPlan`) and edit gradient keys in place only when they changed, so an unchanged tint never refreshes a GPU gradient texture.
- **Render**: `assignParticle.parameters` holds the component's current values; `setParticleParameter` (`value` null clears) updates the entry, even while it prepares, and marks it dirty; slots apply once in the next before-render, and again on creation, rebuild and live edits. `updateLibrary`: a System `parameterDefaults` change, a binding or default change and a graph parameter rename or default are `live`; adding or removing a Parameter node follows the compile key. Particle Material parameters are not driven (Materials are shared leases).
- **Worker**: `load` and `loadSceneContent` carry `particleParameterCatalog` (`buildParticleParameterCatalog`: each System's derived parameters with the System's own defaults; core `ParticleParameterCatalog`). `RuntimeParticles` keeps runtime values per component (never saved), merges them over `assignParticle.parameters` in `prepare`, forgets them on a clear or a Scene change, and records them in trace frames (`TraceParticleState.parameters`); a restore sets the recorded values and resets later ones. `createParticleParameterBindings` resolves the actor's ParticleComponents (one with a component id) whose System declares the name, resizes to that type (`resizeParticleParameterValue`) and emits `setParticleParameter` per component; Get reads runtime ?? override (`parameterOverrides`) ?? catalog default; Reset sends the override or null. A name no targeted System declares is a no-op with one `Particles` warning per name per session (`particle.unknown_parameter`). Class nodes `particles.{set,get}{Float,Vector,Color}Parameter` and `particles.resetParameter` target an actor (Self by default); the ParticleComponent functions target one component. Admission is Play and Stop's.
- **Component overrides**: ParticleComponent `parameterOverrides` (name → numbers, default `{}`) rides `assignParticle.parameters` (omitted when empty) under any runtime values. The Inspector shows it as a **Parameters** grid (`particleParameterOverrideRows`, System parameters from `useParticleSystemParameters`); editing a value overrides it, clearing **Override** removes it, overrides for names the System no longer declares are kept. The Simulation Inspector lists a running component's parameters as `particle:<name>` (`particle:{float,vec2,vec3,color}`, vectors and colors as X/Y/Z/W records) and writes them as runtime values. The Name pin of a particle parameter node on Self lists the Class's own and inherited components' parameters of the node's type (`ClassParticleSystemsContext`); otherwise it is free text.

## Look

- `bindParticleMaterial` waits for the NodeMaterial build, then `createEffectForParticles`. Particle-mode Materials are not rebuilt when a sampled texture loads (their effects bind textures per draw; a rebuild drops the draw on WebGPU).
- Babylon's `isReady()` needs a ready `particleTexture`, so each native system owns a 1×1 white `slate:particleReadiness` texture that no shader samples.
- Blend: Additive (`additive`, ONEONE, default), Normal (`standard`), Alpha Additive (`add`), Multiply, Subtract. Only ONEONE and MULTIPLY effects compile; the others reuse ONEONE under their own alpha state. Billboard: Camera Facing (`all`), Y Axis, Stretched.
- Particle textures encode KTX2 at block-aligned (multiple of 4) sizes because WebGPU rejects unaligned ASTC/BC7 ([asset-registry.md](asset-registry.md)).

## Runtime

- `ParticleService` is the main-thread owner for overlay Play, the player and previews; the worker never imports Babylon and graphs emit only `assignParticle` / `setParticlePlaying`. Script nodes: `particles.play` / `particles.stop` / `particles.isPlaying` (Actor defaults to self).
- **Reverse channel**: render reports `particlePlaybackEnded` (`finished` / `stopped` / `failed`) through `onPlaybackEnded`, which both hosts forward like `audioVoiceEnded` (worker `postControl`, else `applyParticlePlaybackEnded`). It fires once when a drain completes (a finished Once bundle or Stop), when Stop lands before preparation ends, and when a Play has no playable slot (including an unknown System); never for previews (`"local"` stats), Play's load warm-up, retire or despawn. `RuntimeParticles` (worker) stamps a new session-monotonic `generation` on every Play (`assignParticle` that plays, `setParticlePlaying` true), render keeps the latest one per entry (also on an idempotent Play) and echoes it, and a report older than the component's latest Play is dropped. Stop clears Is Playing at once; a current `finished` / `stopped` report runs the component-bound `onParticlesFinished` (Reason `engine:ParticlesFinishedReason`, Finished / Stopped) through owner admission. Trace frames record each tracked component's flag and generation (`particles`) and `restoreFromTrace` replays them as `setParticlePlaying` with the recorded generation.
- **Spawned effects** (`particles.spawnAtLocation` / `particles.spawnAttached`, `RuntimeParticleEffects`): an engine-internal actor of the base `Actor` class with one Play On Start `ParticleComponent`, realized synchronously (`ActorRealization.spawnEngine`) so the handle works in the same frame. Their System pins are built-in asset pins (shipped dependencies). A non-empty runtime asset catalog rejects a guid that is not a Particle System (`particle.unknown_system`, once per guid; null handle). Auto Destroy removes the actor on its current `particlePlaybackEnded` (failures too). When an attached effect's parent departs (`retireActor`, or the publish that releases a World-destroyed parent's slot), the effect detaches at its composed world pose, clears its bone attachment, stops and destroys itself after the drain; children of authored actors keep their link. At most `PARTICLE_TRANSIENT_EFFECT_BUDGET` (256) live: the oldest are stopped and destroyed after their drains, with one `particle.transient_budget` warning per session.
- Each slot is one native system whose `emitter` is an enabled geometry-less `particleEmitter:<key>` mesh parented to the actor. A hidden emitter hides its particles because FrameGraph culling drops it.
- A failure skips and disposes only its slot (`particle.unknown_emitter`, `particle.missing_material`, `particle.graph_invalid`, `particle.compile.*`, `particle.apply_failed`); only readiness timeout, a throw outside a slot, or no playable slot fails the entry. `particle.unknown_system` skips playback.
- Readiness waits are stall bounds, not durations (`boundParticlePreparation`; [render.md](render.md#loading-and-readiness)): 4 s without progress, not charged for a thread held by a synchronous shader link, renewed while shaders finish on the Engine, ending at the preparation ceiling. A Material that stalls its bind skips its slot; a bundle whose slots stay unready fails with `particle.apply_failed` and the shader counts.
- **Retrigger**: Overlap moves a draining bundle, or a playing one whose slots are all Once, into the entry's ghosts (its systems stopped, on its own emitter node, with a fresh GPU drain clock) and prepares a new bundle; a playing bundle with a looping slot ignores Play. Ghosts drain like a bundle (`slotsDrained`), then dispose; at most `PARTICLE_GHOSTS_PER_COMPONENT` (3) per component, the oldest cut. They count in `stats().systems`, follow pause, never report `particlePlaybackEnded`, and go with retire, re-assign, despawn, owner change and scene dispose. Restart (the property, or `setParticlePlaying` `restart: true` from Restart Particles / the component's Restart, which works on a playing loop too) cuts the bundle and the ghosts and prepares again.
- Lifecycle: incarnation + generation per component; Play is idempotent while preparing (and, under Overlap, on a looping playing bundle); Stop drains (CPU by live count, GPU by a conservative lifetime bound; no GPU readback). Pause sets `updateSpeed = 0` (graphs also set `paused`); systems readied while paused start on resume. Play close, `changescene`, despawn and a null `assignParticle` retire immediately; `stats().systems` must return to 0.
- **Time scale**: the worker sends `setSimulationTimeScale` (its `slomo` dilation) at session start, on every change and on trace restore. Each record, ghosts included, keeps its authored `updateSpeed`; the live one is authored × scale, or 0 (with native `paused`) while paused or at scale 0, which halts without pausing the service so a later scale resumes. The emission driver clock (rate curves, burst schedule, cycle wrap), GPU drain timers and graph Time / Delta Time all read the live speed. Pre Warm simulates authored seconds (CPU starts at the authored speed; GPU keeps it until its prewarm render).
- `updateLibrary` applies change tiers (`none`, `live`, `respawn`, `rebuild`; graphs: Material change is `live`, compile-key change rebuilds only that slot). Previews debounce heavier tiers (`PARTICLE_PREVIEW_EDIT_DEBOUNCE_MS`) and keep a graph's last valid build while it has errors.
- Previews run a `"local"`-stats `ParticleService` on a disposable Scene on the app-lifetime Engine (RTT + 2D blit). Play takes emitters and Systems from open tabs first; export packs all three types and the player hydrates them with `particleLibraryFromAssets`.
- Babylon patch dependencies (shader language through particle effect recreation, GPU `paused`): [render.md](render.md#babylon-pin-and-workarounds).
