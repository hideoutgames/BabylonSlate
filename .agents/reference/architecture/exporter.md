# Exporter

Export Game and Preview Build: the headless `@haptic/exporter` closure and packer, the `game.json` catalog, and the `apps/player` host that boots it.

## Decisions

- `@haptic/exporter` imports no React, Babylon or Capacitor. Callers compile graphs and load payloads; the package tree-shakes, packs and emits files.
- Targets: the web/itch.io zip, and native packages that wrap that same build in a prebuilt shell ([Native packages](#native-packages)); no target has its own runtime.
- Packaged games always boot `project.json` `startupSceneGuid` (an asset guid). Never boot or tree-shake from `HprojectManifest.startupScene` or a guessed `assets/main.scene.hasset`. A missing or stale startup scene fails with `MISSING_STARTUP_SCENE_MESSAGE` ("Set Startup Scene in Project Settings."). Overlay Play and Preview Build may seed the open Scene tab for that session only (Debug **Start In Open Scene**, default on); Export Game never does.
- Every export writes independent `assets/data-<n>.bin` files with `assetCatalogVersion: 1`; there is no packed/loose choice and no `mode` field. ZIP is delivery only, not a runtime archive. Static hosting needs no HTTP Range support.
- Export Game and Preview Build share one closure and compile path (`collectAndExportGame`). A reached asset that fails to load, has a non-current format version, or whose Class / Animation Graph codegen throws fails the export by name; nothing ships silently without it.
- Preview Build packs PNG/pixels, never KTX2 (`use-preview-build.ts` passes `transcoderAvailable: false`), so a cold iframe matches overlay Play; Export Game packs KTX2 only when the full self-hosted transcoder ships.
- No game HUD keys in `GameManifest`; the player never hydrates a HUD and never packs EditorUtilityInterface assets.

## Closure

- Not `header.dependencies` alone (scene saves often leave them empty). Roots: `startupSceneGuid`, `gameInstanceClass`, Project Settings `audioMixerGuid`, Input assets, debug commands, every Class whose parent chain reaches `GameSubsystem` / `SceneSubsystem` (`subsystemBaseClassIdOf`), and every asset under Project Settings `alwaysPackageFolders`. A listed Scene starts its own closure.
- Export-preset `pluginOverrides` apply **before** the walk, so disabled plugin roots are absent ([plugins.md](plugins.md)). `isEditorOnlyAsset` strips PluginSettings, SkyboxCreator, EditorUtilityObject / EditorFunctionLibrary and leftover EditorUtilityInterface.
- The walk reads only typed reference fields (asset guids, or a Class compile id from its file stem via `classIdForAssetPath`); display names never resolve and ordinary strings are never searched for guid text. It follows payload fields (sprite `textureGuid`, overlay 2D guids including RichText `[img]`), asset-typed variable and pin defaults, Class `parentClass` metadata, Model slots → Material → Texture, to a fixed point.
- Reachability includes deferred references; the manifest separately records `requiredDependencies`. Startup acquires only the entry Scene and declared project systems; inclusion never implies startup loading.
- The player loads an asset's `requiredDependencies` before the asset, so every one must be packed. Otherwise the export fails, naming the asset, the dependency and why: not in the project, its plugin disabled, Editor Only, or no data to pack.
- Release exports compile with `stripDevelopmentOnly`; Preview Build and `bundleDebugger: true` presets keep Development Only nodes. Each Class compiles under `classIdForAssetPath`; subsystems need no manifest field because the runtime discovers them from the scripts.
- `loadExportDocuments` reads each asset's document and chunks from one saved version (`loadDocumentWithChunks`), so a save or encode between reads cannot mix versions. The Scene reverb flush runs first and is never superseded by edits or Auto-Save ([audio.md](audio.md)).

## Files and catalog

```
index.html          # player CSS inlined; <title> is the project name; itch requires it at the zip root
icon.png            # the App Icon at 256 px, linked as the page's favicon; only with an App Icon
player.js           # every module a WebGL2 game runs; workers and the page's on-demand code stay separate files
game.json           # catalog: required dependencies, paths, byte lengths, SHA-256
assets/data-<n>.bin # one per asset or sidecar
coi-serviceworker.js, havok/ (3D), assets/rapier-*.js and rapier/ (2D or physics SceneLayers), assets/recast-*.js, recast/, ktx2/, draco/, meshopt/
player-webgpu.js, player-rapier.js, player-HavokPhysics_es.js, player-recast-navigation.wasm.js
```

- `player.js` holds every page module a WebGL2 game runs, Babylon's lazily imported GLSL shaders and loaders included (`codeSplitting.groups` in `apps/player/vite.config.ts`), so an export stays a handful of files under the itch cap. `player-webgpu.js` holds Babylon's WebGPU engine and every WGSL shader, which only a WebGPU game loads (`isWebGpuOnlyModule` in [`apps/player/vite-webgpu-chunk.ts`](../../../apps/player/vite-webgpu-chunk.ts); [render.md](render.md#babylon-modules-and-registrations)); `webGpuChunkGuard` fails the build when `player.js` statically imports another file or holds a WebGPU-only module, so a WebGL2 device never fetches it. Every export ships it. The wasm runtimes the page loads on demand also stay `player-<name>.js` beside it: Rapier 2D and Havok for the in-process runtime (used when the game worker cannot start) and Recast for the navigation debug overlay. Their names keep `rapier` / `havok` so `selectPlayerRuntimeFiles` drops the engine a game does not use.

- Sidecars use typed ids: `navmesh:<sceneGuid>` (`NavMesh`), `audioReverb:<sceneGuid>`, `font-facetype:`, `font-msdf:`, `font-msdf-png:`, area emission. Packed Audio is a **BSAU** envelope, packed Model a **BSMO** envelope (payload incl. `importScale`, `materialSlots`, `autoLod` + GLB).
- `selectPlayerRuntimeFiles` keeps Havok for 3D, Rapier for 2D, and Rapier in 3D only when a reached SceneLayer enables physics (an unreadable layer keeps it).
- Platform modules: the player is built once for every platform, so engine code in it marks only whole files (`platformModuleCondition`: first line `// #if <condition>`, last `// #endif`, no other directive; any other directive in a player module fails the build). `platformModules` ([`apps/player/vite-platform-modules.ts`](../../../apps/player/vite-platform-modules.ts), page and worker builds, `enforce: "pre"` so it reads the source before transpiling) records them; `platformModuleGroup` gives each condition its own file (`player-platform-<condition>.js` on the page; `includeDependenciesRecursively: false`, so shared imports stay in plain files and a platform module's private helpers must be platform modules too, or they ship everywhere), and the build fails when a file mixes conditions or plain code (bundler `\0` helpers aside) or plain code imports a platform file statically: load one with `import()` behind a platform check. The page build writes `platform-modules.json` (file → condition); `selectPlayerRuntimeFiles(…, { platform })` drops the files whose condition fails for `platformSymbols(platform, { editor: false })` and never ships the list. Editor builds keep every platform module: stripping applies to packages only.
- The Havok wasm ships once, as `havok/HavokPhysics.wasm` (copied from `apps/editor/public/havok/`); the page and the game worker both load that URL. `havokHostedWasmVitePlugin` ([`apps/editor/vite-havok-wasm.ts`](../../../apps/editor/vite-havok-wasm.ts)) removes the Havok glue's unused `new URL("HavokPhysics.wasm", import.meta.url)` fallback in the editor and player page and worker builds, which would otherwise emit a 2 MB copy per bundle into every 3D export and native shell.
- The Rapier 2D wasm ships once, as `rapier/rapier_wasm2d.wasm`, which the page's and the game worker's Rapier chunks both fetch. `rapierHostedWasmVitePlugin` ([`apps/editor/vite-rapier-wasm.ts`](../../../apps/editor/vite-rapier-wasm.ts)) emits it from the base64 copy the compat glue embeds and hands its URL to the glue's `init` in the editor and player page and worker builds, which would otherwise carry a 3.4 MB copy per bundle into every 2D export and native shell. It fails the build if a Rapier upgrade changes that glue; the path keeps `rapier`, so `selectPlayerRuntimeFiles` drops it with the Rapier chunks.
- The Recast wasm ships once, as `recast/recast-navigation.wasm`, which the page's (navigation debug overlay) and the game worker's Recast chunks both fetch; every export keeps it, as navigation runs in 2D and 3D. `recastHostedWasmVitePlugin` ([`apps/editor/vite-recast-wasm.ts`](../../../apps/editor/vite-recast-wasm.ts)) resolves the compat build that `init()` imports to the package's file build and emits its wasm in the editor and player page and worker builds, which would otherwise carry a base64 copy in every Recast chunk (the editor page, its game and bake workers, the player page and worker). It fails the build unless the compat build embeds exactly that wasm, if the file glue's wasm URL changes, or if the compat build still reaches a bundle. It shares the base64 extraction and emission in [`apps/editor/vite-hosted-wasm.ts`](../../../apps/editor/vite-hosted-wasm.ts) with the Rapier plugin.
- Filenames stay distinct on case-insensitive filesystems and cannot contain separators or Windows reserved names. File count warns at 800 and fails at 1000 by default (preset-overridable) because itch caps uploads.
- `zipExport` uses a fixed local-noon 1980-01-01 mtime (`SAFE_ZIP_MTIME`): UTC midnight is 1979 west of UTC and DOS dates reject it.
- `game.json` carries `project: { name, version }` (Get Project Name / Version; the player refuses a manifest without it), `render` normalized by `normalizeRenderProjectSettings`, `playFrameCap`, the Font `globalFallback`, 2D settings, `physicsWorld`, `platform` (the `BuildPlatform` it was packaged for: `web` for web packages and Preview Build; Play's in-memory manifest uses the editor's), audio settings, and `assets[]` with `assetPath` for authored entries. Debugger loop settings appear only when `bundleDebugger` is true. `extensionLibraries` (linked gameplay Extension modules, dependencies first; absent when none) goes on the player's `load` control as in editor Play. `parseGameManifest` rejects outdated manifests and asks for a rebuild.

## Player

- `apps/player` is a Vite canvas host: runtime, render, bridge, physics, debugger; no DockView, editor chrome or React shell. It owns its own Engine (never `registerView` onto the editor Engine). One private constructor canvas owns the context; the visible canvas uses the shared-view path.
- It loads current exports only (SHA-256 `revision` on every entry, BSMO/BSAU envelopes, prefixed sidecars). Startup reads the entry Scene closure plus startup-required assets; everything else is read on acquire. `AssetLoadingService` publishes sources only after the required closure succeeds.
- A launch overlaps its download with the runtimes it will need: the game worker and its physics engine ([bridge.md](bridge.md)), and the decoder files (`decoder-prefetch.ts`): the first KTX2 texture read fetches the KTX2 decoder module and, for UASTC, Zstd and the small per-GPU target transcoders (the large ETC1S transcoder only for an ETC1S texture), and a Model whose GLB lists `KHR_draco_mesh_compression` or `EXT_meshopt_compression` in `extensionsUsed` fetches that decoder. Each file is fetched once into the HTTP cache; decoding and its thread are unchanged.
- Boot hydrates packed Sprite, Tilemap, Animation, Behaviour Tree, Material, Material Function, particle and audio payloads into `createEngine` and the worker before `play`, then waits for model instances, sample-ready textures and `prewarmSceneMaterials`. KTX2 decodes on the main thread with `forceRGBA`.
- A published payload is never edited in place (`GameSourceContent`). `packedContentFromGame` keeps each payload's normalized value by payload identity, and each Material Instance's materialized document while its chain is the same documents, so a source refresh or a render subset parses and normalizes only new payloads; the hydration steps that read textures and the clip catalog still run on every call.
- Debug commands and the stats HUD follow `bundleDebugger`; Print and Draw Debug always apply; Line Trace debug lines follow `traceDebugDraw: manifest.bundleDebugger`. Engine Settings `postProcessingEnabled` is never read by the player.
- Stop, fatal load failure and startup rollback share one release path; the backend Engine is disposed after the view release settles or 5 s pass. Worker failures report `player.worker.failed`; late disposal failures `player.cleanup.failed`.

## Native packages

- Desktop (`windows-x64`, `linux-x64`): `packageDesktopGame` ([`native-desktop.ts`](../../../packages/exporter/src/native-desktop.ts), subpath `@haptic/exporter/native-desktop` so the Packaging dialog stays off the main entry) writes one ZIP: Electron's runtime under a folder named after the project (executable renamed, `resources/default_app.asar` dropped), the game host as `resources/app/main.cjs` with a `package.json` (`productName`, `version`, `hapticGameId` = project guid), and the web export in `resources/game/`. `writeZip` ([`zip-merge.ts`](../../../packages/exporter/src/zip-merge.ts)) copies runtime entries' compressed bytes, CRC and attributes unchanged (Unix modes keep Linux executables runnable), so packaging never re-deflates ~300 MB; Zip64 is refused.
- Linux also packages as a `.deb` (`packageLinuxDeb`, [`native-deb.ts`](../../../packages/exporter/src/native-deb.ts), subpath `@haptic/exporter/native-deb`; the Packaging dialog's default **Format**): the ZIP's folder at `/opt/<package>/`, `chrome-sandbox` setuid root (04755, repeated by `postinst`) so Chromium's SUID sandbox works where Ubuntu 23.10+ AppArmor refuses unprivileged user namespaces, a `/usr/bin` link and a `.desktop` entry; `amd64`, Version from the project when Debian accepts it, else `0`, no Depends (desktop systems carry Electron's libraries). The tar is ustar with GNU long names (dpkg reads them) and every parent folder as a record; `data.tar.gz` streams through fflate's `Gzip`, inflating one runtime file at a time.
- macOS (`macos-arm64`, Apple Silicon only): packaged in the desktop app's main process on a Mac (`game-shell:package-mac`, [`mac-game-package.ts`](../../../apps/desktop/src/mac-game-package.ts)) with Apple's tools: `readBundledShell` reads and checks the bundled runtime itself (the renderer never names a file), `ditto` unpacks, `Electron.app` becomes `<Display Name>.app`, `plutil` sets `CFBundleIdentifier`/`Name`/`DisplayName`/`ShortVersionString`/`Version` and the helpers' `<appId>.helper[.GPU|.Renderer|.Plugin]` IDs, the game host and game go in `Contents/Resources/{app,game}`, then `codesign` ad-hoc (`--deep`) or with a Developer ID from the keychain, nested code deepest first with the hardened runtime, a timestamp and V8's JIT entitlements, `codesign --verify --deep --strict`, and with a notarytool keychain profile `notarytool submit --wait` and `stapler staple`; `ditto -c -k --keepParent` archives. Identity: Project Settings `appIdentity` (`resolvedAppIdentity`: App ID default `com.example.<name>`, IDs limited to the letters-and-digits form Apple and Android both accept). Signing: Engine Settings `macSigning` (per computer; an identity must be one `security find-identity` lists, the profile is only a name). The game host keeps an About/Hide/Quit and Edit menu on macOS. `smoke-mac-game.mjs` packages, verifies and launches one in the macOS inspection job.
- Runtimes are Electron's official release zips, byte for byte: `apps/desktop/scripts/build-game-shells.mjs` runs after `vite build` in the editor's `build` script when `HAPTIC_GAME_SHELLS` (bundled targets) or `HAPTIC_GAME_SHELL_OWN` (a desktop app's own OS) is set, checks each zip against the lockfile-pinned `electron/checksums.json`, splits bundled ones into 48 MiB parts (GitHub Pages refuses files over 100 MB) and writes `dist/game-shells/manifest.json` with the game host's SHA-256. Unset (Verify, development), nothing is written and Packaging lists Windows and Linux as not included.
- Which build carries what (`distribute.yml`, `inspect-desktop-packaging.yml`, `preview.yml`): Pages, iPadOS, Android and macOS carry Windows and Linux, and macOS also `macos-arm64`; the Windows and Linux desktop apps carry the other OS and reuse their own Electron for their own (`game-shell:runtime` IPC: `ownRuntimeZip` reads the release's file names from the install folder, the running executable under the release's name, refused unless the manifest's Electron version is the app's).
- `loadDesktopShell` ([`game-shells.ts`](../../../apps/editor/src/lib/game-shells.ts)) joins a bundled runtime's parts and accepts it only with the published SHA-256, and checks the host's; a mismatch says the player is damaged. The manifest is fetched from `${BASE_URL}game-shells/`, the same origin as the editor on every host (browsers cannot fetch GitHub release assets: no CORS headers).
- The game host ([`game-host.ts`](../../../apps/desktop/src/game-host.ts)) serves `resources/game` at `app://game/` through `gameFile` (the editor's `app://` path rules) with the editor's COOP/COEP headers, one sandboxed, context-isolated window with no preload or Node, single instance, no navigation or windows off `app://game` (HTTP(S) links go to the system browser), one service endpoint (`POST /.haptic/discord-presence`, Discord Rich Presence, [editor-extensions.md](editor-extensions.md#discord-rich-presence)), permissions limited to full screen and pointer lock, autoplay allowed, spellcheck off (Electron would otherwise download dictionaries from Google), and `userData` under `appData/Haptic Games/<hapticGameId>`.

## Android packages

- The desktop editors only (`game-shell:package-android`, [`android-game-package.ts`](../../../apps/desktop/src/android-game-package.ts)): the main process copies the Gradle project template [`apps/desktop/android-game`](../../../apps/desktop/android-game/) (shipped as `host/android-game` by `build-host.mjs`), writes `androidProjectFiles` ([`native-android.ts`](../../../packages/exporter/src/native-android.ts), subpath `@haptic/exporter/native-android`) into it, and builds `assembleRelease` (APK) or `bundleRelease` (App Bundle) by running the Gradle wrapper's main class with the user's `java` (no shell scripts), `ANDROID_HOME` and `JAVA_HOME` set for it. Unsigned outputs are signed afterwards: the APK `zipalign -f 4` then `apksigner.jar sign`/`verify` from the newest SDK build-tools that has both; the bundle with the JDK's `jarsigner` (apksigner cannot sign bundles), checked with `jarsigner -verify`. The work folder is temporary; Gradle's own caches live in the user's `~/.gradle`.
- Template: `com.haptic.game.GameActivity` (Android SDK only, no third-party libraries in the game) is one full-screen WebView serving `assets/game` at `https://appassets.androidplatform.net/game/` (a host reserved for app content) through `shouldInterceptRequest` and the service-worker client, with the editor's COOP/COEP/CORP headers; other http(s) links open the browser; Back sends Escape; render-process loss recreates the activity; config changes never restart it. `app/build.gradle` reads `app/haptic-game.properties` (UTF-8: `applicationId`, `versionCode` = Build Number up to 2,100,000,000, `versionName` = project version, `hasIcon`); the label is `res/values/haptic_game.xml`. minSdk 24, compile/target SDK 36, AGP 8.13, Gradle 8.14.3 (wrapper and SHA-256 shared with the editor's Android project), JDK 17+; lint is off for release builds; `bin` and `wasm` assets stay uncompressed.
- Settings are the main process's, in `userData/android-packaging.json` (`AndroidPackagingSettings`: JDK, SDK, keystore, alias), changed only through `game-shell:android-settings` (`pick` opens a native picker, `clear` returns to finding it, `alias`): the renderer never names a program the main process runs. Unset folders are found from `JAVA_HOME`/Android Studio's `jbr` and `ANDROID_HOME`/`ANDROID_SDK_ROOT`/Android Studio's SDK folder; a JDK below 17 is skipped with a reason. A null keystore signs with `~/.android/debug.keystore` (created with `keytool` when missing). Keystore and key passwords are in the desktop secret store under `ANDROID_SIGNING_SECRETS`, read by the main process at signing and given to the signers only through environment variables; an empty key password uses the keystore's.
- App Icon: legacy `mipmap-<density>/ic_launcher.png` (48 dp) and an adaptive `mipmap-anydpi-v26/ic_launcher.xml` whose foreground insets `ic_launcher_image` (72 dp, the masked area) by 16.667 % over white; without an icon the manifest uses the system default.
- `inspect-android-toolchain.yml` `game-package` (`smoke-android-game.mjs`) builds a small game with the runner's JDK and SDK as an APK with a new keystore and a bundle with the debug key, and checks them with `apksigner verify`, `aapt2 dump badging`/`resources` and `jarsigner -verify`. Release builds shorten resource paths, so checks use resource names.

## App Icon

- Project Settings `appIdentity.iconTextureGuid` (a Texture; null keeps every platform's default) is a packaging input, not a closure root: the Texture ships only if the game reaches it.
- `exportProjectGameArtifact` reads the Texture's `pixels` chunk (the imported file, never its KTX2) and `renderAppIconImages` draws it on an `OffscreenCanvas` at every `APP_ICON_SIZES` edge (16 to 1024), halving from the source so small sizes average every pixel. The source must be square and at least `APP_ICON_MIN_SIZE` (1024; `appIconSizeProblem`, which Project Settings shows on the row); anything else fails the export by name. Preview Build skips it.
- `exportGame({ appIcon })` writes `icon.png` and returns the PNGs on `ExportArtifact.appIcon`; the native packagers take them from there. `@haptic/exporter` stays canvas-free: it only packs PNG bytes (`encodeIco`: PNG entries 16 to 256; `encodeIcns`: PNG elements `icp4` to `ic10`).
- Windows: `packageWindowsGame` (subpath `@haptic/exporter/native-windows`, the only importer of `resedit`) rewrites `electron.exe` when there is an App Icon: its one icon group gets the ICO, its version details the game's name, file name and version (Electron's company and copyright removed). That executable, the runtime's largest file, is inflated, rewritten and deflated again on the main thread; without an icon it is copied byte for byte. Electron's release executable is unsigned.
- Linux `.deb`: PNGs 16 to 512 under `/usr/share/icons/hicolor/<n>x<n>/apps/<package>.png` and `Icon=<package>`. Every `.deb` also writes `StartupWMClass=<product name>` (Electron's X11 window class) and `desktopName: <package>.desktop` in the game's `package.json` (Electron's Wayland application ID), so the window matches its menu entry.
- macOS: the renderer encodes the ICNS and sends it as `ElectronMacGameRequest.icon` (IPC accepts only `icns` magic, at most 32 MiB); `packageMacGame` writes it over `Contents/Resources/electron.icns` (`CFBundleIconFile`) before signing.
- The game host gives its window `resources/game/icon.png` on Windows and Linux when present; macOS shows the bundle's.

## Preview Build

- Toggle in the Debug menu (`debuggerDefaults.previewBuild`, default off). It always bundles the debugger and runs the hosted player in a same-origin iframe. The pack lives in memory, is rebuilt every time, and is never written into the project.
- Handoff is a handshake: the player posts `PREVIEW_REQUEST_PACK_MESSAGE` once listening and the editor answers (re-sending per request); posting only on iframe `load` raced module evaluation. The iframe receives only `game.json` and requests files through `createPreviewAssetClient`. Boot failures post `PREVIEW_ERROR_MESSAGE` and render as an Alert, never a silent black frame.
- `canSendPreviewPack` refuses replies after Stop; a `runtime.infinite_loop` diagnostic closes Preview like Stop. The player keeps at most 1000 posted diagnostics.
- Player URLs go through `playerHostBase()` / `playerPreviewSrc()` with `import.meta.env.BASE_URL`; hardcoding `/player/` breaks sub-path deployments such as Pages. `loadPlayerDistFiles` accepts only relative paths inside the player root and rejects dot-named parts; the player build's `player-files.json` omits dot-named files (`ktx2/.keep`), as desktop staging drops those markers.
- The handshake carries the Engine Settings Trace Memory Budget; standalone games use the runtime default (128 MiB). Save storage is forwarded to the editor host ([save-games.md](save-games.md)).
