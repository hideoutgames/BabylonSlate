# Object Model

Headless runtime object graph: World, Actors, components, subsystems, tick order, class registry, guids and snapshots.

## Ownership

- [`packages/object-model/src/`](../../../packages/object-model/src/) (`@haptic/object-model`) depends only on `@haptic/core`. Never import React, Babylon or Capacitor here.
- Runtime systems that drive it: [`packages/runtime/src/`](../../../packages/runtime/src/) (driver, script host, `PhysicsWorldSync` in `physics-sync.ts`, `world-component-index.ts`, `actor-world-transform.ts`).
- Component placement (`world` / `overlay` / `any`) is declared once in `ENGINE_COMPONENT_DESCRIPTORS` ([`packages/core/src/engine-components.ts`](../../../packages/core/src/engine-components.ts)); SceneLayer allow/deny lists and object-model ids derive from it.
- Deterministic harness: `runDeterministicScenario` in [`packages/test-kit/src/harness.ts`](../../../packages/test-kit/src/harness.ts) (seed, fixed dt, N ticks, canonical snapshot golden).

## Types

| Type | Contract |
| --- | --- |
| `Object` (`EngineObject`) | Root class. guid, classId, variables, `onCreation` / `onTick` / `onDestroyed`. `variablesRevision` advances only on a real change. |
| `Actor` | Transform plus ordered components. Writing `parentId` through `variables` bumps `World.structuralRevision`; writing `name` bumps `World.actorNameRevision` only (names are not structure). `World.identityRevision` (the sum) covers listings that show names: the Play Inspector tree and Debug Instance class rosters. |
| `ActorComponent` | Own variables and interfaces; Begin Play after owner spawn. `attachComponent` throws on a destroyed actor. |
| `Scene` | Live Play scene, `classId` `Scene:{assetGuid}`, running its SceneScript; `sceneName`, `assetGuid` (Get-only), `gravity` (Get/Set). Not spawnable. |
| `LayerCamera` / `SceneCameraManager` | Locked engine objects, never creatable or collected. A `LayerCamera` (guid `<owner>:layerCamera`) belongs to one Scene or SceneLayer and reads as destroyed with it; `getVariable` reads its live `state` (location, rotation, zoom), and writes go through the runtime. The World holds one `SceneCameraManager` (fixed guid `scene-camera-manager`), whose Layer Camera / Camera Actor / Camera Component the runtime reads live. |
| `SceneLayer` / `SceneLayerActor` | Overlay session instance (not an Actor; `classId` `SceneLayer:{assetGuid}`, running its SceneLayerScript) / overlay actor tagged `sceneLayerId`, same World tick. |
| `GameInstance` | Session singleton. |
| `Subsystem` → `GameSubsystem`, `SceneSubsystem` | Hidden abstract base (never in pickers) → session-lifetime / main-Scene-lifetime singletons. ClassKind stays `object`. |
| `World` | Owns GI, subsystems, actors in spawn order, seeded RNG, deferred destroy, `currentScene`. `findActor` / `liveActorsByGuid()` answer from one guid index (spawn order); runtime code reads it instead of building its own. |
| `ClassRegistry` | Inheritance graph. `MAX_CLASS_INHERITANCE_DEPTH` = 16 (including self). Locked engine ids (`isLockedEngineClassId`) cannot be reparented. |

## Invariants

- Simulation code never calls `Math.random`; use the World RNG (`createSeededRng`, core).
- Never iterate a `Map` for tick or snapshot order. Spawn/attach use arrays; subsystem lists sort with `compareClassIds` (code-unit order, never locale).
- Mid-tick spawn/destroy enqueue and flush after the current phase, so a destroy never skips a sibling.
- A committed destroy leaves the actor's slot in the actor list (so spawn indices stay valid) and the next reader of the list (`getActors`, a spawn, a tick phase) drops every removed actor in one pass and reassigns dense `spawnIndex`; tearing down N actors is O(N), and hooks see the list without the actors already destroyed. `Actor.spawnOrder` is never reassigned: it orders actors across removals (`walkComponentOwners` resumes by it). `tick()` is not re-entrant. An ended World never ticks (`tick()` returns -1), refuses `createScene` and cancels queued spawns.
- Code that edits `actor.components` in place must call `World.markStructureChanged()`: `componentOwners` (component-class owner lists) is cached on `structuralRevision`. The same index lists the actors of each class. Script class queries (Get All / Get Actor Of Class, Get First / Get All Components Of Type) answer from it through `script-class-queries.ts`: each target class is resolved to its matching class ids and their actors, in world order, once per `structuralRevision` and `ClassRegistry.revision` (which advances on every register, unregister, `ensure` merge and reparent), and `destroyed` is read live on each query. A script host without a world (`ScriptHostServices.getWorld` left out) walks `getActors()` instead.
- `EngineObject.interfaceHandlers` is null until the script host binds a handler.
- Destruction releases state (`EngineObject.releaseState`, then `stateReleased`): `World.commitDestroy` calls it for the actor and its components after every hook and `onActorDestroyed` observer ran, and `ObjectCollector` for each collected object after its release handlers. Variables are cleared except `name` (labels and messages), `interfaceHandlers` drops to null. `destroyed` is already true inside the object's own destruction hooks, which still read its state; `stateReleased` marks that nothing may. Engine code reads what it needs from a destroyed object in hooks or observers, never later.
- Script access to destroyed objects ([`destroyed-access.ts`](../../../packages/runtime/src/destroyed-access.ts)). Messages name the class as the editor does (`destroyedClassName`): Scene or Scene Layer by kind, a Class or Prefab by its loaded script's `className` (`ScriptHost.classDisplayName`), else the class id (engine classes). a compiled node whose subject pin holds a destroyed object skips itself and calls `ctx.destroyedAccess(__access_<graph>_<node>, target)`, a frozen module-scope location (asset, graph, node, `kind` access / set / call, member) hoisted by `accessLocation` in the compiler, so the valid path costs the existing `destroyed` test only. `ScriptContext` `getVariableFrom` (null), `setVariableOn`, `callInterface` (pin defaults), `callComponentFunction`, `invokeCustomEvent` and `invokeFunction` (`{}`) on an object with `stateReleased` report without a location; the host maps the stack (`mapStackToAnchor`). The runtime reporter (`reportDestroyedAccess` in `runtime-host-output.ts`) records `runtime.destroyedAccess` (severity error) once per location, member and class id per session through `recordDiagnostic` (so Pause On Errors), the Output Log and the `diagnostic` command, and nothing once Play stopped. Dispatcher calls skip listeners whose object is released without a report. Is Valid, Validated Get, Cast, equality and passing references never report.
- `createActor` / `createComponent` / subsystem creation deep-copy class variable defaults (`hydrateClassVariableValue`); no two instances share an object value.
- Play binds a per-frame `onTick` only where a script can run (scripted actor lineages, project component classes); engine component classes never get one.

## Tick phases (`TICK_PHASES`, fixed order)

1. `gameInstance`: GameInstance `onTick`, then live GameSubsystems in class-id order.
2. `sceneSubsystems`: main Scene's SceneSubsystems; gated by `canTickScene` then `canTickSceneSubsystem`.
3. `actors` (spawn order) → 4. `components` (attach order) → 5. `objects` (`addTickingObject` order: Create Object objects with Tickable Object; destroyed ones are dropped in place, ones added during the phase tick next tick; the list is not a root) → 6. `physics` (backend `step` + write-back, filled by `@haptic/physics`) → 7. `postPhysics` (boundary only).

Every phase of a tick receives the same `TickContext` (`dt`, `tickIndex`, World and the input provider's members), built once per `tick()`. Script calls do not read input from it: they use the ScriptHost's `input` service ([input](input.md#runtime)).

`World.gamePaused` (Set Game Paused; the runtime sets it before each tick) narrows every phase to what ticks on pause: phase 1 ticks only a Game Instance with `tickOnPause` and no GameSubsystems; phases 2, 5 and 6 are skipped; phases 3–4 tick only actors for which `ticksWhilePaused` holds (`Actor.tickOnPause`, from Actor Defaults, or a SceneLayer with `tickOnPause` that owns the actor) and their components. The check precedes admission and has no side effects.

Tick Interval (`ActorDefaults.tickInterval`, seconds, `normalizeActorTickInterval`: finite, clamped 0..3600, otherwise unset; default 0) throttles only an actor's Event Tick. `ActorRealization.applyDefaults` sets `Actor.tickInterval` and `Actor.tickStride = actorTickStride(interval, rt.dt)` (round to the nearest undilated fixed step, at least 1) at spawn, like `tickEnabled`; hot reload and the runtime Inspector (read-only row) do not change live actors. The World still calls the actor's tick hook every admitted step; `ScriptHost.hooksFor`'s `onTick` dispatches input events every step, then for `tickStride > 1` adds `ctx.dt` to `Actor.eventTickElapsed` and runs Event Tick only when `(tickIndex + spawnOrder) % tickStride === 0` (`spawnOrder`, never `spawnIndex`, so the phase survives compaction; first tick within `tickStride - 1` steps of the first admitted step) with the accumulated delta, which Get Delta Seconds (and so Add Force / Add Torque) reads during that dispatch (`intervalTickDeltaSeconds`). Steps the World does not admit (pause without Tick On Pause, scene preparation, Event Tick disabled) add nothing; dilation counts per step. Components and engine systems are never throttled. A stride of 1 costs one `instanceof` and integer compare. Deterministic from tick index, spawn order and the step deltas: nothing new is persisted or traced.

`WorldOptions.canTickScene` suspends phases 2–7 during cooperative scene preparation while the Game Instance keeps ticking; `canTickActor` gates individual owners and SceneLayers. Both are rechecked mid-tick, right before each tick hook; the `actors` and `components` phases skip an object without `onTick`, or whose hooks' `ticks` predicate says the hook has nothing to run now (`EngineObject.ticks`), before any check, so both gates and the predicate must stay free of side effects.

## Subsystems

- No registration list: every **leaf** user class of a subsystem lineage is instantiated automatically (`instantiableSubsystemClassIds`). Overlay Play, Preview Build and exports all do this.
- Fixed guids, never from `guidFactory` (so actor guids do not shift): `subsystem:<classId>`, `scene-subsystem:<classId>:<n>` (`n` counts main-Scene creations).
- `ended` flips when End starts (Get, ticks, notifications skip it); `destroyed` when End returns. Init runs at most once and never after End.
- Order: `start()` runs GameSubsystems On Init, then Game Instance On Init. `setGameSubsystems` throws after `start()`. `end()` exits the scene, then GI On End, then GameSubsystems On End in reverse.
- Every main `createScene` (including same-scene reload) builds fresh SceneSubsystems before its actors spawn; streamed sub-scenes and SceneLayers never create them. `clearCurrentScene` is the single exit path: SceneSubsystems On End (reverse) → Scene `onDestroyed` → On Scene Exit.
- Scene Actor Spawned fires immediately before `onCreation` (world actors only); Destroyed/Removed reach exactly the subsystems that heard Spawned/Added. Hooks from `WorldOptions.sceneSubsystemHooksFor` run synchronously; deferring hosts must preserve order.
- `findSubsystems(classId)`: GameSubsystems, then current SceneSubsystems, each in class-id order; first entry is the Get result.

## Guids and identity

- Two live actors never share a guid. `spawnActor` throws `DuplicateActorGuidError` (queued destroys still hold their guid). Documents repeating an actor id are rejected at load (`normalizeScene`, `normalizeSceneLayer`, realization), never repaired.
- Replacement commits the predecessor's destruction first (Change Scene, Save Game restore).
- Instanced ids are scoped: streamed actors `scene-stream:${JSON.stringify([instance, id])}`, SceneLayer actors `<layerGuid>:<id>`; scripted spawns get fresh guids.
- Cleanup that may race a successor reusing a guid works by object identity: `destroyActorInstance`, script Destroy Actor (`runtime-host-actors.ts`: a destroyed or detached actor is a no-op; one still in the spawn queue keeps the guid route so it commits, then goes), render slots (owned by actor objects), physics body incarnations, inspector tokens, stale load cleanup.
- Scripts treat an object with `destroyed === true` as not valid: subject guards skip it and log, and Is Valid, Validated Get, Assert Is Valid, Cast (`ctx.isA`) and breakpoint conditions report it as not valid. An actor queued for destruction stays valid until the commit.
- `World.findActor` uses an incremental guid index; queued spawns stay invisible and queued destroys visible until commit.

## Object lifetime

- [`object-collector.ts`](../../../packages/object-model/src/object-collector.ts) `ObjectCollector`: owned objects (actors, components, Scenes, Scene Layers, subsystems, the Game Instance) end only through their own routes and are roots while alive; collectable objects (`register`) live while a root reaches them through object variables, arrays, maps (keys and values) and plain structure records. Other class instances (delegates, handles) are never scanned, so they are weak.
- A pass marks with a per-pass epoch and a worklist (no recursion through object chains), sets stored references to destroyed objects to None (array slots, map values; map entries with a destroyed key are removed), then destroys unmarked collectables in creation order without script events and runs `onRelease` handlers. `VersionedVariables` tracks `nonPrimitiveCount` (`EngineObject.hasNonPrimitiveVariables`), so owners holding only primitive variables skip variable map iteration in O(1) while still participating in incremental revision rechecks. Frozen containers (`Object.isFrozen`) are skipped from incremental container rechecks. Declared variables whose type can never hold an object (`canHoldReference`) are skipped; the runtime's per-class scalar sets are rebuilt when `ClassRegistry.revision` moves (hot reload). `ScriptRuntime.liveObjects()` omits locked engine components other than `AnimationGraphComponent` from GC roots since engine components hold only engine properties, never user gameplay variables.
- Cycles are atomic (`collect`) or incremental (`begin`, `step(budget)` between ticks, `finish`). Steps mark from a root snapshot and record each owner they scan with its `variablesRevision` and the containers its variables held. Variable maps count every write, but containers change in place unseen (Execute JavaScript gets the stored array, Map or structure by identity), so mutation is only partly observable: `finish` is atomic and re-establishes reachability at that moment before sweeping: it marks the current roots and root sources, rescans in full every recorded owner whose revision moved, rescans the recorded containers of the rest, and drains. Objects created during a cycle are ordinary: reachable at `finish` means reached then. The sweep never leaves `finish`: weak paths (dispatcher bindings, delegates, the Objects tick list, Execute JavaScript state) let a script store an unreached object again between ticks, so an unreachable set computed earlier can be stale. When the steps already marked every live collectable, `finish` skips the recheck (nothing can be collected). Floating garbage (unreachable after a step reached it) survives to a later cycle; the first cycle that runs while the graph does not change is exact. Marks live on the object (`EngineObject.collectorMark`, cycle numbers unique across collectors), so an object belongs to one collector's graph. `workDone` counts work units: a root taken, a value inspected (variable, array slot, map key or value, structure field), an owner or collectable rechecked.
- Runtime: [`object-lifetime.ts`](../../../packages/runtime/src/object-lifetime.ts) `RuntimeObjectLifetime` runs at the end of `runTick`, in the timed `garbageCollection` phase after Scene Systems, when no script is mid-call. A cycle starts at a tick index that is a multiple of `garbageCollectionIntervalTicks`, when none is in progress and collectables exist or `World.destroyCount` moved since the last cycle began. It steps `GARBAGE_COLLECTION_SLICE_WORK` units per tick (a step stops between owners, so it overshoots by at most one owner's values) and finishes at the tick after marking ran out, or in the starting tick when all marking fit its first slice (small worlds behave as one atomic pass). A Scene change and `request()` (Collect Garbage, the `gc` command) finish in that tick: the cycle in progress, or an atomic pass. A `ClassRegistry.revision` change during a cycle restarts it as an atomic pass (scalar variable sets may have changed). `dispose` cancels a cycle in progress. The remaining spike is the finishing tick with an unmarked collectable: about one root and one owner check per owned object plus every container value. The interval is `ProjectSettings.garbageCollectionIntervalTicks` (`normalizeGarbageCollectionIntervalTicks`: a whole number ≥ 1, default 60), sent in the `load` message by editor Play and Preview, and written to `game.json` as a required field for exported players. Roots are `ScriptRuntime.liveObjects()` plus root sources: waiting latent frames (`LatentFrameRoots`, filled by `ctx.holdFrame` from compiled async entries) and behaviour tree blackboards.
- Determinism: roots and collectables are visited in fixed order; collection timing comes from tick counts and work units, never wall time.
- Create Object ([`creatable-objects.ts`](../../../packages/object-model/src/creatable-objects.ts)): `isCreatableObjectChain` accepts a class whose nearest engine base is `Object` (never a locked engine base or a Scene script class). `ScriptRuntime.createObject` builds it with `World.createObject` (class defaults, guid factory), binds interface handlers, registers it with the collector, adds it to the Objects phase when it implements `TICKABLE_OBJECT_INTERFACE_GUID` (`engine:TickableObject`, an engine interface with no methods), then runs its `onInit` through `OwnerAdmission.runCreation`. Its hooks resolve `hooksFor` per call. On release the driver drops its admission queue and `ScriptHost.releaseObject` clears flow state and dispatcher bindings; Delays resume a destroyed owner at once and its continuation is cancelled, so no event runs. `receivesEngineTick` names the chains (Actor, component, Game Instance, subsystems, Scene scripts) for which Tickable Object is `interface.tick_already_exists`.

## Transforms and change observers

- `Actor.transform` and `ActorComponent.transform` are live observed objects made once per instance ([`observed-transform.ts`](../../../packages/object-model/src/observed-transform.ts)): plain objects with enumerable accessors, so spreading, `JSON.stringify`, `structuredClone` and deep equality see plain values. Assigning `transform` or its `position`, `rotation` or `scale` copies the values into the same objects; they are never replaced. A held reference (`const prior = actor.transform`, a `position` passed on) aliases the live pose and follows every later write: copy (`copyTransform`, `structuredClone`) anything that must outlive a write, such as a rollback pose or a load-time origin.
- `transformRevision` (actor and component) advances only on a real coordinate change (`Object.is`), whoever writes it. `Actor.writeTransformPoseFromPhysics` is physics readback's write and notifies source `"physics"`; every other write notifies `"script"`.
- `World.getChildren(parentGuid)`: live direct children by `parentId` variable, kept on spawn, destroy and `parentId` writes, for descendant walks without scanning the World.
- `WorldChangeObserver` (`World.addChangeObserver`, which returns the unsubscribe): passive notifications of spawn, destroy (after `onDestroyed`), parent change, transform change (with source), actor variable change (including `generateHitEvents` and `generateOverlapEvents`), component change (`attached`, `destroyed`, `variable`, `transform`, `meta` for `assetGuid` and `parentId`) and Scene Layer change. Each consumer keeps its own dirty sets (each `PhysicsWorldSync`, `SnapshotPublisher`). Every coordinate write calls every observer, so an observer returns early for an actor it already queued, walks a subtree at most once per cycle, and never mutates the World. A consumer that ends before its World unsubscribes (`SnapshotPublisher.dispose` when the runtime stops). A consumer that keeps derived state current from these notifications (`SnapshotPublisher` keeps its rows and poses without whole-World passes) relies on every spawn, destroy, parent, component and Scene Layer change notifying: a new way to change them must notify too. Snapshot verification, on for every `node` project test, catches one that does not ([bridge](bridge.md#snapshot-layout-version-2)).

## Actor hierarchy

- `parentId` names the parent guid; parents resolve through the live guid index. Child world matrix = `local × parentWorld` (Babylon parenting; math in [`packages/core/src/affine-transform.ts`](../../../packages/core/src/affine-transform.ts)).
- Shear from nonuniform parent scale with an oblique child: exact translation, per-axis world length scale, nearest proper rotation (polar decomposition), one `actor` warning per actor. Physics still rejects shear.
- Parent cycles in loaded data are broken at load: the link closing the cycle (last-spawned member's) is cleared with a warning; streamed actors re-root under their streaming actor.

## Snapshots

- `createWorldSnapshot`: canonical JSON golden for the harness, sorted variable keys. **Not** the bridge binary layout ([bridge](bridge.md)). `subsystems` is omitted when empty so subsystem-free goldens stay byte-identical.
- `createDebugInspectSnapshot`: lossy, JSON-safe Play inspector tree; every actor appears once even with parent cycles.

## Script surface

- `ENGINE_CLASS_SCRIPT_APIS` ([`engine-script-api.ts`](../../../packages/object-model/src/engine-script-api.ts)) is the Get/Set/Call/Add Event catalog: `variables`, `functions`, component-bound `events`, and Self lifecycle `nativeEvents` (which never feed `engineEventTypeClassIds`). Nothing is exposed automatically from component properties: every `ENGINE_COMPONENT_DESCRIPTORS` class has a catalog entry or a reasoned exemption (`COMPONENTS_WITHOUT_SCRIPT_MEMBERS` in `engine-script-api.test.ts`), so a new component cannot ship without graph members unnoticed.
- Overlay pointer events live only on `2DButtonComponent`; collision events on `ColliderComponent`. Animation Graph, Behaviour Tree, NavMesh, NavMesh Blocker and Blocking Volume are ref-only.
- `dispatchInterface` returns pin defaults (fresh deep copy) when no handler exists, never `undefined`.
- `ClassRegistry.reparent` rejects cycles, locked ids and depth overflow, and returns invalidated inherited members. `ensure` merges metadata but never rewrites `parentClassId`. `loadScripts` registers parents before children.

## Product decisions

- No `ModelComponent`: imported models bind on `MeshComponent.assetGuid`.
- **Prefab** (`.prefab.hasset`, kind `prefab`) is logic-free `{ components }` (`SerializedPrefab`). Placed instances are plain `Actor`s with baked components and `prefabGuid`; the runtime ignores `prefabGuid` and never loads the Prefab, and Spawn Actor cannot spawn one.
- `DeformerComponent` is visual-only: physics, navigation and CPU picking keep the original shape. The worker sends revisioned `setActorDeformers` control snapshots, never vertices. Limits in [`deformer-component.ts`](../../../packages/core/src/deformer-component.ts) (`resolution` clamps to 2–4 per axis, so at most 64 controls; coordinates clamp to ±1e10 (`DEFORMER_MAX_COORDINATE`) before Float32 upload). Unavailable in SceneLayers.
