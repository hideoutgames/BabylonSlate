## Document invariants

- One world Scene tab at a time; opening another closes the previous (Save / Discard / Cancel). Graphs, Content Browser and SceneLayer tabs stay. Closing the Scene disposes its viewport `Scene`, never the project Engine.
- SceneLayer is a separate 2D overlay document ([scene-layers.md](scene-layers.md)). Scene Streaming places a `SceneStreamingActor`; the editor never realizes the target scene's actors, only an `editorOnly` label.
- Load always runs `normalizeScene`. Additive settings keys never bump `SCENE_SCHEMA_VERSION`; files are not rewritten on load. Old scenes without this step crashed the Inspector.
- Actor ids are unique runtime GUIDs ([object-model.md](object-model.md#guids-and-identity)): `assertUniqueSceneActorIds` rejects duplicates (never renames). Place, Duplicate, Paste and drag-copy mint fresh ids; Add Component allocates an unused actor-local component id.
- Rotation is a quaternion `[x,y,z,w]` on disk; UI shows Euler degrees. Missing component `transform` normalizes to identity.
- Folders (`folders[]`, `actor.folderId`) are editor-only and ignored by runtime. Transform hierarchy is `actor.parentId`; `wouldCreateCycle` refuses self-ancestry.
- Components with `editorOnly: true` are excluded from Play/player rendering.
- Scenes carry no Game Instance; Play/export read `ProjectSettings.gameInstanceClass`.
- A scene never mixes physics worlds (`settings.physicsWorld`). `viewportMode` is authored data (Play camera, 2D materials, navigation), so toggling it dirties the scene.

## Command path

- Every Inspector / Outliner / viewport mutation: `applySceneChange` → `planSceneChange` → undo stack + crash journal ([command-layer.md](command-layer.md)). Nothing bypasses it.
- `diffSceneCommands` must produce a delta for every authored field; anything it cannot express becomes one `scene.replace`. Add a command when adding an authored field.
- Optional settings reset by deleting their key; diffs record removals so inheritance survives Undo/Redo/recovery.
- Gizmo drags coalesce on `transform:{actorId}` / `transforms:{sortedIds}` (one undo per gesture). `commitGizmoTransform` only runs after `onGizmoDragStart`; a drag-less `onDragEnd` must not write TRS (it re-dirtied after Save All).
- `RemoveActorCommand` stores one actor; hierarchy deletes emit one remove per actor.
- `DocumentService.lockAuthoring(reason)` leases authoring writes (Simulation). Setters, commands, Undo/Redo, prefab sync and reloads respect the lock.

## Selection and session state

- `SceneEditingProvider` is the only selection owner; panels consume `useSceneEditing()` and never keep separate selection.
- Locking an actor removes it from `selectedActorIds`; locked actors are unpickable and never get a gizmo.
- `EditorSessionStateProvider` keeps camera poses, graph viewports and similar view state per document id for one project session (non-reactive; moves on `repathed`). It also holds the Place Actors view (search, category, filters, sort, scroll), one for Scenes and one for Scene Layers, which every Outliner's dialog reads on open; memory only, never persisted. Pivot Around Center, shading mode and Show Collisions are session-only, never scene JSON. It also holds the two editor clipboards, each a `structuredClone` snapshot that outlives the document it came from: Outliner actors (`copyActors`) and Class members (`copyClassMembers`, see [scripting.md](scripting.md#class-member-copy-and-paste)). They are separate slots with distinct payload types; copying one never clears the other.

## Assets panel

- Design-mode window `scene-assets` of Scene and Scene Layer tabs ([`scene-assets-panel.tsx`](../../../apps/editor/src/panels/scene-assets-panel.tsx); listing, filters, selection and drop layout in [`scene-assets.ts`](../../../apps/editor/src/lib/scene-assets.ts)). A Scene lists Models, Classes whose ancestry has Actor but not SceneLayerActor, Prefabs, Sprites and Tilemaps; a Scene Layer lists its built-in 2D elements first (Featured order), SceneLayerActor Classes, Models, Sprites and Tilemaps. World Actor Classes and Prefabs stay out of layers, as in Place Actors. Sprites and Tilemaps place through `spawnPlacedActor`'s asset branch, so the component's `assetGuid` is the asset.
- **Asset Types** is a shown set (`shownKinds`), not a narrowing filter: an empty set lists nothing. `DEFAULT_SCENE_ASSET_KINDS` shows every kind but Sprites and Tilemaps; each host reads only the kinds `sceneAssetFilterKinds` offers it. Chips and the Filter badge count the host's kinds that differ from the default (`changedSceneAssetKinds`); **Clear Filters** restores the default. The Folder filter offers folders of the shown kinds and plugins.
- Plugin entries are assets in `plugin:<guid>` content roots. Asset Types, **Show Plugin Content**, Cards/List and Sort are session preferences on `EditorSessionState`, separate from the Content Browser's project-level Show Plugin Content.
- Selection is panel-local and follows the Outliner (replace, Ctrl/Cmd toggle, Shift range from the anchor; hold menu Select / Deselect); entries hidden by search or filters leave it. Dragging a selected entry carries the selection in list order, any other entry goes alone.
- Placement, here and in Place Actors, goes through `usePlaceActorItems`: one scene change and undo entry, and the placed actors become the scene selection. Listed Classes resolve their Prefab components from open Class tabs and closed Class header rows, as sync does (`useProjectPlaceActors`); a Class without resolved Prefab components (a header with no rows) loads its graph first and places into the scene as it is when the load finishes; a second placement during that wait is ignored, so ids cannot collide. Several entries land on a near-square grid centred on the drop point or view centre, `SCENE_ASSET_DROP_SPACING` apart, across X/Z in 3D and X/Y in 2D Scenes and Scene Layers.
- Drops target the document's Viewport through `ViewportDropApi`; placement is off while the document is simulating.

## 2D Z-Order of new actors

- Every path that adds actors to a Scene or Scene Layer (Place Actors and the Assets panel through `usePlaceActorItems`, an Outliner row dropped on the viewport, Paste, Duplicate) adds them through `addNewSceneActors` in [`new-actor-z-order.ts`](../../../apps/editor/src/lib/new-actor-z-order.ts), with `copies` set for the last three. A new path adds actors the same way.
- Flat hosts (`isFlatScene`): a Scene Layer tab (`overlayEditor`) or a Scene whose `viewportMode` is 2D. 3D Scenes add actors unchanged.
- Without stacking, placed actors get Z-Order 0 (`position.z = 0`) and copies keep theirs; an Outliner row dropped on a flat viewport takes X/Y from the drop and the source's world Z (`droppedCopyPosition`), since the copy becomes a root.
- App setting `viewportStackNewActors2D` (`"disabled"` default, `"scenes"`, `"sceneLayers"`, `"both"`; Engine Settings > Viewport, read at the action through `getAppSettingsSnapshot`) turns on stacking per host: each new actor goes one world Z-Order above the highest actor with a drawing component (`DRAWN_2D_COMPONENT_CLASS_IDS`: meshes, Sprites, Tilemaps, text, particles, cables, 2D elements), 0 when none draws, and each further new actor one above that. Cameras, lights, audio and volumes do not count: a 2D Scene's default Camera sits far back at a high Z-Order.
- Only new actors whose parent is not new are set; a child of an existing parent gets the local Z that gives the target world Z, assuming 2D turns only about Z. Children of new parents keep their offsets, actors with a CameraComponent keep their Z (their distance from the 2D plane), and Scene Layer anchors stay put.

## Prefab instance sync

- Placement (Place Actors and the Assets window's Place at the view centre, an Assets drag or an Outliner row dropped on the viewport) asks `ViewportDropApi.placementAtViewCenter` / `placementAtClient`. With **Place On Surfaces** (app settings `viewportPlaceOnSurfaces`, `viewportPlacementDistance`, default 25) a 3D viewport traces from the camera (`surfacePlacementAtViewCenter` / `surfacePlacementFromCanvas` in `editor-surface-placement.ts`, `scene.pickWithRay` against `isPlacementSurface`: enabled, visible, not helpers, sky, lines or collider visuals) and returns the hit point and camera-facing normal, or the trace's end with no normal; 2D and the setting off keep the view-plane position. The spawn commits with `placementMergeKey(id)` (`usePlaceActorItems` keys a multi-item placement by its first actor and rests each item through its own grid position with the hit normal); with a normal the caller asks `restOnSurface`, which the viewport runs once `dropReady` holds a scene containing the actor (models loaded): `calculateSurfaceRestTransforms` moves it along the normal until its visual AABB (`actorVisualBounds`) touches the hit plane, committed under the same key, and skipped when the actor no longer sits at its placement point (moved, Ground's y = 0 rule, removed). Duplicate and Paste keep their positions.
- Place Actors copies the ancestor-merged Class prefab and stamps `sourceId`. Name, actor transform, visible, locked, `parentId`, `folderId` stay instance-owned.
- `overrideKeys` mark instance-owned component fields; `suppressedComponentSourceIds` stops sync resurrecting deleted prefab rows.
- Components without `sourceId` were added to the instance (in the editor or kept from Play) and sync leaves them alone: a row the template gains later, even of the same class, is instantiated beside them, never linked to one.
- Each scene edit (not a Class or Prefab sync) stamps `overrideKeys` (`stampUserComponentOverrides` in `apps/editor/src/lib/prefab-instance-sync.ts`): the sourced fields it changed become overrides, and keys whose value matches the template again are dropped. Actors and components the edit left as the same objects are not walked, so an edit costs what it touched, and a key a template change made redundant stays until its component is next edited.
- Opening a Scene syncs instances in memory; if that changes it, history is dropped and the Scene is dirty. Sync compares instances structurally, so object key order alone is not a change. Closed Scene files are never rewritten in the background. Prefab edits with the Scene open sync through scene commands.
- A closed Class or Prefab syncs from its header alone, so the header's component rows must carry every field sync copies onto an instance (`name`, `properties`, `transform`, `parentId`, `materialInstance`). A field the header drops is stripped from instances on every open and leaves the Scene dirty. Writer and reader share `classHeaderComponentRow` and `classGraphComponentFromHeaderRow`. A header is rewritten only when its Class is saved, so a Class saved before a field joined the header keeps stripping that field until it is saved again.
- Prefab is a window of the Class document, not a `DocumentKind`. Its world origin is the Prefab Root, which equals `SerializedActor.transform` once placed.

## Viewport rules

- Camera and gizmo are mode-parametric (`ViewportMode`). 2D is fixed: XY plane, +Y up, +X right, camera at −Z looking +Z, `useRightHandedSystem = false`. 2D Z-Order is the negated `position.z`.
- World Scenes use Babylon Position/Rotation/Scale gizmos on a utility layer (`manipulator: "trs"`). SceneLayer documents and SceneLayerActor prefabs pass `createEngine({ overlayTransformBox: true })`. Never `BoundingBoxGizmo` or a React overlay.
- Linked Scale: `GizmoHost.setLinkedScale` makes an X/Y/Z scale handle rewrite the other shown axes after each Babylon drag step (`linkedAxisScale`, the Inspector's `editVectorAxis` rule; 2D keeps Z), not Babylon's `uniformScaling`, which adds equal snapped amounts and scales Z in 2D. The Model editor (selected collider) and Simulation (`scaleLinkKey.runtime`, through `RuntimeTransformTools.setLinkedScale`) push one link (`scaleGizmoLinked` in `linked-scale.ts`). The Scene and Class/Prefab viewports pass linked actor ids instead (`EditorTools.setLinkedScaleActors`; Scene Layer anchors count only when every other selected actor is linked; a Prefab component under `documentComponentClassId`), and the viewport tools link the host only when every selection root is linked. A partly linked selection behaves like the Inspector's multi-edit: the followers take the delta of the unlinked pivot drag (`axisScaledPivotWorld` for an axis handle, since Babylon compounds the relinked pivot; the box recomputes from its start), then each linked root rescales its other axes (`linkedAxisScale` from the pivot's dragged axis, `linkedScaleFromChange` for a follower), and the end of the drag does not re-apply the delta. 2D Text roots keep their box-driven wrap. The SceneLayer transform box gets it through the host (`OverlayTransformBox.setLinkedScale`, `OverlayBoxDragStart.linked`): an edge scales the other axis by the same factor about the box's centre on that axis, a corner projects the pointer onto the diagonal from the fixed corner, the dragged axis (X for a corner) snaps, and Z stays.
- Gizmo styling is a restyle of Babylon gizmos (constants in `gizmo-host.ts`); do not `setCustomMesh` the uniform-scale handle. `GIZMO_AXIS_COLORS` mirrors CSS `--axis-*` ([theming.md](theming.md)).
- The Engine lives on a hidden canvas; Scene blit and Prefab `present: "rtt"` forward pointers into Engine pick space (`gizmos.forwardPointer`).
- `EditorSceneSync` applies edits incrementally and rebuilds only on visual fingerprint change. Multi-visual actors get a hidden origin pick proxy (`visibility = 0`) with children `editorActor:<id>|<componentId>`; picks walk up to `editorActor:<id>`. Components are not independently movable in the Scene viewport.
- `setMeshAssets` is a no-op for equivalent payloads, because disposal would leave gizmo and outline on a ghost mesh. A visual adopted after its apply (a loaded texture or model replacing the actor's root mesh) calls `onAfterApply`, which runs `refreshSelectionGizmo`: the gizmo reattaches when the selection's attach mesh or box visuals changed, except mid-drag or on a selected spline or deformer point. KTX2 re-encodes swap bytes (`replaceTextureBytes`) without rebuilding.
- The editor never freezes the active-mesh queue; the FrameGraph collects its own objects.
- Actor Visible and Locked reach every part under a model placeholder, InstancedMeshes included (glTF parts that reuse a mesh load as instances with their own `isVisible` / `isPickable`); LOD levels follow their master (`applyModelPlaceholderVisibility` in `scene-loader.ts`).
- Loading Scene blocks remounts, shading changes and context recovery, not incremental applies. Every load carries an abort signal; superseded batches cannot write.
- Collider dashes are world-group meshes, not UtilityLayer or UI overlays. The skybox mesh is always unpickable.
- Camera helper geometry is generated from `engine-content/editor-models/camera.blend` by [`create-editor-camera.py`](../../../scripts/blender/create-editor-camera.py) into [`editor-camera-geometry.json`](../../../packages/render/src/editor-camera-geometry.json). Billboards come from [`engine-content/billboards/`](../../../engine-content/billboards/).

## Modes, Play seed and Simulation

- Scene Mode Design / Landscape / Foliage / Script / Timeline share one scene and history; each has its own DockView layout. Script edits the embedded SceneScript ([scripting.md](scripting.md#embedded-scene-scripts)) through `scene.setScript`, whose merge key continues one graph gesture (`script:<graph command key>`); the viewport is not mounted in Script mode. Foliage is static thin-instanced geometry (no actors, scripts or bodies). Landscape sculpting edits one `LandscapeSculptSession` and rebuilds once per pointer event. Timeline mode edits `timelineClips` ([`packages/core/src/timeline-clips.ts`](../../../packages/core/src/timeline-clips.ts)) through `scene.addTimelineClip`, `scene.removeTimelineClip`, `scene.setTimelineClip` (one clip replaced by id; merge key `timelineClip:<id>`, superseding in the journal) and `scene.reorderTimelineClip`; the Clips window's edits are pure helpers in `apps/editor/src/lib/timeline-clip-edits.ts` (names unique per document, copies drop `timelineAsset`), the selected clip is `SceneTools.timelineClipId`, and copied clips are a third `EditorSessionState` clipboard slot. An empty list removes the field, so documents without clips never have it. Keys are `CurveKey` ([`curves.ts`](../../../packages/core/src/curves.ts)) plus an id; [`timeline-evaluate.ts`](../../../packages/core/src/timeline-evaluate.ts) is the one evaluator for the editor preview and Play: `evaluateTimelineTrack` interpolates float, vec2, vec3, rotator (authored degrees per axis) and color tracks through `evaluateCurve` with constant ends and steps the other value types; `applyTimelineClipToScene` returns a derived scene in which only animated actors are copies (others keep identity for the renderer's pose path), writing transform, visibility, actor `properties` (script values such as `{ x, y, z }`) and component `properties` (vectors, rotators and colours as arrays; a colour keeps its 3 or 4 channels). The Timeline window (`apps/editor/src/panels/timeline-panel.tsx`) edits one clip at a time through `scene.setTimelineClip` (a key drag is one gesture: each move recomputes from the clip at drag start, `shiftTimelineKeys`), with pure clip edits in `apps/editor/src/lib/timeline-track-edits.ts` (a key set or moved onto another key's frame replaces it; moves are clamped to the clip) and rows in `timeline-rows.ts` (a group's summary key stands for its tracks' keys on that frame). Add Track offers `timeline-property-catalog.ts`: transform and Visible, single Class variables of a track value type (`timelineValueTypeFor`), and component properties passing `isTimelineAnimatableComponentProperty` (`packages/object-model/src/live-properties.ts`: the runtime inspector's live rule, shared through `engineComponentPropertyCapability`, plus the 2D properties tweens animate); new keys take the track's evaluated value, else the authored value. `SceneTools` holds the playhead (`TimelinePlayhead`, an external store so playback re-renders only its readers), the key selection (`keyRefId` of track and key ids), the selected row and the drop target the Timeline window registers while it shows a clip; the Outliner reads that registration for **Add to Timeline Clip**, its clip diamonds and drops onto the window. Copied keys are an `EditorSessionState` slot. Commands `timeline.setKey` (K), `timeline.previousKey` ([) and `timeline.nextKey` (]) are scoped to focus within the window; `timeline.addSelectedActors` (Shift+A) to the window being shown. In Timeline mode with a clip selected, `SceneDetailsPanel` renders `TimelineInspector` (`apps/editor/src/panels/timeline-inspector.tsx`: Key, Keys, Track or Actor, then Timeline Clip; a Track or an actor's row adds its tracks' values at the playhead in `TimelineTrackValues`, the only part subscribed to the playhead, where an unkeyed value wins and an edit is `setTimelineKeys` at the playhead whatever Auto Key, dropping that track's unkeyed value) instead of the actor Inspector; both Timeline windows read the clip through `useTimelineClip` (`apps/editor/src/context/use-timeline-clip.ts`). Key and track menus act on the selection only when the pressed key is in it (the menu opens in the same event that selects it); copied tracks are an `EditorSessionState` slot and paste onto the same property, a component track onto a component of the copied class. Preview: in Timeline mode with a clip selected, the viewport passes `applyTimelineClipToScene(editorScene, clip, playhead, unkeyed)` to `useViewportSceneLoad` (recomputed on document or unkeyed changes) and a playhead subscription re-applies it with `handle.loadScene` directly (not React state; skipped during a gizmo drag), so the document is never written; transform-only tracks take the pose path, other track types a full sync. `commitGizmoTransform` routes through `timelineTransformEdit` (`apps/editor/src/lib/timeline-transform-edit.ts`): animated, unmuted Location/Rotation/Scale channels keep the authored transform and become keys (`SceneTools.timelineAutoKey`) or `SceneTools.timelineUnkeyed` values (track id to value, rotators unwrapped toward the shown value, cleared whenever the playhead moves), other channels edit the actor; keys and actor edits commit as one scene change. `applyTimelineClipToScene` takes the unkeyed values as overrides; Set Key prefers them. The Curves view hosts the shared `CurveEditor` for the selected interpolated track through `apps/editor/src/lib/timeline-curves.ts` (Vector 2 and Rotator as `vec3`, Rotator pitch/yaw/roll as X/Y/Z; key ids kept by position, else by time), with constraints `timeRange` [0, length], `timeSnap` 1/fps while snapping and `extrapolation: "constant"`.
- Timeline Assets (`Timeline`, `.timeline.hasset`, document kind `timeline`; [`packages/core/src/timeline-assets.ts`](../../../packages/core/src/timeline-assets.ts)) store only `description`. A scene clip names its asset (`SerializedTimelineClip.timelineAsset`); clip edits (`timeline-clip-edits.ts`) drop it on duplicate, copy and paste, and `bindTimelineClip` sets or clears it through `applySceneChange`. Which clips an asset holds is derived (`projectTimelineClips` over Scene/Scene Layer header meta, open documents first), so the asset never stores a clip list and binding rewrites nothing else. `timelineBindBlocker` refuses a bind whose name the asset already holds; `timelineClipNameCollisions` feeds `timeline.clip_name_collision` in the owning documents' Compiler Results. Clips window commands: Bind to Timeline Asset (single-pick `ChecklistDialog`), New Timeline Asset and Bind (`AssetCreateApi.createAsset` with `ownerPath` = the document, so it lands beside it), Unbind, Show in Content Browser (`ProjectSearch.revealAsset`). The asset's DockView document (`timeline-asset-editor.tsx`): Timeline Clips (Description, bound clips, **Open** = `requestTimelineClipFocus` + open + `setSceneMode(…, "timeline")`, consumed by the target's Clips window) and Events (the selected clip's dispatchers).
- Timeline Clip assets (`TimelineClip2D` / `TimelineClip3D`, `.timelineclip2d.hasset` / `.timelineclip3d.hasset`, document kinds `timeline-clip-2d` / `timeline-clip-3d`; [`packages/core/src/timeline-clip-assets.ts`](../../../packages/core/src/timeline-clip-assets.ts)) hold one clip and its Proxies (`TimelineProxy`: id, unique name, `represents` actor or component, `classId`, its own tracks) plus the required `timelineAsset`; types never convert. `editorPreview.proxies` (colour from `TIMELINE_PROXY_COLORS`, representation, preview location, rotation and scale, Preview As, and editor-only `assets`, one per Model, Material and Texture representation, read through `timelineProxyPreviewAsset`; an earlier uniform `size` folds into an Actor proxy's scale and a single `assetGuid` into its representation's slot when the payload is normalized) is stripped by `stripTimelineClipAssetEditorData` and is never a dependency (`asset-dependencies.ts` adds only the Timeline Asset and proxy Classes, soft). `timelineClipOfAsset` / `withTimelineClipOfAsset` map the payload to and from the shared `SerializedTimelineClip` (clip id `clip`, each proxy an object track whose `actorId` is the proxy id) so the Timeline panel and evaluator are reused. Header meta lists the clip under `TIMELINE_CLIPS_META` (also written at creation, so the index lists it before a save); `projectTimelineClips` names it after the asset and `isSceneClipDocument` keeps clip assets out of the scene-clip Get nodes (`timelineScriptAssets`). New Asset requires the Timeline Asset (or creates `<Name> Timeline` beside the clip); picker Create New rows exclude both types. The document (`timeline-clip-asset-editor.tsx`, wrapped in its own `SceneToolsProvider`) has **Viewport**, **Proxies** (class lists from `subclassClassEntries`, components filtered by overlay or world placement), **Timeline** and **Inspector**. Its Timeline windows read a `TimelineClipSourceProvider` (`use-timeline-clip.ts`) instead of the scene document: `TimelineClipAssetSource` builds `timelineProxyScene` (`timeline-proxy-scene.ts`: each proxy an actor, an Absolute one at its preview placement and a Relative one at the origin so its transform keys record offsets; an Actor proxy of its Class with the Class graph's components, a Component proxy holding that one component under the proxy id) and writes clip edits back with `withTimelineClipOfAsset`. With `proxies` set, the panel offers no Outliner rows, Remove From Clip or Select in Viewport and Outliner, and Delete keeps proxy rows; the Inspector shows `TimelineInspectorContent showClip={false}` above the proxy and clip grids. The Viewport (`timeline-clip-preview-panel.tsx`) renders to RTT on the shared Engine like the Prefab viewport: `timelineProxyPreviewScene` swaps each proxy's components for its representation (`TimelineProxyShapeComponent`, a Mesh, a 2D Texture or Material; Class keeps them; a Component proxy keeps its own component); the proxy actor carries the placement scale, which sizes them, the clip is applied at the playhead (subscription, no React state), then `composeTimelineProxyPreview` puts Relative proxies at their placement (location plus the placement rotation of the offset; scale times the placement scale, as a Relative binding multiplies the bound actor's). The selection is a list of proxy ids per document (`selectProxies` / `useSelectedProxies` in `timeline-clip-asset-editor.tsx`): a pick selects one (`selectProxy`; an additive Shift / Ctrl tap toggles it), the 2D hold-marquee and Drag Select (`onMarqueeSelect`, live rect from `onMarqueeMove`) replace it, the Proxies TreeView toggles (Ctrl) and range-selects (Shift), and the Inspector edits a proxy only while exactly one is selected. Assets reload only when the representations change (`previewLoadKey`). A released gizmo (`onGizmoDragEnd`) goes through `timelineProxyGizmoEdit`: live transforms are taken out of a Relative proxy's placement into clip space, `timelineTransformEdit` (`keyedTracksOnly`) keys channels whose track has keys (Auto Key) or returns unkeyed values, and Location, Rotation or Scale without a track or without keys overwrites the preview placement (a Relative proxy turned in place keeps its drawn position). A drop that changes nothing reloads the live pose and then the evaluated one, because `EditorSceneSync.applyPoses` re-poses only actors whose loaded pose changed. Gizmo tool, space and snap are synced from `useSceneEditing` and the viewport prefs; with `joystickEnabled` it shows `ViewportJoystick`, which flies `editor.camera` under a continuous render lease, as the Prefab viewport does. Test builds expose `__hapticClipPreviewTest` (proxy positions, playhead, `nudgeProxy`, the 2D box and a proxy's drawn bounds) for `e2e/timeline-clip-proxy.spec.ts`.
- Timeline playback in Play ([`packages/runtime/src/timeline-runtime.ts`](../../../packages/runtime/src/timeline-runtime.ts)): `TimelineRuntime` owns one `TimelineClipObject` (engine base class `TimelineClip`, guid `<owner guid>:timeline-clip:<clip id>`, never registered for collection) per clip per live owner, created on first use from the owner's document (`sceneLayerLibrary` for a layer copy, `playScene` for the current Scene) and destroyed with the owner or on Stop. It advances in tick phase 2 after tweens and before `world.tick()`, only for owners `admission.canRun` admits; Auto Play starts on the first admitted advance. `advanceTimelinePlayback` ([`packages/core/src/timeline-playback.ts`](../../../packages/core/src/timeline-playback.ts)) is the one Once / Loop / Ping Pong state machine; the playback state carries its own rate (never negative; Reverse sets direction -1) and loop mode, seeded from the clip, so scripts change them per copy without touching the authored clip. Stop returns to the start, or to the end while reversing. Values come from `evaluateTimelineTrack` and are written like tweens: transform through `applyTweenTransform` in local space plus `teleportActor`, Visible and Class variables with `setVariable`, component properties with `setVariable` plus `refreshComponent` (shape kept by `timelineStoredValue`). Animated actors resolve per owner copy (`ownedSceneActor`, as Get <Actor>). When Finished: Restore State captures the animated values when Play (or Set Position) starts with nothing captured, writes them back when a Once clip finishes, and clears them so the next Play captures afresh. Each step returns `sweeps`, the time it passed over in travel order (start inclusive, end exclusive, a reached end inclusive; a Loop's other end is included, a Ping Pong turn's end is not), so `timelineEventKeysInSweeps` fires every event key once in playback order (ties by track order); then On Looped per cycle, then for a finished Once clip When Finished and On Finished. A listener that changes the clip's playback (`TimelineClipObject.generation`) ends the step's firing. Set Position with Fire Events sweeps from the old to the new time. Clip objects are of their document's clip class (registered on first use) and are released through `ScriptHost.releaseObject` with their owner. Custom Event Tracks are edited in the Timeline window under an Events group row (`TIMELINE_EVENTS_ROW_ID`; pure edits in `apps/editor/src/lib/timeline-event-edits.ts`, input types limited to `TIMELINE_EVENT_INPUT_TYPES` so keys hold literals); their keys share the key selection, drag (`clampTimelineEventKeyShift` with the property clamp), Delete and Previous/Next Key with property keys.
- Timeline Clip asset instances (`Create <Name> Timeline Clip`, `timeline.createClip`; `TimelineRuntime.createInstance`): a `TimelineClipInstance` (subclass of `TimelineClipObject` in [`timeline-clip-object.ts`](../../../packages/object-model/src/timeline-clip-object.ts); class `TimelineClip:<clip asset guid>:clip`, guid `<asset guid>:timeline-clip-instance:<n>`, owner the asset's `TimelineObject`) over `timelineClipOfAsset` of the packed payload. It is collectable: `register` puts it under the collector, a root source (`forEachPlayingInstance`) keeps it while it plays, and `forget` drops it on release; Stop destroys every instance. Instances advance after scene clips in the same phase, never Auto Play, and re-fire on their Timeline under the asset's name. Each proxy track writes through `bindings` (proxy id → `TimelineProxyBinding[]` in bind order, each: target, `absolute`, `base` = the target's local transform at bind time) to every bound target: `bind` appends, or replaces the entry of a target already bound there, `unbind` clears the proxy's list, `bound` returns the live targets (Get Timeline Proxy's array); Absolute writes an actor's transform in world space and a component's in local space; Relative writes `base` composed with the key (location turned by `base.rotation`, rotation after it, scale multiplied) in local space. An Actor proxy's component tracks resolve by authored id (`findComponentById`), a Component proxy's own track (`componentId` = proxy id) writes the bound component. A destroyed target (or a destroyed component owner) leaves its proxy's list; a proxy with none is unbound, and its tracks are skipped with one Output Log warning per instance and proxy. Create binds connected inputs Relative and refuses objects of the wrong kind (`timelineProxyAccepts`).
- Clip asset packaging: a Create node's clip asset is a required dependency of its graph (`asset-dependencies.ts`), so it is in the Play closure and the export. `packedContentFromGame` turns `TimelineClip2D` / `TimelineClip3D` payloads into `timelineClipAssets` (`timelineClipAssetCatalogEntry`: normalized, `stripTimelineClipAssetEditorData`), sent in `loadSceneContent` (and the initial `load`) into `RuntimeDriver.timelineClipCatalog`; exported bytes are stripped the same way (`export-game-inputs.ts`). Clip asset documents have a closed-by-default Compiler Results window fed by `timelineClipAssetDiagnostics` (`timeline-clip-diagnostics.ts`): `timeline.clip_asset_unbound`, `timeline.proxy_name_collision`, `timeline.proxy_class_missing` (`registryClassParentLookup`) and the `timeline.proxy_placement` warning (Component proxies by `SCENE_LAYER_EXCLUSIVE_COMPONENT_CLASS_IDS` / `isSceneLayerDeniedComponent`, as the Proxies class lists filter). Open clip asset tabs feed the graph catalog (`graph-panel-catalogs.ts`) as open Scenes do. Tracks that cannot animate (`timelineTrackProblem` in `timeline-property-catalog.ts`: `missing_target` for a missing actor or component, `property_unavailable` when `timelinePropertyEntries` has no entry or another value type) carry `TimelineRowModel.problem`, render with a red label and warning icon in the Timeline, and become `timeline.missing_target` / `timeline.property_unavailable` warnings (`timelineTrackDiagnostics`) in Compiler Results for Scenes, Scene Layers and clip assets (over `timelineProxyScene`). Key Copy, Paste, Cut and Duplicate carry event keys too (`copyTimelineSelectedKeys` / `pasteTimelineSelectedKeys` in `timeline-event-edits.ts`: `CopiedTimelineKeys.events`, pasted onto the same track id or an event track of the same name, keeping values of inputs it has).
