## Document invariants

- One world Scene tab at a time; opening another closes the previous (Save / Discard / Cancel). Graphs, Content Browser and SceneLayer tabs stay. Closing the Scene disposes its viewport `Scene`, never the project Engine.
- SceneLayer is a separate 2D overlay document ([scene-layers.md](scene-layers.md)). Scene Streaming places a `SceneStreamingActor`; the editor never realizes the target scene's actors, only an `editorOnly` label.
- Load always runs `normalizeScene`. Additive settings keys never bump `SCENE_SCHEMA_VERSION`; files are not rewritten on load. Old scenes without this step crashed the Inspector.
- Actor ids are unique runtime GUIDs ([object-model.md](object-model.md#guids-and-identity)): `assertUniqueSceneActorIds` rejects duplicates (never renames). Place, Duplicate, Paste and drag-copy mint fresh ids; Add Component allocates an unused actor-local component id.
- Rotation is a quaternion `[x,y,z,w]` on disk; UI shows Euler degrees. Missing component `transform` normalizes to identity.
- Folders (`folders[]`, `actor.folderId`) are editor-only and ignored by runtime. Transform hierarchy is `actor.parentId`; `wouldCreateCycle` refuses self-ancestry.
- Components with `editorOnly: true` are excluded from Play/player rendering.
- Scenes carry no Game Instance; Play/export read `ProjectSettings.gameInstanceClass`.
- A scene never mixes physics worlds (`settings.physicsWorld`). `viewportMode` is authored data (Play camera, 2D materials, navigation), so toggling it dirties the scene.

## Command path

- Every Inspector / Outliner / viewport mutation: `applySceneChange` → `planSceneChange` → undo stack + crash journal ([command-layer.md](command-layer.md)). Nothing bypasses it.
- `diffSceneCommands` must produce a delta for every authored field; anything it cannot express becomes one `scene.replace`. Add a command when adding an authored field.
- Optional settings reset by deleting their key; diffs record removals so inheritance survives Undo/Redo/recovery.
- Gizmo drags coalesce on `transform:{actorId}` / `transforms:{sortedIds}` (one undo per gesture). `commitGizmoTransform` only runs after `onGizmoDragStart`; a drag-less `onDragEnd` must not write TRS (it re-dirtied after Save All).
- `RemoveActorCommand` stores one actor; hierarchy deletes emit one remove per actor.
- `DocumentService.lockAuthoring(reason)` leases authoring writes (Simulation). Setters, commands, Undo/Redo, prefab sync and reloads respect the lock.

## Selection and session state

- `SceneEditingProvider` is the only selection owner; panels consume `useSceneEditing()` and never keep separate selection.
- Locking an actor removes it from `selectedActorIds`; locked actors are unpickable and never get a gizmo.
- `EditorSessionStateProvider` keeps camera poses, graph viewports and similar view state per document id for one project session (non-reactive; moves on `repathed`). Pivot Around Center, shading mode and Show Collisions are session-only, never scene JSON. It also holds the two editor clipboards, each a `structuredClone` snapshot that outlives the document it came from: Outliner actors (`copyActors`) and Class members (`copyClassMembers`, see [scripting.md](scripting.md#class-member-copy-and-paste)). They are separate slots with distinct payload types; copying one never clears the other.

## Prefab instance sync

- Place Actors copies the ancestor-merged Class prefab and stamps `sourceId`. Name, actor transform, visible, locked, `parentId`, `folderId` stay instance-owned.
- `overrideKeys` mark instance-owned component fields; `suppressedComponentSourceIds` stops sync resurrecting deleted prefab rows.
- Opening a Scene syncs instances in memory; if that changes it, history is dropped and the Scene is dirty. Sync compares instances structurally, so object key order alone is not a change. Closed Scene files are never rewritten in the background. Prefab edits with the Scene open sync through scene commands.
- A closed Class or Prefab syncs from its header alone, so the header's component rows must carry every field sync copies onto an instance (`name`, `properties`, `transform`, `parentId`, `materialInstance`). A field the header drops is stripped from instances on every open and leaves the Scene dirty. Writer and reader share `classHeaderComponentRow` and `classGraphComponentFromHeaderRow`. A header is rewritten only when its Class is saved, so a Class saved before a field joined the header keeps stripping that field until it is saved again.
- Prefab is a window of the Class document, not a `DocumentKind`. Its world origin is the Prefab Root, which equals `SerializedActor.transform` once placed.

## Viewport rules

- Camera and gizmo are mode-parametric (`ViewportMode`). 2D is fixed: XY plane, +Y up, +X right, camera at −Z looking +Z, `useRightHandedSystem = false`. 2D Z-Order is the negated `position.z`.
- World Scenes use Babylon Position/Rotation/Scale gizmos on a utility layer (`manipulator: "trs"`). SceneLayer documents and SceneLayerActor prefabs pass `createEngine({ overlayTransformBox: true })`. Never `BoundingBoxGizmo` or a React overlay.
- Gizmo styling is a restyle of Babylon gizmos (constants in `gizmo-host.ts`); do not `setCustomMesh` the uniform-scale handle. `GIZMO_AXIS_COLORS` mirrors CSS `--axis-*` ([theming.md](theming.md)).
- The Engine lives on a hidden canvas; Scene blit and Prefab `present: "rtt"` forward pointers into Engine pick space (`gizmos.forwardPointer`).
- `EditorSceneSync` applies edits incrementally and rebuilds only on visual fingerprint change. Multi-visual actors get a hidden origin pick proxy (`visibility = 0`) with children `editorActor:<id>|<componentId>`; picks walk up to `editorActor:<id>`. Components are not independently movable in the Scene viewport.
- `setMeshAssets` is a no-op for equivalent payloads, because disposal would leave gizmo and outline on a ghost mesh. KTX2 re-encodes swap bytes (`replaceTextureBytes`) without rebuilding.
- The editor never freezes the active-mesh queue; the FrameGraph collects its own objects.
- Loading Scene blocks remounts, shading changes and context recovery, not incremental applies. Every load carries an abort signal; superseded batches cannot write.
- Collider dashes are world-group meshes, not UtilityLayer or UI overlays. The skybox mesh is always unpickable.
- Camera helper geometry is generated from `engine-content/editor-models/camera.blend` by [`create-editor-camera.py`](../../../scripts/blender/create-editor-camera.py) into [`editor-camera-geometry.json`](../../../packages/render/src/editor-camera-geometry.json). Billboards come from [`engine-content/billboards/`](../../../engine-content/billboards/).

## Modes, Play seed and Simulation

- Scene Mode Design / Landscape / Foliage / Script / Timeline share one scene and history; each has its own DockView layout. Script edits the embedded SceneScript ([scripting.md](scripting.md#embedded-scene-scripts)) through `scene.setScript`, whose merge key continues one graph gesture (`script:<graph command key>`); the viewport is not mounted in Script mode. Foliage is static thin-instanced geometry (no actors, scripts or bodies). Landscape sculpting edits one `LandscapeSculptSession` and rebuilds once per pointer event. Timeline mode edits `timelineClips` ([`packages/core/src/timeline-clips.ts`](../../../packages/core/src/timeline-clips.ts)) through `scene.addTimelineClip`, `scene.removeTimelineClip`, `scene.setTimelineClip` (one clip replaced by id; merge key `timelineClip:<id>`, superseding in the journal) and `scene.reorderTimelineClip`; the Clips window's edits are pure helpers in `apps/editor/src/lib/timeline-clip-edits.ts` (names unique per document, copies drop `timelineAsset`), the selected clip is `SceneTools.timelineClipId`, and copied clips are a third `EditorSessionState` clipboard slot. An empty list removes the field, so documents without clips never have it. Keys are `CurveKey` ([`curves.ts`](../../../packages/core/src/curves.ts)) plus an id; [`timeline-evaluate.ts`](../../../packages/core/src/timeline-evaluate.ts) is the one evaluator for the editor preview and Play: `evaluateTimelineTrack` interpolates float, vec2, vec3, rotator (authored degrees per axis) and color tracks through `evaluateCurve` with constant ends and steps the other value types; `applyTimelineClipToScene` returns a derived scene in which only animated actors are copies (others keep identity for the renderer's pose path), writing transform, visibility, actor `properties` (script values such as `{ x, y, z }`) and component `properties` (vectors, rotators and colours as arrays; a colour keeps its 3 or 4 channels). The Timeline window (`apps/editor/src/panels/timeline-panel.tsx`) edits one clip at a time through `scene.setTimelineClip` (a key drag is one gesture: each move recomputes from the clip at drag start, `shiftTimelineKeys`), with pure clip edits in `apps/editor/src/lib/timeline-track-edits.ts` (a key set or moved onto another key's frame replaces it; moves are clamped to the clip) and rows in `timeline-rows.ts` (a group's summary key stands for its tracks' keys on that frame). Add Track offers `timeline-property-catalog.ts`: transform and Visible, single Class variables of a track value type (`timelineValueTypeFor`), and component properties passing `isTimelineAnimatableComponentProperty` (`packages/object-model/src/live-properties.ts`: the runtime inspector's live rule, shared through `engineComponentPropertyCapability`, plus the 2D properties tweens animate); new keys take the track's evaluated value, else the authored value. `SceneTools` holds the playhead (`TimelinePlayhead`, an external store so playback re-renders only its readers), the key selection (`keyRefId` of track and key ids), the selected row and the drop target the Timeline window registers while it shows a clip; the Outliner reads that registration for **Add to Timeline Clip**, its clip diamonds and drops onto the window. Copied keys are an `EditorSessionState` slot. Commands `timeline.setKey` (K), `timeline.previousKey` ([) and `timeline.nextKey` (]) are scoped to focus within the window; `timeline.addSelectedActors` (Shift+A) to the window being shown. In Timeline mode with a clip selected, `SceneDetailsPanel` renders `TimelineInspector` (`apps/editor/src/panels/timeline-inspector.tsx`: Key, Keys or Track, then Timeline Clip) instead of the actor Inspector; both Timeline windows read the clip through `useTimelineClip` (`apps/editor/src/context/use-timeline-clip.ts`). Key and track menus act on the selection only when the pressed key is in it (the menu opens in the same event that selects it); copied tracks are an `EditorSessionState` slot and paste onto the same property, a component track onto a component of the copied class. Preview: in Timeline mode with a clip selected, the viewport passes `applyTimelineClipToScene(editorScene, clip, playhead, unkeyed)` to `useViewportSceneLoad` (recomputed on document or unkeyed changes) and a playhead subscription re-applies it with `handle.loadScene` directly (not React state; skipped during a gizmo drag), so the document is never written; transform-only tracks take the pose path, other track types a full sync. `commitGizmoTransform` routes through `timelineTransformEdit` (`apps/editor/src/lib/timeline-transform-edit.ts`): animated, unmuted Location/Rotation/Scale channels keep the authored transform and become keys (`SceneTools.timelineAutoKey`) or `SceneTools.timelineUnkeyed` values (track id to value, rotators unwrapped toward the shown value, cleared whenever the playhead moves), other channels edit the actor; keys and actor edits commit as one scene change. `applyTimelineClipToScene` takes the unkeyed values as overrides; Set Key prefers them. The Curves view hosts the shared `CurveEditor` for the selected interpolated track through `apps/editor/src/lib/timeline-curves.ts` (Vector 2 and Rotator as `vec3`, Rotator pitch/yaw/roll as X/Y/Z; key ids kept by position, else by time), with constraints `timeRange` [0, length], `timeSnap` 1/fps while snapping and `extrapolation: "constant"`.
- Timeline playback in Play ([`packages/runtime/src/timeline-runtime.ts`](../../../packages/runtime/src/timeline-runtime.ts)): `TimelineRuntime` owns one `TimelineClipObject` (engine base class `TimelineClip`, guid `<owner guid>:timeline-clip:<clip id>`, never registered for collection) per clip per live owner, created on first use from the owner's document (`sceneLayerLibrary` for a layer copy, `playScene` for the current Scene) and destroyed with the owner or on Stop. It advances in tick phase 2 after tweens and before `world.tick()`, only for owners `admission.canRun` admits; Auto Play starts on the first admitted advance. `advanceTimelinePlayback` ([`packages/core/src/timeline-playback.ts`](../../../packages/core/src/timeline-playback.ts)) is the one Once / Loop / Ping Pong state machine; the playback state carries its own rate (never negative; Reverse sets direction -1) and loop mode, seeded from the clip, so scripts change them per copy without touching the authored clip. Stop returns to the start, or to the end while reversing. Values come from `evaluateTimelineTrack` and are written like tweens: transform through `applyTweenTransform` in local space plus `teleportActor`, Visible and Class variables with `setVariable`, component properties with `setVariable` plus `refreshComponent` (shape kept by `timelineStoredValue`). Animated actors resolve per owner copy (`ownedSceneActor`, as Get <Actor>). When Finished: Restore State captures the animated values when Play (or Set Position) starts with nothing captured, writes them back when a Once clip finishes, and clears them so the next Play captures afresh. Each step returns `sweeps`, the time it passed over in travel order (start inclusive, end exclusive, a reached end inclusive; a Loop's other end is included, a Ping Pong turn's end is not), so `timelineEventKeysInSweeps` fires every event key once in playback order (ties by track order); then On Looped per cycle, then for a finished Once clip When Finished and On Finished. A listener that changes the clip's playback (`TimelineClipObject.generation`) ends the step's firing. Set Position with Fire Events sweeps from the old to the new time. Clip objects are of their document's clip class (registered on first use) and are released through `ScriptHost.releaseObject` with their owner. Custom Event Tracks are edited in the Timeline window under an Events group row (`TIMELINE_EVENTS_ROW_ID`; pure edits in `apps/editor/src/lib/timeline-event-edits.ts`, input types limited to `TIMELINE_EVENT_INPUT_TYPES` so keys hold literals); their keys share the key selection, drag (`clampTimelineEventKeyShift` with the property clamp), Delete and Previous/Next Key with property keys.
- Start In Open Scene (Debug menu, default on) seeds the open Scene tab, else `startupSceneGuid`, which Preview never writes. Overlay Play and Preview Build never share an Engine.
- `captureSimulationScene` captures only at an acknowledged quiescent boundary and returns a complete scene or a named failure, never a subset. It rejects streamed/overlay instances, Dynamic Runtime Mesh and ambiguous identities. References use `$sceneValue` tags resolved by `hydrateScenePropertyReferences`.
