# Scripting

Contributor reference for Haptic's visual scripting: Class graph IR, pin types, validation, JavaScript code generation, runtime binding in `ScriptHost`, and the editor graph surfaces.

- The compiler takes a **node registry injected at compile time**; `scripting` never depends on `scripting-nodes`. `scripting` may import only `instrumentJsLoops` from `@haptic/debugger`.
- Node codegen emits `ctx.*` calls only. Navigation (Recast), physics and rendering live behind `ScriptHostServices`; nodes never import them.
- `graph-ui` stays catalog-free: hosts hydrate pins (`__pins`, `__category`, `__pure`, `__latent`, `__editorOnly`) before handing graphs to it. Keep graph-kind specifics injectable; do not hardcode scripting assumptions into the canvas.

## Formats

- Class assets are `.class.hasset`; parents include `Object`, `Actor`, `ActorComponent`, `GameInstance`, `GameSubsystem`, `SceneSubsystem`, `FunctionLibrary`, `EditorFunctionLibrary`, `DebugCommand`, `EditorUtilityObject` and the `BT*` bases. The hidden `Subsystem` base is never offered.
- IR: `LogicGraph { id, kind: "event" | "function", nodes, edges }`; nodes carry `typeId` (catalog id), typed `pins` and `properties`; edges name both pin ends. `SerializedGraph` adds `members` (variables, locals with `functionId`, functions with `pins[]`, interfaces, custom events, Event Dispatchers with input `pins[]`), `functionGraphs[id]` and Actor prefab `components`.
- Display units (`core/value-units.ts`, `VALUE_UNITS`): optional `unit` on Class variables (`GraphClassMember.unit`, stamped onto variable node data for the Set value pin), function and custom-event inputs (`GraphClassMemberPin.unit`, carried to Call pins by `memberPinUnit`), `StructField.unit` and `BlackboardKey.unit`. Only `int`, `float`, `vec2`-`vec4` keep one (`declaredValueUnit`); every closed-header and payload parser copies it. It reaches `GraphPin.unit` / `SerializedPin.unit` / `LiteralPinDefault.unit` and `PropertyRow.unit`; values are never converted, and the runtime inspector does not show units.
- Schema changes raise the Class asset version and add a migration step ([schema versioning](../engine-plan.md#schema-versioning)). Versions older than the release are refused with `AssetFormatVersionError`.
- Literal pin defaults are stored as `default:<pinId>` keyed by **pin id**, never display name. Lookup order: wire → `default:<pinId>` → catalog `GraphPin.defaultValue` → type default. Instance pins (`objectRef`) take no literal (`pin.invalid_default`; compiles to `null`). Because the lookup always yields a value, `pin.missing_input` never fires for literal pins; it covers instance pins (error), Class/Asset pins with no authored or catalog default, other non-literal kinds, `reference: "required"` pins and interface-implementation Output pins (error).
- Pins named from authored text (signature rows, Make/Break Structure fields, On Command Run parameters) use the name as the pin id unless it equals an id the node reserves; `memberArgPinId` then appends `__arg`. The name stays the display label and the value key. On Command Run reserves only `execOut`, Make Structure `out` and Break Structure `in`. Signature-row nodes share a set: `CALL_PIN_IDS` (`execIn`, `execOut`, `target`) on member Call nodes (function Call, interface Call, Call Custom Event, Call Event Dispatcher), `EXEC_PIN_IDS` (`execIn`, `execOut`) on member event entry and Call Parent nodes, so an entry node reserves `execIn` without having that pin; Event Custom also reserves `OutputDelegate`. Adding an id to a released node's set renames the pins of rows already using that name, and their stored edges stop resolving.
- Map variable defaults persist as `{ key, value }[]` JSON and hydrate to `Map` (later duplicates win). Arrays persist as `unknown[]`.
- Tags: project `settings.tags` `{ tags: [{ id, path, parentId }], nextId }`; IDs are stable u32 (0 = None), never reallocated from display order; discarded IDs still advance `nextId`.
- Asset/Class-typed declarations carry **Loading**: absent = Soft (referenced, never loaded with the owner); `"hard"` joins the owner's required closure (Class header `requiredVariableNames`). Synchronous readers (`input.*`, `data.readEntry`) still require their values. Dependency metadata is stamped on save.
- Data Definitions (`.datadefinition.hasset`) and Data Trees (`.datatree.hasset`) address entries by exact, case-sensitive name paths; internal IDs are never lookup fallbacks.
- A data node's Definition types its Value at authoring time. Read Data Entry keeps it in `definitionGuid` (Inspector, or inferred from a literal Tree and Entry Path). Read Unknown Data Entry (`data.readUnknownEntry`) and Async Read Unknown Data Entry (`data.readEntryAsync`) keep it on their Data Definition pin (`default:definition`, `dataDefinitionPinGuid`), never infer it, and report `data.wired_definition` when it is connected, because a wire cannot type Value. Graphs saved before the async pin keep `definitionGuid`, which applies until hydration moves it onto the pin (`applyStructEnumSchema`).
- A Data Tree entry's values are editable (Data Tree editor, `editorData.updateEntry`) only once its Definition's added or renamed fields are applied and no structural conflict remains: `dataEntryNeedsDefinitionApply` and `dataEntryStructuralIssue` on a `reconcileDataEntry` result ([`data-values.ts`](../../../packages/scripting/src/data-values.ts)).

## Pin types

- Kinds (`types.ts`): `exec`, `bool`, `int`, `float`, `string`, `tag`, `vec2/3/4`, `rotator`, `quat`, `transform`, `color`, `objectRef`, `classRef`, `assetRef`, `structRef`, `enumRef`, `array`, `map`, `delegate`, `resolvingWildcard`, `boxedWildcard`. Math kinds are first-class, not fake Structures.
- `delegate` is structural: `delegateOf(inputs)` with `outputs: []`; assignability is per input (contravariant), so an Int input still fits a Float one. Member rows type it as `typeId: "delegate"` with the input types copied onto the row as `signature` (recursive `VariableTypeSpec[]`) and the source dispatcher in `typeClassId` (`delegateSignatureSource`, `<classId>::<name>`), so catalog pin functions stay pure functions of node data. Delegate inputs take no literal (`pinRejectsStoredDefault`), report `pin.missing_input` as an error like object inputs, and can be subjects.
- Assignability: `int` → `float` only; subclass refs → superclass pins of the same kind by class hierarchy (actors are `objectRef` of `Actor` or a subclass; there is no separate actor kind); any instance ref → `objectRef("Object")`; narrowing needs Cast; `classRef` is a class value, never an instance; `structRef`/`enumRef` need an exact guid (empty guid assigns nowhere); anything → `boxedWildcard`, never implicit unbox.
- Two wildcards, never conflated: **resolving** (compile-time generic for container nodes; one group `T` per node unless `group` set; inputs are hard constraints, wider compatible types win) and **boxed** (raw runtime value for Print and user wildcard params).
- `resolveWildcardPinTypes` ([`wildcard-resolve.ts`](../../../packages/scripting/src/wildcard-resolve.ts)) is a view: stored `__pins` stay `resolvingWildcard`. Compilation applies the resolved view to a temporary graph; canvas connection checks use resolved display types.
- Values are not boxed on the wire. `WildcardTo*` uses the source's compile-time tag when typed, otherwise infers from the runtime value; enums, classes and assets are strings at runtime.
- Engine enums/structs (`engine:CollisionChannel`, `engine:HitResult`, `engine:TagContainer`, …) live in `ENGINE_ENUMS` / `ENGINE_STRUCTS`, not the Content Browser.

## Validation

- Pure `(graphs, TypeContext, rules) → Diagnostic[]`; packages add rules with `registerValidationRule`. Diagnostics anchor to `assetGuid`, `graphId`, `nodeId`, `pinId` (plus `bodyLine` for ExecuteJavaScript). Behaviour Trees use `validateBehaviourTree`.
- Validator and compiler share the TypeContext builder: a graph that validates compiles.
- Node-scoped diagnostics run only on nodes the compiler would emit (`compiledNodeIds`); isolated nodes and exec islands without a trigger never block Play. `validateGraphs` applies the same filter to registered rules. A rule that checks a pin literal (`readPinDefault`) skips the pin when it is wired, because the stored default stays behind and is hidden in the Inspector.
- `event.duplicate` (error) names a second entry of a singleton event in one graph: same `typeId` + `componentId`, same custom event name, or same Input Action/Axis for `input.*` events (all of which share the `onTick` handler, so the handler name is never the identity). A wired Input Binding or an unbound input event cannot be compared and is skipped. `event.name_collision` stays for differently spelled custom names that compile to one identifier.
- Paste and Duplicate never author either diagnostic. The Class graph host (`prepareClassGraphPaste`, via `GraphEditor.preparePaste`) renames each renamable custom event copy to the first free name among its own name, `<Name>_1`, `<Name>_2`, … (`freeCustomEventName` in `apps/editor/src/lib/custom-event-names.ts`; free = no custom event node or declared event member in any graph of the Class shares its identifier or its case-folded name, the `event.name_collision` and `customEventRenameError` rules). It leaves out a copy whose `singletonEventKey` (exported from `validate.ts`, the same key as `event.duplicate`) is already in the target graph, including custom events that cannot be renamed (inherited or component events, events wired to Call Parent Event), and reports them in a canvas notice. Nodes alone declare custom events: copies get no `members` row, like Add Node's Event Custom; the Inspector adds the row on the first pin edit.
- `pin.unexecuted_source` (warning) anchors on a compiled node's data input wired from an impure node (one with exec pins) that is not in `compiledNodeIds`: unwired impure nodes do not run, so their output slots keep type defaults. `relatedNodeId` is the source.
- Diagnostic messages name pins and events by display label (`humanizePropertyLabel` / `formatEventTitle`, both in `core`), never by pin id.
- Runs on edit (250 ms debounce, open graph), save (document + dependents), editor Compile (compiles every project graph; Compiler Results keeps only the focused class's diagnostics, like edit-time validation), pre-Play (dependency closure of the played scene, Game Instance and subsystems), export (adds export-only rules) and CI golden fixtures (`packages/scripting/fixtures/`, one broken graph per code).
- Warnings never block. Errors block Play through a dialog with **Play Anyway** per run; there is no persistent bypass. Demote noisy rules rather than hardening the dialog.
- Parent cycles are refused at write time (Attach Actor, Attach To Bone, `parentId` sets) with a warning; loaded data breaks cycles at load.

## Compiler and codegen invariants

- IR → plain JavaScript ES modules (no TypeScript in the browser). Output is deterministic text; golden tests are the primary gate. Compiled output is derived data outside the project folder.
- Anchors: per-statement `{ line, column, assetGuid, graphId, nodeId, bodyLine? }` plus `//# sourceURL=haptic:///<assetGuid>.js`. Anchor tables are position-based: any pass that moves lines must rewrite offsets. **Never minify compiled game scripts.**
- Exec flow compiles to native `if`/`for`/`while`; back-edges restart through labeled loops, not recursion. Pure data inlines with CSE.
- Latent work (Delay, async ExecuteJavaScript, latent Call Function, tweens, async loads) makes the entry `async`. Latency is transitive through Call Function and overrides. A node that emits `await` must call `ctx.requestAsync()` or declare `latent: true`. `ScriptHost` skips a latent entry that is still pending so Tick cannot stack runs.
- Impure output slots are declared once at the top of each entry (never inside a branch), named from the pin **id** (`_n_<node>_<pinId>`). Never introduce fixed-name temporaries outside a block.
- Read each input once per output or statement; bind multi-use inputs first so impure inputs (Random) sample once. Use `ctx.isWired(pinId)` (compiler's incoming-edge index), `ctx.hoist` for module-scope helpers and constants (deduplicated by name), `ctx.shared` for work shared between outputs.
- Editor/debugger compiles prepend `ctx.checkInfiniteLoop()` to impure emits and loop bodies; `ctx.checkInfiniteLoop` is always a function. `runtime.infinite_loop` stops Play immediately.
- Simulation compiles also emit execution-trace probes (`instrumentExecutionTrace`): `ctx.debugTrace` is always set, null unless the instance is the one the editor follows. Probes never change evaluation order or count; the contract and runtime are in [debugger.md](debugger.md#simulation-graph-debugging). `compileAnimGraphScripts` passes the flag to the Animation Object graph only; its `ctx.debugTrace` is the followed component's, not the actor's.
- **Development Only** (Print, Print String, the Assert family, Draw Debug by default) is stripped from release exports (`stripDevelopmentOnly`, derived from the same value as `bundleDebugger: false`); exec continues at `then`, data pins compile as type defaults. **Editor Only** nodes and EditorUtilityObject/EditorFunctionLibrary functions never reach runtime graphs.
- Custom events export the event name (`_` appended to JS reserved words); functions export by member name; Call uses `ctx.invokeFunction` / `ctx.invokeCustomEvent`; static Function Library calls pass the library class id.
- `GraphScriptCompileCache` keys exclude node positions (event and function graphs) but include members, defaults and saved parents.
- Modules ([`packages/scripting/src/`](../../../packages/scripting/src/)): `compile.ts` is the public entry (`compileGraph` plus explicit re-exports; never `export *` an internal module, because `index.ts` re-exports `compile.ts` whole). `compile-codegen-state.ts` holds `CodegenState`, the one object every `compileGraph` code generator takes: `nextLabel`, `hoisted`, `loopStack` and `pureInProgress` span the module, `beginEntry` resets the per-entry fields. Data pins, pure nodes and `CodegenContext` live in `compile-expressions.ts`; statement nodes, subject guards and trace/breakpoint probes in `compile-statements.ts`; the exec walk, Branch, Switch on Enum and Switch on Tag in `compile-exec-chain.ts`; loops, Break, Do Once/N, Gate, Flip Flop and Switch on Int and String in `compile-structured-flow.ts`; gated input event entries in `compile-input-events.ts`; the preamble, entry functions and anchor table in `compile-module.ts`. Shared helpers: `compile-graph-index.ts`, `compile-pin-values.ts`, `compile-events.ts` (event tables, `jsIdent`), `compile-types.ts`. `compile-transition-rule.ts` is the separate transition-rule compiler. Flow modules receive the exec walker as an `EmitAlong` parameter instead of importing `compile-exec-chain.ts`, so module imports stay acyclic.

## Event Dispatchers and delegates

- **Member**: `kind: "dispatcher"`, `pins` (inputs only), `category`. Not in Function Libraries, Script Interfaces or Scene / Scene Layer scripts (those bind only; `classAllowsMemberKind`). Inherited along the lineage; `dispatcher.name_collision` reports a redeclared or same-identifier name. Closed Classes expose them through the header payload's `dispatchers` key, written only when non-empty (`classHeaderMeta`, `classGraphFromHeaderPayload`); Delegate variables and pins carry `signature` there too.
- **Nodes** ([`dispatchers.ts`](../../../packages/scripting-nodes/src/dispatchers.ts)): `flow.dispatcher.call|bind|unbind|unbindAll` (generic ids hidden; Add Node injects one row per dispatcher and action, titled `dispatcherNodeTitle`, plus **Assign** as a `PaletteNode.bundle`, and from a dragged delegate pin **Add Custom Event for X** / **Create Event for X**; Event, Assign and Add Custom Event for X name the event after the dispatcher via `freeDispatcherEventName`: `X`, else `X_1`, …, and the row sets `PaletteNode.nodeTitle` so the node is titled `Event X`, not the row label) and `flow.delegate.create` (pure). Ids avoid the `flow.event.` prefix, which `displayNodeTitle` and `nodeVisualRole` treat as event entries. Properties: `name`, `classId`, `implicitSelf`, `pins` (the dispatcher's inputs, synced by `patchClassMember` like Call Custom Event); Create Event: `memberName`, `memberKind` (`event` | `function`), `classId`, `implicitSelf`, `pins` (the member's inputs). Event Custom gains `OutputDelegate`, a `placement: "header"` pin typed by its outputs.
- **Codegen**: Call → `ctx.callDispatcher(target, jsIdent(name), [values in signature order])`; Bind / Unbind → `ctx.bindDispatcher` / `ctx.unbindDispatcher(target, name, delegate)` with `target` and `event` both subjects; Unbind All → `ctx.unbindAllDispatcher`. A delegate is `ctx.eventDelegate(object, jsIdent(member), kind, __delegateParams_<hash>)`, the parameter names hoisted once per content; Event Custom's Output Delegate is that on `ctx.self`, readable from any entry because the node is pure.
- **Runtime** ([`script-dispatchers.ts`](../../../packages/runtime/src/script-dispatchers.ts)): one `DispatcherBindings` per `ScriptHost` (dropped with it at Stop); lists in a `WeakMap` keyed by owner. `eventDelegate` returns one frozen `EventDelegate` per object and member (identity makes Unbind find Bind's). Bind ignores a duplicate target (object + name + kind), a destroyed owner or listener and non-delegates; it works on pending owners, so a spawner can bind before Begin Play. Call iterates a snapshot in bind order: removed bindings are skipped, destroyed listeners skipped and pruned, values mapped onto each delegate's own parameter names, then `invokeCustomEvent` / `invokeFunction` in the caller's frame (latent work does not hold the caller; the pending-latent and owner-admission rules of custom events apply). Nested Calls of one dispatcher stop at `DISPATCHER_MAX_DEPTH` (64) with one logged error per Call. `onDestroyed` forgets the owner's bindings after its final event. Never saved. `callDispatcher` is a per-call ctx member (it needs the frame); the rest are host members. `formatValue` prints a delegate as `Delegate(<name> on <Class>(<guid>))` (`EVENT_DELEGATE_BRAND`).
- **Validation**: `member.missing_dispatcher` (node names no dispatcher of its class), `dispatcher.name_collision`, `delegate.missing_member` (Create Event without a member, or one its class lacks), `delegate.signature_mismatch` (error: Create Event rows differ from the member; warning: a Delegate row's copied signature differs from its source dispatcher). Event symbols carry `pins` for these checks.
- **Editor**: dispatcher edits (`patchClassMember` → `syncDispatcher`) update this Class's dispatcher nodes, the custom events wired into their Bind / Unbind `event` pins, and Delegate copies whose `typeClassId` names the dispatcher; deleting one drops its nodes. Wiring a custom event with no outputs to a delegate input adopts that signature in the same commit (`adoptBoundEventSignatures`; `scriptPinCompatibility` accepts an empty `OutputDelegate` into any delegate input); while wired, its Outputs are read-only in the Inspector. Create Event's member picker lives in the node body (`createEventCandidates`: the Object's lineage, functions without data outputs, filtered by the wired delegate). Delegate appears in `CLASS_PIN_PICKER_TYPES` only (Class variables, signatures, Script Interface and Execute JavaScript pins), never in data assets (Structures, Data Definitions, Save Games, Blackboards).

## Embedded scene scripts

- A Scene's **SceneScript** (`SerializedScene.script`) and a Scene Layer's **SceneLayerScript** (`SerializedSceneLayer.script`) are optional `SerializedGraph`s stored in the owner document (`normalizeEmbeddedScript` drops components, Actor Defaults and the Prefab frame). They have no asset, are not creatable on their own and are never parents.
- They compile as class `Scene:<guid>` (parent `Scene`) / `SceneLayer:<guid>` (parent `SceneLayer`), `className` the asset name, bundle `assetGuid` the owner (`embeddedScriptHost`, `logicGraphHostClass` in [`lib/embedded-script.ts`](../../../apps/editor/src/lib/embedded-script.ts); `loadEmbeddedScriptDocuments` in Play, the export closure in `export-game.ts`). The scoped Play compile key holds the scripts, not the owner revisions. Asset dependencies include the script's references; no metadata version change.
- Editor: `serializedGraphFromDocument` / `commitLogicGraph` read and write `content.script` (`kind: "scene"` commits go to `applySceneChange`); the Class panels take class id and parent from `logicGraphHostClass`. Scene / SceneLayer chains get Begin Play, Tick and Destroyed (`isEmbeddedScriptChain`); graph diagnostics publish only in Script mode.
- Runtime: the main Scene (`SceneRealizer`), each streamed Scene and each layer instance is created with `ScriptRuntime.embeddedScriptHooks()`, which applies class defaults, binds interface handlers and resolves `hooksFor(self.classId)` lazily through `OwnerAdmission`. Tick is `tickEmbeddedScripts` (main Scene, ready layers) and `SceneStreams.tickScenes`, only after Begin Play ran. Script replacement keeps `Scene:` / `SceneLayer:` classes registered (re-ensured without members).
- **Get <Actor>** (`scene.getOwnedActor`) and **Get <Component> (<Actor>)** (`scene.getOwnedComponent`) are hidden catalog nodes injected per owned actor and component (`ownedGetPaletteNodes`, `PaletteOwnedActor` from `ownedActorsOfScene`). They store authored ids plus display names (refreshed from the live document by `refreshOwnedGetNodes`; `ownedGetDiagnostics` reports removed targets). Codegen calls `ctx.getOwnedActor(id)` / `ctx.getOwnedComponent(actorId, componentId)`, which resolve by `ctx.self`: a layer instance's `<layer guid>:<id>`, a streamed Scene's instance map, the main Scene's own id (never a layer actor). The host's own placed-component member rows (`scene:<guid>:component:*`) are not offered in its SceneScript.

## Runtime binding

- Lifecycle mapping: Actor/Object → `onCreation` (Begin Play) / `onTick` / `onDestroyed`; GameInstance and GameSubsystem → `onInit` / `onTick` / `onEnd` plus scene events; SceneSubsystem → its own set. `changeScene` never dispatches `onEnd`; On End is the final lifecycle on every exit path.
- Play path: compile → worker `loadScripts` → `loadCompiledModule` (blob URL, `new Function` fallback) → `registerAnchors` → realize scene actors → tick.
- `ScriptHost` resolves exports along the class lineage: lifecycle, custom events, functions and interface handlers inherit; a child implementation replaces the ancestor's. Console commands, BT node events, Animation Graph events/rules and prefab data stay exact-id. Locked engine ids never inherit.
- `ctx` members that depend only on the host live on a shared prototype built once by `createHostMembers`; `createContext` (`createScriptContext`) allocates per-call members only. Inherited members must never read `this`.
- Simulation time: every per-tick system uses the step captured when the tick began (`dt` × time dilation). Delay runs on the tick clock, never `setTimeout`. Pause reasons (`user`, `lifecycle`, `loading`; [`bridge/src/channels.ts`](../../../packages/bridge/src/channels.ts)) compose; Resume clears only its own. Custom JS timers and promises are cooperative, not suspended.
- Self is decided by the compiler, never by a runtime helper. A pin that reads Self while unwired is `optional` + `selfWhenUnwired` (`selfPin` / `selfActorPin` in `scripting-nodes/src/self-pin.ts`): `disconnectedPinLiteral` compiles it to `ctx.self`, and the graph shows a read-only `Self` placeholder field before the pin name while unwired (`pinDefaultPreview`, where an empty reference names its class); the handle's accessible name stays `<Pin> (Self)`. Every Actor `target` reads Self (Possess Camera, the transform, Add Impulse, Move Character, Move To, Stop Movement, Get Actor Name, Attach/Detach Actor, Get Parent, Get/Set Owner and Tween Actor nodes), except Attach To Bone's bone owner; so do Destroy Actor, Get/Has/Add Component, Play/Stop Particles, Get Owning Scene Layer and Attach To Bone `actor`, and the `Target` of member Call nodes on the graph's own class (`implicitSelf`: Call Function, Call Custom Event, Call Interface Function, Get Component Ref, via `memberTargetPin`). Own-class Get/Set/Validated Get keep no Target pin; a member of another class, or an engine class, keeps a required Target. `ctx` helpers (`getVariableFrom`, `setVariableOn`, `invokeFunction`, `invokeCustomEvent`, `callInterface`, `getComponentById`, `callComponentFunction`, Actor-pin helpers) never default a missing object to Self.
- **Subject pins**: `GraphPin.subject` marks the object (or delegate) input a node reads, writes, calls or moves (Target, Actor, Component, Material, Layer, a Bind node's Event…). The compiler (`emitStatementNode`, `guardPureExpression`; also the transition-rule compile) reads each subject once; when it is null or a destroyed object (`destroyed === true`, `deadReference`) the statement is skipped and its data outputs reset to type defaults (a pure node's output reads its type default; a latent node's Completed/continuation does not run), and `ctx.nullAccess("<Class>: <Node Title> (<Pin Label>) tried to access null.")` (or `…tried to access a destroyed object.`) logs an error through `ScriptHostServices.log` (`runtime.log` diagnostic anchored to the node) on every occurrence. No rate limiting: only `SessionDiagnosticAggregator` collapses repeats (by code, asset and node) for the session report. The class name is `CompileOptions.className`: the Class asset's name as the Content Browser lists it (file name without its container suffix, `classDisplayNameForGraphPath` in `script-compiler.ts`, so "My Hero" not the class id `My_Hero`); a packed export keys documents by guid and passes it explicitly. The title is the node's authored `title` or its catalog title. The catalog pin's flag wins over the saved pin's, so graphs saved before a flag existed are guarded. Never set `subject` on an input where null is a legitimate value (Set Variable value, Is Valid, Cast input, Set Owner `owner`, Attach Actor `parent`, optional Water Actor, wildcard fallbacks).
- Owner admission: calls into pending owners return output defaults; events do not run or queue. Destroying an actor while its Delay or continuation waits ends that graph silently.
- **Spawn Actor**, **Create Scene Layer**, **Set Material Instance**, texture parameters and console commands are latent and prepare resources first (`spawnActorAsync`, …); synchronous variants require prepared assets and report a cold-load error. `shouldSpawnScriptedActor` ([`play-load.ts`](../../../packages/runtime/src/play-load.ts)) never spawns GameInstance, libraries, editor objects, Scenes or subsystem lineages; `spawnActor` refuses `SceneLayerActor`.
- **Deferred Spawn Actor** (`ctx.beginDeferredSpawnActorAsync`) prepares like Spawn Actor but stops at `ActorRealization.prepareScripted`: the actor has its class defaults, components and stream adoption but no World entry, render slot or creation hooks, and owner admission refuses its events and functions. **Finish Deferred Spawn Actor** (`ctx.finishDeferredSpawnActor`) runs `finishScripted` (the `realize` half of `spawnScripted`), so Begin Play sees the variables, transform and components written meanwhile. `createActorHostBindings` tracks unfinished actors in a `WeakMap` with the Class preload each one owns from creation; Destroy Actor on one discards it (`destroyActorInstance`) and releases that preload; finishing a non-deferred live actor throws. `spawnable-lights.ts` scans both compiled spawn calls.
- Load handles (Unreal StreamableManager style): opaque String handles; priority Low/Normal/High maps to background/preload/gameplay preparation; blocking loads share one `simulationBlocking` hold with blocking Scene streams; ownership follows the calling object, else Scene, else session.
- Component property Set is not store-only: `setVariableOn` routes to render commands, `PhysicsWorldSync.applyComponent` / `syncActor`, navigation `updateAgent` or audio gain. A property enters the catalog only when the Inspector serializes it **and** Play can apply it.
- Pose writes publish the body immediately so a Line Trace later in the same event sees it. Queries run against the caller's physics world (SceneLayer scripts see only their layer).
- Subsystems: only leaf classes are created; GameSubsystems before `World.start()`; SceneSubsystems per main Scene. A base with several leaves is `subsystem.ambiguous` in the editor; at runtime the first in class-id order wins with one warning.

## Editor surfaces

- Wiring rules: exec inputs fan in; each exec output drives one wire in the Class graph (`singleExecOutputOnConnect`; replacing one shows a notice pointing to Sequence); a new data wire replaces the old one; wires persist output→input.
- Generic catalog ids for Get/Set/Validated Get, Call Function, Call Custom Event, Cast, Make/Break, enum rows and Get `<Subsystem>` are hidden; the palette injects one row per member/class/type. Heavy injectors run only when Add Node opens and memoize on class-set identity.
- Add Node history (`packages/graph-ui/src/add-node-history.ts`): hosts opt in with `GraphEditor.addNodeHistoryScope` (Class graph `script`, Material and Material Function `material`, Particle Graph `particle`); Animation Graph and Behaviour Tree stay on the default order. A pick is recorded only when Add Node from a dragged pin connects the new node. Context key: scope, source `__nodeType`, pin direction, pin id and resolved display type. Each palette id keeps a score that halves every 21 days; at most 5 ids with a decayed score of 2 or more move to the front of `filterPaletteForPin` order (score first, ties in default order). Limits: 16 ids per context, 1000 contexts (least recently used evicted). Storage is device-local IndexedDB (`haptic-add-node-history`, one record per context, changed contexts saved within a second and on page hide), not `AppSettings`, so it never competes with the settings `localStorage` quota; unreadable records are dropped and a schema change bumps `DB_VERSION`, which discards the store. `graphAddNodeHistoryEnabled` (reaching `GraphInteractionSettingsContext` as `addNodeHistoryEnabled`, unset = off) stops ranking and recording without deleting; **Clear Add Node History** deletes.
- Hydrate regenerates member, struct, enum and interface pins from live schemas, keeps wires whose pin ids still match, and prunes the rest. It also replaces the saved pins of the nodes whose Actor input reads Self (`SELF_ACTOR_NODE_IDS` in `graph-node-refresh.ts`), so graphs saved before a pin read Self show it (Tween nodes regenerate already). A new pin flag that the compiler reads (`subject`) needs no regeneration: the compiler takes it from the catalog pin. Seeding of native events and Call Parent wiring runs on create, never on hydrate.
- Editor graph services import through [`services/graph-validation.ts`](../../../apps/editor/src/services/graph-validation.ts), which holds validation and re-exports the public names of its sibling modules: hydration, component event binding, materialization and the one default node registry (`graph-hydration.ts`, the only `createDefaultNodeRegistry()` call), per-node pin refresh (`graph-node-refresh.ts`), default Class graphs (`class-graph-defaults.ts`), the palette entry, cache and schema rows (`script-palette.ts`) with its class-member injector rows (`script-palette-members.ts`), and Class lineage and symbols (`graph-class-symbols.ts`). The siblings never import `graph-validation.ts` and never read a binding imported from a sibling at module load: they sit on an import cycle through `script-compiler.ts`.
- Undo goes through `@haptic/edit` commands (`graph.setFunctionGraphs`, members, components); position drags commit once per gesture.
- Large lists (palette, Compiler Results) use the existing windowing components; do not add a virtualizer library.
- Play never writes unsaved edits without asking (Save & Play / Play Without Saving / Cancel).
- Class members are pure functions over `SerializedGraph`. [`lib/class-members.ts`](../../../apps/editor/src/lib/class-members.ts) owns member add, rename, patch, prune and remove plus `DEFAULT_FUNCTION_PINS` and `seedFunctionGraph`, and re-exports the public names of five sibling modules: native event and script catalog legality per class lineage (`class-event-catalog.ts`), Class tree sections and new-member defaults (`class-member-sections.ts`), Get/Set and Call nodes bound to members (`class-member-nodes.ts`), event node seeding and Call Parent wiring (`class-event-nodes.ts`) and Class tree drops onto a graph (`class-member-drop.ts`). The five must not import `class-members.ts`, so no import cycle can reach their module-level tables; anything they need from it moves down into one of them.
- The graph Inspector ([`panels/inspector-panel.tsx`](../../../apps/editor/src/panels/inspector-panel.tsx)) routes the selection: `inspector-graph-node-details.tsx` (selected node), `inspector-class-member-details.tsx` (variables, functions, implemented Script Interfaces; pin row and default helpers in `inspector-member-rows.ts`) or `inspector-prefab-component-details.tsx` (one component of a Class or Prefab). The multi-selection, component member, Prefab Root (Parent Class, actor defaults) and empty views stay inline. Registry and open-tab catalogs come from `use-inspector-catalogs.ts`. The panel keeps the node view's pin selection and picker state, so it survives switching to another view and back.

### Class member copy and paste

Owner: [`lib/class-member-clipboard.ts`](../../../apps/editor/src/lib/class-member-clipboard.ts) (pure) and the Class panel ([`panels/my-class-panel.tsx`](../../../apps/editor/src/panels/my-class-panel.tsx)).

- **Selection**: the Class tree is a multi-select `TreeView`. The panel keeps the entry set; `primary` (the one chosen last) is the only entry that drives graph focus through `onSelectMember`, exactly like a single selection, and equals `selectedId` while the set applies, so an external selection collapses it. A Shift range starts at the anchor (the entry last chosen without Shift) and runs over visible rows, dropping section and folder rows. Touch has no modifier: a two-finger tap range-selects (`TreeView`), and the hold menu offers **Select** (adds the entry to the selection the hold replaced) and **Deselect**. A hold or right-click replaces the selection on an unselected entry and keeps the group on a selected one. Swipe-add stays off because the tree drags out to the graph.
- **Copy** (`copyClassMembers`, shown only when `canCopyClassMembers`): variables (plain, local and component), functions and events in any mix; a Script Interface or a row whose source is gone rules it out. An inherited variable or function is read from the parent graph by name. Payload `ClassMemberClipboard`: variable members as stored (a local keeps its `functionId`; a component variable carries its `SerializedComponent`, read from the Class's own `components` before the declaring parent's, because the variable is virtual and has no `members` row); per function the member, its local variables, its graph slice and its source class id; per event the node and whether it is `bound` (override, component event, wired to Call Parent). Events are the node only, never what it runs.
- **Paste** (`pasteClassMembers`) is one graph change, never a move:
  - Names: `nextCopyName` when taken (`Health_1`; a copy of a copy continues the sequence). Locals share the variable namespace. Events keep the underscore too (`Open Door_1`; `formatEventMemberName` keeps a trailing `_<n>`) and are unique by case and compiled identifier across the event graph, function graphs, member rows and parent Classes.
  - A function copy gets fresh node and edge ids (Input / Output keep `<id>-input` / `<id>-output`) and drops `implementsInterface` and `overrides`.
  - References inside a pasted body, for nodes that use the running object (`implicitSelf` not false, no component, no engine `runtime` / `propertyKey`): local variables to the copy's locals; variables, functions and custom events to the copy that came in the same paste (by source id or source class + name), else to a member of the target or its parents with the same name and type (functions and events: same data pins), else untouched so `member.missing_*` reports them. Nothing is created. Rebound nodes get the target's class id (or the parent that declares the member). One exception to "running object only": a `flow.event.call` (`implicitSelf: false`) whose `target` pin is wired from a `variables.get` of a component copied in the same paste, naming one of that component's pasted custom events, is retargeted by `retargetComponentEventCalls` to the unbound copy (`name`/`title`/`pins` of the copy, `implicitSelf: true`, target class id); the `target` wire is removed, and the Get (and its edges) when no other wire leaves it.
  - Local variables: pasted into `targetFunctionId` (the panel passes the selected own function, else the focused one) with a name free among all variable names and `functionId` rewritten; no valid function leaves them out (`reason: "function"`). Allowed in function libraries.
  - Component variables: the copy is a new `SerializedComponent` appended to the target's `components` (`classId`, `name`, `category`, `properties`, `transform` as stored; id from `nextPrefabComponentId` over inherited and local components). A Class that never authored `components` and inherits none keeps its implicit starter box in the new list. The name is free among the Class's variable names, then `_1`, `_2`, … like variables and functions (`uniqueName`; components added through the component tree keep the row scheme ` 2`), and is stored only when it differs from the type label. `parentId` is the copy of the source parent when that was pasted too, else null (Class root); `*ComponentId` properties follow copies the same way. Get nodes in pasted function bodies bound to a pasted source component are rebound to the copy. Components the target host cannot take (Scene Layer vs world placement) and function libraries are `reason: "kind"`. No variable row is stored; the pasted id is `component:<id>`.
  - Events: a native event the target's own event graph lacks (a parent authoring it does not count) and its Class can have (`isScriptCatalogNodeAllowed`) is pasted as itself (`singletonEventKey` decides sameness) with Call Parent from `ensureCallParentForEvent` when the target has a parent Class, the event is one of its `nativeEventStubs`, like a stub added by hand; a child's event replaces its parent's unless it calls it (`script-host.ts` `eventScriptsFor`). Otherwise (present or the Class cannot have it) it becomes a custom event named like a duplicate of its display name (`Begin Play_1`) whose pins are the catalog's data outputs (name, type, order; `nativeEventOutputPins`). Every component-bound event (`data.componentId`), native or custom, becomes an unbound custom event whether or not the target has the component or the paste adds it: the name drops the component qualifier (`On Hit (Collider)` → `On Hit_1`, unique like any custom event), the pins are the native outputs or the custom event's own `pins`, and no Call Parent is added. An Inherited override is pasted as is when the target inherits that event (it also gets Call Parent from `ensureCallParentForEvent`, parent = the nearest ancestor with that event, as the Events + menu does), left out as `present` when the graph has it and as `unavailable` when the target does not inherit it. The Events + menu (`pickEvent`) passes the parent Class for a native stub, so it gets Call Parent like a stub row click. Function libraries take functions and local variables only. Nodes go below the graph (`graphNodesBounds`); skipped members come back as `skipped` with a reason and the panel shows a notice.
- **Drag**: dragging a selected entry drags the whole selection (tree order); an unselected entry drags alone. `resolveClassMemberDrop` / `completeClassMemberDrop` place one node per droppable row stacked from the drop point (Get pill 56, otherwise the pin-row estimate, plus `NODE_PLACEMENT_GAP`) in one change. Variables ask Get / Set once (`MemberAccessChooser`, which applies to every variable that can take it); rows that cannot drop and variables the access refuses are named in the notice.
