# Shader Graph

Material, Material Function and Material Instance documents: the Babylon-free IR, validation, lowering and GLSL conversion, and how render compiles, previews and binds them.

## Decisions

- [`packages/shader-graph`](../../../packages/shader-graph/src/) owns the IR, catalog, validator, lowering and GLSL conversion and imports no Babylon or React. [`packages/render`](../../../packages/render/src/) maps a lowered plan onto real NodeMaterial blocks and owns every GPU resource. Material is the only shader editor.
- Values are `float`, `vec2`, `vec3`, `vec4`, `texture`. Colors are float vectors with a pin hint and booleans are floats, so the catalog stays inside Babylon's portable block set; the Babylon boundary picks `Color3/4` vs `Vector3/4`.
- Material Function calls are **inlined** at lowering under `callNodeId/innerNodeId` ids, because Babylon has no runtime function object. Each inlined operation maps back to its call node for diagnostics. A plan holds at most `MATERIAL_MAX_OPERATIONS` (4096) operations: nested functions that each call the next several times multiply, and past the bound lowering fails with `material.tooLarge`. A Function Input or Function Output in a Material, or a Material output node of any domain (Decal included) in a function, fails validation with `material.function.misplaced`. A function's Texture input is satisfied only by a wire: a numeric default left from an earlier type is dropped (`callDefinition`). A sample node's own `textureGuid` binds only while its Texture pin is unwired.
- Blocks Babylon lacks are composed from existing blocks (`fwidth` = derivatives + abs + add, `log2` = scaled ln, `inversesqrt` = reciprocal sqrt), never raw source. The one exception is the User Interface shape and progress nodes: compiler-owned GLSL blocks ([`user-interface-blocks.ts`](../../../packages/render/src/user-interface-blocks.ts)) with no `bind`, not Custom GLSL in the plan cost, so the Material stays bounded and batchable (every compiled Material is GLSL).
- Modulo (`math.mod`) is `sign(A) × mod(|A|, |B|)`, composed from blocks: Babylon's `ModBlock` alone is GLSL `mod` (the sign of B), and the node promises the sign of A.
- Fresnel (`shading.fresnel`) is a rim term like Unreal's and Unity's: `saturate(pow(saturate(Bias + 1 - |N·V|), Power))`, 0 facing the camera and 1 at the silhouette. Babylon's `FresnelBlock` is the inverse (1 facing), so render uses it only for `|N·V|` (bias 0, power 1) and composes the rest.
- Search aliases come from one table (`MATERIAL_SEARCH_ALIASES`, merged into every node by `withSearchAliases`) plus a node's own `searchAliases`: other engines' names (append, one minus, panner, lerp) go there.
- The **Particle Texture** node is removed (emitters have no texture). Old graphs that contain `input.particleTexture` report `material.unknownNode` and do not compile; there is no migration.
- Not implemented: motion vectors, object IDs.
- The graph algorithms Material and Particle graphs share live once in [`node-graph-core.ts`](../../../packages/core/src/node-graph-core.ts) (`@haptic/core`): node and edge sanitising, the first-edge index of input pins (`indexIncomingPinEdges`), `findPin`, and the lazy generic resolver (`createPinTypeResolver`: per-node memo, a node reached again while it resolves reads as a conflict). `createTypeResolver` supplies the catalog, Named Reroute types, Float for a wildcard pin and `resolveGenericType`; lowering reuses its resolver's incoming index for each graph. The operation budget (`MATERIAL_MAX_OPERATIONS`) stays here: only Material Function inlining can multiply a plan.

## Documents

| Type | Kind | Suffix | Schema |
| --- | --- | --- | --- |
| `Material` | `material` | `.material.hasset` | `MaterialDocument`: `domain`, `shadingModel` (`pbr`/`unlit`), `blendMode` (`opaque`/`masked`/`translucent`/`additive`/`multiply`), `twoSided`, `defaultNormals` (`model`/`flat`), `alphaCutoff`, `preview`, graph |
| `MaterialFunction` | `material-function` | `.matfunc.hasset` | Typed `inputs` / `outputs` with **stable pin ids** (renames never break callers), graph |
| `MaterialInstance` | `material-instance` | `.matinst.hasset` | `parentGuid`, cached `domain`, typed `overrides` by parameter name, `preview`; no graph |

- Domains: `surface`, `landscape`, `postProcess`, `particle`, `text`, `decal`, `ui` (**User Interface**: the Material of Scene Layer 2D components, [scene-layers.md](scene-layers.md)). Unknown strings parse as `surface`; a leftover `"interface"` is not `ui`. `materialBlendModesFor` lists a domain's Blend Modes: Multiply in Surface, Landscape and Decal; Text and User Interface keep Translucent and Additive (their Scene Layers can composite through a transparent target, where a product has nothing to multiply); Particle and Post Process have none, and the Material editor shows no Blend Mode row for them (nor for Text, whose settings are forced); `normalizeMaterialDocument` stores Post Process as `opaque` (nothing reads it; it only keyed recompiles).
- `text` and `ui` force their settings (`isOverlayDomain` in `document.ts`): `shadingModel: "unlit"`, `twoSided: true`, preview mesh `plane`, `blendMode` `translucent` (default) or `additive` (anything else normalises to translucent). A new `ui` document wires a `const.color` into User Interface Output's Color, as the Surface default feeds Base Color. Imported `Material` stubs open as `material`.
- `materialDependencies()` is the only source of `header.dependencies[]` (textures, called functions, inline Texture Sample guids, preview mesh) so references, delete guards and the export closure agree. Save also writes `domain` onto `header.payload`.
- Parameter names (`properties.name`) are nonblank, trimmed, case-sensitive and unique across Float/Vector2/Vector3/Vector4/Color/Texture parameters (`isMaterialParameterNode`); validation reports every unnamed or duplicate one and Save rejects them. Only root-Material parameters are runtime-settable; Material Function parameters stay internal defaults. The editor never leaves one blank or taken: `nameNewMaterialParameters` names added, copied and pasted parameter nodes (`Parameter`, else the stem plus the first free `_N`), and Inspector and header renames (title double-click or **Rename** in the node menu, `useMaterialCanvasNaming` in `material-editor.tsx`, which also renames Named Reroute declarations) go through `renameMaterialParameter` (same suffixing). The node menu converts Float/Vector2/Vector3/Color constants to parameters and back (`convertMaterialConstantToParameter` / `convertMaterialParameterToConstant`; a Color's wires move between the constant's `out` and the parameter's `rgb`), and the Inspector **Type** row retypes a parameter (`retypeMaterialParameter`, dropping wires from an output the new type lacks). Set/Get/Reset Material Parameter Name pins list the Class's mesh components' Materials' parameters of their type (`ClassMaterialsContext`, `useMaterialParameterNames`; an instance lists its root Material's).
- A root-Material Float or Color parameter with `properties.perInstance: true` (`isPerInstanceParameter`) compiles to an instanced attribute instead of a uniform ([`instance-parameters.ts`](../../../packages/render/src/instance-parameters.ts)): each mesh drawn with the Material carries its own value, so pool members that differ only in it share a group. The flag is part of the plan hash; a Function's parameters ignore it.
- Literals are shader constants, parameters are uniforms: a pin default, a `const.*` node and every fixed value the compiler adds are `InputBlock`s with `isConstant` (`createConstantBlock`), so they cost nothing per bind and the driver folds them; `param.*` nodes and Global Parameters pass `uniform` and stay rewritable. Constant values are therefore part of the plan hash by design. A Gradient's stop colours go to linear space by the exact sRGB curve, as a Color node's do.
- Parameter writes: a scalar, vector or colour write only makes the Scene forget its last bound Material (`resetCachedMaterial`), so the next bind uploads the uniform; only a texture write marks submeshes dirty (`createMaterialParameterBindings`). In Play, a write to a component that already has a Material of its own goes straight to that Material (`SnapshotSceneBinding.setMaterialInstanceParameter` → `MaterialLibrary.setParameter`) without resolving or binding again; the first write, and a write that only touches per-instance parameters, take the resolving path.
- Build failures and warm-ups: where the library's generation hash carries each texture's identity (`textureIdentity`), a build that fails because a texture is missing is remembered like a plan failure, so each mesh that asks does not build again; the texture arriving makes a new generation. `prewarmMaterial` ends at once, reporting no stall, when its Material or its mesh is disposed while it compiles.
- `param.vec2` / `param.vec3` / `param.vec4` hold exactly 2 / 3 / 4 raw components (`normalizeMaterialDocument` pads with 0), compile to a Vector2 / Vector3 / Vector4 `InputBlock` uniform and travel as `MaterialParameterValue` `{ kind: "vec2" | "vec3" | "vec4", value }` (`copyMaterialParameterValue`, `isFiniteMaterialParameterValue` in core). They are never Per Instance. A Vector4 and a Color are different kinds although both hold four numbers: a Color's block has `convertToLinearSpace` (its RGB is picked in sRGB), a Vector4's does not, and neither is accepted where the other is declared. Scripts have one node family per type and action (`material.{set,get,reset}{Float,Vector2,Vector3,Vector4,Color,Texture}Parameter`), each with a pin of exactly that type and each touching only a parameter of that kind; there is no catch-all Vector node, which would have to drop or invent components. A Mesh or Dynamic Runtime Mesh component's **Get Material** function (`getMaterialObject`) returns its `MaterialObject`.
- Pin defaults persist as `default:<pinId>` on the node; lowering prefers the override, then the catalog default; pins with neither stay unset so the compiler can attach mesh or screen UV. Perlin and Worley Noise leave Coordinates without a default for the same reason: unwired, their adapter exposes a `uv` input (`noiseCoordinates`) that becomes `(u, v, 1)`, what wiring the UV node gives. Defaults are identities where one exists (Multiply B = 1, Mix B = 1 and Alpha = 0.5), so a half-wired node shows something.
- `setMaterialDomain` drops nodes the new domain disallows. Surface and Landscape share the Material Output and keep it; between Material Output and Decal Output (same pin ids) the node is retyped, keeping the wires and `default:*` of the pins both have; other switches (into or out of `ui` among them) replace the terminal. Switching to Particle wires **Particle Color** into Color; leaving Text or User Interface, or entering User Interface, takes the target domain's shading/blend/two-sided defaults (`createDefaultMaterialDocument`), since the overlay domains' forced values were never authored.

## Material Instances

- `resolveMaterialInstance` walks parents to the root Material (`MATERIAL_INSTANCE_MAX_DEPTH` = 16), nearest override wins. Missing parents, cycles and over-deep chains are errors, never silent fallbacks.
- `materializeMaterialInstance` yields a `MaterialDocument` keyed by the instance guid (root graph, parameter defaults replaced when the kind matches, runtime-only `instanceOf`). Every consumer uses these through the existing `Map<guid, MaterialDocument>` paths.
- `MaterialLibrary` compiles an instance under its root's name and then renames it; all instances of a root share one GPU program (as any Materials of one graph shape and values do, [Compilation](#compilation)); override edits are uniform/texture writes, never recompiles. Every Material picker also offers instances of the matching domain.
- Material slots by domain (editor, `apps/editor/src/lib/material-asset-filters.ts`): `materialDomainsFromAssets` maps every Material and Instance guid to a domain, open documents first; an Instance resolves through `parentGuid` to its root (the cached `domain` only when no root is reached), a Material without one is `surface`. Each slot passes its one domain (`AssetPickRequest.materialDomain` for component rows); `materialSlotPickerAssets` filters the picker, `materialSlotTakes` guards the pick, and `materialSlotRowState` gives the row `acceptsAsset` (Paste refuses other domains, `property-clipboard.ts`) and `error` for a held Material of another domain (no migration). Surface: Mesh (a 3D mesh in a Scene Layer too), Dynamic Runtime Mesh, Cable, Mirror, Model slots, Foliage override, Water. User Interface (`ui`): Scene Layer 2D Material, 2D Panel (Material source), 2D Joystick (both) and 2D control parts. Landscape, Decal, Text (2D Text, 2D Rich Text), Particle (emitters) and Post Process (Scene and Scene Layer stacks, `2DPostProcessingPanelComponent`) are their own. Scripting pins: `MATERIAL_PIN_DOMAINS` in `packages/scripting-nodes/src/material-pin-domains.ts` (post-process Register/Unregister, Spawn Decal, Set Material Instance) drives the pin pickers and the `material.pinDomain` validation rule; at runtime `setMeshMaterial` already admits only surface (`acceptsAssignment`) and the decal pass only decal. No script node or runtime Inspector edit assigns a 2D component's Material (Set Material Instance targets Mesh and Dynamic Runtime Mesh only, and 2D Material slots are not live properties), so no pin names `ui`; render's `acceptsUserInterfaceMaterial` is the final check that a 2D component draws only `ui`. Material Instance **Parent** takes any domain; picking one writes the root's domain into the cache. The Simulation Inspector's runtime Material values are not filtered.

## Type rules

- Any numeric output connects to any numeric input. A Float fills every channel (Float `x` → V3 `(x,x,x)`), as in GLSL and Unreal. A vector keeps leading channels, drops trailing ones and fills missing channels with **1** (V2 `(x,y)` → V3 `(x,y,1)`); supplied zeros are preserved. Generic nodes take the widest connected input regardless of order. Declared function and Custom GLSL pins keep explicit types. The scripting graph keeps its stricter exact-kind rule.
- A scalar default on a wider pin fills every channel. Conversions compose across function boundaries and participate in the plan hash; render realises them with splitter/merger blocks and CPU baking applies the same rule.

## Named Reroutes

- `reroute.declaration` (**Named Reroute**: input `in`, no output; `properties.name`, `properties.color` `[r, g, b]` 0–1) and `reroute.usage` (**Named Reroute Usage**: output `out`, no input; `properties.declarationId`), category `Reroute`, cost 0, legal in every domain. Material graphs have no plain reroute knot.
- Scope is one graph: a usage reads only a declaration in its own Material or Material Function body (lowering and validation look it up frame-locally).
- Pin kind `wildcard`: the declaration's input takes any output, Texture included, with no conversion at the reroute. `createTypeResolver` gives both pins the type wired into the declaration (`namedRerouteType`; Float when unwired, missing or looping) so generic nodes, conversions and the canvas see the real type. The resolver resolves usage → declaration → source under its own in-progress guard, so hydrate, preview and pin defaults terminate on looping graphs, which they resolve without validating first.
- Canvas: `materialPinsAreCompatible` lets any output meet a declaration's input (a wired one is drawn as its type with `type.wildcard: true`); a usage connects as its carried type, or to numeric inputs while it carries none. Hydration titles declarations and usages by the declaration's name (`Missing Reroute` without one) and stamps `__headerColor` (`namedRerouteColorCss`), an editor key never saved.
- Collapse invariant: **the plan never contains a reroute node.** `operandForOutput` returns a usage's declaration source operand unconverted; the consumer's wire converts from the real source type, so a graph routed through Named Reroutes lowers to the same plan and hash as the direct wires (no recompile). An unwired declaration reads constant Float 0. The World Position Offset stage walk follows usage → declaration input.
- Validation (errors, before type resolution): `material.reroute.missingName`, `material.reroute.duplicateName` (with the parameter-name checks), `material.reroute.missingDeclaration`, `material.reroute.selfUse` (walking upstream from a declaration through wires and usages reaches its own usage; every declaration on a loop between reroutes is reported). A reroute loop suppresses type resolution like `material.cycle`, which sees only wires and so never reports the same loop.
- Names: unique among the graph's declarations, `Reroute`, `Reroute_1`… (`uniqueNamedRerouteName`, the parameter suffix rule via `uniqueSuffixedName`). `nameNewNamedReroutes` runs with `nameNewMaterialParameters` in both canvas fold-backs, so added, pasted and duplicated declarations get a free name and, when they have none, the default colour indexed by the declaration count modulo 8. Renames go through `renameNamedReroute`. Paste keeps usages on the original declaration unless the host remaps them to a declaration pasted with them (`remapPastedNamedReroutes(pasted, idMap)`).
- Add Node: the static palette omits both types; `namedReroutePaletteNodes(graph)` lists **Create Named Reroute…** first, then one usage row per declaration by name (`id` `reroute.usage:<declarationId>`, `nodeType` `reroute.usage`).

## Validation and lowering

- Codes are `material.*`, each anchored to a node, pin or edge for Compiler Results (Named Reroute codes: [Named Reroutes](#named-reroutes)). `material.postProcessCost` is a warning. `material.stageMismatch` fires when a fragment-only node (derivatives, `texture.sampleLod`, Normal Map, …) reaches World Position Offset, including through functions.
- Function validation visits each referenced function once (including disconnected calls); recursion and missing functions are errors.
- `lowerMaterialDocument` produces a deterministic `MaterialBuildPlan`: ordered operations, explicit conversions, texture bindings, `bufferRequirements` (`sceneColor`/`sceneDepth`/`sceneNormal`), cost features and a hash that **ignores node positions**. The plan also carries `programHash` and `valueHash`: the program hash is the graph's shape (operations by plan position, never node id, their wiring and conversions, the literals the shader holds, the properties that change code, which samples have a texture bound, and domain, shading, blend, two-sided, normals and alpha cutoff); the value hash is what a plan binds rather than compiles (parameter names and defaults, texture guids and filters, Global Parameter selections, bounds padding). Plans equal in both compile byte-identical shader text whatever their Materials and node ids; `hash` stays the full content identity (ids included, as diagnostics anchor to them) for generations and compile keys. A call input is lowered only when the body reads it. Lowering validates once: `checkMaterialDocument` returns the diagnostics with the type resolvers it built (the document's and one per reached function body), and lowering reuses them, one resolver per function however many calls inline it.
- Material and Material Function documents are immutable once handed to lowering or a `MaterialLibrary`: hosts replace a document to change it. `lowerMaterialDocumentCached` ([`lower-cache.ts`](../../../packages/shader-graph/src/lower-cache.ts)) is the realm's one memo, used by every `MaterialLibrary.planFor` and `buildMaterialParameterCatalog`. Per document object and shading variant it keeps the last result with the value each reached function guid had in the functions record, so a lookup that finds the same function documents (in any record) serializes nothing. A miss looks in a 512-entry LRU keyed by the variant, the document's JSON and the guid and JSON (once per function document) of every function its `function.call` nodes reach, transitively, with a marker for a missing one, so equal graphs in different objects share one plan; nothing else reaches lowering (no capabilities, texture registry or Global Parameter catalog). A content miss lowers the live documents. A reached guid the record does not hold as an own object bypasses the memo. Failed lowerings are kept with their diagnostics. Results are shared and never changed; under Vitest each is deep-frozen (with the document values it holds) so a mutation fails its test. `buildMaterialParameterCatalog` rebuilds a functions Map's record whenever its entries change, since hosts sync one Map in place.

## Compilation

- `compileMaterialPlan` instantiates real blocks and connects real ports. Babylon reports build failures through `onBuildErrorObservable`; the compiler turns them into diagnostics. `TextureBlock.autoConfigure` is not used (surface plumbing names UV `material_uv`).
- Block names never carry the Material: plumbing blocks take the fixed prefix `MATERIAL_BLOCK_PREFIX` (`material_lighting`, `material_fog`, …) and an operation's blocks are named by its plan position (`materialOperationBlockName`: `op` plus the index in letters, as Babylon strips digits from the shader symbols it derives from names), never its node id. Babylon derives every generated symbol from block names, so Materials of one shape and values generate the same text. Custom GLSL keeps its id-derived function name (`customGlslFunctionName`, for its line diagnostics); it never shares a program anyway.
- Catalog conventions, which a new node follows:
  - Masks: comparison nodes (Equal, Not Equal, Less Than, Less Or Equal, Greater Than, Greater Or Equal) return 1 or 0 per component; And, Or, Not and Select's Condition read a value above 0.5 as true. Select keeps one `ConditionalBlock` for a Condition that is one Float (a constant with equal components, or an operand whose last conversion is from Float) and one per component for a vector Condition.
  - Colour sources (Texture Sample, Triplanar, Color Parameter, a Color Global Parameter, Vertex Color, Particle Color, Scene Color) all have outputs named **RGBA**, **RGB** and **A**; their pin ids differ for historical reasons (`rgba` / `out` / `color`).
  - The Vector nodes (Combine, Split, Component Mask, Swizzle) name components X, Y, Z and W. Component Mask stores its toggles as `r`/`g`/`b`/`a` and shows them through `vectorMaskChannelName`; Swizzle stores `components` (one to four of `xyzw`, in output order) and takes its width and title from it (`swizzleDefinition`).
  - Angle pins say their unit in the pin name ("Rotation (Radians)", "Angle (Radians)").
  - User Interface nodes (`UI_NODES`, category User Interface, `domains: ["ui"]`, fragment only, `requires: ["derivatives"]`): positions and UV start at the element's bottom left, like UV and Screen UV; units are pixels of the target drawn into (the screen in Play, the Preview buffer in the editor), said in the pin name ("Size (Pixels)"). Position, Size and UV pins have no default: unwired, the compiler feeds them User Interface Input's Element Position, Element Size and Element UV. Element Size is `1 / length(dFdx(uv), dFdy(uv))` per component, exact for any affine quad, so it needs no per-mesh uniform. Shape and progress outputs antialias over one pixel; progress masks are exactly 0 at Progress ≤ 0 and 1 at ≥ 1.
  - A node that is one existing node under another name is not added: Landscape layers blend with Mix, Darken and Lighten are Minimum and Maximum (search aliases cover the other names). Add Node (`materialAddNodePalette`) omits the output node, which every Material already has exactly one of.
- A composite adapter never uses Babylon's `ElbowBlock` to feed one input into several blocks: behind a constant or a parameter the Elbow takes the vertex target, which costs a varying per input and hands the fragment stage an interpolated copy (a Flipbook frame read through one could floor to the wrong cell). `BlockRealization.fanIn` lists an input's further connection points and the compiler wires the operand to each; `link()` joins internal blocks whose types only resolve after that.
- Screen UV is legal in every domain: a Post Process reads the fullscreen pass position, any other Material divides `FragCoordBlock` by `ScreenSizeBlock`, 0 to 1 from the bottom left. World Normal is normalised in the stage that reads it. Object Position is the world matrix applied to the local origin (a `TransformBlock`, so per instance) plus the floating origin. Triplanar is Babylon's `TriPlanarBlock` at the absolute world position times Scale; it needs a wired Texture (its sampler comes from the source's `ImageSourceBlock`) and, unlike Texture Sample, does not take the texture quality LOD bias.
- Trigonometry: radian nodes say "(Radians)"; each Degrees variant (Sine … Arctangent 2) compiles as the radian block behind a Babylon `TrigonometryBlock` Radians or Degrees conversion, componentwise like its radian twin.
- The compiler owns plumbing the graph does not author: Surface attributes, transforms and `PBRMetallicRoughnessBlock` unless unlit; Post Process fullscreen quad and screen UV (no WPO); Text Output multiplied by glyph coverage (only 2D Text / 2D Rich Text accept it): the graph's linear colour is encoded for display once (`ColorEncodingBlock`, [`color-encoding-block.ts`](../../../packages/render/src/color-encoding-block.ts), `toGammaSpace` on RGB) and then multiplied by the display-space glyph colour (span colour or atlas) and overlay style into `DisplayFragmentOutputBlock`, which shows it unchanged or decodes it once for a Scene Linear stage, so a picked Color shows as picked and an unmaterialed white output leaves span colours exact; User Interface Output (below); Particle mode (`NodeMaterialModes.Particle`, `particle_color` / `particle_uv`, and outside the editor preview a `ParticleBlendMultiplyBlock` before the output). Particle Color is the emitter's display colour, decoded to linear where it enters the graph (`ColorEncodingBlock`, `toLinearSpace` on RGB; the preview's white constant too); the graph's result is encoded for display once before the blend block, which lerps to white in display space as Babylon's Multiply mode expects, into `DisplayFragmentOutputBlock` (unchanged, or decoded once for a Scene Linear stage). A graph that only wires Particle Color draws exactly as the emitter set it; Color, Parameter, Gradient and colour texture values show as picked; scalar factors on a colour (a falloff, an intensity) act in linear light, as in every other domain.
- Every domain's graph colour is linear (Color constants and Parameters decode the sRGB pick, Gradient stops are linear, colour textures decode) and is encoded for display exactly once: by the surface's image processing or fragment output, `UserInterfaceFragmentOutputBlock`, or `ColorEncodingBlock` where it meets display colours (Text, Particle).
- User Interface (`ui`) plans compile in Material mode with the surface plumbing (`createSurfacePlumbing`) and nothing lit: no lighting, fog, water, alpha-to-coverage or depth pre-pass, both faces, alpha blending (`ALPHA_COMBINE`, `ALPHA_ADD` when additive). It is the Text path without `TextMaterialBlock`: `(Color, Opacity)` × `OverlayStyleBlock` (always present, white by default, so the component's tint and opacity apply) into `UserInterfaceFragmentOutputBlock`. The colour is linear (a Color constant is the decoded sRGB pick) and the output encodes it with `toGammaSpace`, as an overlay Surface Material does, unless the Scene applies image processing by post-process (`applyByPostProcess`, a Scene Linear stage, which encodes the frame once): Scene Layer Scenes never do, the editor's Scene Layer tab and the Material preview may. A Color constant so shows as picked in all three, and the result does not depend on the library's `unlit` / `overlay` option. User Interface Input is composed (Element Size from `DerivativeBlock`, Screen UV and Size as their nodes, Screen Position `FragCoordBlock`); outputs nothing reads are never built. `metadata.materialDomain` is `"ui"`; only the Scene Layer 2D components draw it ([scene-layers.md](scene-layers.md)). A bounded `ui` Material batches like an overlay Surface Material ([render.md](render.md#draw-batching)).
- Every Surface Material but a screen overlay fogs through `SceneFogBlock` ([`scene-fog-block.ts`](../../../packages/render/src/scene-fog-block.ts)), lit or unlit: Babylon PBR's rule, the linear-space factor `toLinearSpace(CalcFogFactor())` (`sceneFogKeep`) toward the linear fog colour. Built-in water and the water nodes that undo or read the fog use the same factor, the unlit Material (sprites, 3D Text, overlay surfaces) through `SceneFogBlock`'s display-space mode with its distance per vertex, and the legacy CEL surface through the block's `displaySpace` mode; one rule keeps a surface's fog the same whichever material draws it.
- World Position Offset is added in world space after the world transform; World Position nodes feeding WPO read the undisplaced vertex. Displacement does not inflate the AABB; use **Bounds Padding (Local)**.
- Sampled textures: acquire/`resolveMaterial` stay synchronous; the compiler binds the live Texture, builds, then rebuilds on `onLoadObservable` (unfreezing and refreezing a frozen material; a texture that loads while a build still waits for its blocks' shader code rebuilds once that build settles, as Babylon drops a `build()` meanwhile). `texture.isReady()` is not proof: Babylon's error sampler reports ready. A load error becomes `material.missingTexture`.
- `shareCompiledProgram` lets a Material-mode build without Custom GLSL adopt the `buildId` of a live build on the same Engine whose compiled shader text is byte-identical, whatever its Material: the registry is keyed by surface variant, Scene Layer (overlay) and shader language, then by the code itself. So two Material assets of one graph (an imported glTF's per-material graphs of one shape and values), their Instances and copies, and each one's outline, capture, shadow and water variants draw with one program each. Only a first build adopts another material's program. The compiler's own rebuild for a texture that arrived keeps the program it had when its code did not change (counted as `sameShaderRebuilds`, [render.md](render.md)); a rebuild whose code changed, or one the compiler did not start, keeps Babylon's new id, so policies that trust a build id (`registerCacheableShadowMaterial`) see the change.
- `shareParticleProgram` does the same for Particle builds without Custom GLSL, whose Effects Babylon names after the material and its build id (`name + buildId + "_" + blendMode`) rather than their code: a first build adopts the id an earlier build of the same name and shader language took for byte-identical code. The Engine remembers the `PARTICLE_PROGRAM_CACHE_SIZE` (256) most recently used programs, keyed by name, language and an FNV-1a digest of the code and checked against the code itself, so a digest collision adopts nothing; a forgotten program costs only a later build its own compile (no Effect is disposed). Remembered ids outlive their materials, so every emitter's instance of one particle Material and the next Play's builds of it share one Effect (kept across Plays by `keepPlayEffects`, [render.md](render.md#loading-and-readiness)); a link failure the compiler reports drops its id. A particle system binds its own Material again right before each draw (`onBeforeDrawParticlesObservable` in `node-material-particles.ts`): every system's binding observer on a shared Effect runs when it is enabled, the last one's values winning, and none runs when consecutive draws use the same Effect. Post Process builds keep their own ids: Babylon creates a pass's Effect a tick after registering its source under `name + buildId`, and a retiring pass (`OwnedPostProcess`) or a rebuild deletes the sources by that name, which another Material's pass sharing it would then fetch as a URL.
- **Decal domain**: `output.decal` (Base Color, Opacity, Normal, Roughness, Metallic, Emissive; all optional). Legal nodes list `decal` explicitly (it inherits nothing from Surface): UV (the projected UV), World Position/Normal/Tangent, View Direction, Camera Position, Object Position (the decal's centre), Normal Map, Fresnel, Triplanar, plus every domain-free node; no vertex inputs, Vertex Color, World Position Offset, water, Mirror Reflection or scene buffers. The compiler builds `createDecalPlumbing` (the hidden `DecalProjectionBlock`, [render.md](render.md)) instead of surface plumbing, then `attachDecalShading`: Base Color and Emissive times the instance Tint, `HapticLightingBlock` unless Unlit, alpha = Opacity × instance Opacity × fade, `SceneFogBlock` toward the fog colour (black for Additive, white for Multiply), Opaque discarding below fade 0.5 and Masked below Alpha Cutoff (both alpha 1), then `LinearSurfaceImageProcessingBlock` (or the Multiply factor). Every Decal Material is alpha-blended (`transparencyMode`) so the light block never compiles Screen-Space Shadows; its `alphaMode` (`decalAlphaMode`) is DISABLE, DISABLE, COMBINE, ADD or MULTIPLY. Per Instance parameters stay uniforms (the box carries only the decal's rows). Programs per root Decal Material: one per render mode (`HAPTIC_CEL`), plus the editor's Unlit view (`HAPTIC_UNLIT`) and debug defines; blend, lit/unlit and fog are the Material's or the Scene's, never the decal's; its Instances and private copies share it.
- **Multiply**: `Constants.ALPHA_MULTIPLY` (destination × source) with alpha-blend transparency and a depth pre-pass like Translucent; the colour output is `MultiplyBlendFactorBlock` (`mix(1, colour, opacity)`, alpha 1) gamma-encoded alone (`GeometrySurfaceOutputBlock.linearFactor`, `MultiplyFactorOutputBlock`), never tone mapped, unless a Scene Linear display stage encodes; fog fades it toward 1. Outline and shadow variants read Opacity as for Translucent. An overlay compile (Scene Layer) draws a Multiply Material as Translucent (ALPHA_COMBINE, ordinary colour output): a post-processed layer composites through a transparent target.
- A Surface Material compiles no water blocks. A water mesh draws its water variant (`acquireWaterVariant`, `CompileMaterialOptions.water`): the same graph plus the hidden Water Cut block and, when translucent, the Water Coverage block, shared by every water mesh of one Material generation and fed the base's parameters ([render](render.md)).
- `MaterialLibrary` caches per Scene by asset guid + plan hash with refcounts. A new build replaces the old only after it builds, so a failed edit keeps the previous material on screen. `invalidate()` recompiles onto live GPU state after context restore.
- Custom GLSL (`custom.glsl`) is a typed function body (Babylon `CustomBlock`); derivatives or `discard` make it fragment-only. Readiness includes a hidden GPU probe: 15 s GLSL budget after the probe effect exists, a separate 120 s texture wait reporting `material.missingTexture`. Both credit time a probe held the thread (a synchronous link without parallel shader compile) up to `SCENE_THREAD_HELD_BUDGET_MS` each, and start again while shaders keep finishing on the Engine ([render.md](render.md#frame-path)), so a slow link is not a timeout and a shader that never compiles still fails. The compile budget's progress counts from the probe effect's creation. On a parallel-compile driver (D3D11 through ANGLE) the probe effect itself pending also renews them until it has been pending `SCENE_DRIVER_COMPILE_TIMEOUT_MS`, so a hung compile there fails after about 75 s, not 15 s.
- Post-process buffers: Scene Color → `CurrentScreenBlock`, Scene Depth → `SceneDepthBlock` (`useNonLinearDepth = false`), Scene Normal → `PrePassTextureBlock`. A stack that cannot supply a buffer skips only that pass with an anchored `material.framegraph.buffer`. In a view's stack (`ScenePostProcessGraph`) Scene Depth and Scene Normal sample the stack's shared geometry pass (`LogicalSceneTextureBlock`): normalized view depth in a single-channel float target (Scene Depth reads red alone), world normal in RGBA8.

## Preview

- The preview is a disposable Scene on the app-lifetime Engine, presented through `camera.outputRenderTarget` and a 2D blit. Never `registerView`, render the default framebuffer, or `camera.attachControl` (it binds the Scene/Play input element); gestures attach to the preview canvas only. Recreating the preview Scene bumps an epoch so the graph recompiles.
- `materialPreviewReducer`: `clean → dirty → queued → lowering → gpuCompiling → ready | error`, generation-safe; the last good image stays up while editing.
- `classifyMaterialCost` auto-compiles while measured compile time stays within two frames of the frame budget (`AUTO_COMPILE_FRAME_ALLOWANCE`); Custom GLSL and post-process graphs are always manual. Timings are session-local, never stored.
- **Render** (global toolbar, Material documents only) is disabled while compiling and for `MANUAL_RENDER_COOLDOWN_MS` (3 s) after a manual result. Position-only moves never recompile.
- Particle materials preview on one plane with a white Particle Color default and no Multiply block.
- User Interface materials preview flat (`MaterialPreviewScene.flat`): the mesh is hidden and a unit quad (`MATERIAL_PREVIEW_USER_INTERFACE_NAME`) sits under a front-on orthographic window of ±0.5, which the projection stretches to the buffer, so at any aspect the quad fills the Preview, Element UV spans it and Element Size is the buffer size. The presenter waits for the quad and draws at the canvas's device pixels, longest side at most 2048 (other previews keep the 512 CSS-pixel cap). No mesh choice, orbit or zoom: the editor hides the mesh toolbar and zoom controls, and the gestures do nothing while the camera is orthographic (only the flat state makes it so). It is its own preview state beside the particle plane, text preview and post-process states; another domain's Material, a post process or a particle Material restores the orbit camera as it was and the mesh. A `ui` Material's thumbnail (`asset-thumbnail.ts`) is that flat quad filling the frame, not the sphere. RenderTargetTexture samples preview as opaque black.
- **Preview Node** ([`node-preview.ts`](../../../packages/shader-graph/src/node-preview.ts)): `MaterialEditingProvider.previewNode` is tab state (never saved, never an undo step). While set, the provider compiles `materialNodePreviewDocument` instead of the document: the target output alone into the output node's colour (Base Color, or Color outside Surface/Landscape) through a Split and Combine (Float grey, Vector2 blue 0, colour alpha 1), unlit and opaque, every other output-node input and `default:*` dropped. It goes through the same state machine, cost class and library as the Material. `materialNodePreviewOutputs` lists the numeric outputs (none for Texture outputs or output nodes); a target that stops resolving, once functions have loaded, clears the preview. `lowering` on the context stays the Material's own, so Details and cost describe the Material. Material documents only: Functions have no preview and Instances no graph. Its key, `material.previewNode` (P, category Material), registers in `MaterialGraphPanel` with `focusWithinRef` on the canvas and runs only with exactly one selected node (`previewNodeKeyResult`: preview the first numeric output, or stop on the previewed node or on the output node while previewing); the menu shows the chord on the entry the key runs. The graph tag and ring are `GraphEditor.previewedNode`; the Preview's banner and frame are `MaterialPreviewSurface.previewedNode`; titles come from `materialNodeTitle`, as on the canvas.

## Runtime

- `MeshComponent.materialGuid` overrides the whole mesh; Model `materialSlots` apply by glTF `materials[]` index, then name. Play sends `assignMaterial`; editor viewports bind through `EditorSceneSync` instead.
- `SceneSettings.postProcessStack` (ordered Material guid + Enabled) compiles into the view's FrameGraph, skipping and reporting missing, non-post-process or failing entries rather than blacking out.
- Play and export close over surface, decal (Decal components and Spawn Decal pins) and stack materials (including disabled entries), Material Functions and textures; the player hydrates documents, functions and the stack into `createEngine`. Preview Build packs PNG/pixels, never KTX2, so a cold iframe matches overlay Play; Export Game packs KTX2 when the transcoder ships.
- Default material, editor freeze and `postProcessingEnabled` rules: [render.md](render.md).
- **Global Parameter** (`global.parameter`, [`global-parameter.ts`](../../../packages/shader-graph/src/global-parameter.ts)): properties `{collectionGuid, parameterId, valueType}` only, never the value, so a default edit or a Play set never changes the plan hash. Its outputs follow `valueType` (Color: `out` RGBA and `rgb`; none without a selection); the title comes from the editor catalog (`MaterialPinContext.globalParameters`); `selectMaterialGlobalParameter` drops wires from outputs a new selection lacks; validation warns (`material.globalParameter`) when the selection is unset, gone or retyped. The selection parser, title and warning text are shared with the Particle Graph node (`globalParameterSelection`, `globalParameterNodeTitle`, `globalParameterNodeWarning` in [`core/src/global-parameters.ts`](../../../packages/core/src/global-parameters.ts)); each graph keeps its own outputs and wire pruning. `materialDependencies.globalParameterCollections` puts the collection in the Play closure. The compiler realizes it as a uniform (`createGlobalParameterBlock`) whose value callback refreshes from a `GlobalParameterValueSource` only when its revision moves; Babylon transmits Color uniforms from the stored value even with a callback, so vectors and colors are updated in place. See [scripting.md](scripting.md#global-parameters) for the sources.

## GLSL to Material

- `convertGlslToMaterial(source, { name?, bindings? })` returns `{ ok, document, diagnostics }` or `{ ok: false, diagnostics }`; it validates and lowers but never saves or GPU-compiles. Output is an unlit translucent surface Material of ordinary nodes, no Custom GLSL.
- Subset: one `main`, float/vector locals, arithmetic, swizzles, numeric uniforms, explicit `uv`/`time` bindings and listed builtins. Control flow, helper functions, samplers, arrays, matrices, booleans, integer math and macros fail with a source-line diagnostic and no partial output. Limits: 32768 characters, 4096 tokens, 64 nesting, 2048 nodes.
- Exposed through the bundled GLSL to Material extension ([editor-extensions.md](editor-extensions.md)).
