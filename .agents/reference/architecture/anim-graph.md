# Animation Graph

Worker-side Animation Graphs (one State Machine whose states each own a pose graph) plus per-instance Animation Object graphs that drive glTF Animation clips and Sprite Animation assets.

## Invariants

- `@haptic/anim-graph` has no React and no Babylon; the evaluator runs in the game worker.
- Render seeks `AnimationGroup`s and sprite frames from `animState` and never lets Babylon auto-advance gameplay animation. Groups stay paused with live animatables (`play()` then `pause()`); never `stop()`, which empties animatables and makes `goToFrame` a no-op.
- `animState` is an extra command-channel message ([bridge.md](bridge.md)), not a snapshot stride change. One `animState` per actor slot: the last graph in component order wins playback.
- Behaviour Tree Play Animation emits the same `animState`; there is no second playback clock.
- A player's Play Rate scales its clip duration, and a player at Play Rate 0 or below holds its pose: its clock never advances. Fact durations divide by Play Rate floored at 0.001 to stay finite.
- Pose and frame wires are structure, read by the evaluator; only data inputs compile. Phase 1 still plays through `AnimationGroup` weights: the evaluator flattens a graph into weighted clip layers (`AnimClipLayer`), with no per-bone pose buffers.
- Treat evaluated documents as immutable: derived lookups are cached per document object, so replace a document instead of mutating it.

## Document format

- Asset types `AnimationGraph3D` (document kind `anim-graph-3d`, `.anim3d.hasset`) and `AnimationGraph2D` (`anim-graph-2d`, `.anim2d.hasset`) share one document shape and one editor; `isAnimGraphAssetType` / `isAnimGraphDocumentKind` ([`document.ts`](../../../packages/core/src/document.ts)) test for either. The type is the dimension: a 3D graph plays `animation` clips on its `skeletonGuid` (null plays Animations with no Skeleton), a 2D graph `sprite` clips with `skeletonGuid` null. `validateAnimGraph(doc, catalog, { dimension })` reports `anim.clipKind` and `anim.clipSkeleton` on the state that plays the clip; the editor's clip picker lists only matching assets. The Animation Graph component's row warns when a 3D graph's Skeleton is not its actor's Model's.
- Fields: `skeletonGuid`, `previewModelGuid` (3D, editor only: the Preview window's Model, null for the first listed; a dependency, never read by Play), typed `variables[]` (bool / int / float / string / tag / Tag Container), `stateMachine` (`entryStateId`, `states[]` with `stateGraph`, `transitions[]` with `blendSeconds`, `priority` — lower wins, `ruleGraph`, side handles) and `animationObject` (a scripting graph seeded with protected Event Initialize / Update Animation). `parseAnimGraphDocument(value, dimension?)` returns null without a `stateMachine`; `dimension` (the asset type's) refills a state graph a state lost, else the stored state graphs give it.
- A graph is exactly one State Machine, the root: there is no top-level pose graph and no State Machine pose node, so one active state is what Get Current State, Jump To State, the top-level `AnimEvalState` fields and the debugger follow. Layering (such as upper-body gestures) belongs in pose nodes inside state graphs, not in more State Machines.
- Every state graph (`stateGraph`) has one protected output (`anim.pose.output` / `anim.frame.output`, id `output`); its type also gives the document's dimension (`animGraphDimension`: 2D when any state graph ends in Output Frame).
- Transition ids are unique in the State Machine (`anim.duplicateTransitionId`): rule class ids, breakpoints and `patchTransition` find a transition by id alone.
- Clip nodes (players, Sequence Evaluator) store `assetGuid`, filled `clipName`, `durationMs` and, for sprites, `frameCount` (`resolveAnimGraphClips`); 3D clips are Animation assets (a guid naming a Model resolves to nothing and plays nothing), 2D clips Sprite Animations. Node settings (clip, Loop, blend times, input `count`) live in node data; data pin values in `default:<pin>`.
- A state graph that is one player wired to the output (`singlePlayerOf`) is edited by the state's Inspector rows; any other graph is edited as a graph.
- Animation asset payload ([`animation-payload.ts`](../../../packages/assets/src/animation-payload.ts)): `durationMs` is the authored length of one pass (the Inspector's Duration) and `clipDurationMs` the clip's length in the source file, set at import and used as Duration's Reset default. A missing Duration defaults to the clip's length. Clip refs carry `durationMs`, and `resolveAnimGraphClips` refreshes it from the catalog at Play and export load, so the asset's Duration sets the playback rate; render seeks the group's authored frame range by normalised time, never by the asset's duration.
- Compiled class ids: `AnimGraph:{guid}` (Animation Object), `AnimRule:{guid}:{transitionId}` (`export function evaluate(ctx)` → `{ enter, exit }`) and `AnimPose:{guid}:{graphKey}` (`evaluate(ctx)` → `{ [nodeId]: { [pin]: value } }`, wired data inputs only; a graph with none compiles no module), all `parentClassId: "Object"`. `graphKey` is the state id (`animPoseGraphKey`). Loading compiled scripts never instantiates actors.
- `AnimState.position` and editor-only `clipLabel` are presentation data; `__disabled` on One Way rules is canvas-only and stripped on persist.

## Evaluator

- Pure `(graph, dt, previous, inputs) → AnimEvalState`, deterministic and golden-tested. It runs the State Machine: its active state's graph from the output, then its transitions, then the blend with the graph of the state a blend leaves. Output: the State Machine's `stateId`, `normalisedTime`, `blendWeights` and timing `facts`; player clocks `players[graphKey#nodeId]`; Blend Poses By Bool / Int weights `selectors`; weighted `layers[]` (2D layers carry Flip Frame's `flipX` / `flipY`).
- Players keep their own clocks and advance whenever their graph is visited, even at weight 0; a fresh visit (state entry) restarts them at their Start Position or Start Frame. A state's facts follow its primary player (`primaryPosePlayer`: from the output through each node's first pose input), else a 1 s looping clock, and start where that player starts.
- Data inputs come from `inputs.poseData(graphKey, facts)` (the compiled module; facts are the owning state's before this tick's advance), else the node's stored default. Frames never blend: select nodes show one input, and render shows the heaviest sprite layer.
- A transition fires when both Exit State and Enter State are true; unwired sinks default true. `decideTransition` sees post-advance facts; `undefined` (missing class or throw) passes. An infinite-loop abort is rethrown.
- Blend length is captured when the blend starts so a duplicate `(from, to)` row cannot change it mid-blend.
- Exit Time Reached fires on crossing (Unity-style), once per loop for `exitTime ≤ 1`, once for `exitTime > 1`; non-looping states use a level test. Plain `normalisedTime` is post-wrap; use Exit Time Reached for end-of-loop thresholds.
- Missing entry state starts on the first state; transitions to missing states never fire. Nothing throws.
- `animEvalWithJump` replaces the State Machine's evaluation with the target state at `timeMs -1`, which the next evaluation enters fresh with no blend.

## Runtime

- `AnimationGraphComponent.graphGuid` attaches a graph. `AnimGraphRuntime.tick` visits only owners from the shared component owner index ([object-model.md](object-model.md)).
- Per component: seed its own copy of variable defaults → Initialize once per `componentGuid:graphGuid` → Update every tick → evaluate → set or clear the actor sprite clip.
- Evaluation and pending Jump To State belong to one graph guid; switching graphs restarts at the entry state. Jumps apply on the next `tickAnimGraphs`, so Actor `onTick` cannot race the evaluator.
- `self` in Animation Object scripts is the Actor. Actor Class graphs use `anim.actor.*` nodes with a required `AnimationGraphComponent` target; unwired targets are no-ops.
- Play/export load only Animation Graphs in the session dependency closure; editor Compile compiles every project graph.
- An Animation layer with neither clip name nor clip guid (a state with no clip) plays nothing and rests the slot's groups; it is not a missing clip. A named clip the slot lacks is warned once per slot and clip per Play session.
- Trace frames record per-component evaluation, graph guid and pending jump; restore does not re-run On Initialize Animation.
- The Simulation's graph debugger follows one `AnimationGraphComponent` ([debugger.md](debugger.md#simulation-graph-debugging)): `AnimGraphRuntime` reports, for it only, the State Machine's weighted states and taken transition under the debug graph id `ANIM_STATE_MACHINE_DEBUG_GRAPH_ID` (`"state-machine"`, `reportStateMachine`), and its Animation Object scripts get `ctx.debugTrace` through the component, their variable store. State and transition breakpoints use the same graph id. Transition rule and pose graphs carry no probes.
- A Flip Frame sprite layer mirrors the quad's UVs and pivot (render) and the frame's collision box (physics) through `flipSpriteAnimationFrame`.

## Render rules

- Clip lookup is per slot (`getAnimationGroups(slotId)`); never seek another actor's same-name group. With `clipAssetGuid` set, untagged groups do not match.
- Each Model is loaded once per Scene; actors instance under a `__importScale` child of an empty named root (`editorActor:<id>` / `actor-N`) so import scale never overwrites snapshot TRS.
- Material slots map by the glTF material index each primitive names (`modelMaterialIndexOf`), not child visit order; the file's own materials are never loaded. `MeshComponent.materialGuid` overrides the whole visual.
- `resolveAnimGraphClips` keeps Animation guids (never rewrites Animation → Model). Retargeted Animations load the source Model GLB and retarget at rest pose.
- A Model plays every Animation on its Skeleton: `retargetAnimationLoadsFromAnimations(animations, modelSkeletons)` ([`animation-payload.ts`](../../../packages/assets/src/animation-payload.ts)) lists, per Model, Animations retargeted onto it and every other Model's Animation on its Skeleton (`bindByName`); `beginSlotModelAnimLoad` binds the latter with `bindAnimationGroupByName` ([`node-rig.ts`](../../../packages/render/src/node-rig.ts)): same-named nodes and morph targets, the clip's keys shared unchanged. Play (`modelGuidsForPlayRetarget`) loads those source Models.
- `anim.skeletonMismatch` is an error when an Animation's skeleton differs from the owning Model's.

## Editor rules

- DockView document kinds `anim-graph-3d` and `anim-graph-2d`, with one DockView surface and the same windows (Focus keep key `anim-graph`): **Graph** (the State Machine, state graphs and rules), **Animation Object** (the script, a `GraphPanel`, tabbed beside Graph by default), Variables, Inspector and Compiler Results. The editing context's `canvas` is the canvas last brought forward or pressed in (`useAnimCanvas`); the Inspector follows it, and changing it clears the shared node selection. Each canvas brings its own panel forward for a focused diagnostic. The Graph's validation rows use graph ids under `${documentId}:` and the Animation Object's the document id, so neither replaces the other's.
- Rule palettes (`animationGraphHost: "rule"`) allow `anim.state.*`, pure nodes and Get Variable only; pose palettes (`"pose"`, with the `animPose` dimension; state graphs only) allow the dimension's pose or frame nodes except its output, `anim.state.*`, pure nodes and Get Variable; Object palettes (`"object"`) add `anim.event.*`; Actor palettes hide all and show `anim.actor.*`. Protected nodes: initialize/update events, Enter/Exit sinks and pose graph outputs.
- Navigation (`AnimEditorLocation`: `machine`, or `state` with its id) lives in the editing context and opens on the State Machine; a state that no longer exists falls back to it. Breadcrumbs read **State Machine**, then the state's name in its graph (**State Machine › Walk**), and **Back** steps out; double-click steps in (a state to its graph). Double-clicking a wire opens its transition's rule (`transitionAtWire`: on a mirrored pair's shared wire, the direction whose target state is nearer the point); Inspector Open Rule does the same, and **Back To State Machine** closes it. On the State Machine canvas the Details panel edits state and transition rows, or the graph's own rows (3D Skeleton) with nothing selected; in a state graph or rule it is the node Inspector.
- One directed `(from, to)` pair is one transition; extra rows warn `anim.duplicateTransition`. A reverse pair shares one edge (`animTransitionBoth`) only when mirrored (`findMirroredReverse`: B's side out is A→B's side in and back); otherwise each is its own edge. Re-drawing a pair moves its transition (id, rule, settings kept) to the new sides; the hidden half of a mirrored pair stays with its old sides when the shared wire moves.
- Dragging (`connectDraggedToNode` → `animTransitionFromDrag`): the dragged state is always the source, leaving by the dragged side (either plate); the target side is the released handle's, else the side nearest the release point, else (near the middle) the side facing the source. Transitions stored without sides load on the sides their states face (`facingTransitionSides`). The canvas uses `connectEndMode="zone-add-node"`: a far release opens Add Node, a release near a compatible pin snap-connects, and any other release breaks; `GraphEditor.edgeBreaksAtPin` = `animTransitionOnSide` makes a break remove every transition on the dragged state's dragged side, in or out, whichever plate was dragged.
- A selected state and a selected transition exclude each other; Open Rule selects the rule's transition. The State Machine passes the selected transition to `GraphEditor.selectedEdgeId` as its drawn edge (a reverse row maps to its pair's edge), so the wire stays highlighted when a rule closes.
- State names must be non-empty and unique (trimmed, case-insensitive). Diagnostics publish only for the active mode.
- Renaming or retyping a variable rewrites bound Get/Set nodes in `animationObject`, every rule graph and every pose graph.
- Pose and frame pins (`{kind:"pose"}`, `{kind:"frame"}`) connect only to their own kind (`isStructuralPinKind`) and draw heavy wires; pose nodes use the `anim-pose` (mustard) and control nodes the `anim-control` (amber) roles.
- Preview: `AnimGraphPreviewProvider` (one `AnimGraphPreviewSession` per open graph, mounted inside the editing provider) runs `evaluateAnimGraph` on the editor main thread. It loads the graph's compiled `AnimRule:` / `AnimPose:` modules (`collectPlayPreviewScripts`, debounced) into a private `ScriptHost`, with Preview Values as the variable store; a rule not yet loaded is closed, never passing. Values persist per variable name while its type fits and reset to the default otherwise; they never write the document. Time advances only while the Preview window is visible and playing: real time × Speed, capped at 0.1 s a frame; Step is one 1/60 s tick and pauses. While the Preview window is shown its `runTrace` lights the State Machine canvas (a Simulation trace wins), with the debugger's graph id and node/edge ids. Windows default above the Inspector (Preview) and below Variables (Preview Values).
- Preview 3D: Models on the graph's Skeleton (none: the Models its Animations come from), on its own `createModelPreviewScene` on the shared Engine with a floor grid; clips load per source like Play (own groups, `bindAnimationGroupByName` for same-Skeleton Models, `retargetAnimationGroupWithMeshProxy` for retargeted Animations), wrapped with `wrapGameplayAnimationGroup` and seeked by `applyAnimStateToScene`. Bones swaps in `attachSkeletonPreview`. Preview 2D draws the heaviest sprite layer's frame with its flips.
- `AnimPinGlyph` (`packages/graph-ui/src/graph-nodes.tsx`) draws them boxless: Phosphor `UserFocus` for pose at 1.6× the pin size (its glyph is padded) and Bootstrap Icons `image` for frame at 1.4×, each icon's outline glyph unwired and its fill glyph wired, imported from its own module ([no-ai-artwork.md](../../rules/no-ai-artwork.md)).
