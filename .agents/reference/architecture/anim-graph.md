# Animation Graph

Worker-side Animation Graphs (one State Machine whose states each own a pose graph) plus per-instance Animation Object graphs that drive glTF Animation clips and Sprite Animation assets.

## Invariants

- `@haptic/anim-graph` has no React and no Babylon; the evaluator runs in the game worker.
- Render poses 3D clips with its own pose evaluator ([`anim-pose.ts`](../../../packages/render/src/anim-pose.ts)) and bakes sprite frames from `animState`. Babylon never starts, seeks, weights or advances a gameplay `AnimationGroup`: a group is only the source of a `PoseClip`'s channels.
- `animState` is an extra command-channel message ([bridge.md](bridge.md)), not a snapshot stride change. One `animState` per actor slot: the last graph in component order wins playback.
- Behaviour Tree Play Animation emits the same `animState`; there is no second playback clock.
- Animation Tick Mode (`tickMode` component property and variable, [`animation-tick-mode.ts`](../../../packages/core/src/animation-tick-mode.ts), engine enum `engine:AnimationTickMode`, Get/Set Animation Tick Mode): `never` skips the component in `AnimGraphRuntime.tickActor` (state kept, no events, no `animState`, the pose holds); `whenVisible` evaluates as `always` and marks `animState.whenVisible`, and render's `AnimVisibilityGate` ([`anim-visibility.ts`](../../../packages/render/src/anim-visibility.ts)) poses it only while the actor's bounds sphere (measured once from its hierarchy, grown ×1.25 for poses and ×3 for shadow casters) meets an active camera's frustum (`viewOfBox`), else holds the slot's latest state in `pendingAnimState` and poses it before the render that first sees it, or before a ragdoll capture. Visibility never reaches the worker, so evaluation, events and replay do not depend on the view.
- A player's Play Rate scales its clip duration, and a player at Play Rate 0 or below holds its pose: its clock never advances. Fact durations divide by Play Rate floored at 0.001 to stay finite.
- Pose and frame wires are structure, read by the evaluator; only data inputs compile. The worker evaluator flattens a graph into weighted clip layers (`AnimClipLayer`); render blends them per animated property in the slot's pose rig.
- Treat evaluated documents as immutable: derived lookups are cached per document object, so replace a document instead of mutating it.

## Document format

- Asset types `AnimationGraph3D` (document kind `anim-graph-3d`, `.anim3d.hasset`) and `AnimationGraph2D` (`anim-graph-2d`, `.anim2d.hasset`) share one document shape and one editor; `isAnimGraphAssetType` / `isAnimGraphDocumentKind` ([`document.ts`](../../../packages/core/src/document.ts)) test for either. The type is the dimension: a 3D graph plays `animation` clips on its `skeletonGuid` (null plays Animations with no Skeleton), a 2D graph `sprite` clips with `skeletonGuid` null. `validateAnimGraph(doc, catalog, { dimension })` reports `anim.clipKind` and `anim.clipSkeleton` on the state that plays the clip; the editor's clip picker lists only matching assets. The Animation Graph component's row warns when a 3D graph's Skeleton is not its actor's Model's.
- Fields: `skeletonGuid`, `previewModelGuid` (3D, editor only: the Preview window's Model, null for the first listed; a dependency, never read by Play), typed `variables[]` (bool / int / float / string / tag / Tag Container), `stateMachine` (`entryStateId`, `states[]` with `stateGraph`, `transitions[]` with `blendSeconds`, `priority` — lower wins, `ruleGraph`, side handles) and `animationObject` (a scripting graph seeded with protected Event Initialize / Update Animation). `parseAnimGraphDocument(value, dimension?)` returns null without a `stateMachine`; `dimension` (the asset type's) refills a state graph a state lost, else the stored state graphs give it.
- A graph is exactly one State Machine, the root: there is no top-level pose graph and no State Machine pose node, so one active state is what Get Current State, Jump To State, the top-level `AnimEvalState` fields and the debugger follow. Layering (such as upper-body gestures) belongs in pose nodes inside state graphs, not in more State Machines.
- Every state graph (`stateGraph`) has one protected output (`anim.pose.output` / `anim.frame.output`, id `output`); its type also gives the document's dimension (`animGraphDimension`: 2D when any state graph ends in Output Frame).
- State Aliases (`stateMachine.aliases`: `id`, `name`, `position`, `anyState`, `stateIds`; parse drops unknown state ids and fills `[]`): a transition whose `fromStateId` is an alias leaves from each covered state (`animAliasStates`) except its own target, merged into that state's outgoing list by priority, then document order (`machineIndex`). Nothing enters an alias (`anim.badTransition`); one covering no state warns `anim.emptyAlias`; alias names share the state namespace. On the canvas an alias is an `anim.alias` node (dashed card, `stateCount`), refused as a connection target and dropped as one by `serializedToStateMachine`; a palette alias starts with Any State.
- Transition ids are unique in the State Machine (`anim.duplicateTransitionId`): rule class ids, breakpoints and `patchTransition` find a transition by id alone.
- Blend Space asset (`BlendSpace`, kind `blend-space`, `.blendspace.hasset`): `skeletonGuid`, editor-only `previewModelGuid` (a soft dependency), one or two `axes` (`name`, `min` < `max`, `gridDivisions` 1–64, `smoothingSeconds` ≥ 0, `wrap`) and `samples` (`animationGuid`, `x`, `y` — 0 on one axis —, `rateScale` > 0). The header payload is the whole normalised payload (`headerMetaForSave`), so the clip catalog (`animClipCatalogFromAssets`, the exporter's `hydrate`) reads its layout without loading the document; its samples' Animations are required dependencies, so they join Play and export closures through it.
- Sprite Blend Space (`SpriteBlendSpace`, kind `sprite-blend-space`, `.spriteblend.hasset`): the same axes and samples (Sprite Animation guids in `animationGuid`, `y` 0 on one axis), plus `hysteresis` (0–0.5 of each axis's range) and `keepTime`; no Skeleton. A new one has one wrapping Direction axis. Its header payload is the normalised payload too; its samples are required dependencies.
- A Sprite Blend Space Player (`anim.frame.spriteBlendSpacePlayer`, 2D, X / Y / Play Rate → Frame) resolves into the same `data.blendSpace` with each Sprite Animation's length and the `hysteresis` and `keepTime`; `anim.clipKind` when the guid is not a Sprite Blend Space. Both players are `isBlendSpacePlayerType`.
- A Blend Space Player (`anim.pose.blendSpacePlayer`, 3D) names a Blend Space in `assetGuid`; `resolveAnimGraphClips` stores it on the node as `data.blendSpace` (`axes` without names and grid, `samples` with each Animation's `clipName` and `durationMs`; samples whose guid is not an Animation are dropped). Validation: `anim.clipKind` when the guid is not a Blend Space, `anim.clipSkeleton` when its Skeleton is not the graph's. It is a time source (`isPoseTimeSourceType`, so `primaryPosePlayer` stops on it) but not a single player the state Inspector edits; the state card names its Blend Space.
- Clip nodes (players, Sequence Evaluator) store `assetGuid`, filled `clipName`, `durationMs` and, for sprites, `frameCount` (`resolveAnimGraphClips`); 3D clips are Animation assets (a guid naming a Model resolves to nothing and plays nothing), 2D clips Sprite Animations. Node settings (clip, Loop, blend times, input `count`) live in node data; data pin values in `default:<pin>`.
- A state graph that is one player wired to the output (`singlePlayerOf`) is edited by the state's Inspector rows; any other graph is edited as a graph.
- A pose or frame output drives one wire (`pinAllowsMultipleOutgoing` in [`graph-connect.ts`](../../../packages/graph-ui/src/graph-connect.ts): a new wire replaces it), as in Unreal; a pose is reused through cached poses.
- Layered Blend Per Bone (`anim.pose.layeredBlendPerBone`): pose inputs `basePose`, `blendPose<i>`, data `blendWeight<i>` (default 1) for `count` 1–16 (`layeredBlendInputCount`); node data `layers[i].branches` = `{ bone, blendDepth }[]` (`layeredBlendFilters`, `normalizeAnimBranchFilters`). Blend Depth 0 is full weight on the bone and below, N > 0 ramps `min(1, (d + 1) / N)` d bones down, < 0 excludes; the nearest branch root up a bone's chain decides (`animBranchWeight`).
- Cached poses: Save Cached Pose (`anim.pose.saveCachedPose`, pose input, data `name`) and Use Cached Pose (`anim.pose.useCachedPose`, pose output, data `name`); names are trimmed and graph-wide, across every state graph. Validation: `anim.emptyCachedPoseName`, `anim.duplicateCachedPose` (the first in state order wins), `anim.missingCachedPose`, `anim.cachedPoseCycle` (a cached pose that reaches its own Use, directly or through others). Hydration titles both `Save Cached Pose <name>` / `Use Cached Pose <name>` (`cachedPoseNodeTitle`).
- Transform Bone (`anim.control.transformBone`, the first `anim.control.*` skeletal control, amber `anim-control` role): Source Pose (`sourcePose`), Translation (Vector3), Rotation (Rotator), Scale (Vector3, default 1), Alpha (default 1) → Pose; node data `bone`, `<channel>Mode` (`ignore` default, `replace`, `add`) and `<channel>Space` (`actor` default, `parent`, `bone`) for translation, rotation and scale. Validation warns `anim.missingBone` without a bone. 3D only.
- Animation asset payload ([`animation-payload.ts`](../../../packages/assets/src/animation-payload.ts)): `durationMs` is the authored length of one pass (the Inspector's Duration) and `clipDurationMs` the clip's length in the source file, set at import and used as Duration's Reset default. A missing Duration defaults to the clip's length. Clip refs carry `durationMs`, and `resolveAnimGraphClips` refreshes it from the catalog at Play and export load, so the asset's Duration sets the playback rate; render poses the clip's authored frame range by normalised time, never by the asset's duration.
- Compiled class ids: `AnimGraph:{guid}` (Animation Object), `AnimRule:{guid}:{transitionId}` (`export function evaluate(ctx)` → `{ enter, exit }`) and `AnimPose:{guid}:{graphKey}` (`evaluate(ctx)` → `{ [nodeId]: { [pin]: value } }`, wired data inputs only; a graph with none compiles no module), all `parentClassId: "Object"`. `graphKey` is the state id (`animPoseGraphKey`). Loading compiled scripts never instantiates actors.
- Animation Events ([`animation-events.ts`](../../../packages/assets/src/animation-events.ts)): Animation payload `events` (`id`, `name`, `timeMs`, `durationMs` > 0 = window, `triggerWeight` default 0.5, `action`: `playSound` {assetGuid, volume} or `spawnParticles` {assetGuid, bone} or null; sorted by time, absent when empty); Sprite Animation frame `events` (no time: they fire at the frame's start); `AnimState.events` {`enter`, `exit`, `fullyBlended`} names; Blend Space `eventMode` (`highestWeight` default, `all`, `none`). Action assets are dependencies. The clip catalog carries `events` (`animationClipEvents`, `spriteAnimationClipEvents`: frame events at `spriteAnimationFrameStartMs`) and `blendSpace.eventMode`; `resolveAnimGraphClips` copies them onto player `data.events` and each Blend Space sample, so the worker needs no Animation payloads. Event names are one namespace across clips and states.
- `AnimState.position` and editor-only `clipLabel` are presentation data; `__disabled` on One Way rules is canvas-only and stripped on persist.

## Evaluator

- Pure `(graph, dt, previous, inputs) → AnimEvalState`, deterministic and golden-tested. It runs the State Machine: its active state's graph from the output, then its transitions, then the blend with the graph of the state a blend leaves. Output: the State Machine's `stateId`, `normalisedTime`, `blendWeights` and timing `facts`; player clocks `players[graphKey#nodeId]`; Blend Poses By Bool / Int weights `selectors`; weighted `layers[]` (2D layers carry Flip Frame's `flipX` / `flipY`).
- Blend Space Player: X and Y wrap or clamp to their axes and ease toward the input by `1 − e^(−3·dt/smoothing)` (the short way round a wrapping axis), held in `selectors[key]`. Weights: one axis interpolates the two neighbours (the end sample alone past either end); two axes use a Delaunay triangulation on the range-normalised grid (cached per resolved object), barycentric inside a triangle, else the nearest hull edge (collinear samples: the shortest edge holding the point). Samples share one phase; one cycle is `Σ wᵢ · durationᵢ / rateScaleᵢ`, recomputed each tick, and the clock carries `normalised` (not `timeMs`) across cycle changes, as the state clock does for it (`synced`). Each sample above weight 1e-4 emits a layer; it always loops. Its tick is computed once per key per evaluation and shared by the state clock and the layers.
- Sprite Blend Space Player: eased inputs as above; `nearestBlendSpaceSample` picks the nearest sample in grid widths (the short way round wrapping axes), keeping the playing one (held in `selectors[key + "#sample"]`) until another is nearer by more than `hysteresis`. Its cycle is that sample's length over its rate scale; on a change the phase carries over with Keep Time, else the player and its state clock restart at 0 (`restart`). It emits one sprite layer through the flip-aware `emit`.
- Sync Groups: a looping player's or Blend Space Player's `data.syncGroup` (trimmed name). `syncGroupPhase` advances each group once per evaluation from `syncGroups[name]` of the previous one (`phase + dt / cycleMs`, wrapped), and every member this tick takes that phase (players, and a state clock whose primary player is in the group). The heaviest member by local weight leads next tick (the first at a tie: the state blended into is visited first); a group absent last tick starts at its first member's own clock. A state entered with a blend adopts the group's phase. Groups live in `AnimEvalState.syncGroups` (`{ phase, cycleMs }`), so trace frames keep them.
- Players keep their own clocks and advance whenever their graph is visited, even at weight 0; a fresh visit (state entry) restarts them at their Start Position or Start Frame. A state's facts follow its primary player (`primaryPosePlayer`: from the output through each node's first pose input, so a Layered Blend's Base Pose and a Transform Bone's Source Pose), else a 1 s looping clock, and start where that player starts. A Use Cached Pose ends the walk: its players never give a state its facts.
- Layered Blend Per Bone flattens like the other blends: the Base Pose's layers at the incoming weight and each input's at weight × Blend Weight, every one tagged in `AnimClipLayer.masks` (`{ blend, input }`, outermost first; input -1 is the Base Pose) with the blend's `{ filters (animBranchFilterKey), weights }` appended to `AnimEvalState.layerBlends`. Inputs are visited at weight 0 when their Blend Weight is 0 (clocks keep running); a blend whose weights are all 0 adds no blend and no masks. Render resolves the per-bone weights.
- Cached poses evaluate on demand (`cachedPoseVisit`): once per evaluation, in the saving state's graph (`graphKey` = its state id, data from `poseData(key, null)`), at the tick's `dtSeconds`, never fresh, so their players keep time across the states that use them; whichever use comes first tags the layers' `stateId`, and each use copies the layers (retagged with its state, weight × use weight, masks prefixed by the use's). A cached pose evaluating itself reads nothing. Each use pushes a `{ cached, weight }` marker into the events; `resolveCachedPoseEvents` replaces the first marker per name with the cached pose's own events at the uses' summed weight (≤ 1, nested uses counted through their parents) and drops the rest, so events fire once.
- Transform Bone visits its pose first, then appends an `AnimBoneModifier` (bone, alpha = Alpha × weight, channels not on Ignore, Rotation converted by `rotatorToQuat`, masks of the inputs it is under) to the visit, so deeper changes come first. Visits scale modifiers' alpha like layers; `AnimEvalState.boneModifiers` holds the left state's then the entered state's. A Transform Bone outside the last node before the output applies its change to the whole pose at its weight (exact for Add in translation, approximate otherwise).
- Data inputs come from `inputs.poseData(graphKey, facts)` (the compiled module; facts are the owning state's before this tick's advance), else the node's stored default. Frames never blend: select nodes show one input, and render shows the heaviest sprite layer.
- A transition fires when both Exit State and Enter State are true; unwired sinks default true. `decideTransition` sees post-advance facts; `undefined` (missing class or throw) passes. An infinite-loop abort is rethrown.
- Blend length is captured when the blend starts so a duplicate `(from, to)` row cannot change it mid-blend.
- Exit Time Reached fires on crossing (Unity-style), once per loop for `exitTime ≤ 1`, once for `exitTime > 1`; non-looping states use a level test. Plain `normalisedTime` is post-wrap; use Exit Time Reached for end-of-loop thresholds.
- Missing entry state starts on the first state; transitions to missing states never fire. Nothing throws.
- `animEvalWithJump` replaces the State Machine's evaluation with the target state at `timeMs -1`, which the next evaluation enters fresh with no blend; it records `exitingStateId` so the next evaluation fires the left state's Exit event.
- Animation Events ([`events.ts`](../../../packages/anim-graph/src/events.ts)): each pose visit returns its layers, the clip events its players crossed (`animClipSweep` from the previous to this clock, `animSweepCrossings`: once per pass, wrap included; a fresh or first visit counts its start) and the sources it played, at the visit's own weight; the State Machine scales them as it scales layers (left state 1 − t, an instant transition's left state 0). `fireEvents` then fires in order: a single event or window begin at weight ≥ `triggerWeight` (and > 0), a window end once begun; a restarted source and any source no longer playing (weight 0 or not visited) end their open windows, so begin and end pair. `AnimEvalState.events` (fired, ordered) and `openWindows` (by `source#index`) are absent when empty. Order per tick: left state's crossings, its Exit, the entered state's Enter, its crossings, then Fully Blended (entry with no blend, or the tick a crossfade completes). Blend Spaces fire per `eventMode` (Highest Weight at the Blend Space's own weight; All at each sample's); a Sprite Blend Space fires its playing sample's. Sequence Evaluators fire nothing.

## Runtime

- `AnimationGraphComponent.graphGuid` attaches a graph. `AnimGraphRuntime.tick` visits only owners from the shared component owner index ([object-model.md](object-model.md)).
- Per component: seed its own copy of variable defaults → Initialize once per `componentGuid:graphGuid` → Update every tick → evaluate → set or clear the actor sprite clip.
- Evaluation and pending Jump To State belong to one graph guid; switching graphs restarts at the entry state. Jumps apply on the next `tickAnimGraphs`, so Actor `onTick` cannot race the evaluator.
- Fired events (`AnimGraphRuntime.fireEvents`): each event's action first (host `playEventSound`: a `playSound` with the actor as emitter; `spawnEventParticles`: `RuntimeParticleEffects.spawn` attached to the actor at the bone, auto-destroyed), then `invokeAnimEvent(AnimGraph:{guid}, "onAnimNotify", actor, dt, extras, {name, phase, animation})`. Animation Event nodes (`anim.event.notify`, data `eventName`, `window`) all compile to `onAnimNotify` as gated entries (`emitInputEventEntry`) that run only for their own name: `execOut` on `event`, `begin` / `end` for a window. They exist only in the Animation Object (no component event for Actor Class graphs); Add Node offers one per name from `animGraphEventEntries` (the graph's playable clips' events and its state events; a name that is a window anywhere is a window), never a bare node.
- `self` in Animation Object scripts is the Actor. Actor Class graphs use `anim.actor.*` nodes with a required `AnimationGraphComponent` target; unwired targets are no-ops.
- Play/export load only Animation Graphs in the session dependency closure; editor Compile compiles every project graph.
- An Animation layer with neither clip name nor clip guid (a state with no clip) plays nothing and rests the slot's groups; it is not a missing clip. A named clip the slot lacks is warned once per slot and clip per Play session.
- Trace frames record per-component evaluation, graph guid and pending jump; restore does not re-run On Initialize Animation.
- The Simulation's graph debugger follows one `AnimationGraphComponent` ([debugger.md](debugger.md#simulation-graph-debugging)): `AnimGraphRuntime` reports, for it only, the State Machine's weighted states and taken transition under the debug graph id `ANIM_STATE_MACHINE_DEBUG_GRAPH_ID` (`"state-machine"`, `reportStateMachine`), and its Animation Object scripts get `ctx.debugTrace` through the component, their variable store. State and transition breakpoints use the same graph id. Transition rule and pose graphs carry no probes.
- A Flip Frame sprite layer mirrors the quad's UVs and pivot (render) and the frame's collision box (physics) through `flipSpriteAnimationFrame`.

## Render rules

- Clip lookup is per slot (`getPoseClips(slotId)`, from `binding.slotPoseClips`); never pose another actor's same-name clip. With `clipAssetGuid` set, untagged clips do not match.
- Pose evaluator ([`anim-pose.ts`](../../../packages/render/src/anim-pose.ts)):
  - `bindPoseClip` / `bindGameplayAnimationGroup` turn an AnimationGroup into a `PoseClip`: per channel the Babylon `TargetedAnimation` (its `target` read at each write, since `handOverNode` re-targets pooled leaves and ejected members), the property path, the compiled track and the rest value. Rest is read at bind time, before pooling or any pose; `beginSlotModelAnimLoad` binds right after instantiation.
  - `poseTrackOf` compiles a Babylon `Animation` once (WeakMap; a Model's instances share keys) into Float64 frames and values, flagging tracks whose keys never change (`constant`). `samplePoseTrack` follows `Animation._interpolate`: clamped to the first and last key, STEP held, Hermite where the start key has an out-tangent and the end key an in-tangent (tangents × frame delta; quaternions normalised), linear otherwise; quaternion keys under 90° apart take a parameter-corrected nlerp (within 0.005° of slerp, no trigonometry), farther ones `Quaternion.SlerpToRef`'s slerp. Each bound clip keeps a key hint per channel (`keyHints`), so forward playback skips the binary search. Easing functions are not sampled. Float, Vector2/3, Quaternion and Color3/4 tracks only; other channels are skipped.
  - `poseRigFor(clips)` (WeakMap by the slot's clip list, rebuilt when the list changes in place) maps each clip channel to one property per (target, path). `applyPose` blends clips by weighted sum in any order (quaternions aligned to the sum's hemisphere, then normalised: the nlerp blend, order-independent for layering); a total below 1 adds the rest value for the remainder, above 1 normalises. Each property is written at most once per pose: TransformNode values in place (`copyFromFloats`, then `markAsDirty`), Bones through their setters, floats (morph `influence`) assigned. A property already holding the value (`last`) is not written, so Babylon does not recompute its node, and a pose whose clips, frames and weights equal the last pose's returns at once. A property no layer plays returns to rest once; a fresh rig rests everything its first pose leaves out.
  - Anything else that moves posed nodes calls `invalidatePoseRig(clips)` so the next pose writes everything (the ragdoll does on retire).
  - Layers sharing a clip (and the same `masks`) play it once at the current state's time with summed weight. A lone layer below weight 1 blends toward rest (Rest Pose fades).
  - Layered Blend Per Bone (`PoseLayering`, from `animState.layerBlends` and each layer's `masks`): a property's weight under each branch filter comes from its target's chain of names (`nodeChainNames`, then `animBranchWeight`), worked out once per rig and filter key (`rig.branchWeights`); morph targets have no chain and stay with the Base Pose. Per pose, each blend sums `Σ wᵢ · branchᵢ(p)` per property (`sumBlends`); a layer under input i takes `branchᵢ(p)` (÷ the sum above 1), under the Base Pose `1 − min(1, sum)`, multiplied over nested blends (`layerFactors`). Properties then blend as before, so a branch bone the input's clip lacks fills from rest. Mesh-space rotation blending is not supported: bones blend in their parent's space.
  - Transform Bone (`applyBoneModifiers`, after the blend writes): the bone is the rig's animated target of that name, else a same-named descendant of the topmost ancestor (`boneNodeOf`, cached by name). A bone's first change in a pose starts from its blended values where clips animate the channel, else from its rest (read when first changed); later changes in the pose build on it. Channels apply scale, rotation, translation (`modifiedLocalTrs`): parent space on the local values; bone space before the local transform (translation along the bone's scaled axes); actor space through the parents' local matrices below the topmost ancestor (the actor root), keeping a mirrored axis's sign on Replace. The result blends with the pose by alpha × the inputs' per-bone weights (`nodeMaskFactor`) and writes only the changed channels; animated channels it changed are marked unwritten so the next pose writes them, and a bone no change touches any more has its unanimated changed channels restored to rest. The layering's JSON joins the unchanged-pose check (`rig.lastLayering`).
  - Writes land when the `animState` command applies, before the frame renders, so bone attachments, ragdoll capture, pose bounds and the skeleton preview read the posed nodes.
- Each Model is loaded once per Scene; actors instance under a `__importScale` child of an empty named root (`editorActor:<id>` / `actor-N`) so import scale never overwrites snapshot TRS.
- Material slots map by the glTF material index each primitive names (`modelMaterialIndexOf`), not child visit order; the file's own materials are never loaded. `MeshComponent.materialGuid` overrides the whole visual.
- `resolveAnimGraphClips` keeps Animation guids (never rewrites Animation → Model). Retargeted Animations load the source Model GLB and retarget at rest pose.
- A Model plays every Animation on its Skeleton: `retargetAnimationLoadsFromAnimations(animations, modelSkeletons)` ([`animation-payload.ts`](../../../packages/assets/src/animation-payload.ts)) lists, per Model, Animations retargeted onto it and every other Model's Animation on its Skeleton (`bindByName`); `beginSlotModelAnimLoad` binds the latter with `bindAnimationGroupByName` ([`node-rig.ts`](../../../packages/render/src/node-rig.ts)): same-named nodes and morph targets, the clip's keys shared unchanged. Play (`modelGuidsForPlayRetarget`) loads those source Models.
- `anim.skeletonMismatch` is an error when an Animation's skeleton differs from the owning Model's.

## Editor rules

- DockView document kinds `anim-graph-3d` and `anim-graph-2d`, with one DockView surface and the same windows (Focus keep key `anim-graph`): **Graph** (the State Machine and an open transition rule), **Animation Object** (the script, a `GraphPanel`, tabbed beside Graph by default), Variables, Inspector and Compiler Results, plus one `anim-state-graph` tab per open state graph (`AnimStateGraphPanel`, id `anim-state-graph:<stateId>`, `openAnimStateGraphPanel` in `shell/function-graph-panels.ts`). State tabs are document content like Class function tabs (`isGraphContentPanelId`): carried in the DockView snapshot, not catalog placements, shown with a state icon, joined to the phone Window picker and to the desktop layout beside the Graph; a deleted state closes its tab and a rename retitles it. The editing context's `canvas` (`stateMachine`, `animationObject` or `state:<id>`) is the canvas last brought forward or pressed in (`useAnimCanvas`); the Inspector follows it, and changing it clears the shared node selection. Each canvas brings its own panel forward for a focused diagnostic. The Graph's validation rows use graph ids under `${documentId}:`, each state tab's `${documentId}:pose-state:<id>` (cleared when the tab closes) and the Animation Object's the document id, so none replaces another's.
- Rule palettes (`animationGraphHost: "rule"`) allow `anim.state.*`, pure nodes and Get Variable only; pose palettes (`"pose"`, with the `animPose` dimension and the graph's `cachedPoses`; state graphs only) allow the dimension's pose or frame nodes except its output and the bare Use Cached Pose, `anim.control.*` in 3D, `anim.state.*`, pure nodes and Get Variable, plus one injected `Use Cached Pose <Name>` row per saved name (`cachedPoseUsePaletteNodes`); Object palettes (`"object"`) add `anim.event.*`; Actor palettes hide all and show `anim.actor.*`. Protected nodes: initialize/update events, Enter/Exit sinks and pose graph outputs.
- The Graph always shows the State Machine; double-clicking a state, or Inspector **Open State Graph**, opens or focuses its tab beside the Graph. Double-clicking a wire opens its transition's rule in the Graph (`transitionAtWire`: on a mirrored pair's shared wire, the direction whose target state is nearer the point); Inspector Open Rule does the same, and **Back To State Machine** closes it. Picking a state in Variables brings the Graph forward and selects it. On the State Machine canvas the Details panel edits state and transition rows, or the graph's own rows (3D Skeleton) with nothing selected; in a state tab or rule it is the node Inspector.
- One directed `(from, to)` pair is one transition; extra rows warn `anim.duplicateTransition`. A reverse pair shares one edge (`animTransitionBoth`) only when mirrored (`findMirroredReverse`: B's side out is A→B's side in and back); otherwise each is its own edge. Re-drawing a pair moves its transition (id, rule, settings kept) to the new sides; the hidden half of a mirrored pair stays with its old sides when the shared wire moves.
- Dragging (`connectDraggedToNode` → `animTransitionFromDrag`): the dragged state is always the source, leaving by the dragged side (either plate); the target side is the released handle's, else the side nearest the release point, else (near the middle) the side facing the source. Transitions stored without sides load on the sides their states face (`facingTransitionSides`). The canvas uses `connectEndMode="zone-add-node"`: a far release opens Add Node, a release near a compatible pin snap-connects, and any other release breaks; `GraphEditor.edgeBreaksAtPin` = `animTransitionOnSide` makes a break remove every transition on the dragged state's dragged side, in or out, whichever plate was dragged.
- A selected state and a selected transition exclude each other; Open Rule selects the rule's transition. The State Machine passes the selected transition to `GraphEditor.selectedEdgeId` as its drawn edge (a reverse row maps to its pair's edge), so the wire stays highlighted when a rule closes.
- State names must be non-empty and unique (trimmed, case-insensitive). Diagnostics publish only for the active mode.
- Renaming or retyping a variable rewrites bound Get/Set nodes in `animationObject`, every rule graph and every pose graph.
- Pose and frame pins (`{kind:"pose"}`, `{kind:"frame"}`) connect only to their own kind (`isStructuralPinKind`) and draw heavy wires; pose nodes use the `anim-pose` (mustard) and control nodes the `anim-control` (amber) roles.
- State graph node Inspector (`animPoseNodePropertyRows`, with `AnimClipPickGraph` carrying the graph's `cachedPoses` and the node Inspector resolving its Skeleton's bones): Layered Blend's **Blend Poses** count and its **Blend Pose N Branches** lists (`LayeredBlendBranchFilters`, [`layered-blend-branch-filters.tsx`](../../../apps/editor/src/components/layered-blend-branch-filters.tsx): bone names verbatim, Blend Depth, **Add Branch** from the Skeleton's bones through a SearchDialog); Save Cached Pose's **Name**; Use Cached Pose's **Cached Pose** (saved names, a missing one kept); Transform Bone's **Bone** (the Skeleton's bones, verbatim; typed without a Skeleton) and each channel's **Mode**, with its **Space** only while the mode is not Ignore.
- Preview: `AnimGraphPreviewProvider` (one `AnimGraphPreviewSession` per open graph, mounted inside the editing provider) runs `evaluateAnimGraph` on the editor main thread. It loads the graph's compiled `AnimRule:` / `AnimPose:` modules (`collectPlayPreviewScripts`, debounced) into a private `ScriptHost`, with Preview Values as the variable store; a rule not yet loaded is closed, never passing. Values persist per variable name while its type fits and reset to the default otherwise; they never write the document. Time advances only while the Preview window is visible and playing: real time × Speed, capped at 0.1 s a frame; Step is one 1/60 s tick and pauses. While the Preview window is shown its `runTrace` lights the State Machine canvas (a Simulation trace wins), with the debugger's graph id and node/edge ids. Windows default above the Inspector (Preview) and below Variables (Preview Values).
- Animation editor windows Preview, Timeline (`animation-timeline`, `AnimationTimelinePanel`, [`animation-timeline.tsx`](../../../apps/editor/src/components/animation-timeline.tsx)) and Inspector share `AnimationEditingProvider` (the Preview's `AnimationPreviewClock` and the selected event ids). The Timeline is a `KeyframeTimeline`: single events on the `events` row (diamonds), each window on `window:<id>` with `<id>:begin` / `<id>:end` keys (`moveAnimationEvents`: both ends shift the window, the begin alone keeps the end, the end alone sets Duration; a drag is one undo step per gesture key); scrubbing seeks the clock; Add Event / Add Window place at the playhead; selected keys open their cards in the Inspector's `AnimationEventsEditor`.
- Event flashes ([`anim-event-flashes.tsx`](../../../apps/editor/src/components/anim-event-flashes.tsx)): the Animation Preview flashes events its clock passes while playing (a wrap within one frame step counts, Restart and seeks do not); the Animation Graph and Blend Space Previews flash `AnimEvalState.events` of each evaluation (`useFiredEventFlashes`). Event actions never play in the editor.
- Animation asset Preview (`AnimationPreview`, [`animation-editor.tsx`](../../../apps/editor/src/components/animation-editor.tsx)): an `AnimationPreviewClock` ([`animation-preview-clock.ts`](../../../apps/editor/src/lib/animation-preview-clock.ts)) holds the playhead in authored time (Duration, else the clip's file length); the canvas binds the clip (`bindPoseClip`) and poses it (`applyPoseClip`) at the clock's normalised time each frame. Time advances only while the window is shown and playing (real time × Speed, capped at 0.1 s a frame); Step is one file frame of the Duration; scrubbing pauses.
- Blend Space editor: DockView kinds `blend-space` and `sprite-blend-space` share the windows; `useBlendSpaceDocument` reports the dimension, and the panels list Animations on the Skeleton or every Sprite Animation, show the Skeleton row or Hysteresis and Keep Time, draw triangles and blended weights or the nearest sample, and preview a Model or frames (`AnimSpriteFrameView`). Kind `blend-space` (Grid primary, Animations left, Inspector right, Preview above it), `BlendSpaceEditingProvider` holding the selected sample and the preview point (default: each axis's minimum). Samples snap to grid lines on add, drag and Inspector edit; a drag is one undo step (`blend-space:sample:<i>:<t>`). The Preview runs a `BlendSpacePreviewSession`: a one-state graph whose Blend Space Player gets the payload resolved from the registry (`blendSpaceNodeDataOf`) and the preview point as X and Y, through `evaluateAnimGraph`, so weights, time sync and smoothing match a game.
- Preview 3D: Models on the graph's Skeleton (none: the Models its Animations come from), on its own `createModelPreviewScene` on the shared Engine with a floor grid; clips load per source like Play (own groups, `bindAnimationGroupByName` for same-Skeleton Models, `retargetAnimationGroupWithMeshProxy` for retargeted Animations), bound with `bindGameplayAnimationGroup` and posed by `applyAnimStateToScene`. Bones swaps in `attachSkeletonPreview`. Preview 2D draws the heaviest sprite layer's frame with its flips.
- `AnimPinGlyph` (`packages/graph-ui/src/graph-nodes.tsx`) draws them boxless: Phosphor `UserFocus` for pose at 1.6× the pin size (its glyph is padded) and Bootstrap Icons `image` for frame at 1.4×, each icon's outline glyph unwired and its fill glyph wired, imported from its own module ([no-ai-artwork.md](../../rules/no-ai-artwork.md)).
