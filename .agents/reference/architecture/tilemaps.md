# Tilemaps

Tileset and Tilemap assets, chunked geometry, merged chain collision, animated tiles, autotile terrains and the paint editor.

## Decisions

- Not Babylon `SpriteMap`: that format cannot golden-test geometry or emit collision chains.
- Geometry and collision builders in `@haptic/assets` are pure and Babylon-free; callers pass world tile size (`px / pixelsPerUnit`) so assets never read project settings.
- Atlas materials stay unlit, double-sided and alpha-tested (same path as sprites) in both 2D and 3D; they disable fog and image processing. Switching to blend needs an on-device fill-rate measurement.
- Autotile terrains resolve into ordinary GIDs: render, physics, nav bake and the runtime never see terrain data, and a stored map stays valid whatever its Tilesets do.
- Maps also store, per Tileset ref, the stamp of the terrain data their cells were resolved against; every load re-resolves the cells of a Tileset whose stamp moved (`refreshStaleTilemapTerrains`). Reason: Tileset edits reach every map without rewriting closed files, and every consumer derives the same cells from (stored map, current Tilesets).
- The author picks the autotile style per terrain (`sides` or `blob`) rather than per Tileset, so one sheet can mix a 4-side strip set and a blob ground set.
- One terrain and one set per tile: a neighbour's terrain is unambiguous, so re-resolving never has to guess.
- Transitions are per pair of terrains of one Tileset (border sets), not a separate terrain: a seam belongs to whichever side draws it, and terrains of other Tilesets never meet.
- Unbounded maps place tiles around a pivot, not around cell (0, 0): the user paints outward from the actor's origin in every direction, and cell coordinates never change when the pivot moves (so moving it rewrites no chunk). The pivot snaps to half cells so cell corners, edge middles and centres are all reachable.
- The render applies the pivot through a node above the chunk meshes, not in their vertices: layer parallax owns `chunk.position`, and chunk geometry stays in map space (goldens, live chunk patching).
- Bucket on an unbounded map stops at the layer's painted extent (with the start cell) grown by `TILEMAP_BUCKET_MARGIN` (16): an empty region has no map edge to stop it, and painted area plus margin keeps a fill near the tiles.

## Formats

- Tileset (`.tileset.hasset`, kind `tileset`): `textureGuid`, `atlasWidth/Height` (source pixels, needed before the texture loads), `tileWidth/Height`, `margin`, `spacing`, per-id `tiles` metadata (`collision` none / full / chain points, `flags`, `animation`, `animationFrameDurationMs`, optional `terrain`), optional `terrains`.
- Terrains: `terrains: [{ id, name, style: "sides" | "blob", borders?: string[] }]` (unknown style → `sides`); a member tile has `terrain: { id, mask, border?: string }`. `borders` lists other terrains of the Tileset this terrain has a transition (border) set for; a tile with `border: U` is in its terrain's set drawn against U (open sides show U), one without is in the default set (open sides show nothing). Keys are omitted when empty. Normalize drops border ids that name no other terrain of the Tileset and duplicates, drops a membership whose terrain the Tileset does not define or whose `border` its terrain does not declare (whole, never into the default set), and clamps `mask` to 8 bits. `setTilesetTerrains` keeps the same rules on edit, so removing a terrain also drops it from other terrains' `borders` with their tiles drawn against it. `mask` stores raw bits so switching style keeps corner bits; the style's canonical form is applied when resolving.
- Terrain stamp (`tilesetTerrainStamp`): FNV-1a hex of each terrain's id, style and sorted borders and each in-atlas tile's membership (id, terrain, mask, border), sorted by id; names, order and other tile data do not count, a payload stamps the same with or without `ensureTilesetTiles`, and a Tileset without terrains stamps `"0"`. Cached per payload object.
- Mask bits, clockwise from north in +Y-up tile space: N 1, NE 2, E 4, SE 8, S 16, SW 32, W 64, NW 128 (`TERRAIN_*`). Canonical `sides` keeps N/E/S/W (16 variants); canonical `blob` keeps a corner only when both adjacent sides are set (47 variants).
- Tile id 0 is empty; id 1 is the first atlas cell, row 0 at the image top.
- Tilemap (`.tilemap.hasset`, kind `tilemap`): Tiled-style `tilesets` `{ guid, firstGid, tileCount, terrainStamp? }`; cells store global GIDs (`firstGid + localId - 1`); `tileWidth/Height`; `chunkSize` (default 32); ordered `layers` with visibility, collision opt-in, sorting, parallax and sparse chunks; then either a size or a pivot (`TilemapPayload = BoundedTilemapPayload | UnboundedTilemapPayload`). `terrainStamp` is the Tileset's stamp when the map's terrain cells were last resolved against it; omitted means stale. `addTilemapTileset` writes the current stamp (no cell uses the Tileset yet).
  - Bounded (default; no `unbounded` key): `width/height` in tiles (default 64×64); cells 0 ≤ x < width, 0 ≤ y < height; no `pivot`.
  - Unbounded: `unbounded: true` and `pivot: { x, y }` in tile units, each snapped to the nearest 0.5 (`snapTilemapPivot`; non-finite → 0, never -0, clamped to `TILEMAP_CELL_LIMIT`), default (0, 0); no `width/height` (normalizing drops them; the type tolerates them on edit intermediates, and nothing reads them). Cells at any integer coordinates with |x|, |y| ≤ `TILEMAP_CELL_LIMIT` (2^20 − 1, the range `tilemapCellKey` keeps distinct), so chunks may have negative `cx`/`cy`. Normalizing a stored `unbounded: false` or a bounded map's `pivot` drops them.
- Pivot maths: `tilemapPivot(map)` is the unbounded pivot or (0, 0). Cell (gx, gy) occupies [(gx − pivot.x)·w, (gx + 1 − pivot.x)·w] × [(gy − pivot.y)·h, (gy + 1 − pivot.y)·h] in the Tilemap's local space (w, h = world tile size). A bounded map is the pivot (0, 0) case.
- Chunk `{ cx, cy, tiles }`, `tiles.length === chunkSize²`, index `ly * chunkSize + lx`, (0,0) bottom-left, +Y up, XY plane. Empty cells and chunks are never allocated. A Chunk Size edit re-cuts every layer (`rechunkTilemap`: each cell keeps its map cell, nothing is clipped, negative cells included, new chunks list bottom row first); normalizing never re-cuts, it only pads or truncates `tiles`, keeps negative chunks, and folds a chunk listed twice in a layer into the first one with its key (later non-empty cells win, as they drew on top); a chunk listed once keeps its object.
- Payloads are never changed in place; edits share untouched layers, chunks and `tiles` arrays with the map they came from. `normalizeTilemapPayload` keeps parts already in normalized form as the same objects (an already normalized payload returns itself) and reads the painted extent only when the map stores no size. Caches and deltas key on these identities. Cells and chunks are keyed by `tilemapCellKey(x, y)` (a number, distinct for coordinates within ±2^20, negative ones included), never by strings or by the map's width.
- `decodeTileGid` picks the highest `firstGid <= gid`; a map without tilesets owns no GIDs. `tileCount` never shrinks; `reconcileTilemapTilesets` relocates growing ranges and remaps cells as part of the next authored edit (so it undoes with it). Closed maps are never rewritten across documents.
- Removing a Tileset erases its painted cells without compacting other GIDs.

## Geometry and render

- One draw per chunk per atlas, tile 0 skipped; quad order BL, BR, TR, TL like sprite `CreatePlane`. Quads occupy exact grid cells; UVs inset half a texel so NEAREST never samples a neighbor. `tilemapChunkDraws` builds a chunk's static and animated draws for every atlas in one pass over its tiles. Every quad faces -Z, so normals are the constant (0, 0, -1), never computed; only animated chunks get an updatable buffer (their UVs).
- An atlas without a texture draws per-tile vertex colours (`tilePlaceholderHsl(gid)`, the same hue as the paint canvas) on one shared unlit, double-sided, fog-free Standard material per Scene (`applyTilemapAlbedoTextures`); chunks never keep Babylon's lit default material.
- Albedo uses a per-sampling-key `ResourceCache` wrapper (`PIXEL_ART_TEXTURE_SAMPLING`). Extra keys use another `createObjectURL` of the same Blob — never `#nomip` / `#ninv` fragments on `blob:` URLs; use explicit loader hints.
- Play builds `actor-N` plus one child per non-empty static chunk per atlas (`:a1`, `:a2` …) and an `:anim` sibling for animated tiles. Editor children are `editorActor:<id>:<layer>:<cx>:<cy>` (negative `cx`/`cy` included); picking maps back to the actor.
- An unbounded map's chunks hang under a `<root>:pivot` TransformNode at (−pivot.x·w, −pivot.y·h, 0) (`createTilemapMeshes`, registered with `setTilemapPivotNode`); bounded maps keep their chunks directly under the root. Anything that needs the chunk meshes reads `tilemapChunkParent(root)` / `tilemapLayerMeshes(root)` (component sorting, `applyActorComponentSorting`, `patchTilemapMeshes`), never `root.getChildMeshes(true)`. Bounds, culling, picking, the selection outline and framing read world bounding boxes, so they follow the painted extent; an empty map draws no chunk, as a bounded one.
- Editor viewports show an open Tilemap document as it is edited: `useLiveTilemapEdits` hands each referenced open document to `EngineHandle.setLiveTilemap` once per frame with its open-document payload revision. `EditorSceneSync` normalizes and refreshes it against the installed Tilesets, installs it in its assets, and for each actor drawing that Tilemap rebuilds only the chunk meshes whose cells changed (`patchTilemapMeshes`: a chunk keeps its meshes when its `tiles` is the same array or an equal one, so a tab opened after the Scene read the file rebuilds nothing; chunk meshes carry `metadata.tilemapChunk`, the component root `metadata.tilemapAssetGuid`). A change to tile or chunk size, the Tilesets' GID ranges, the layer list, a layer's visibility, sorting or parallax, `unbounded` or the pivot rebuilds that actor's visual only. Live content wins over a collected payload of another revision at install, so a collection that ran during an edit never shows the older map, and a save's re-collection of the same revision rebuilds nothing. A tab closed with unsaved edits hands the Tilemap back and re-collects the saved map. Edits that land during a realization apply when it completes. Play, Simulate and Preview Build read the saved or working content as before and never use this path.
- Animated tiles update only their UV buffers. Play, Simulate and Preview Build use the runtime `tilemapAnimationTime` (simulation time: pause holds, step advances, dilation scales). Editor views (`createEngine` without `playMode`) never advance it, so tiles keep their first frame, built at time 0. The binary snapshot format is unchanged.
- Parallax offset = camera × (1 − parallax), applied after camera posing and pixel snap via `updateSceneTilemapParallax` as each chunk's own position, in its parent's (root or pivot node) space without translation, so the pivot offset stays; overlay slots skip it.
- A Tilemap component is one sorting group; layers sort inside it by project sorting layer, `orderInLayer`, then list order. Depth testing stays on.
- Disposal or rebinding disposes the owned albedo material but never the shared cache texture.

## Terrains (autotile)

- A cell's terrain identity is `tilemapTerrainKey` (guid + terrain id); its tile's variant and set never matter to neighbours. For a cell of terrain T of Tileset S, each of the 8 directions is: outside a bounded map → joined (ground drawn to the edge runs on past it; an unbounded map has no outside within `TILEMAP_CELL_LIMIT`, so its empty neighbours are open like any empty cell); terrain T of S → joined; terrain U ≠ T of S → open facing U when T has a border set for U with a tile, else joined when U has one for T (U's pieces draw the seam over T), else open facing nothing; anything else (empty, plain tile, a terrain of another Tileset, a terrain without tiles) → open facing nothing. The mask is the joined bits (`terrainCellWant`, used by `resolveTerrainCell` and reported by `tilemapTerrainCellPieces`).
- Set choice: among the open sides (N, E, S, W), the faced terrain that occurs most often (only terrains T has a non-empty set for are faced); when every side joins, the same over the open corners, for `blob` only (a `sides` cell with every side joined is the fill whatever its corners); a tie or no faced terrain picks the default set.
- Resolution (`createTerrainResolver` → `TerrainResolver { resolve(mask, border?), borders }`, `borders` = sets with at least one tile): candidates are the chosen set's tiles, else the default set's, else every tile of the terrain; among them the tile whose canonical mask equals the wanted canonical mask, otherwise the closest by `terrainMatchScore`, compared in order: (1) fewest wanted sides the tile draws open, (2) fewest open sides the tile draws joined, (3) fewest inner-corner notches the tile draws that the cell does not want, (4) fewest wanted notches the tile fills, (5) lowest tile id. Corner terms count only where the tile joins both adjacent sides. Order reason: an edge drawn inside the terrain is the most visible error, a cut-off edge less so, a notch least. Incomplete sheets therefore paint: missing bottom/side edges fall back to fill, a one-high strip keeps its top tiles. `maxTileId` limits members to the map's Tileset range; tiles past the atlas never count, so editor (`ensureTilesetTiles`) and runtime payloads resolve alike. `missingTerrainVariants(tileset, terrainId, border?)` reports one set.
- `paintTilemapTerrain` refreshes a stale map first (below), writes the brush terrain into the target cells (or 0 when erasing), then re-resolves every target and every terrain tile in their 8-neighbourhood against the new membership. Its terrain lookups are cached per (map Tileset list, loaded Tileset payloads) and its resolvers per Tileset payload object (`cachedTerrainResolver`), so successive strokes share them. A cell's resolution reads only its neighbours' terrains, and membership never changes for neighbours, so one pass is exact, transitions included; incremental brush moves equal one batch write. Reads go through `TilemapChunkIndex` positions (or a per-call chunk map), across chunk borders and missing chunks; writes go through `setTiles`, so unchanged cells keep the same map object and out-of-bounds cells are never written. A stroke that changes no cell returns the map it was given.
- A stroke with `terrain` set routes every tool through it: Brush/Rect/Stamp paint terrain cells, Bucket fills the connected cells of the start cell's terrain (whatever their variants), or of its exact GID outside a terrain, and is a no-op on the brush's own terrain. The Eraser always erases through `paintTilemapTerrain(null)` when the Tilesets are loaded, terrain brush or not, so neighbouring terrain tiles re-resolve. Single-tile strokes never re-resolve neighbours, so hand-placed variants stay until that Tileset's terrain stamp changes.
- Plain-tile writes that move terrain cells (selection moves, pastes, cuts and deletes) go through `resolveTilemapTerrainAround(map, { layerId, cells, keep, tilesets })`: every written terrain cell and every terrain tile in the 8-neighbourhood of a written cell re-resolves by the rules above, keeping its terrain. `keep` exempts written cells whose 8 neighbours are all non-empty cells of the same placed block inside the map: their neighbourhood moved with them, so the piece they had is the piece they resolve to, and a hand-placed variant inside a moved block survives. No terrain among the loaded Tilesets returns the map at once.
- `refreshStaleTilemapTerrains(map, tilesets)`: for each ref whose loaded Tileset's stamp differs from `terrainStamp` (or has none), re-resolve that Tileset's terrain cells on every layer by the rules above and write the new stamp; other Tilesets' cells, Tilesets missing from `tilesets`, and terrains that no longer exist or have no tiles stay as they are. Returns `map` itself when every stamp matches (work per ref only; stamps are cached per payload); otherwise one pass over the cells, skipped when no stale Tileset has terrains. A resolution reads only its own Tileset, so the per-Tileset scope is exact. `refreshStaleTilemaps` applies it to a guid → map table.
- Applied once where a load meets Tilemap and Tileset payloads, so every view derives the same cells:
  - Tilemap editor working copy: `workingTilemap` = `reconcileTilemapTilesets` then the refresh ([`tilemap-editor.tsx`](../../../apps/editor/src/components/tilemap-editor.tsx)), built once per stored payload object and loaded Tileset payloads (weak caches shared by Details, Palette and Paint); edits build on it, so the next authored edit stores the refreshed cells and stamps, and undoes with them.
  - Editor Scene and Prefab viewports and nav bake: `collectPlayTilemapContent` ([`play-content-service.ts`](../../../apps/editor/src/services/play-content-service.ts)); viewport reloads follow Tileset revisions.
  - Play, Simulate, Preview Build and exported games: `packedContentFromGame` ([`hydrate.ts`](../../../packages/exporter/src/hydrate.ts)), which feeds the render binding and the `loadTilemaps` control.
  - Runtime physics in every host: `RuntimeDriver` construction and `registerTileContent` ([`driver.ts`](../../../packages/runtime/src/driver.ts)); fast path when content arrives already refreshed.
- `tileCount` caps resolution, so a Tileset that grew resolves within its stored range at load until the map's next edit reconciles it; the editor reconciles before refreshing.
- Standard layouts (`AUTOTILE_LAYOUTS`, row-major from the block's top-left): `sides` 4 × 4 is a 3 × 3 island, a vertical strip, a horizontal strip and a single; `blob` 12 × 4 is that island with every inner corner filled in columns 1-4, then the 31 notched variants in ascending mask order, column-major over columns 5-12, one cell `null`.
- Piece sets: authoring works on `AutotilePieceSet` `{ terrainId, border? }` (the default set, or the border set drawn against `border`); a tile belongs to a set when its membership has that terrain and border. Assigning keeps one tile per canonical piece (other tiles of the set with that piece lose membership, a tile of another set or terrain moves over), spreads the tile's existing membership so other fields survive, and writes or drops `border` to match the set. 4 Sides pieces store their corners filled so a switch to Blob reads them as Blob's Main. Nothing re-resolves on Layout change: tiles keep raw masks; `autotileLayoutChange` reports kept, missing and unused (a second tile of one piece) for the confirm.
- Piece groups (`AUTOTILE_PIECE_GROUPS`, pure data, canonical masks): `sides` has one, **Pieces** (the 4 × 4 block); `blob` has **Main** (the block's columns 1-4), **Inner Corners** (2 × 2, notches toward the centre, around a hole) and the optional **More Corners** (the other 27). Each group carries the block its button assigns (row 0 = north; More Corners' is the standard block's columns 5-12, all 31 notched pieces), so a standard 12 × 4 sheet is two block taps. `autotileBlockPlacement` clips a block at the sheet's right and bottom edges; `applyAutotileBlock` assigns every placed non-`null` cell as `assignAutotilePiece` would. `autotileReady`: the default set has a tile (inside the atlas) for every piece of the style's non-optional groups.
- Preview (`autotilePreviewTiles`) paints the window's 12 × 7 map through `paintTilemapTerrain` on an in-memory map of exactly that size, so terrain at the preview's edge joins past it as on a Tilemap, one batch per terrain (equal to any stroke order: each batch re-resolves its neighbours), so transitions resolve as on a Tilemap. Each cell reports its tile from the Tileset as it is, and the piece and set it wants (`tilemapTerrainCellPieces`) read from a copy with a stand-in member tile, in rows added below the atlas, for every terrain without tiles and for the edited set when it is empty: so a new autotile, or a new border set, shows where each piece goes before it has art. A cell stands in when its tile is not that exact piece of that set (or it has none). Starting shapes: `autotilePreviewSample` (per style; a border set is the autotile inside a field of its border terrain).

## Unbounded maps

- Switching (`setTilemapUnbounded`, one edit, undoable): to unbounded keeps every cell and the layers object, drops the size and sets the pivot to (0, 0), the bounded origin, so nothing moves in the world. To bounded: when any tile lies at x < 0 or y < 0 (`boundedTilemapShift`), every layer is re-cut moved by (−minX, −minY) of the painted extent (`translateTilemap`), then the size is the extent from cell (0, 0) (64 × 64 when nothing is painted) and the pivot is dropped.
- **Center Pivot** (`centerTilemapPivot`): the pivot moves to the centre of the painted extent, ((minX + maxX + 1) / 2, (minY + maxY + 1) / 2), always on a half cell.
- `tilemapPaintedExtent` / `tilemapLayerPaintedExtent`: inclusive cell bounds over every non-empty cell, cached per chunk `tiles` array, so after an edit only the replaced chunks are read.
- Every place that branches on `unbounded`: `tileInBounds` (no size clip, so `setTiles`, terrain painting and the hover readout write and read any cell), `tilemapCellBounds` (selection clamp, cut-off count and tint: ±`TILEMAP_CELL_LIMIT`), `normalizeTilemapPayload` (pivot vs size), `resizeTilemap` (no-op), `tilemapBucketBounds` (margin box), terrain `terrainCellWant` (through `tileInBounds`: no outside join), `tilemapPivot` (render node, chains, physics, nav bake, editor Drop), `createTilemapMeshes` (pivot node), `patchTilemapMeshes` (`unbounded` or pivot change rebuilds), the Paint renderer (`chunkPartInMap`, `drawPreview`, `drawGrid` / `drawEndlessGrid`, `drawPivotMarker`) and `TilemapPaint` (centring, marker drag), `TilemapDetails` (rows and the switch confirm). Chunk caches keyed on `chunk.tiles`, `asset.patchTilemap` deltas (`chunkKey` covers negative chunks; `unbounded` and `pivot` are ordinary top-level fields) and live chunk patching need no branch.

## Collision

- `tilemapLayerChains` merges `full` tiles across all chunks of a layer in integer grid space before scaling: a solid rectangle is one four-point loop with no seams at chunk borders. Custom chain tiles emit open polylines.
- `PhysicsWorldSync` gives every `TilemapComponent` actor a static body and attaches chains only for layers with `collision: true`. Rapier closed loops use an indexed closing segment; repeating the first point makes raycasts miss.
- Chains are in the Tilemap's local space with its pivot at the origin: `tilemapLayerChains({ pivot })` subtracts it after integer-grid merging (`(point − pivot) × tile size`), physics (`SpriteTileColliders`) passes `tilemapPivot(map)`, and `tilemapCollisionChains` reads it from the map. A pivot of (0, 0) gives the same floats as before, so bounded maps' chains are unchanged.
- Nav bake and editor Drop use the same chains (`tilemapCollisionChains`). The 2D nav bake (`navBakeTilemapChains`) bakes per Tilemap actor, in world space: map-space chains (built once per Tilemap) through the component's transform chain, the actor's and its parents' (`local × parent`, the core affine helpers), so a map two actors draw bakes twice.

## Editor rules

- Tileset and Tilemap are DockView documents with Windows enabled (Tileset: Preview primary, Autotiles as a tab in the Preview's group, Inspector; Tilemap: Paint primary, Palette, Inspector). Default tool is Move; two-finger pinch/pan works in every tool and a second finger drops an in-progress stroke without committing.
- One document edit per stroke: the stroke previews locally and commits on release or cancel with merge key `tilemap-stroke:<id>`. Unchanged strokes commit nothing. `setTiles` copies each touched chunk once and returns the same map when nothing changed.
- Strokes (`TilemapStroke`): a move inside the stroke's last cell does nothing; Brush and Eraser queue the cells crossed (each once) and write them in one `applyTilemapPaint` per animation frame (and on release); Rect writes nothing while dragged, the canvas outlines its cells, and it paints (or resolves as terrain) once on release; Bucket and Stamp paint on press. Bucket fills the connected matching cells inside `tilemapBucketBounds`: a bounded map's cells, so an empty layer fills to the map edge; on an unbounded map the box around the layer's painted extent and the start cell grown by 16 (an empty layer: the 33 × 33 box around the start).
- Undo and the journal record Tilemap edits as deltas (`asset.patchTilemap`): `diffTilemapDocument` finds changed chunks by identity (value-comparing only chunks whose `tiles` is a new array) and stores, per changed chunk, its `tiles` before and after (`null` = absent), plus changed top-level fields, the layer settings list when it changed, and per layer the chunk order when its keys or order changed. Applying shares every untouched layer, chunk and array (no clone); inverting swaps sides; a gesture's deltas compose to the first `from` and latest `to`. Its `byteSize` (history budget) and journal record are the delta's. A document that is not a Tilemap of unique layer ids and chunk keys falls back to `asset.setDocument`; an equal document commits nothing.
- Paint (`TilemapPaintRenderer`): each visible chunk of each visible layer is drawn tile by tile into an offscreen bitmap (pixels per cell: the largest Tileset tile side, at most 32 and at most 1024 / chunk size), keyed on its `tiles` array, its in-map columns and rows and the GID table (GID to atlas source rect or placeholder colour, built lazily per Tileset list, loaded payloads and atlas images). A frame composites one bitmap per visible chunk, so pan and zoom redraw no tile and an edit redraws only its chunks. When the Tilesets' tiles are larger than the bitmaps' cells and a cell on screen needs more device pixels than its bitmap holds, the frame instead draws each cell in view straight from its atlas cell (nearest-neighbour, as large as it shows), so Paint is never coarser than the atlas at any zoom; few cells are in view at such zooms. Chunks out of view are not drawn; over a 192 MB budget, bitmaps the latest frame did not draw are dropped, least recently drawn first. Animated tiles show their own (first) cell. The toolbar reads out the hovered cell (mouse, and the finger while it paints) from a store outside React state, and shows **Layer Hidden** when the paint layer is hidden.
- Paint on an unbounded map: chunk bitmaps hold whole chunks, negative ones included (`chunkPartInMap`), the grid is endless (every line in view, no border or clip), the Rect outline is not clipped, and the hovered-cell readout shows any cell. The pivot marker (crosshair and square, `PIVOT_MARKER_STROKE` over a dark halo) draws last, above tiles, grid and outline. The view opens with the pivot at its centre and stays centred through resizes and a switch to Unbounded until the user pans, zooms or presses the marker (`followPivotRef`). A press on the marker (its 12 px arms with a mouse, a 44 px square for touch and pen) takes the pointer in every tool but Select (whose gestures win there): once it moves past 4 px it drags the pivot to the half cell under it (`paintCanvasPivotAt`), shown from local state, and commits once on release with merge key `tilemap:pivot-drag:<id>`; a press that lifts in place runs the tool's press on that cell; a second finger drops the drag. A hovering mouse over the marker gets the `move` cursor.
- Paint **Select** tool (`useTilemapSelectTool`): see [Selections](#selections).
- Inspector **Map** (Details): **Unbounded** (boolean) first; a bounded map shows **Map Width** / **Map Height**, an unbounded one **Pivot** (X/Y vector, merge key `tilemap:pivot`, snapped by `setTilemapPivot`) with **Center Pivot** as its label accessory (disabled with nothing painted) and **Painted Area** (`info`, columns × rows of `tilemapPaintedExtent`, `None` when empty). Switching on is one edit; switching off is one edit, after an AlertDialog when `boundedTilemapShift` reports a move or the pivot is not (0, 0) (a bounded map puts cell (0, 0) at the actor, so the tiles keep their cells but move around it); with neither, nothing moves and it asks nothing.
- Palette: autotiles and coverage are memoized on the Tileset payloads; each Tileset group mounts only the tile rows in view of its scroll container (`windowedSlice` rows; every row while nothing is measured, as in jsdom), and every tile is a CSS sprite (percent background size and position) of the one decoded atlas image. `TilemapEditingProvider` holds two contexts: the session (Tileset payload and atlas loaders, the paint layer shared by Paint and the Inspector, selection setters) and the selection (tile, terrain), so a Palette pick does not re-render the Inspector. `TilesetAtlasLoader` reads and decodes each Texture once for the document's Palette and Paint, keyed on the Texture's registry entry object.
- Tile Width/Height use local drafts committed by **Confirm Tile Size** to avoid rebuilding the atlas per keystroke.
- The UI calls terrains **Autotiles** and a border set **Next To** its border terrain; code, data and tests keep `terrain` / `border`. All authoring lives in the **Autotiles** window ([`tileset-autotiles-window.tsx`](../../../apps/editor/src/components/tileset-autotiles-window.tsx)), which works alone (phones show one window) because it has its own `AtlasTileGrid` of the sheet. The Inspector shows only the count and **Edit Autotiles** (opens the window if closed, then activates it); the Preview has only Move and Select, so Paint Collision is the only thing a Preview tap edits.
- Window: three columns (list, pieces with the preview, sheet) by container width, stacking when narrow. List rows are the autotiles (fill-tile swatch, name, `autotileReady` dot) with their border sets as indented **Next To** rows; selecting a row is the only way to change the edited set `{ terrainId, border }`. **+** adds a Blob autotile named `Autotile` (next free number) and starts an inline rename; a rename to a taken name takes the next free number. Row ⋯: **Rename**, **Add Next To** (other autotiles without a set yet), **Delete**; a set row's × removes it. Terrain list edits go through `setTilesetTerrains`, so deleting an autotile also drops other autotiles' sets next to it with their tiles, and removing a set drops its tiles; both are undoable and confirmed only when tiles would leave. **Layout** (default set only) is a segmented 4 Sides / Blob; with tiles assigned it confirms with `autotileLayoutChange`.
- Pieces: the groups of the style (More Corners collapsed by default, its open state kept per window). One piece is selected (default: first empty visible piece); the line above the groups names it (`autotilePieceName`, [`autotile-piece-name.ts`](../../../apps/editor/src/lib/autotile-piece-name.ts)), its tile or `resolve(mask, border)` stand-in, and how many preview cells want it. A sheet tap assigns the tile to it and selects the next empty visible piece; a mouse drag from the sheet (`AtlasTileGrid` `tileDrag`) drops a tile on any slot. A group's block button arms block mode: the outline follows the hovering mouse (`onTileHover`, drawn as the grid's `overlay`), the next tap applies the block at that tile in one edit; Escape or the button disarms it. Clear: the slot's corner ×, the line's **Clear**, Delete/Backspace.
- First-tap rule: nothing in the window shows, hides or moves on hover for touch input. Hover reveals (a slot's corner ×, a row's ⋯ or ×, the preview's board outline) follow `pointerType === "mouse"` events only, and the selected slot or row always shows them, so every control acts on its first tap (iOS turns a tap that reveals content on hover into a hover).
- Preview: per set, window state over `autotilePreviewSample`, never saved; a tap toggles a cell between empty and the autotile (a border set: the autotile and its border terrain), **Reset** restores the sample. Cells wanting the selected piece of the edited set get the selection tint; stand-in cells of the edited autotile get a `--warning` dot and count in the status. Long-press or right-click a cell: **Select Piece** selects its terrain, set and piece.
- Every window edit is one undo step with merge key `tileset:autotile:<id>:<op>…` (`piece:<set>:<mask>:<tile>`, `clear:<set>:<mask>`, `block:<set>:<group>:<anchor>`, `create`, `name`, `layout:<style>`, `border-add:<other>`, `border-remove:<other>`, `delete`; `<set>` is the border id or `default`); edits that change nothing commit nothing. `TilesetEditingProvider` shares `selectedAutotileId`, the tile selection, Paint Collision and the Preview tool.
- The Palette lists every autotile of the map's Tilesets first (fill tile from `terrainFillMask`, coverage "n of total" of the default set); one with no tiles is a **Set Up in Tileset** button (`useAssetOpen`). `TilemapEditingProvider.selectedTerrain` is the terrain brush and selecting a tile clears it; selecting a terrain while Move or Picker is active switches TilemapPaint to Brush, and the Picker on a terrain cell selects that terrain. Strokes capture the brush and the loaded Tileset payloads at pointer-down and keep the one-edit-per-stroke commit.
- Panels share one Tileset payload map from `TilemapEditingProvider`, cached per source object; painting never reads Tilesets from storage.
- Tileset sheets (`AtlasTileGrid`): one canvas draws the grid, selection, collision and host marks for the cells in view; hit-testing and rectangle selection work from columns and rows; one roving focus cell carries keyboard access. The Autotiles window marks its sheet with `cellMarks` (`dot` for the edited set's tiles, `dim` for other sets').
- The Create Project 2D card stays minimal (2D viewport and physics, no default cube, pixel-perfect on); do not turn it into a demo scene.

## Selections

- Model: a selection is a cell rect (`TilemapCellRect`, clamped to `tilemapCellBounds`) plus a scope, the paint layer or every layer (**All Layers**, `layerId: null`, hidden layers included). It is Paint session state, never document data, and shows only in the Select tool. **Select All** is `tilemapSelectionExtent` of the scope.
- A block of copied cells is a `TilemapClip`: per layer, chunks in the block's own cells (cell (0, 0) its bottom-left), plus the Tileset refs its GIDs were copied under and whether it holds every layer. `copyTilemapCells` reads only the chunks the rect touches and shares whole chunks when the rect lies on the chunk grid, so its cost follows painted cells, not area. Empty cells are part of the block and never written: moved and pasted tiles overwrite the destination, holes in the block erase nothing.
- Edits, each one document change with `tilemapSelectionMergeKey(op, id)` (`tilemap-select:<op>:<id>`): `move` (one drag), `nudge` (one key-repeat burst: a new id per non-repeat key press, and the editor's gesture boundary ends on a fresh press), `paste`, `cut`, `delete`. `moveTilemapCells` vacates the source then writes the block in one `setTiles` per layer, so overlapping moves keep the moved tiles. Tiles landing outside `tilemapCellBounds` are dropped (a bounded map's size, an unbounded map's cell limit); `tilemapClipLostTiles` counts them per position, whole chunks at once. With the loaded Tilesets every edit refreshes a stale map first and re-resolves terrain around the written cells (`resolveTilemapTerrainAround`, with `keep` for cells surrounded by their own block).
- Floating preview: a drag of the selection (`lift`) copies the block once at its first cell change and shows it through `TilemapPaintFloat`: the map's own chunks of the lifted layers at an offset (`detached: false`, so the frame composites the chunk bitmaps the map already has and redraws no tile), the source rect clipped out of those layers (`evenodd` hole) and each layer's floating part drawn in that layer's place in the sort order. Nothing is written until release. A waiting paste floats its retargeted clip's chunks (`detached: true`: bitmaps under their own `\u0000float:` keys, dropped once a frame no longer shows them). Cells of the floating block past `tilemapCellBounds` are dimmed and tinted with the dark `--destructive`, and the toolbar shows **N Tiles Will Be Cut Off**. The outline is dashed `--selection` orange over a dark halo, drawn after the grid and before the pivot marker.
- Gestures (one pointer): a press inside the selection drags it once the pointer leaves its cell; elsewhere it draws a new rect; a tap outside clears the selection, and with none selects its cell. While a paste waits, a drag anywhere moves it and a tap places it. A second finger, or a hold that opens the menu, drops the gesture (the rect, lift or paste position return to where they were) without an edit; a platform `pointercancel` lands it, as strokes do. A right mouse press never starts a gesture.
- Menu (`useContextMenu` + `ContextMenuOverlay`, Select tool only): a hold or right-click outside the selection selects that cell first; items **Cut**, **Copy**, **Paste** (at the press), **Delete**, **Select All**, **Deselect**, or **Place** / **Cancel Paste** while a paste waits.
- Keys: `edit.cut`, `edit.copy`, `edit.delete` (Select tool with a selection or a paste), `edit.paste` and `edit.selectAll` (any tool; they switch to Select) register with `focusWithinRef` on the Paint panel; the canvas is focusable and takes focus on press. The canvas handles arrows (nudge, Shift ×8, repeats allowed), Escape (drop the gesture, else the paste, else the selection) and Enter (place) itself, so key repeat works without a `repeat` command.
- Paste: `tilemapClipboard` holds one clip for the editor session, shared by every Tilemap document, never the system clipboard. `retargetTilemapClip` re-numbers GIDs by Tileset guid for the target map (tiles of Tilesets it lacks are dropped), re-cuts chunks to its chunk size and maps layers (every-layer clips by id, one-layer clips to the paint layer). A paste lands centred on the menu press, the hovering mouse or the view's centre and waits; leaving the Select tool, Select All, Deselect and another Paste place it first; Delete and Escape drop it, Cut drops it into the clipboard.
