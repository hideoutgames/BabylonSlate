# VFS And App Settings

Storage port, platform adapters, app-owned libraries, Engine Settings storage, secrets, native HTTP and the native file transfer.

## Ownership and boundaries

- Port: `ProjectStorage` in [`packages/core/src/storage-port.ts`](../../../packages/core/src/storage-port.ts). Adapters and factories: [`packages/vfs/src/`](../../../packages/vfs/src/) (`createStorage`, `createMountedProjectStorage`, `createReadOnlyProjectStorage`, `createTemplateStorage`, `createDerivedStorage`, `createAppSettingsStore`, `createSaveGameStorage`).
- **The UI never imports Capacitor or Electron.** All project I/O goes through `createStorage()`; secrets, CORS-bypass HTTP and the native file transfer stay in `vfs` so they never leak into `@haptic/source-control` or the editor.
- Desktop main process and preload: [`apps/desktop/src/`](../../../apps/desktop/src/). Native plugins: `apps/editor/ios/App/App/`, `apps/editor/android/app/src/main/java/`.

## ProjectStorage contract

- Methods: `pickProjectFolder` / `openDocumentsProject` / `openKnownFolder` / `listProjects` / `getCurrentFolder` / `releaseFolder`; `readText` / `writeText` / `readBinary` / `writeBinary` / `readBinaryRange`; `exists` / `readdir` / `mkdir` / `remove` / `stat`; optional `deleteProject`, `withReadScope`, `getReadMetrics`, `hasStrongSourceRevisions`, `listStagedWrites` (the staged `.haptic-<uuid>.tmp` files `readdir` leaves out, with stats: Node, Electron over `project:listStagedWrites`, Documents, Memory; OPFS has none to offer, its staged files come only from the WebKit fallback and are removed on failure).
- `""` and `"."` name the project root; `..` segments are rejected on every adapter.
- `deleteProject` permanently deletes a project in app storage: OPFS, mobile Documents (refusing the library and derived-data folders that share its root, `isAppOwnedFolder`), and Node/Electron, which accepts only a folder directly in the Projects Folder, never a picked one. Chosen (`external`) folders are refused, so Homepage removal only drops their recent (`removeDeletesProject`). Desktop main also refuses a project another window has open, since it has no cross-window lock.
- **Errors:** a missing path rejects with `StorageNotFoundError` (`code: "not-found"`); test with `isStorageNotFound(error)`, never by message. `exists()` returns `false` only for not-found; permission, I/O, quota, stale-handle and path-escape failures reject. `remove()` of a missing path rejects.
- **Bounded reads:** `readBinaryRange(path, offset, length, expectedRevision?, options?)` returns exact bytes plus size and an opaque revision; short reads and changed revisions reject (`SourceRevisionChangedError`). Never implement a range by slicing a full read. Native bridges cap one transfer at 512 MiB.
- Revisions detect change; they are not transactions. `hasStrongSourceRevisions` is true only for owned memory generations and immutable HTTP catalogs; disk adapters leave it unset, so asset readers refresh headers and fold the header digest into the logical revision.
- `speculativeRangeReads` is true for the local and native adapters (memory, OPFS, Node, Documents, scoped storage, Electron), where a few KiB more in one range read costs less than a second read; a catalog scan then reads a header in one call ([asset registry](asset-registry.md)). The HTTP catalog leaves it unset (each overlapped part is its own fetch); mounted views report it only when every mount does, and the mobile and read-only wrappers forward it.
- `StorageReadOptions.signal` is forwarded through mounted/read-only views; the last interested owner aborts shared transport. Cancellation does not release reservations before the read settles.
- `createMountedProjectStorage` overlays read-only views (most specific path wins) without copying payloads.

## Adapters

| Adapter | Host | Notes |
| --- | --- | --- |
| OPFS | Web | Projects in `project-v2-<SHA-256 hex of JSON id>`; binding/deletion serialize with Web Locks, and a bound project holds a per-project session lock (one tab per project, below); file operations run in the storage worker (below); writes never recreate a deleted project folder; `readdir` skips `*.crswap` and staged `.haptic-<uuid>.tmp` files; range revisions combine `lastModified`, size and a write counter that tells same-millisecond rewrites apart, drawn from one never-reused sequence so a successful `remove` or `deleteProject` can drop a removed path's counter (a failed one keeps it, so unchanged bytes keep their revision); required for browser writes (no temporary in-memory saves). Libraries/derived data bind with `{ library: true }`. |
| Documents | iPad / Android default | `location: "documents"`: `Directory.Documents` (iOS) or app-private `Directory.Data` (Android) under `Projects/`; no picker. `location: "library"` (derived data only): `Directory.Library` under `Application Support/Haptic` (iOS) or `Haptic` (Android, filesDir) (`libraryRoot`). Android projects and derived data excluded from cloud backup. File bytes use the [binary transport](#binary-storage-transport), whose native commit is one POSIX rename over the file. Without it (no transport, or an iOS web view that answered `BODY_MISSING`, after which the session writes through the plugin), writes stage `.haptic-<uuid>.tmp` through Capacitor Filesystem, whose `rename` is no atomic replace (iOS removes the destination, then moves): the file being replaced first moves to an aside copy `.haptic-aside-<8 hex>-<name>.tmp` beside it (`asideWriteName`, [`staged-write.ts`](../../../packages/vfs/src/staged-write.ts)), the staged file moves into place, then the copy is deleted; a new file has nothing to set aside (a `rename` failure that is not not-found is checked with a `stat`). A failure removes the staged file and moves the old one back. A kill at any step leaves the old or the new complete file, settled from names alone, no marker: every `readdir` (scans, Git status, the Content Browser) and binding the folder (`openDocumentsProject`, `openKnownFolder`, for `project.json`) moves an aside copy whose file is missing back into place and deletes one beside its file; copies of this adapter's writes still running are left to them. The state rule needs no age guard: an aside copy beside its file is stale, and one without it holds the only copy. A file name too long for the aside prefix (over 228 bytes) fails that write and keeps the old file. Fallback cost: two extra native calls per replace (set aside, delete), one per new file. `listStagedWrites` lists the staged files `readdir` hides, for the blob sweep. `readdir` leaves out staged `.haptic-<uuid>.tmp` files and aside copies (both match Publish's `.haptic-*.tmp` ignore entry), as the Node adapter leaves out staged files ([`staged-write.ts`](../../../packages/vfs/src/staged-write.ts)): a write or transfer the system killed can leave one, and the Content Browser and Git status must not see it. |
| Scoped / external | iPad / Android opt-in | Security-scoped bookmarks (`NSFileCoordinator`) / SAF tree URIs; root-confined paths; revoked access → **Reconnect Project Folder**. iOS resolves each bookmark once per session (links in the root resolved then too) and holds its access until `releaseFolder` (native `releaseFolder` stops it): every resolution issues a sandbox extension and iOS caps them per process, so resolving per operation exhausted them and failed later folders until relaunch. Opening a folder validates its root; later reads find a lost root through their failures, and writes check it inside the coordination so they never recreate it. SAF overwrites stage a sibling `.haptic-<uuid>.tmp` then rename (SAF has no atomic replace: the old file is deleted before the rename); listings hide staged names. Bytes use the binary transport; text stays on the plugin's `readFile` / `writeFile`. |
| Node | Electron main, tools | Root-confined through real paths; writes stage `.haptic-<uuid>.tmp`, flush and rename (no truncated files). `readdir` leaves them out. Symbolic links inside the project are followed (one leaving it, or leading back up the listed path, is left out of `readdir`), and `readdir` marks them `DirEntry.link`, the only adapter that does: Remove Unused Files removes nothing while one may alias a blob folder. |
| Electron | Desktop renderer | `ElectronStorageAdapter` over `project:*` IPC; one main-process Node adapter per editor document; project ids are `node:` paths under `userData/projects`. |
| HTTP catalog | Bundled engine plugins | `HttpCatalogStorageAdapter` over content-addressed immutable parts; never downloads archives; works without HTTP Range. |
| Read-only wrapper / Memory | Engine plugins / tests | Writes throw / in-memory tree. |

- **OPFS session lock:** a project (non-library) bind holds the Web Lock `haptic:opfs-session:<project id>` until `releaseFolder`, a bind of another project, or deleting that project. It is separate from the `haptic:opfs:<id>` lifecycle lock, which only covers a bind or delete. A project is therefore open in one tab; the journal and saves have a single writer. Refusal is taken with `ifAvailable` and throws `ProjectOpenElsewhereError` (`isProjectOpenElsewhere`) before any folder, meta or bound-project change, so the previous project stays bound. `deleteProject` needs the lock too (its own session counts); it borrows it for the deletion otherwise. Libraries take none. Locks die with their document, so reload and crash free the project, and the lock is released (and awaited) before the folder is reported released so a same-tab reopen is never refused. A host without `navigator.locks` cannot tell, so it does not refuse. Other adapters are single-window and unaffected.
- **OPFS file operations:** one implementation, [`opfs-file-ops.ts`](../../../packages/vfs/src/opfs-file-ops.ts), addressed by project folder name and path. It runs in the storage worker ([`opfs-storage.worker.ts`](../../../packages/vfs/src/opfs-storage.worker.ts), client [`opfs-worker-client.ts`](../../../packages/vfs/src/opfs-worker-client.ts)) when a window (a realm with `document`) has module workers and OPFS, else in place: code already in a worker never nests another; main-thread OPFS calls are separate tasks that a busy render loop delays. It imports only pure helpers (no `@haptic/core` barrel, no `import()`), so the worker's module graph stays minimal. The adapter keeps what must stay on the main thread: `localStorage` metadata, Web Locks, write counters, read metrics, `getCurrentFolder()` and the folder-name digest. Failures are tagged `OpfsFailure` data; one mapping in [`web-adapter.ts`](../../../packages/vfs/src/web-adapter.ts) rebuilds the port's errors on both paths (a cause from the worker becomes an `Error` with the DOM name and message). Tests inject a root or `OpfsStorageOptions.files`, and stay on the main thread unless they inject a worker.
- **Storage worker:** one per page, shared by every OPFS adapter, started by the first call; requests wait for its `ready`. Write bytes bound for the worker are copied at call time, then transferred (the caller's buffer stays usable); result bytes are transferred. While requests are in flight the client pings every 5 s and the worker answers between awaits (staged writes yield every 16 MiB), so a slow write is never taken for a dead worker; a ping unanswered for 10 s counts as a failure after `ready`. No timer runs while nothing is in flight. Failure before `ready` (blocked or unsupported script, or no `ready` within 10 s): the waiting work and every later call run on the main thread, with one warning. Failure after: in-flight reads run again on the main thread; in-flight mutations reject as interrupted ("the change may or may not have been made") and are never repeated; later calls use the main thread. An interrupted write gets a fresh write counter rather than a rollback: its bytes may have landed, so no revision read before or during it may match them. An interrupted remove or project deletion keeps its counters, and a deletion keeps the project registered and bound; an interrupted bind registers nothing and releases a session it claimed.
- **Range reads:** the adapter passes its current write counter for the path; the operation composes the revision, checks it before and after the Blob slice read, and the adapter checks the counter again afterwards, so a write staged meanwhile is a changed revision on either path.
- **Handle caches:** directory handles by `<folder>/<path>` (LRU, 256) and range-read file handles (LRU, 1,024); they hold no locks. `remove` and project removal purge the subtree. A cached handle failing with `NotFoundError`, `InvalidStateError` or `TypeMismatchError` is evicted and the operation runs once more from the root, so another tab removing and recreating a shared library folder never leaves the cache wrong. Writes and `mkdir` always look the project folder up from the root (never creating it) before using a cached descendant, so a save racing a deletion still fails with warm caches.
- **Listings:** `readdir` reads file metadata 16 at a time and keeps the directory's order.
- **Writes:** `createWritable()` (an atomic swap) wherever file handles have it; each operations instance learns which from the first file handle a write sees (the existing target, else a staged file, so it never creates a target only to find no `createWritable`). Only where they lack it but have `createSyncAccessHandle` and `move` (WebKit workers before `createWritable`): stage the bytes in a sibling `.haptic-<uuid>.tmp` through a SyncAccessHandle opened on that file alone for that one write, flush, close, then `move()` it into place; the target is never created beforehand, and any failure removes the staged file and leaves the target as it was (or absent). Neither: the write fails. Never write the target in place, never keep a SyncAccessHandle across calls and never open one to read: a SyncAccessHandle locks its file, and library adapters are shared across tabs and Electron windows.
- `withReadScope` gives a scan a bounded native directory-lookup cache (Android): ≤ 8,192 listing entries per scope, ≤ 8 scopes per plugin, cleared around every mutation. Not a snapshot.
- Mobile startup restores external folder ids without contacting the provider; recents reopen by stable id and never recreate missing folders.

## App-owned libraries and derived data

- `LIBRARY_FOLDERS` ([`library-folders.ts`](../../../packages/vfs/src/library-folders.ts)) is exactly `__haptic_templates__`, `__haptic_engine_plugins__`, `__haptic_engine_extensions__`; renderer and Electron main share it. Electron binds each to `userData/libraries/<folder>` over `library:*` IPC (file operations only: no picker, open, list or release channels) and refuses any other scope.
- Derived data: `createDerivedStorage` root `__haptic_derived__` (OPFS library bind on web/Electron; on mobile the Documents adapter's `library` location, never beside projects). iOS keeps it in `Library/Application Support/Haptic`: hidden from the Files app (which shows Documents, `UIFileSharingEnabled`), never purged by the system, so recovery journals survive, and excluded from backup (the storage plugin creates the folder and sets `isExcludedFromBackup` at load). Android keeps it in `filesDir/Haptic`, excluded from cloud backup by the backup rules. It is a regenerable cache apart from recovery journals.
- Templates: each directory with `project.json` or `.zip` in the template library is a card; only the chosen template is decoded. No user-chosen templates folder.

## Project creation

- Scaffold only into an empty folder (ignoring `.haptic-creating`, `.DS_Store`, `Thumbs.db`, `desktop.ini`); never overwrite. `.haptic-creating` (`PROJECT_CREATION_MARKER` in `@haptic/core`, which Publish's summary and the Git core's clone also skip) marks an app-owned partial scaffold that a retry may clear.
- Persist the recent-project entry before the editor becomes interactive. Project identity for the browser lives in `project.json` metadata (`name`, optional `appearance`; uploaded images ≤ 96 KiB data URL).

## Binary storage transport

File bytes on iOS and Android never cross Capacitor's JSON bridge as one base64 string. [`native-binary-bridge.ts`](../../../packages/vfs/src/native-binary-bridge.ts) is the single source of the wire format; the plugins mirror its names (`BinaryStorageBridge` in the Swift plugin, `BINARY_*` in the Java one).

- **Config:** `getBinaryBridgeConfig()` → `{ baseUrl, token, writes }`, asked once per plugin and page (`nativeBinaryBridge`). iOS: `haptic-storage://bridge`, `writes: "body"`; Android: `<local URL>/_haptic_storage`, `writes: "chunks"`. No config (web, tests, mocks, a host that did not install the handler) → the adapters use the plugin's own calls; there is no version negotiation.
- **URL:** `<baseUrl>/<token>/file?directory=<Capacitor directory>&path=<full path>` (app storage, as `readDocumentsRange` names it: `DOCUMENTS`/`DATA` under `Projects/`, `LIBRARY` under the library root) or `?folder=<id>&path=<project path>[&readScope=<id>]`; a range adds `&offset=&length=[&revision=]`, a write `&size=`. Values are `encodeURIComponent`-encoded.
- **Answers:** 200 with the bytes; a range carries `X-Haptic-Revision`, `X-Haptic-Total-Bytes`, `X-Haptic-Actual-Bytes`. A failure carries the plugin's error code in `X-Haptic-Error` (404 `NOT_FOUND`, 409 `REVISION_CHANGED`, 403 `STALE`/`ACCESS_REVOKED`, 400 `UNREACHABLE`), the message as the body and `X-Haptic-Actual-Bytes`; the client rethrows it shaped as a plugin rejection, so `SourceRevisionChangedError`, `StorageNotFoundError` and reconnect handling are unchanged. Every answer has `Access-Control-Allow-Origin: *`, `Access-Control-Expose-Headers` for those headers, `Cache-Control: no-store` and `Cross-Origin-Resource-Policy: cross-origin`.
- **No preflight:** the token is a path segment, not a header, so a read is a CORS simple GET; an iOS write is a `POST` with a raw body and no `Content-Type`, also simple (a `PUT` would need an `OPTIONS` round trip per new URL). Handlers still answer `OPTIONS` with 204.
- **Security:** the scheme (iOS) and the intercepted path (Android) exist only inside this app's web view, which loads only the app; the token is 24 random bytes per launch, given only to the page; paths pass the same validation and confinement as the plugin's calls (app-storage prefixes, `..` refused, links resolved and checked against the root, chosen folders only by a resolved bookmark or a persisted SAF grant).
- **Reads:** a range is read whole natively (revision checked before and after), then sent as one body. A whole file streams from an open descriptor (iOS 1 MiB chunks with at most four waiting for WebKit; Android `WebResourceResponse` over the file or SAF stream); writers replace files by rename, so an open descriptor reads consistent bytes. The client takes `response.arrayBuffer()`.
- **iOS:** `BabylonSlateBridgeViewController` (Main.storyboard, SceneDelegate) registers the `WKURLSchemeHandler` in `webViewConfiguration(for:)`, before the web view exists, beside Capacitor's `capacitor://` handler. Work runs on one `OperationQueue` (4 at once, shared with the plugin's file operations); every `WKURLSchemeTask` call happens on the main thread and only while the task is live (calling a stopped task raises). A POST body arrives as `httpBody` or `httpBodyStream`; it must hold exactly `size` bytes, else the answer is `BODY_MISSING` and the client writes through the plugin for the rest of the session. The body is staged beside the file as `.haptic-<uuid>.tmp`, flushed and renamed over it.
- **Android:** `MainActivity` calls `installStorageRequests(bridge)` after the bridge exists, replacing Capacitor's `BridgeWebViewClient` with a subclass and its service-worker client (the editor's COOP/COEP service worker repeats page fetches) with one that answer storage URLs and delegate everything else to Capacitor's local server. WebView exposes no request bodies, so writes are `beginWrite` → `appendWriteChunk`… → `commitWrite(last chunk, size)`: 1 MiB chunks, each base64-encoded on its own in JavaScript and decoded on the plugin's storage threads; staged beside an app-storage file and renamed over it, or staged in `cache/haptic-writes` and copied into a chosen folder by the SAF replace above. Any failure aborts the session and leaves the file as it was; sessions idle for two minutes are aborted; leftovers in `haptic-writes` are removed at load.
- **Threads (Android):** file operations run on a four-thread pool, never Capacitor's single plugin thread; each chosen folder has a read-write lock (reads share it, a mutation holds it alone and clears read-scope listings around itself). Transfers keep their own threads.
- **Memory:** no whole-file base64 string exists on either side. A read holds the web view's response buffer and one `ArrayBuffer` (iOS natively holds at most four 1 MiB chunks; Android streams); an iOS write copies the body once into the app process; an Android write holds the source bytes plus one chunk's strings at a time.
- Text reads stay on Capacitor Filesystem (Documents) and the plugin (`readFile` utf8); Documents text writes use the transport for atomic replacement. Workers never use mobile storage: the plugins and the transport serve the window only.

## Write performance decision

Without the binary transport, the Documents tier crosses the Capacitor bridge once per asset write as base64 data with **no** `encoding` option: Capacitor Filesystem treats any encoding name as text (iOS writes an unknown one, such as `"base64"`, as UTF-8), which leaves base64 text on disk that native range reads then see. Either way: (1) write only dirty documents, (2) externalise large immutable chunks to the blob store (existing hashes are never rewritten), (3) debounce behind the command layer. **No pack format**: one `.hasset` per asset stays the on-disk unit, keeping the registry and Content Browser free of pack indirection. Revisit only with device numbers.

## App settings (Engine Settings)

- Global settings live outside any project; schema and defaults in [`app-settings.ts`](../../../packages/vfs/src/app-settings.ts). Backends: Capacitor Preferences (iOS/Android), `globalThis.haptic.userData` (Electron, `engine-settings.json` replaced atomically), localStorage (web).
- `AppSettingsStore.update` is a queued read-mutate-validate-write transaction across store instances; emit change events only after persistence.
- A refused save keeps settings in memory for the session; an unreadable file keeps `automaticUpdatesEnabled` off (it may hold an opt-out). A failed native Preferences read never overwrites stored settings.
- `compactMode` stays unset until chosen, so it follows the platform default (`resolveCompactMode`: on except on iOS and Android); Account → Application and Engine Settings → Interface edit it.
- `appearance.theme` stays in the schema for stored files, but nothing reads it and Engine Settings does not show it (the editor is dark only).
- Accessibility settings (`touchTargetScale`, `textSizePercent`, `reduceMotion`, `holdTimeMs`, `doubleTapTimeMs`, `numberSnapStrength`, `graphTapToConnect`, `graphPinScale`, `graphPinTypeLetters`) are stepped values: the schema rounds each number to its step and clamps it to its range on load. `graphCutToolMode` (`toggle` | `oneShot`, unknown values read as `toggle`) chooses whether a graph's Cut Links tool stays on; `AppSettingsProvider` passes it as `GraphInteractionSettings.cutToolOneShot`.
- Number settings clamp on load (for example `undoHistoryLength` 1–1000, `traceByteBudget` 1–256 MiB, default 128 MiB).

## Secrets and native HTTP

- `SecretStore { available, get, set, delete }`; Source Control keeps every device credential under `source-control:credentials` ([source-control.md](source-control.md#credentials)). Never in Capacitor Preferences or `project.json`.
- `NativeHttpRequest.disableRedirects` returns a 3xx unfollowed on mobile (CapacitorHttp `disableRedirects`); desktop `lfs:fetch` never follows redirects. Credentialed source-control requests set it.

| Host | SecretStore | `nativeHttp` |
| --- | --- | --- |
| iOS | `BabylonSlateSecrets` Keychain plugin (App target, `packageClassList`) | `CapacitorHttp` |
| Android | `BabylonSlateSecrets` AndroidKeyStore AES-GCM, excluded from backup | `CapacitorHttp` |
| Electron | `secrets:get/set/delete` IPC → versioned file of `safeStorage` ciphertext, atomic owner-only writes; without secure OS encryption, memory until quit (`secrets:persistent` false, `ElectronSecretsBridge.persistent`); read failures reject, never reset | `lfs:fetch` → `net.fetch`, text answers ≤ 16 MiB, byte bodies (`ArrayBuffer`, POST or PUT) and binary answers ≤ 512 MiB, never follows redirects (`disableRedirects` is not sent), no cookies |
| Web | `UnavailableSecretStore` (`available: false`): Source Control hidden | none |

- `nativeHttp`: `{ method (GET, POST, PUT), url, headers, body?, upload?, responseType?, disableRedirects? }` → `{ status, bodyText, bodyBytes?, headers? }`. `body` is text or bytes (Git packs, LFS objects); `responseType: "binary"` answers `bodyBytes`. Bytes cross whole, never streamed: CapacitorHttp as base64 `file` data and `arraybuffer` answers, with the platform quirks in [source-control.md](source-control.md#binary-http). `upload` is one base64 image (PNG, JPEG, GIF or WEBP) sent as a `multipart/form-data` POST instead of `body`; the transport owns the encoding and `Content-Type` (Capacitor `formData` entries, or Electron's main process), see [accounts](accounts.md#account-management). Account tokens on Electron use a separate `accountSecrets` bridge.
- Preload exposes `haptic.userData`, `.project`, `.library`, `.secrets`, `.accountSecrets`, `.saveGames`, `.http`, `.fileTransfer` (`files:transfer`, `files:cancel` and the `files:progress` events, [below](#native-file-transfer)), `.files` (`file:save`, see [Saving exported files](#saving-exported-files)), `.memory` (`memory:stats`: the calling renderer's, the GPU process's, the main process's and every app process's working set, read-only, no arguments).

## Native file transfer

- `NativeFileTransfer` ([`native-file-transfer-port.ts`](../../../packages/vfs/src/native-file-transfer-port.ts)), from `createNativeFileTransfer()` (null on the web): `transfer(folder, { method: GET | PUT, url, headers, path, expected?, signal?, onProgress? })` → `{ status, bytes, sha256 }` streams one file between an HTTPS URL and a project file, so its bytes never enter JavaScript (Git LFS objects, [source-control.md](source-control.md#native-file-transfer)). `folderFileTransfer(transfer, storage)` binds it to whichever folder a storage view has bound at each call.
- **Contract:** headers are sent as given and kept nowhere; no redirect is followed, no cookie or cache used. A download is written to `.haptic-<uuid>.tmp` beside the file (whose folder must exist), hashed as it streams, and renamed over it only when it matches `expected`; a non-2xx status writes nothing (`bytes` 0). An upload is hashed in one pass first and sent with its length known, only when it matches (no request goes for a wrong file). The file is read again to send it; that admits only the bytes hashed, since every writer replaces a `.blobs/<oid>` file only when its size is wrong and only with the bytes its name names (the blob store, Revert, a download). Failures callers act on are `FileTransferError` codes: `transfer-mismatch` (nothing committed or sent), `transfer-cancelled` (the signal aborted; the host cancelled its request and removed the staged file; only a killed app leaves one, which listings never show; `listStagedWrites` lists them for the Git core's open and Remove Unused Files, and for Clean Unused Project Storage, which reclaim them once old), `transfer-refused` (a folder or path the host does not transfer into); anything else is a plain error. Progress at most every `FILE_TRANSFER_PROGRESS_MS` (100 ms).
- **Hosts:** iOS and Android through the storage plugin's `transferFile`, `cancelTransfer` (by the id the wrapper chooses) and `transferProgress` events ([`capacitor-file-transfer.ts`](../../../packages/vfs/src/capacitor-file-transfer.ts)): app storage only, named as `readDocumentsRange` names it, refusing chosen folders and the library folders; Electron through `files:transfer` to the main process, over `net.request` (`TransferRequest`: the part of its `ClientRequest` a transfer uses) ([`node-file-transfer.ts`](../../../packages/vfs/src/node-file-transfer.ts), `apps/desktop/src/desktop-file-transfer.ts`), confined to the window's open project through `NodeStorageAdapter.filePath`. `writeRandomObject` (iOS, Android and the Node module) writes the Git benchmark's random objects natively.

## Saving exported files

Every export (theme, project backup, Export Game, plugin, extension, save, diagnostic JSON) goes through `saveFile(name, blob)` in [`save-file.ts`](../../../packages/vfs/src/save-file.ts), which resolves `downloaded` / `saved` / `shared` / `cancelled`. Editor notices come from `savedFileNotice` ([`file-export.ts`](../../../apps/editor/src/lib/file-export.ts)); `cancelled` shows nothing and is never an error. The UI never builds anchors or calls the plugin itself.

| Host | Route | Result |
| --- | --- | --- |
| iOS app | `BabylonSlateFileExport` ([`capacitor-file-export.ts`](../../../packages/vfs/src/capacitor-file-export.ts)): `begin`, base64 `append` in 2 MiB chunks (never one bridge string), `finish` presents `UIActivityViewController` (iPad popover centred on the web view, no arrow) | `shared` / `cancelled` when the sheet closes |
| Android app | Same plugin; `finish` opens `ACTION_CREATE_DOCUMENT` and copies the file. A MIME type whose extension does not match the name is sent as `application/octet-stream`, or the provider appends its extension | `saved` / `cancelled` |
| Electron | `files.save` → `file:save` IPC: save dialog starting in Downloads, then a write; a name only (no separators), bytes ≤ 512 MiB. A larger file downloads, and Electron's default download (no `will-download` handler) also asks with a save dialog | `saved` / `cancelled` (`downloaded` above the limit) |
| iPhone/iPad browsers (`isAppleMobileOperatingSystem`) | `navigator.share({ files })` when `canShare` accepts the `File`; called before any `await`, so a caller inside a tap keeps its activation. `NotAllowedError` (a slow export outlived the tap) falls back to the anchor | `shared` / `cancelled` / `downloaded` |
| Other browsers | Anchor `download` on a blob URL revoked after 40 s (Safari and WKWebView read it late) | `downloaded` |

- Why native code: WKWebView and Capacitor Android ignore anchor downloads (Capacitor 8 has no `WKDownload` delegate or `DownloadListener`; iOS hands the `blob:` URL to `UIApplication.open` and cancels).
- The native temporary file lives alone in `haptic-exports/<id>/` under the app's temporary (iOS) or cache (Android) folder, so the sheet shows its real name; it is removed when `finish` settles, on `discard` (a failed `append`) and at plugin load.

## Platform decisions

- iOS WebContent process termination is handled by Capacitor's native reload; there is no app-level hook and we do not replace its private delegate. Journaled edits recover on reopen; Play and bakes never restart automatically.
- `StatusBarStylePort` only sets glyph style; never hide or overlay the native status bar.
- Android audio lifecycle never requests audio focus. iOS uses a `.playback` session mixed with other apps.
- Gameplay saves never live in project folders ([save-games](save-games.md)).
- File pickers apply no type filter on iPhone and iPad, in the app or a browser (`hostImportAccept`, [`import-picker.ts`](../../../packages/vfs/src/import-picker.ts)): WebKit maps each `accept` extension to a system type and greys out files of an extension iOS has none for (`.fbx`, `.hasset`, `.hextension`, `.hplugin`, `.babsave`). `pickImportFiles` and the hidden inputs iPadOS Safari opens (Content Browser, Plugins) all use it, so every caller checks the type of what it gets and refuses a wrong one by name. Desktop and Android keep the filter. Detection is `isAppleMobileOperatingSystem()` in [`platform.ts`](../../../packages/vfs/src/platform.ts): the iOS host, an iPhone/iPad user agent, or a Mac user agent with touch (iPadOS reports a Mac).
