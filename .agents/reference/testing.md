# Testing and CI

How verification is scoped, how local test execution is throttled, how the Vitest and Playwright suites are laid out, which traps produce false-passing tests, and the standing rules for GitHub Actions.

## Verification scope

- Agents run only explicit targeted test files/cases for changed behavior and directly affected consumers, plus relevant scoped static checks (`pnpm lint <files>` lints only those paths; `pnpm typecheck --filter <workspace>` selects that workspace; unfiltered commands keep the full CI scope). For public API changes, select the directly affected consumers for scoped typechecking.
- Full local suites, coverage, all browser tests, workspace-wide checks and the cumulative `pnpm verify:local` / `pnpm verify` need an explicit user request; they are never automatic PR prerequisites. Prose/instruction-only changes use diff/link review. After a repair, rerun only affected checks and say why reused results still apply.
- GitHub Verify is unchanged and independently reruns the full workspace typecheck, all tooling and distribution contracts, unsharded package coverage, uncovered editor tests and every browser partition. Local selection never removes those merge gates.
- `pnpm verify:local` is an opt-in diagnostic over the cumulative branch diff from the merge base with `main` plus untracked files. It always runs `git diff --check`, lints changed JS/TS, and selects checks by area (below); unit files run in batches of 50. Its `deliveryEligible` certificate needs a clean, unchanged commit and is not required for targeted delivery.

| Changed area | Local preflight selection |
| --- | --- |
| `apps/**` or `packages/**` source/test | Owning package typecheck; exact changed tests and same-directory sibling tests |
| `scripts/**` | Exact/sibling Node tooling contracts (or an explicit covering contract for an entrypoint); `scripts/distribution/**` contracts as a separate phase |
| Verify workflow | `verification-policy.test.mjs` plus the Vitest workflow contract |
| Playwright config or an `e2e/**` helper | Playwright discovery/config contract; authored `*.spec.ts` files are lint-only locally |
| `docs/**` or `apps/docs/**` | Docs catalog contract plus a docs-site build; docs-site code also gets its owner typecheck and tests |
| Agent rules and skills, PR metadata, other prose | Diff check only |
| Root package/compiler/test configuration or unknown path | All workspace typechecks and all root tooling contracts |

### Toolchain rules

- ESLint 10 with `@eslint/js` recommended and `typescript-eslint` 8 recommended for `*.ts(x)` (so `no-useless-assignment`, `no-unassigned-vars`, `preserve-caught-error`: rethrown errors pass `{ cause }`). `eslint-plugin-react-hooks` enables only `rules-of-hooks` (error) and `exhaustive-deps` (warn); its React Compiler rules stay off (hundreds of existing violations). `react-refresh/only-export-components` warns. Package import boundaries are `no-restricted-imports` blocks in the root `eslint.config.js`. Root Node tooling and distribution scripts also get the recommended JS rules (undefined names, unused bindings).
- TypeScript is `~6.0.3` in every manifest (TypeScript 7 waits for typescript-eslint support). TS 6 defaults `types` to `[]`: the root tsconfig lists `"types": ["node"]` and app configs list what they need (`vite/client`, `vitepress/client`). Side-effect `.css` imports are checked: packages without Vite client types declare `declare module "*.css" {}` in `src/styles.d.ts`. `baseUrl` is deprecated; `paths` are relative to their tsconfig; no config uses `ignoreDeprecations`. The editor app is strict, including unit fixtures and browser proof hooks.
- Transitive security fixes are pinned in `pnpm-workspace.yaml` `overrides`, kept within each consumer's release line; review and drop them when upgrading consumers. VitePress 1.x pins Vite 5, so keep docs development local (published docs are static). Editor and player dev servers and `vite preview` bind localhost only; LAN access is opt-in (`pnpm dev --host`). Browser tests own an ephemeral loopback preview server.

## Local test execution

`pnpm test:resources` is a read-only snapshot (no runner, engine or browser loaded): Windows vs WSL, Node/pnpm, physical availability, known constraints, Windows commit headroom, config/state paths, admission tickets, reservations, worker settings and conflicting execution flags. Unknown observations stay explicit and observation failures exit nonzero. Run it before choosing a small reproduction; an exit code alone does not diagnose OOM.

- **Default is low-memory**: one root workload, one Vitest worker, one Playwright worker, workspace concurrency one, no automatic local retries. `CI=true` may enable strict assertions but cannot bypass admission. Verify selects `BL_EXECUTION_POLICY=hosted-ci` (validated against GitHub Actions hosted-runner, run, repository and OS context; partial hosted environments fail before spawn): four Vitest workers, one browser worker. These checks prevent accidental misuse, not deliberate spoofing.
- **Config file** (per user, never rewritten by the resolver; missing = low-memory defaults): `%LOCALAPPDATA%/BabylonSlate/local-resources.json` on Windows, else `$XDG_CONFIG_HOME/babylonslate/local-resources.json` (default `~/.config/...`). An absolute `BL_LOCAL_RESOURCE_CONFIG` may select another file but cannot relax the default host policy; an empty override is rejected. Shape: `{ "version": 1, "profile": "low-memory" }` (other fields: `reserveGiB`, `maxHeavy`, `maxBypasses`, `cacheDirectory`).
- **Profiles**: both keep at least 2 GiB host headroom (higher reserves are preserved) even if the file asks for less. Low-memory also forces `maxHeavy=1`, one root and zero bypasses. The host owner may select `standard` after measurement (bounded lightweight bypass, three reservation slots); `fast` cannot override low-memory; worker/retry CLI overrides are rejected before tests start. Keep `BL_TEST_PROFILE=shared`; never reduce estimates, lower reserves, raise heaps or bypass admission to escape a queue.
- **Reservations are scheduling estimates, not OS quotas.** Every low-memory root occupies all three legacy reservation slots while running one worker, so builds stay admissible and older callers cannot overlap an active root. The native Windows queue keeps `%LOCALAPPDATA%/Temp/babylonslate-test-admission-v1`, independent of shell TEMP/TMP; with legacy tickets elsewhere, establish quiescence before migrating. Do not terminate other agents or rewrite their checkouts.

| Workload | Worker slots | Memory reservation |
| --- | ---: | ---: |
| Node tooling | 1 | 0.75 GiB |
| Node unit | 1 | 1.5 GiB |
| Focused unit or owner typecheck | 1 | 1.5 GiB |
| DOM/Babylon unit | 1 | 2 GiB |
| Docs build | 1 | 1.5 GiB |
| Application build | 2 | 2 GiB |
| Browser | 1 | 2 GiB |
| Coverage | 1 | 3 GiB |

- Admission needs available memory for headroom + the next reservation + outstanding active reservations (conservative; can delay work that would fit; unknown availability blocks; known memory constraints cap the budget). Thresholds: tooling 2.75 GiB free, focused tests 3.5, browser/application builds 4, coverage 5 (higher host reserves raise them). Root test scripts and package test entrypoints share one resolved plan for admission and worker arguments; discovery is admitted too. Before spawning, the wrapper rechecks that the host policy did not become stricter while the plan waited; if stale it releases the claim and fails (start a new invocation, never auto-retry with other settings).
- Nested stages claim sequential scopes under one lease; parallel siblings, stale scopes and resource upgrades fail immediately instead of waiting while holding the only slot. A dead launcher does not prove descendants exited: active ownership stays after abrupt death with an explicit cleanup blocker. Establish ownership and complete cleanup before removing a blocked ticket; never delete live leases or kill processes by executable name. Queue updates retry transient Windows sharing errors; waiters remove only their own tickets under the queue lock (the lock carries owner pid + token; a killed owner's lock is removed only after an exclusive `lock.claim` re-read). Root release fails on remaining nested scopes or live children; uncertainty is a failure, never a cached pass.
- **Not covered**: no Windows Job Object supervisor, full-tree memory/commit pressure cancellation or PID-reuse creation-identity tracking (PID-scoped taskkill/POSIX cleanup remains). Direct package build/typecheck commands bypassing the root wrapper, raw executables, older schedulers, WSL and containers are outside the serialization guarantee; do not overlap native Windows and WSL/container heavy work. A safely queued test is not a fixed memory failure.
- **Build cache**: low-memory enables the verified disk cache by default (`cacheDirectory` absolute path or `null` to disable; defaults `%LOCALAPPDATA%/BabylonSlate/build-cache` or `$XDG_CACHE_HOME/babylonslate/build-cache`, else `~/.cache/babylonslate/build-cache`). `pnpm test:e2e` builds or reuses an exact-source artifact under ignored `.cache/test-build`, owns an ephemeral loopback Vite preview server and verifies build identity and run nonce; direct Playwright CLI is for discovery only. Identity covers source/config/assets, tracked and installed lockfiles, Node/platform/architecture and build-environment inputs (ignored app env files, Vite variables; values hashed, never recorded; constructed dotenv names unsupported). Known test/doc areas are excluded, so test/docs-only commits reuse identical inputs. Shared lookup checks file integrity and repeats after admission with source revalidation; publication uses complete immutable generations (incomplete/corrupt entries are skipped). CI builds its own artifact and never reads the user cache. The cache is not auto-pruned.
- **Verification phase cache**: successful clean phases are recorded under ignored `.cache/verification`, keyed by command, source identity, environment, tool versions/lockfile, Node and platform; typechecks can survive browser/prose-only commits, repository-reading test/lint phases include the whole revision (some tests inspect tracked files and Git history). A later phase failure leaves earlier successes reusable but never passes overall. `BL_VERIFY_CACHE=0` forces execution; CI and explicit browser runs always execute.
- Isolated forks stay enabled. Pure editor/VFS/graph logic runs in Node; `vitest.environments.ts` names DOM-dependent logic tests (incl. real phone Dockview layouts) and a discovery regression checks every authored test appears exactly once. Package coverage and uncovered editor tests stay separate: editor logic runs once, editor DOM tests restart in batches of at most 50 files; focused preflight also batches 50.
- Local preflight never launches browser suites. For focused debugging: animation graphs use the content suite, behaviour trees the tree-editor and AI suites, shader graphs the material/content and particle suites, scripting/shared graph UI the scripting suite. CI runs every retained suite.
- `pnpm test:benchmark --agents=4 --script=test -- --project node packages/core` records queue/execution time, browser starts, sampled process-tree CPU and aggregate RSS and surviving processes under `.cache/benchmarks` (estimates, not quotas; 2 s sampling misses short-lived processes).
- Windows: use a POSIX script shell (e.g. Git Bash via `npm_config_script_shell`) for package scripts that set environment variables inline. The owned test-build command passes environment variables directly, preserving the URL base `/` against MSYS path conversion.

## Quiet agent waits

Launch one foreground helper and keep its session; the helper owns polling ([wait-efficiently skill](../skills/wait-efficiently/SKILL.md)).

- `pnpm --silent agent:wait local --script test -- packages/core/src/project.test.ts` runs a selected check (`--script verify:local` only on explicit request). Arguments after `--` belong to the package script (quote the separator as `'--'` with `pnpm.ps1`). `--timeout-seconds <n>` overrides the two-hour deadline. The helper launches the current `npm_execpath` through Node (or executable pnpm directly), never a Windows `.cmd` shim, and does not change script-shell configuration.
- `ci --pr <number>` captures the head, discovers its latest pull-request `verify.yml` run (up to ten minutes), then `gh run watch --exit-status --interval 60`. Final head/run/attempt checks reject superseded results; success requires `static`, `unit`, all four e2e shards and no skipped/unsuccessful jobs (a draft run cannot satisfy it). Other required checks and merge gates remain the agent's job.
- `slot --pr <number>` checks every 60 s for fewer than four other counted non-draft PRs to `main` (see the [workflow](../rules/agent-workflow.md#workflow)). Recheck capacity immediately before marking ready; the helper never opens, readies or merges PRs.
- Output: a start record and a terminal result (success output < 1 KiB; failures add at most 40 trailing log lines, < 4 KiB). `output.log` keeps full output (pnpm append-only reporter so an outer `--silent` does not hide recursive diagnostics); `result.json` records status, elapsed ms, exit code, commit and CI URL. Verification saves initial/final working-tree snapshots (final snapshot has its own 5 s limit; unavailable final state is recorded and the operation stays unsuccessful). Delivery eligibility needs a clean unchanged commit and an unfiltered `verify:local`/`verify`; recheck commit and tree before reusing any saved result.
- Statuses: `success`, `failure`, `cancellation`, `timeout`, `stale`. Package failures keep their exit code; timeout 124, SIGINT 130, SIGTERM 143, stale 3. Missing prerequisites fail without changing global setup. Cancellation stops only owned children; the helper never retries tests/workflows.
- `pnpm test:agent-wait` (real process fixtures + a fake `gh` on Node's test runner) is part of `pnpm test:tooling` in the CI static job.

## Environment limits

These have produced false-passing tests; check them before trusting a green unit test.

- **jsdom has no `PointerEvent`.** `fireEvent.pointerDown` degrades to a bare `Event` with `clientX`, `pointerId` and `pointerType` undefined, so pointer-gesture assertions pass vacuously. Use `dispatchPointerEvent` from [`packages/editor-kit/src/test-support/pointer-events.ts`](../../packages/editor-kit/src/test-support/pointer-events.ts).
- **jsdom has no `ResizeObserver` or `DOMMatrixReadOnly`** (React Flow touches both on mount); `vitest.setup.jsdom.ts` installs minimal stand-ins and stubs `HTMLCanvasElement.getContext` (`measureText` width 8). Anything layout-dependent, including a panel that lays out to zero height, belongs in Playwright.
- **Consumer tests do not mount `DocumentProvider`**; they mock it (next section) and set `registryEpoch` themselves, so they prove what the consumer keys on, not that the provider keeps the epoch stable across edits, tab switches and dirty changes (it is built from registry generation plus its own registry counter, separate from the per-edit `bump()`). Only `apps/editor/src/context/document-context.test.tsx` (action/route/document-list contracts) and `apps/editor/src/panels/graph-panel.test.tsx` (a mounted Class graph's Add Node palette follows an unsaved edit in another tab) mount the real provider. Their setup (in-memory OPFS root on `navigator.storage`, empty engine plugin/extension libraries, stubbed KTX2 transcoder probe and scene-loading paint wait from `@babylonslate/render`) lives in [`apps/editor/src/testing/real-document-provider.ts`](../../apps/editor/src/testing/real-document-provider.ts); each file keeps its own hoisted `vi.mock` calls. Reuse it rather than mocking more of the provider.
- **`vi.stubEnv` does not reach `import.meta.env`**, so the `VITE_TEST_MODE` branch of `isTestModeEnabled` is covered by Playwright (which builds with `VITE_TEST_MODE=true`).
- **`?test` activates only on QA-compiled bundles**: `isTestModeEnabled` honors the query flag when built by the Vite dev server (`import.meta.env.DEV`) or with `VITE_TEST_QUERY=true`; production output ignores it. Distribution builds hard-fail on either flag. `apps/editor/test-mode-bundle.test.ts` proves the boundary against real `vite build` output. Ad-hoc simulator/QA web builds needing query activation pass `VITE_TEST_QUERY=true`.

## Document context mocks

Editor tests replace `context/document-context` with the shared helper in [`apps/editor/src/testing/document-context-mock.ts`](../../apps/editor/src/testing/document-context-mock.ts) instead of hand-written factories. Load it inside the factory so mock hoisting cannot reorder the import:

```ts
vi.mock("../context/document-context", async () =>
  (await import("../testing/document-context-mock")).documentContextMock(() => ({
    openDocuments: harness.documents,
  })),
);
```

- The callback runs inside every mocked hook call (hooks allowed) and returns only the fields the test controls. A component may call several document hooks, so state a test or action changes lives in `sharedMockState(initial)` (read with `.use()`), not `useState` (each hook call would own a separate copy); it restarts from `initial()` when its last subscriber unmounts and is used as-is (getters and mutations stay live, identity is preserved).
- Every other field has an inert default (no project, no documents, no-op actions, loaders find nothing; defaults that would invent project content reject). Unless supplied, `documentRevisions` and `tabsRevision` advance whenever `openDocuments` is replaced (mutating in place changes nothing). Defaults are typed against the real context value, so a new context field fails typecheck until it has a default.
- `DocumentProvider` renders its children; `useDockWindowTick` returns 0 (override with `{ useDockWindowTick }`). `useDocumentActions()` and the slice hooks (`useRegistryState()`, `useProjectState()`, `useSaveState()`, ...) return the same value, so a field is supplied once; `useAppRoute()` returns `route`; `useOpenDocument(id)` / `useDocumentDirty(id)` find the document by id (fixtures need real `kind:path` ids); `useOpenDocumentTabs()`, `useActiveDocumentId()`, `useTabOrder()`, `useDocumentKindsRevision()` read their fields. An unknown new `use...` hook returns the documents value; a new single-value hook needs an entry in the helper.

## Playwright

- **Projects**: `desktop-chrome` (full suite) and `ipad-landscape` (`hasTouch`, DPR 2, iPad Pro 11 landscape 1194x834, Chromium). iPad portrait is unsupported: do not add an `ipad-portrait` project. Builds use `VITE_TEST_MODE=true` and an owned loopback server. Default test timeout 60 s. `testIgnore` excludes the perf routes (`rendering-baseline`, `play-performance-route`, `play-sustained-route`, `feature-test-perf-route`, `feature-test-flythrough-route`, `editor-edit-profile`); they run only through `playwright.perf.config.ts` (projects `perf-gpu`, `perf-software`; 600 s timeout, one worker). Worker count comes from `BL_TEST_BROWSER_WORKERS`, retries from `BL_TEST_RETRIES` (both set by the admission plan).
- **iPad set**: `ipad-landscape` greps `@ipad`. Tag tests that depend on touch, coarse pointer or landscape viewport with `IPAD_TEST_TAG` from `e2e/ipad-tag.ts`; behaviour independent of viewport/pointer (Play, scripting, import, Engine Settings, smoke) stays desktop-only. `playwright.config.test.ts` lists the iPad set via `playwright test --list`. Chromium device emulation is not WKWebView: `@ipad` proves viewport / `hasTouch` / DPR, not Safari Workers, `createImageBitmap` in a Worker or Capacitor (encode `decode_unavailable` / `Image.decode` fallback is unit-tested in `worker-encode` / `decode-source-rgba`).
- **Phone layout**: `e2e/phone-editor.spec.ts` (390x844 window switcher with one visible Dockview window, 844x390 landscape round trip, injected safe-area insets, restore to 1194x834 tablet) and `e2e/phone-content-browser.spec.ts` run under desktop-chrome with phone viewport/touch overrides. Tablet folder-pan tests need enough rows to scroll at 1194x600, keeping the coarse-pointer viewport above the 500px phone-layout height breakpoint. Phone emulation does not certify native iOS/Android packaging or physical-device behavior; real-Home-Screen testing is still needed for iOS status-bar effects, installed-phone insets and rotation timing.
- **Touch UX**: `e2e/touch-shell.spec.ts` holds the touch audits (app-wide native context-menu suppression with `SelectableText` as the opt-out, pointer context menus, a project long-press menu that stays open after release).
- **WebKit smoke lane** (optional Safari-engine coverage; never a PR check, never required): `playwright.webkit.config.ts` reuses the default config with one project `ipad-webkit` (Playwright WebKit, iPad Pro 11 landscape descriptor, `profileContext`, 120 s timeout, traces kept on failure under `test-results/webkit`). Scope = tests tagged `WEBKIT_SMOKE_TAG` (`@webkit-smoke`, `e2e/ipad-tag.ts`): `editor-smoke`, `p4-play`, `p14-export`; keep it small. `playwright.config.test.ts` pins the set, checks each also runs on `desktop-chrome`, and checks Verify stays on Chromium. `.github/workflows/webkit-smoke.yml` runs on push to `main` and `workflow_dispatch` only (one standard `macos-26` job, 30 min, installs only WebKit, `pnpm test:e2e:webkit` on the `ci-bundle` build; results uploaded on failure for 3 days); a failure is a Safari-compatibility finding to triage. Locally `pnpm test:e2e:webkit [spec...]` goes through `scripts/run-tests.mjs e2e` with admission and needs a local WebKit build. macOS, not Linux: Playwright's Linux WebKit has no `navigator.storage` (no OPFS) and no `navigator.gpu`, so the editor cannot create a project there. A profile, not an ephemeral context: an ephemeral WebKit context has no usable OPFS (`getDirectory()` rejects), so the specs import `test` from `e2e/profile-context.ts`, and `profileContext` runs each test in a persistent context in a temporary directory. WebKit keeps OPFS outside that directory and shares it between profiles, so the fixture empties it for the origin before each test; keep the lane at one worker. Limits: macOS headless WebKit is not iPadOS Safari/WKWebView (no Capacitor or iPad GPU stack), but it exercises the COI service worker, OPFS, workers and WebGL2. Physical iPad/Simulator testing remains necessary.
- **Wait/helper rules** (each prevents a known flake):
  - Dirty Play shows the Preparing Play dialog before `play-overlay` mounts: use `clickPlayAndWaitForOverlay` from `e2e/play.ts` (60 s), not the 5 s default; long dirty-Play cases raise `test.setTimeout`. The prepare dialog can close within one poll, so record its phases with a `MutationObserver`. Preview Build waits go through `waitForPreviewBuildBoot` (overlay visible, then `data-booted` with `data-scene-loading="false"`: the player reports booted from its first tick, while software GL still links the Scene's effects on the page's only thread, and a 5 s assertion made then cannot be answered).
  - Project creation helpers select Basic 3D before filling details (2D cases select Basic 2D) and wait for cross-origin isolation after navigation (the COI service worker may reload on first registration; the bootstrap reloads only after the worker can control navigation, including a late `controllerchange`); they allow 30 s for editor chrome after storage, scaffolding and imports, polling the real ready UI. Wait for the launcher splash to unmount before editor gestures.
  - `e2e/save-all.ts` clicks Save All once and polls until the document service and toolbar report clean (15 s); it never retries the click to hide a re-dirty producer, waits for scene reloads and clicks actionably so a loading backdrop cannot eat it. The Auto Bake On Save test must not trigger a second overlapping save when the bake dialog closes.
  - Class recovery/state-preservation tests wait for a visible graph node before saving; dispatching the Content Browser double-click alone does not prove the graph loaded. Use `openAssetFromBrowser` / `createContentBrowserAsset` (they select the `assets` tree row first and fill Content Browser search when a tile is off-screen so windowed-grid tests still mount the card). Browser probes of OPFS assets/journals/thumbnails resolve each logical project id through its registered catalog directory; recovery polling tolerates a not-yet-created journal subtree but fails unexpected storage/parse errors.
  - Trace tests wait on `__babylonslatePlayTest.tickIndex` (sim ticks), not `data-fps` (a 1 Hz integer that can stay `60`). Audio/particle tests read the test-mode hatches `window.__babylonslateAudioStats` and `__babylonslateParticleStats`; audio Play/Preview Build cases turn on Preview **Loop** first (the fixture beep is ~0 ms and finished one-shots drop `voices` to 0 before the poll).
  - Test-only hosts (`__babylonslateTest`) expose live Babylon visual positions and material names; assert rendered state, not just command records or tick counters. `e2e/preview-scene-fixture.ts` is the shared authored scene (separated actors plus a parented child) for Scene viewport, overlay Play, Preview Build and served-export assertions. Startup regressions verify deployment-base WASM URLs, failed explicit downloads and retry, strict Play backend initialization and no ticks after physics startup fails; they exercise error paths rather than trusting Node's local WASM file. Preview Build always packs PNG/pixels (not KTX2); `apps/editor/vite-player-host.test.ts` pins that the player is served through the configured Vite base, which a root-base e2e cannot see.
  - Software-GL fixtures (e.g. the Basic 3D mannequin shadow test waits for three presented frames after a WebGPU backend switch) qualify functionality, not device performance.
  - A page reads a WebGPU canvas back only in the task that acquired its texture, and screenshots of a visible, continuously rendering WebGPU canvas take seconds on the software adapter and stall under heavy rendering. `e2e/direct-presentation-probe.ts` therefore checks a directly presented WebGPU view on screen with screenshots taken while `__babylonslateViewportTest.holdViewportFrames(true)` holds the viewport's frames and the GPU is idle, and samples further frames through the view canvas (the test-build read sync writes the held image into it).
- **Texture encode / KTX2**: block alignment, padding, re-encode requeue and source-control interaction are pinned by `packages/assets/src/texture-compression.test.ts`, `registry-texture-alignment.test.ts`, `project-service.assets.test.ts`, `packages/render/src/ktx2-webgpu-rgba.test.ts`, `ktx2-transcoder.test.ts`, `resource-cache-texture.test.ts`, `particle-preview-recovery.test.tsx`, `texture-editor.test.tsx` and `e2e/texture-webgpu-fallback.spec.ts`; read them before changing encode alignment, `Retry Encoding` or KTX2 orientation. Hardware WebGL2's block-compressed path and WebGPU KTX2 orientation have no browser proof.
- **Invariants pinned by tests** (read the test before changing the behavior): Play compile cache does not recompile on position-only edits (`apps/editor/src/services/script-compiler.test.ts`); lazy Audio loads only the chosen chunk, and the packed player leaves `audioBytes` empty until `loadGameAudioClipBytes` (`packages/render/src/audio-service.test.ts`, `apps/editor/src/lib/play-audio.test.ts`, `apps/player/src/hydrate.test.ts`); windowed Output Log / Compiler Results / SearchDialog (`packages/editor-kit/src/windowed-list.test.tsx`, `output-log-panel.test.tsx`, `output-log-ring.test.ts`); script palette injectors do not rebuild on unrelated pin edits (`apps/editor/src/services/graph-validation.test.ts`); Global Search indexes on demand and never reads a Scene bake chunk (`packages/assets/src/search-index.test.ts`); editor freeze/shader-warm behaviour (`packages/render/src/p20-editor-scene-freeze.test.ts`, `scene-perf.test.ts`, `apps/editor/src/lib/scene-viewport-load.test.ts`); runtime perf smoke asserts stats cadence, never wall-clock budgets (`packages/runtime/src/p14-perf-smoke.test.ts`); headless behaviour-tree acceptance and `.babtrace` replay (`packages/runtime/src/p11-acceptance.test.ts`, `trace-recorder.test.ts`); audio routing/gain proofs (`packages/render/src/p16-acceptance.test.ts`); trace inspection (`apps/editor/src/lib/trace-snapshot.test.ts`, `trace-view.test.ts`, `components/trace-editor.test.tsx`, `packages/editor-kit/src/tree-view.test.tsx`, `components/debug-inspect-dialog.test.tsx`, `e2e/p8-trace.spec.ts`). ## Other harnesses

- **Golden files**: `readGolden` / `writeGolden` / `normalizeGoldenText` in `@babylonslate/test-kit` back byte-exact surfaces (container formats, compiler output, world snapshots, tilemap chunks, 2D projection); `normalizeGoldenText` normalizes CRLF and trailing newlines. There are no migration fixtures (the engine is unreleased; older formats are refused, not migrated). A future released-format fixture is frozen input that `UPDATE_GOLDENS=1` must never rewrite; `UPDATE_GOLDENS=1` only refreshes current-format output, and regenerated container headers must be reviewed with payload bytes verified unchanged.
- **Deterministic runtime harness**: `runDeterministicScenario` drives an in-process `@babylonslate/object-model` World with a seeded RNG and fixed dt; a 120-tick scenario matches a committed golden and is identical across two runs. Multi-transport parity (in-process, transferable ping-pong, SAB when `SharedArrayBuffer` / `crossOriginIsolated` exists) is never SAB-required: `transport-parity.test.ts` republishes one in-process buffer through SAB and transferable (payload fidelity only). Live Play always uses transferable ping-pong (`worker-entry.ts`).
- **Property tests**: `fast-check` for pure logic (`.babasset` chunk round trips, edit-command apply-then-invert and scene diff round trips, navigation coordinate remapping, actor world-transform composition vs runtime composition).
- **Editor-edit profiling** (reports React commit cost per edit; never asserts timing): `apps/editor/src/lib/render-profile.tsx` mounts `<Profiler>`s only when the build can report them (`import.meta.env.DEV` or `VITE_REACT_PROFILING=true`, which aliases `react-dom/client` to `react-dom/profiling`) **and** test mode is on (build-time constant; distribution builds refuse `VITE_REACT_PROFILING`).   `VITE_REACT_PROFILING=true pnpm run test:e2e e2e/editor-edit-profile.spec.ts --config playwright.perf.config.ts --project perf-software` (agents wrap it in `pnpm --silent agent:wait local --script test:e2e -- <same arguments>`). `BL_PERF_SCENARIOS` selects a subset of `idle`, `scene`, `graph`, `content-browser`, `tilemap` (default all, fixed order; compare windows only between runs of the same selection; unknown names fail before the project opens); `BL_PERF_EDITS`, `BL_PERF_SEARCH`, `BL_PERF_QUIET_MS` (default 750), `BL_PERF_LABEL` adjust bursts and report. Scheduler/cache contracts live in the canonical render tests; synthetic memory-store timing loops are not device performance measurements. ## GitHub Actions

- **Standard runners only.** Never use, enable or recommend larger runners, paid services, self-hosted testing or extra paid storage (AGENTS.md). `scripts/workflow-runner-policy.test.mjs` checks every workflow (and local reusable workflows, matrix values included) against a literal standard-runner allowlist and rejects larger/paid labels, runner groups and uncontrolled runner expressions. Standard public-repo compute is free; storage has separate allowances, so keep the 3-day artifact retention and establish account entitlement before adding uploads. A repository visibility change needs a new cost review. If a job is slow or OOMs, shrink it, split it or cache; do not buy a bigger runner.
- **Workflows**: [`verify.yml`](../../.github/workflows/verify.yml) is the merge gate; [`preview.yml`](../../.github/workflows/preview.yml) deploys GitHub Pages from `main` only (a dispatch on another ref is skipped; build, deploy and smoke run sequentially and the smoke job checks the live editor and docs index pages match the uploaded build byte for byte; bundle sizes are reported with `node scripts/bundle-report.mjs`, a non-blocking measurement); [`webkit-smoke.yml`](../../.github/workflows/webkit-smoke.yml) is the optional lane above.
- **Verify job shape** (`scripts/verification-policy.mjs`: `{ e2eShards: 4, readyPrSlots: 4 }`): `static` (15 min: tooling and distribution contracts, workspace typecheck, lint, docs-site build), `unit` (45 min: unsharded `pnpm test:coverage`; per-package 60% gates need the full suite, so do not shard Vitest coverage), and `e2e` shards 1-4 (35 min each, `fail-fast: false`, `pnpm test:e2e --partition=N/4`). Required job names are `static`, `unit`, `e2e (1)` through `e2e (4)`. Verify cancels superseded runs for the same PR (or `main` ref); Preview cancels in-progress Pages deploys.
- **Independent shards.** Shards start in parallel with `static` (no `needs: static`) and each builds its own player and editor bundle with the hosted-only `BL_TEST_BUILD_MODE=ci-bundle`. That mode does not assert typechecking passed: the required `static` job owns typechecking, so a static failure blocks merge even if browsers pass. There is no shared build artifact between jobs and no one-day browser-build rerun input; a delayed shard rerun builds from its checked-out source. Bundle-only artifacts have a distinct identity from standalone typechecked builds, and local selection of `ci-bundle` fails before compilation. Build source, environment, toolchain and file-integrity validation stay in place. Do not restore a shared producer or add a browser dependency on `static` without updating the workflow contract.
- **Browser result integrity.** A zero browser exit code is accepted only with a JSON report bearing this invocation's server nonce and containing executed passing tests. Missing/stale reports, all-skipped selections, runner errors and unexpected outcomes fail; skips and retry outcomes stay visible in a compact result log. After admission the session rechecks source, toolchain, build contract and file integrity before starting its server, so a source edit while a completed build waits for capacity fails clearly instead of exercising a stale bundle or silently rebuilding.
- **Playwright in CI**: each shard restores `~/.cache/ms-playwright` keyed on `pnpm-lock.yaml` and runs `playwright install chromium` (5-minute timeout; not `--with-deps`, not `install-deps`: `ubuntu-latest` already has Chromium's libraries and the extra CJK/Cyrillic font apt packages time out when shards hit the archive together; the suite has no screenshot baselines needing them). One Playwright worker; each test owns a fresh browser context and storage. Partitioning (`scripts/browser-partition.mjs`, weights in `scripts/browser-timings.json`) is deterministic longest-group-first, grouping by file and browser project so serial suites never split; new tests default to 30 s; timing updates affect placement only, never cases, assertions, retries or limits. Browser timings and failure traces upload for three days. The Feature Test starter is covered by the node scaffold test `apps/editor/src/services/project-service.feature-test.test.ts`; its browser route is perf-only.
- **Concurrency budget and the four-ready-PR cap.** Plan around 20 concurrent jobs. Each ready PR uses 6 Verify jobs; four ready PRs use 24, and a merge adds `main` Verify (6), Preview (three sequential jobs, one at a time) and one optional macOS WebKit job. GitHub queues jobs beyond the cap rather than failing them. Preserve the four-ready-PR cadence ([workflow](../rules/agent-workflow.md#workflow)): open as a draft after targeted local checks, mark ready once when fewer than four other counted non-draft PRs target `main`, otherwise wait. `ready_for_review` or a later non-draft `synchronize` starts Verify; agents watch the current head, repair, rerun only checks affected by each repair, and merge when every gate passes.
- **Skipped-check ghosts.** A draft PR still triggers Verify, but the job `if` skips the runners; a skipped matrix does not expand, so the draft run shows bare `static` / `unit` / `e2e` (the unsharded `e2e` looks like a leftover full job), and `ready_for_review` on the same SHA adds the real six. The Checks tab keeps both runs (often 9 rows); skipped rows do not count toward the 20-job cap. Do not add a second "full" workflow or drop the draft `if` to hide them.
- **Security scans** keep pull-request, push and individual comment events in separate cancellation groups: a comment cannot cancel the PR commit scan and newer comments cannot cancel scans of earlier comments.
