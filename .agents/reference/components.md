# Editor UI component catalog

Reusable Editor UI components (`@haptic/ui`, `@haptic/editor-kit`, `@haptic/graph-ui`, multi-screen app wrappers): what each does and where it is used. Pick from here before writing editor chrome.

## Rules

- Do not add raw styled `<input>`, `<select>` or `<button>` in `apps/editor/src`; compose from this catalog.
- Adding, removing or changing the purpose or typical use of a reusable component updates this file in the same change; never defer it. Reusable means `packages/ui` primitives, exported `editor-kit` composites, `graph-ui` components meant for reuse, and `apps/editor/src/components` wrappers used from more than one screen. One-off screens (Homepage, Play overlay, Settings modals, dock panels) and test files are not cataloged.
- Keep each row short: name, what it does, where it is used. Composition parts (`DialogTitle`, `FieldLabel`) go on the family row; hooks and helpers stay in the "Related hooks" line. Delete rows for components no longer reused. Kit-level additions also go in the Component Gallery (dev-only visual audit: `/?test=1&gallery=1`).
- `AppSettingsProvider` is the editor-root owner of engine settings: it hydrates once, exposes a versioned reactive snapshot plus focused update operations, and rejects hydration completions superseded by live updates, so viewport, graph and Play consumers cannot diverge.
- Settings control descriptions live inside the owning `Field`, beneath the control and before its separator. Horizontal copy uses `FieldContent`; compact action buttons in a vertical field use a flex wrapper.
- Asset document shells are DockView ([`DockviewShell`](../../apps/editor/src/shell/dockview-shell.tsx) + [`window-catalog.ts`](../../apps/editor/src/shell/window-catalog.ts)), not shadcn `Tabs` and not a standalone page. Register every panel so the toolbar **Windows** menu can show, hide and restore it. Compose each dock tab from this catalog (`PanelFrame`, `PropertyGrid`, ...). The one chrome exception is the Animation Graph **State Machine | Animation Object** mode bar outside DockView. Rule: [dockview-editor-tabs](../rules/dockview-editor-tabs.md).
- `DockviewShell` fills its host (including stacked Animation Graph surfaces) before reserving space for the phone **Window** picker. It restores a saved layout with each catalog window under its current catalog `title` (function graph tabs keep their saved titles), so renaming a window needs no `layout.json` migration.
- Scene documents pass `sceneMode` to the shared DockView catalog: Design uses the existing windows, Landscape adds a filtered Outliner and Settings, Foliage adds Groups, Settings and a filtered Outliner. `SceneModeSelect` sits in the global action bar. `SceneBrushToolbar` replaces the Design viewport island in painting modes (grouped segmented tool toggles with tooltips plus the current landscape or foliage group) with Design's compact outline controls and spacing, including the 28px control height on tablets. Focus preferences and saved placements are independent per mode.
- Density: `NumericDragField` is compact in desktop and tablet Inspectors (28px inputs, 12px text, narrow axis handles, 6px horizontal padding); phone keeps separate 44px input and scrub targets.
- Numeric fields show their unit after the value, never in the label: set `PropertyRow.unit` (or the field's `unit`). Short units (`s`, `ms`, `px`, `%`, `deg`, `/s`, `m/s`) render in number, vector and slider fields; phrases such as `scene units` stay after the label. Never write a unit into a label (`Frame Duration MS`, `Rotation (Degrees)`).
- Numeric fields show two decimals by default. `NumericDragField.precision` and numeric `PropertyRow.precision` opt into finer display without rounding stored values (Water Buoyancy Volume: six places, `0.0001 m³` scrub step).
- Token and action-vs-pressed rules live in the theming reference; touch sizing in the [gesture rules](architecture.md#gesture-rules).

Source: [`packages/graph-ui/src/`](../../packages/graph-ui/src/). Reused by script, shader, animation, behaviour-tree and particle graphs and the Content Browser read-only References dialog.

- `BlueprintNodeShell` draws a 44px marker centered 6px inside the top-right corner (Clock = latent action, Plug Zap = event entry, Gamepad 2 = input event, Plug = Script Interface endpoint) with a drop shadow, outside the clipped body: it never affects node size or pointer input, the title reserves right padding, and an error badge moves to the top-left. - Writable-reference inputs (Tween Target) omit literal previews and Inspector defaults; script connection rules accept only mutable variable outputs of the exact type.
- Read-only mode keeps node/wire selection and focus framing (the editor waits for the focus node to be measured) but accepts no topology or position edits.
- Add Node: toolbar insertions (no chosen point) are centred on the canvas (the graph wrapper's rect, not the window) and, when that spot is taken, step by the new node's footprint through the surrounding slots to the nearest one clear of every node (measured size, else the pin-row estimate; `graph-placement.ts`); pin-drag, right-click and double-tap additions keep the chosen drop position. Paste keeps its 40px cascade.
- Selected wires paint `--graph-state-selected` at exec width + 1px on every GraphEditor canvas (the inline pin-colored stroke would otherwise hide XYFlow's `.selected` style); behaviour-tree and animation canvases keep their thinner neutral override.
- Node Connection Assistant: dragging a node previews nearby unused, compatible right-output / left-input pins with grey 50%-opacity wires (measured handle centers, configurable screen radius, default 48px, 8-200 in Engine Settings → Graph; previews live outside graph state and commit together on release after validation). Occupied pins (incl. multi-connect exec/output), disabled nodes and links inside the dragged selection are excluded. Moving away, Escape, pointer cancel, focus loss or external graph replacement clears them; host refreshes discard stale previews without ending assistance. Releasing before a fresh preview appears does not connect; read-only and fixed-node canvases offer none. Shake Nodes To Disconnect needs three deliberate direction reversals and commits immediately (assistance stays off for the rest of that drag); Escape, pointer cancel or a second touch cancels.
- **Format** keeps execution paths aligned, places joins after incoming branches, reserves nested branch lanes; small pure trees keep diagonal placement, tall parameter trees use compact horizontal rows; unrelated nodes stay put.
- Serialized graph pins may supply a compact `typeLabel` and a `group` heading (Material graphs use them for numeric widths and Material Output channel groups). `GraphEditor.renderNodeBody` adds host content below pin rows (material graphs: bounded four-line static code preview).
- NodePalette rows expose optional registry descriptions as `title` and `aria-description` without changing row height.

## Feature panels reusing the kit

Per-feature composition rules; no new components unless noted.

- **Rendering settings disclosures**: Project Settings → Rendering hosts Scalability, Shadows, Post Processing, CEL Shading, Environment Lighting, Resolution and Play Preview in `DisclosureSection`s, all closed by default; `renderingSectionForTarget` maps a settings-search result to the disclosure it must open. Property search reveals matching categories; clearing it restores manual disclosure state without writing scene data; new rendering override categories start closed too. EngineSettingsForm gates local resolution, texture budget and post-processing fields behind **Override Project Rendering** (inheriting the project is the default); settings search covers render mode, quality groups, shadow distance, local shadow budget and that switch.
- **Add Component → General → Movement**: shared catalog and compact `PropertyGrid` (numeric / boolean / enum rows for speed, jumping, capsule dimensions, graph input conversion); Class/Prefab Inspector omits ineffective local Transform controls; physics diagnostics name conflicting components.
- **Save Game**: component rows are `PropertyGrid` booleans (transform/destruction, per-variable checkboxes incl. inherited). Save Game documents pair a searchable typed Fields tree and named Add Field prompt with a selected-field Inspector, Single/Array controls and EntryListEditor defaults; Save Setup holds the project default slot/profile, schema version and generated types sit under Advanced; raw identities stay out of authoring controls. `TypeVisualIcon` supplies the asset glyph.
- **Rendering components**: Outline (Enabled, Color, Width, Render Through Meshes; groups an actor's eligible world meshes; actors sharing a model keep separate styles; excluded from SceneLayer catalogs because world depth and layer ordering differ); Fog Volume (Enabled, Shape, Size, Density, Edge Falloff; project Volumetric Fog quality stays editable while Scene-Wide Fog is off); Dynamic Runtime Mesh (Material, Enable Collision default off, collision filters, shadows; geometry comes from component-targeted NodeGraph calls during Play: no mesh asset editor, no Place Actors preset); Deformer (Target Mesh lists only Mesh Components on the same actor; Add Component targets the first sibling Mesh and enables it, otherwise Enabled stays off and the target None; Strength, 2-4 controls per axis, auto/manual bounds, up to 64 control offsets; Resolution changes reset offsets; deformation is visual only: collision, marquee and Play picking keep the original geometry, viewport taps select the drawn shape). The Camera Inspector shows Field Of View (Perspective) or Orthographic Size (steps by tenths); Near/Far Clip errors appear only after an invalid edit. The Material Inspector also offers the Text domain (glyph preview, Text Output); Scene/Prefab Inspectors filter Text Materials by live domain and add a Material UV enum.
- **Deformer cage**: the selected actor's Deformer shows its lattice on the gizmo utility layer (`deformer-handles.ts`, the shared shape-handle lifecycle): edges between controls, one handle per control at rest plus its authored offset (Strength not applied), camera-plane drag, double-click reset, translate gizmo on a clicked point, live lattice preview only for the target's applied cage, one history entry per released gesture. Fit To Mesh boxes come from `latticeFitBounds` (undeformed bounds) and refit after async model loads. Deformer cards get **Edit In Viewport** like shapes.
- **Spline / Water River**: Spline (Add Component > General) and Water River share typed Curvature, Path Point Count and XYZ point rows (Spline adds Closed Loop; River keeps per-point Width Scale) and one viewport handle lifecycle (live drag, midpoint insert, double-click remove; a clicked Spline point also takes the translate gizmo; one history entry per released gesture). Scene component cards show **Edit In Viewport** even collapsed; **Editing In Viewport** marks the active shape, choosing another redirects handles without changing disclosure, and the target is session-only (no scene or history change); locked actors and multi-selection disable it.
- **Water asset editor**: DockView Preview + Inspector, Surface Material picker; New Asset offers Realistic and Stylized presets; Place Actors has Global Water Volume, Ocean, Lake, River, Puddle, Water Removal Volume (placing a Water asset creates a lake using it). Global Water Volume hides finite Width/Length; Ocean exposes fixed rectangular bounds; Water Removal Volume shows only the dimensions its shape uses (Diameter for Sphere/Cylinder/Capsule; Height hidden for Sphere; Length Box-only). Viewport handles are engine-side on the gizmo utility layer and edit the same properties.
- **Input asset editors**: standard DockView shell with Bindings (`InputBindingsPanel`: PanelFrame, SearchDropdown, BindingCodePicker, compact Buttons; whole rows select a binding for the Inspector by click/keyboard, right-aligned trash removes) and Inspector (`PropertyGrid`); shared selection in `InputAssetEditingProvider`. Authoring is reached through Content Browser > Input, not Project Settings. Input events and rebinding nodes share the native Key enum and Input Binding structure; Make Structure exposes a Structure Type selector with named Make/Break entries for engine and project structures.
- **Data assets**: Data Definition = primary Fields panel (Add Field above the compact list) + Inspector (type swatch/summary header, **Field**, **Default**, **Field Rules** sections), both under Windows (saved layouts can reopen the Inspector there). Data Tree = Tree, Entries, Values, Validation; the Tree panel is laid out and sized like the Outliner (fixed header and **Tree Root**, only the plain TreeView scrolls; 44px rows only on touch phones) with ancestor-preserving search; branch browsing is separate from entry identity; Entries is a borderless typed grid for one Definition (Tag cells use inline `TagPicker`s) or metadata/filtering for mixed branches; Validation opens ancestors and focuses the entry/field. Entries and Validation rows are striped; Entries rows are 44px in the touch layout. Undo/Redo/Save are global commands. Icons: File Box (Definition), Database (Tree). Generic record type selectors accept Structure and Data Definition assets; uncontrolled `PinListEditor` keeps internal row selection so function pins expose record-type parameters on click/focus.
- **Inline NodeGraph asset controls** show icon + truncated name without subtitle (96x32px desktop, 44px touch) through `AssetPickerControl`'s `asset-picker-control` slot and `PickerIdentity`'s `picker-description` slot; nodes suppress Open Asset via a locally disabled asset-open context while Inspector pickers keep it. Utility-opened tree documents may stay in the background until explicitly opened; Save All, recovery and dirty-close guards include them.
- **SceneLayer UI controls** share the Overlay Add Component and Place Actors catalogs: Slider, Range Slider, Checkbox, Radio Button, Toggle, Text Input, Numeric Input, Dropdown (options via NamedListEditor), Progress Bar use typed PropertyGrid rows; visual slots reuse Material / Material Instance and Texture pickers; Virtualized List / Grid use SceneLayerActor class choices plus counts and dimensions; Mask, Mask Panel, Safe Area share layout rows; focus-neighbor choices include interactive controls. **2D Joystick** reuses the Overlay catalogs/placement and PropertyGrid (Background / Joystick Material via AssetPicker, Radius, Dead Zone, Enabled, Touch axis selectors).
- **Scene Inspector / Components**: the actor's component cards follow its properties under the Components panel's header: a **Search components** field (filters cards by name; "No Matching Components") and a **+** IconActionButton (`details-add-component`, catalog titled `Add Component To <Actor>`); it keeps the 28px island height on desktop and tablets. Outliner row menus share actor, class-asset and selection indexes (O(actors + assets + selection) per render; the class-asset index refreshes each render because registry contents change without replacing the registry).
- **Physics Constraint** Inspector rows reuse PropertyGrid and SearchDialog for a searchable scene-actor target, local anchors, frame rotations and degree-based hinge limits.
