# Asset registry

Shared surface for P2 Content Browser, import, thumbnails, and texture compression (engineplan §§2.4, 3.3, 3.5, 10.2). Implementation lives in `@babylonslate/assets`.

## Invariants

1. **Bounded header indexing.** Scan and browse read the 12-byte `.babasset` prefix, validate the header length (16 MiB maximum), then read exactly that header through `ProjectStorage.readBinaryRange`. Large inline payloads remain unread. Show References and Delete also include references from already-loaded open documents. Project-wide **text** search is a separate `ProjectSearchIndex` that may read Scene/Class (and legacy Graph) document chunks only ([global-search.md](global-search.md)).
2. **Content-root-aware from day one.** Roots are first-class. P13 mounts enabled plugin roots (`plugin:<guid>`) with optional `storage` and `readOnly`; P2 still tests a second synthetic root.
3. **Payloads on demand.** `AssetLoadingService` owns shared source/document representations and consumer scopes above the existing per-engine `ResourceCache`. Storage I/O, retained source bytes, decoded CPU data and GPU resources have separate accounting.
4. **File create/delete outside undo.** Registry owns asset files; `packages/edit` owns in-document edits ([command-layer.md](command-layer.md)).

Saving or renaming an indexed asset preserves inbound GUID references while rebuilding its outbound edges. Folder moves copy all files and empty directories, including source files and sidecars outside the asset index, before removing the source. Case-only renames use a recovery copy on case-insensitive volumes; a failed destination write restores the original, and failed recovery reports the retained backup path. Existing destinations are rejected rather than overwritten. These portable copies protect reported I/O failures; they are not filesystem-atomic across a process crash.

Folder moves and deletions wait for pending asset writes and creations before enumerating the tree. Writes submitted during relocation wait until it finishes; GUID-based saves resolve their current path after admission. This includes newly created assets that were not indexed when the move was requested.

**Destination path reservations.** Every operation that writes a new path (`createAsset` and imports, `duplicateAsset` / `copyAsset` / folder copies, `moveAsset`, `renameAsset`, `createFolder`) claims it synchronously with its index check, before its first await, and holds it until the write settles.

- Keys are case-folded, matching how `moveStorageFile` treats spellings that alias on case-insensitive volumes.
- A path that is reserved or indexed rejects the second writer with the usual `Asset already exists` / `Target path already exists` / `Folder already exists` error. Overlapping writers can no longer both succeed and orphan the first GUID.
- Duplicate skips names another write holds and files already on disk (including unindexed ones), so overlapping Duplicates of one asset get distinct `stem_N` names.
- Indexing a newly created or duplicated file refuses to evict a different GUID at that path; rescans and `reindexPath` still replace entries.
- The Content Browser marks Duplicate and **Create Material Instance** busy while they run, so a repeated press or Mod+D waits; failures appear in the operation alert.

`unmountRoot` also forgets that root's folders unless another mounted root covers them, so a remount (every plugin sync) shows only folders still on disk.

Asset renames preserve Unicode display names and the complete asset suffix (including `.class.babasset` and `.scene.babasset`). Invalid path names are rejected. Class renames update saved and open instances, child-Class parents, typed Class references and project settings; an unwritable referrer blocks the operation. Referrer write failures restore the original bytes and Class path. Open referrers retain unsaved edits; their old undo commands are discarded so undo cannot restore a missing Class name.

Saved layouts include each tab's asset GUID, allowing tabs, dock layouts and panel placements to follow renames or folder moves on reopen. Legacy layout entries with missing paths are skipped so a stale tab cannot prevent opening the project; other read failures remain visible.

Retained `.babylonslate-move-*` recovery folders stay on disk for recovery/export but are excluded from asset discovery, so their duplicate GUIDs cannot replace live entries after reopening.

## Content roots

```ts
interface ContentRoot {
  id: string;
  kind: "project" | "plugin" | "synthetic";
  /** Path prefix inside ProjectStorage holding this root's `.babasset` tree. */
  pathPrefix: string;
  /** Engine plugin roots refuse create/delete/move. */
  readOnly?: boolean;
  /** Engine plugins mount from a separate storage; defaults to the registry's. */
  storage?: ProjectStorage;
}
```

- Project open mounts the project root (`assets/`). Enabled plugins mount as extra roots; disable unmounts them. Detail: [plugins.md](plugins.md).
- Guids are unique across the project and its plugins; references are ordinary guid edges.
- Resolve / watch / save paths always take a root id (or resolve via guid → root). `storageFor(rootId)` / `blobsFor(rootId)` use `root.storage ?? this.storage` and `{pathPrefix}/.blobs`.
- `createAsset` / `deleteAsset` / `moveAsset` throw on `readOnly`. Cross-root `moveAsset` throws until an explicit fix-up pass exists ([plugins.md](plugins.md#cross-root-moves)).
- `listDocumentPaths({ rootId: "project" })` feeds `project.json` scenes/graphs — plugin Class/Scene paths must not leak into the manifest. Play/search use `registry.list()`.

## Registry surface

| API | Role |
| --- | --- |
| `mountRoot` / `unmountRoot` | Add or remove a content root and (re)scan headers; unmount drops the root's folders |
| `reindexPath` | Re-read one `.babasset` header after an in-place save |
| `getByGuid` / `list` / `folderTree` | Index queries (folder tree includes marker-backed empty folders) |
| `createFolder` / `moveFolder` | Empty folders (`.babylonslate-folder`) and folder moves |
| `moveAsset` / `renameAsset` / `duplicateAsset` / `copyAsset` | Path ops; guid stable on move/rename |
| `showReferences(guid)` | Inbound + outbound deps from header `dependencies[]` |
| `importFile` | Document-picker bytes → importers → write `.babasset` + enqueue work |
| `createAsset` / `deleteAsset` / `deleteFolder` | File ops (confirm delete in UI via Show References) |
| `accountedPayloadBytes` | Requested chunk bytes; not a measurement of physical storage I/O |
| `payloadLoader.snapshot()` | Chunk request counts and the latest 128 paths, chunks, revisions, statuses and byte counts; retains no payloads |
| `storageFor(rootId).getReadMetrics?.()` | Actual adapter bytes and full/range read operations |
| `getAssetLocator` / `readChunk` / `readAssetDocument` | Revision-checked reads of selected content only |
| `generation` | Monotonic change counter (below) |

### Generation

- `AssetRegistry.generation` advances on every change to what the index reports: a header indexed or removed (scan, create, import, `reindexPath` after a save or chunk write, delete, placeholders), a move or rename, a folder added, moved or removed, a root mounted or unmounted, a Texture's compression state or committed encode (the registry's own rewrites), and an atlas status change. Reads never advance it.
- `IndexedAsset` entries are replaced, never mutated, so a memo keyed on the generation sees every change.
- `RegistryGenerationClock` holds the counter. `ProjectService` passes one clock to every project registry and advances it when a project closes, so a remount or project switch never reports a lower or repeated generation. Its `registryGeneration` getter reads it. Export scans use their own registry and clock.
- The editor combines it with plugin, search-index and Show Plugin Content changes into `registryEpoch` (see Content Browser below).

### Storage and dependency metadata

`AccountedPayloadLoader` receives a storage locator and chunk descriptor. Inline chunks read exactly their range; blob chunks read only their named blob. Header/payload reads carry an opaque storage revision, validate bounds and lengths, and verify chunk hashes. A concurrent save invalidates the old request. Browser files use `Blob.slice`; a ranged HTTP response must be a valid partial response. A server returning the whole file is rejected and its transferred bytes are counted, never reported as a successful partial read.

Header dependency metadata has an independent version:

| Field | Meaning |
| --- | --- |
| `dependencyMetadataVersion: 1` | Complete typed collection contract |
| `dependencies` | All declared references for export reachability, Show References and deletion |
| `requiredDependencies` | Only edges needed to prepare this consumer now, including the references of Hard (Load With Owner) declarations |
| `requiredVariableNames` (Classes) | Property keys consumed by synchronous readers or declared Hard (Load With Owner), so actor/component overrides inherit the required role |
| `classReferences` / `requiredClassReferences` | Typed Class identities resolved to GUIDs from the catalog, including imports encoded without authoring context |
| `consoleCommand` (Classes) | Command name, description and parameters for registration without graph loading |

Active actor/component resources, materials, textures, animation clips, particle emitters, audio routing, font fallbacks and enabled default SceneLayers are required. Input bindings, called function modules, literal Tree inputs of synchronous data readers, and data schemas are also required by their active Class; typed upstream graph inputs are followed with a cycle guard. Streamed scenes, gameplay Class/asset literals, data values, disabled default layers and material preview meshes remain references for later use, unless their declaration is Hard (see below). The same GUID may occur in both roles; a required occurrence wins for that consumer. Class IDs resolve using catalog identities, and data/graph values follow their declared schemas, including arrays, maps and nested structures. Ordinary names, IDs and source text are not references. Native class identities, including the exact built-in Behaviour Tree task, decorator, service and composite IDs, do not become asset reads; missing or ambiguous required custom identities produce an actionable error. Actual subsystem leaf Classes and the selected Game Instance are startup consumers. Debug command registration uses header metadata and acquires the chosen Class only when invoked.

**Loading policy.** Class variables, Structure fields and Data Definition fields of asset or Class type are Soft (Load On Demand) by default: the reference is only in `dependencies` (and `classReferences`). A declaration persisted with `loading: "hard"` (Load With Owner) also puts the GUID in `requiredDependencies` (a Class reference in `requiredClassReferences`) of the owning asset. For a Class variable that covers its default, including array items and map keys and values, and the property key joins `requiredVariableNames`, so Scene actors and prefab components that override it require the override too. For a value walked through a Structure or Data Definition (a struct-typed variable, instance override or Data Tree entry) the innermost declaring field decides; a Data Tree entry takes the Definition's current Loading when it can be resolved and its own snapshot otherwise. Synchronous-reader inference still requires the whole variable. `ASSET_DEPENDENCY_METADATA_VERSION` is unchanged and saves re-stamp as before, so a changed declaration reaches dependants when they are next saved.

Imports and saves stamp both graphs. Template rewrites also stamp their final payload, so the Basic 3D mannequin's authored lit Material and Texture become required when the template assigns the Model slot. Show References and Delete also overlay already-open unsaved documents. Legacy incomplete metadata is listed in the existing migration prompt; approving migration runs `upgradeAssetDependencyMetadata`, a versioned, cancellable maintenance pass. It reads document/schema data explicitly, preserves inline bytes and external blob locators, and never fetches unrelated source blobs. Normal project opening does not perform this pass. Loading an unupgraded asset reports its GUID and the required upgrade. Read-only content must be upgraded by its provider; bundled starter content carries current metadata.

### Scoped source loading

Scoped reads pass their cancellation signal through registry catalog/chunk reads, blob storage and the storage adapter. A canceled scoped header refresh cannot cancel an unrelated metadata reader. Noninterruptible storage work remains pending until its transport settles; cancellation never releases its reservation by racing the real read.

`ProjectService.assetLoadingService` is shared by editor documents, previews and Play. Cache identities include project/root, asset, revision and representation. Required closures tolerate cycles, compatible in-flight reads/decodes are deduplicated, and cancellation stops shared work only after its last owner leaves. Failed requests can be retried. Scope release makes unowned data eligible for expiry/LRU trimming and removes decoded/source references when evicted; a project switch disposes the session.

Root load state stays `loading` until its required closure is usable and becomes `failed` when a required dependency fails. Cancelling one waiter preserves another waiter's readiness. Completed cache entries retain representation metadata without decoder closures that could capture otherwise-evicted source buffers. Play refreshes bounded catalog headers before following dependency edges and rejects a save that changes them during preparation. Each request refreshes its catalog once when it starts, and each source read validates storage again; later consistency checks compare against the registry's current snapshot instead of re-reading headers. A Play preparation refreshes its closure once, prepares documents, chunks and compiled code from that snapshot (`refresh: false`), and validates every revision against storage again before publishing, so a cold spawn during Play does not repeat bounded header reads for each step. A catalog scan re-reads a file, up to three times, when a save lands between its two bounded header reads.

Admission reserves retained source, decoded CPU and temporary bytes before expensive work. Work uses bounded concurrency with gameplay before explicit preload before background work. Requests larger than a budget fail with the asset and consumer, instead of waiting forever or disposing owned resources. Initial configurable defaults are 128 MiB source, 128 MiB decoded, 64 MiB temporary, four concurrent operations and one second of unowned retention. These are provisional implementation defaults, not measured A16 limits. GPU accounting and native disposal stay in `ResourceCache`; Babylon objects do not enter the platform-independent assets package.

Scoped Play compilation lives in the source service's owned decoded cache. Explicit editor and toolbar compilation uses a separate `GraphScriptCompileCache` LRU with configurable `maxBytes` and `maxEntries`, provisionally 16 MiB and 256 combined graph/animation entries. Its estimate includes retained key strings, serialized compiled results and entry overhead. Oversized results are returned without caching; eviction drops only cache references, preserving any caller's active result. These editor defaults also await physical-device measurement.

A save or background bake can replace a Scene while Play prepares it. Typed source-revision invalidation retries the complete acquisition at most three times, releasing each failed scope before resolving the current catalog and selected chunks again. Ordinary editor document and chunk reads also retry their complete snapshot up to three times. Publication still validates the full revision set. Cancellation, superseded requests, project changes, corruption and budget failures do not trigger retries; repeatedly changing sources produce an actionable failure asking the developer to let saving or baking finish.

`snapshot()` exposes retained/reserved bytes, active/queued work, cache hits, revisions, representations and retaining owners. Storage metrics separately report actual read bytes, including failed range transports. Physical A16 iPad, Android and desktop peak-memory/frame-time qualification remains required; unit tests establish contracts, not device performance results.

## NodeGraph Asset Registry

Unreal AssetRegistry-style query nodes ([scripting](scripting.md#asset-registry-nodes)) read a **runtime asset catalog**: a list of `RuntimeAssetCatalogEntry` (`@babylonslate/core`: `guid`, header `name`, `type`, authored `path`, Class assets' `classId` and `parentClass`, header `dependencies`, `requiredDependencies`). `RuntimeAssetCatalog` (`@babylonslate/runtime`) is the pure query module; scripts reach it as `ctx.assetRegistry`.

| Host | Catalog contents |
| --- | --- |
| Editor Play | The **packaged set** from registry headers, snapshotted when Play starts and sent in the `load` control as `assetCatalog` |
| Preview Build / exported game | Manifest entries that carry `assetPath` (every exported authored asset; generated entries such as compiled scripts and sidecars have none), read by the player into the same `load` control field |
| Editor graph hosts (Editor Utility Object / Editor Function Library) | The live registry across mounted roots, editor-only assets included, rebuilt on first use after `registry.generation` changes; the registry's empty folders count as folders |

- **Paths** are the registry's full storage paths, including the content-root prefix: the project root is `assets`, a plugin's is `<plugin folder>/assets`, so plugin assets never collide with project assets. An asset's **Folder** is the parent directory of its path.
- **Folder inputs** are trimmed, lose leading and trailing `/`, and collapse `//`; matching is exact and case-sensitive. An empty Folder with Recursive means every root. Exported games know only the folders of packaged assets, so an empty folder does not exist there.
- **Class queries** resolve ancestry from the catalog's `classId` / `parentClass` chain and continue into engine base classes through the object-model class registry; no Class has to be loaded.
- **Dependencies and referencers** consider only catalog entries; Hard Only uses `requiredDependencies`.
- **Packaged set.** The export closure ([exporter](exporter.md#export-closure)) decides it, so Play and exports agree. Editor Play uses the header-only walk (`collectHeaderReachability`) from the same roots, with the Scene it starts from as an extra Scene root beside the project startup Scene; editor-only assets and disabled plugin content are excluded in both.

### Always Package Folders

`ProjectSettings.alwaysPackageFolders` (default `[]`, normalized wherever project settings default) lists storage folders such as `assets/Weapons`. Every asset under a listed folder, subfolders included, is an export and Play root, so it ships and appears in the catalog even when nothing references it. Editor-only assets and disabled plugin content stay out.

- **Project Settings → Export → Always Package Folders** lists the folders; **Add Folder** opens a folder picker over every mounted root, and a folder that no longer exists shows a **Missing Folder** badge.
- Moving or renaming a folder in the Content Browser rewrites matching entries by path prefix, and deleting one removes them.

## Importers

Pure functions keyed by extension: `(bytes, options) → ImportResult[]`.

| Inputs | Produces |
| --- | --- |
| images | Texture |
| ENV / prefiltered DDS | Texture with cube dimension, HDR encoding, face size and roughness mip metadata; original `source` chunk retained |
| glb / gltf | Model (+ Material / Texture / Skeleton / Animation as needed) |
| audio | Audio |
| woff2 / woff / ttf / otf | Font |
| facetype JSON / MSDF JSON + PNG | Attach to an existing Font, or **create** a Font when the family is missing. MSDF PNG is a Font sidecar (`msdf-atlas-png`), not a Texture |
| `.babasset` | Unpack / remapped copy |

Cross-project import remaps colliding guids and rewrites references in the incoming set. Template instantiate keeps guids as-is.

Environment imports accept Babylon RGBD ENV v1/v2 and square, power-of-two, six-face DDS cubes with a complete mip chain in linear RGBA16F or RGBA32F (legacy FourCC or DX10). ENV base faces must be at least 2×2 to match the native Babylon loader; their complete chain still includes 1×1 mips. DDS must already be authored as prefiltered: headers establish layout and encoding, not whether convolution was performed. Ambiguous RGB/DXT DDS, arrays, volumes, missing faces/mips and out-of-bounds data are rejected. ENV headers, image dimensions, face ranges and optional irradiance coefficients are validated; Babylon owns image decoding and reports invalid encoded pixels when loading. HDR conversion and runtime prefiltering are not part of import.

Cube Texture metadata is read-only in the existing asset editor. Assign cubes through Scene Defaults → Environment Texture. Ordinary Material Texture Sample/Parameter pickers and runtime validators require 2D textures. Source bytes and metadata survive rename, reopen and export; the normal scene GUID reference retains the cube in export closure. Cube dimension bypasses compression and 2D LOD even if stale usage/encode settings are present.

## Thumbnails

- Surface Material tiles render the saved material on a sphere. Actor-derived Class (Actor Prefab) tiles render their saved component hierarchy, including inherited components, imported models and assigned materials. Non-Actor classes, non-mesh Material domains, empty prefabs and failed captures retain their type icon.
- Browsing requests only existing derived thumbnails; missing previews keep their type icon without reading source assets. Select Models, Animations, Materials or Actor Prefabs and choose **Generate Thumbnail** / **Generate Thumbnails** from the context menu (right-click or long-press) to request capture. This action requires **Generate Thumbnails** in Engine Settings to be enabled. Saved asset and transitive dependency revisions key the disk/decoded caches; prefab keys also include project pixels-per-unit. Unsaved document edits do not change the cached image.
- All rendered types share one serialized capture queue; newer queued revisions replace older ones. Explicit selection retains every lightweight job descriptor, while only one active job reads payloads or prepares resources. Each capture owns a temporary background-priority source scope and reads only its selected asset/dependencies and chosen texture representations. Completion, cancellation and project switches release that scope. Captures use the project Engine and shared ResourceCache, dispose temporary scenes/materials/targets, yield between jobs, and reject stale results after project switches, thumbnail disablement or newer saves. Recent missing-capture attempts are bounded to 256 entries.
- Model and Animation imports and saves also request captures. Existing project assets require the explicit context action when their cached image is missing.
- Model/Animation captures hold one background reservation on the shared per-engine preparation scheduler from decode through cleanup, including target/retarget overlap and readback buffers. Their construction-model loader makes no nested admission requests. Prefab model loads use the same scheduler individually at background priority. Oversized work keeps the icon; cancellation removes queued work and in-flight native admission remains held until that work settles. Texture ownership remains in ResourceCache.
- Captures wait for imported materials/textures to become ready before reading the shared Engine's transparent 128px render target. Animation thumbnails use the selected clip's first pose, including a retargeted source clip; unavailable clips keep the type icon. Failed captures can be retried with the explicit action.
- Rendered thumbnails use a versioned derived-data key so older blank captures can be replaced. A completed capture invalidates only that asset's decoded cache and thumbnail revision. Mounted tiles retain their current images while replacements load; unrelated assets keep the same blob URLs throughout batch generation. Cancelled refreshes discard only newly allocated URLs; Texture thumbnail storage is unchanged.
- Superseded tile loads release their newly created Blob URLs without publishing stale images or revoking URLs still owned by the current grid.

Texture thumbnails generate at import (on the encode worker when textures compress). Texture thumbs: `generateThumbnailBytes` passes the source chunk MIME into the decode `Blob` (JPEG/PNG/WebP); JPEG sources keep JPEG output; other image sources use PNG to preserve alpha. Existing JPEG thumbnails from alpha-capable sources regenerate lazily when first displayed. Model thumbs: the editor captures the **construction** GLB on the shared Engine (`captureModelThumbnailPng` in `@babylonslate/render`) as a **transparent PNG** (max edge 128) after an explicit **Generate Thumbnail(s)** request, a Model/Animation import, or a Model/Animation document save. Do **not** compile slot NodeMaterials or construct a second `ResourceCache` (default 512MiB ceiling) for that throwaway Scene — extra GPU on the shared Engine can lose the WebGL context and remount Material Preview (`previewSceneEpoch`). Leftover OBJ/STL `.babasset`s from older projects keep the Lucide fallback if they cannot load as glTF. Stored under `derived/{projectGuid}/thumbnails/` as small compressed images. Content Browser sniffs PNG vs JPEG magic when creating the tile `Blob` and decodes lazily for **window-virtualised** grid cells only (`p18-content-browser-virtualize`). Off-screen blob URLs revoke. Thumbnail LRU is **separate** from the scene payload / P4 cache (`ThumbnailDecodeLru.delete` invalidates a Model tile after recapture). Folder **TreeView** is already windowed.

## Texture compression state

Per Texture asset (engineplan §3.5):

| State | Meaning |
| --- | --- |
| `pending` | Source written; not yet queued |
| `encoding` | Encode job in flight |
| `compressed` | KTX2 chunk present |
| `fallback_uncompressed` | Transcoder unavailable / failed — render from source |
| `encode_failed` | Worker encode failed — **source still renders**. `encode_failed` is a badge/diagnostic, not a broken texture. |

Queue: `EncodeQueue` on `ProjectService` (one job at a time; pause on document `visibilitychange` / Preview hooks; recycle counter after N jobs). `DocumentProvider` owns the queue-pause subscription and encode worker: its effect initializes them and provider unmount disposes them, including Strict Mode probe remounts. Closing a project only clears project-scoped registry/index/plugin state, so the provider-lifetime queue resources remain available for the next project. Import of compressible textures enqueues immediately; `commitCompressedTexture` writes the KTX2 chunk + `compressed` state. The registry owns `compressionState`, `ktx2ChunkId`, `encodeError`, `encodeWallMs`, `ktx2Width`, `ktx2Height`, `ktx2BlockAlign` and `ktx2Sha256`: saving a Texture document takes them from the file, so a tab opened before an encode committed cannot point `ktx2ChunkId` back at a superseded encode. Policy defaults leave pixel art, sprites, UI, and fonts uncompressed (no `pending` state). Compressed Textures encode at base dimensions rounded up to a multiple of 4 after the clamp and Downsample (`textureEncodePadding`, `textureEncodeSize`: 1×1 → 4×4, 1000×750 → 1000×752, whole image resampled once), so they stay block-compressed on WebGPU, which rejects ASTC/BC7 uploads whose base size is not block-aligned. **Atlases**, Textures a Tileset, Sprite or Sprite Animation uses, keep their size so tile and frame rects are not resampled; a misaligned atlas decodes to RGBA on WebGPU ([render](render.md#project-lifetime-engine)). Particle always aligns, atlas or not. A known size already on the grid is never padded. The size is the payload's `width` / `height`, which image and Model imports record (`sniffSourceImageSize`: PNG, JPEG, WebP, GIF; WebP, GIF and Model-extracted Textures imported earlier have none), else the source bytes sniffed the same way at enqueue. Only a source none of those formats reads pads without a known size: a no-op for a grid size, but it records `ktx2BlockAlign`, so such a Texture re-encodes once if it later becomes an atlas. The resolver, overlay sizing and `ResourceCache` accounting keep `sniffImageSize` (PNG, JPEG), so an existing size-less WebP or GIF Texture keeps its preferred id; a new Model Texture's recorded size also makes the registry and resolver agree on its Downsample clamp. The padding is encode-only: only Particle keys `blockAlign: 4` into the settings hash (`textureEncodeChunkId`), so existing `ktx2:<hash>` ids never change, an aligned Texture is never re-encoded by the alignment pass (except that one-off atlas case), the resolver's preferred id still matches, and a re-encode off the grid overwrites the same chunk. Commits otherwise keep superseded `ktx2:` chunks, and the resolver binds one whose id it prefers (editor LOD, or a registry and resolver that compute different ids, e.g. under a project max other than 2048) or else the first; so a commit on the grid for a Texture no atlas uses drops older chunks off the grid, while an atlas keeps them (its own-size encode, for a Usage switched back from Particle). A Texture whose committed encode was already on the grid never re-commits for alignment, so it keeps any older off-grid chunk (an earlier Downsample's), which binds only in those cases and then decodes to RGBA on WebGPU. `textureEncodeSettingsFor(payload, projectSettings, usage, { atlas, sourceSize })` builds every queued encode's settings (quality, Downsample and project clamp, padding from the payload size or the sniffed source); each job carries its chunk id and Usage. A commit records the committed KTX2's `ktx2Width` / `ktx2Height`, `ktx2BlockAlign` whenever padding was requested (even as a no-op for a grid size), and `ktx2Sha256` of those bytes. The pass trusts that record only while `ktx2Sha256` matches the committed chunk's sha256: a writer that replaced the encode but kept the fields (an editor from before they existed) leaves it describing other bytes, so the pass ignores it and falls back as for a legacy encode. Max *import* dimension clamp default 2048 (Project Settings). Per Texture **Downsample** (`payload.downsample`: Full / 1/2 / 1/4 / 1/8 / 1/16; legacy `maxDimension` migrates). Editor Texture LOD is Engine Settings only and does not change export. **Retry Encoding** in Project Settings requeues every failed, fallback or interrupted encode; Texture Details retries one Texture (after a failed encode, or while its committed encode breaks the size rule, below). Explicit texture processing can re-queue `fallback_uncompressed`, `pending`, and interrupted `encoding` jobs; registry mounting does not start this work, except a Texture this session's queue already holds (`EncodeQueue.has`: waiting or encoding; a commit in flight is awaited first), so remounts (Content Browser changes, returning to the app) never queue a second copy. **Alignment pass:** saving a Tileset, Sprite or Sprite Animation writes `atlasTextures` header meta (`atlasTextureGuids`); the registry indexes atlas referrers from it. Explicit legacy-atlas maintenance can decode metadata-less documents (`resolveLegacyAtlasReferrers`), remembering their textures by type and document chunk sha256 in a map `ProjectService` keeps across remounts (`legacyAtlasCache`), so an unchanged one is not read and decoded again. `reconcileTextureAlignment` requeues only `compressed` Textures whose encode is stale: a non-atlas encode off the grid (recorded size; else, for a legacy encode under today's id, the clamped payload size when it is on the grid; else the committed chunk's KTX2 header, which also tells a padded encode whose record an older editor dropped from an unpadded one, cached by chunk sha256 across remounts) that a re-encode would change (padded, or under current settings, both built as the requeue builds them, with the sniffed source size when the payload has none), or a padded atlas encode. It skips Particle, other states, Textures the queue already holds, Textures without source `pixels`, and read-only roots and plugins. **Source control decides what re-encodes in the background.** Project open, registry remounts, and source-control setting changes do not run a project-wide alignment pass. Explicit processing and newly imported/edited content can run it. With source control enabled, older shared Textures require explicit processing: it re-aligns only when the user re-encodes it (a Texture Details change that re-encodes: Downsample, Compression Quality, or a Usage change into or out of Particle; or **Retry Encoding**, each a forced retry with the atlas-aware settings), and until then still draws (RGBA on WebGPU). Texture Details shows **Retry Encoding** (no extra note) for a `compressed` Texture whose committed encode the pass would requeue while no job holds it (`ProjectService.textureAlignmentStale` → `AssetRegistry.isTextureAlignmentStale`, with the tab's Usage, rechecked on every registry change); this also applies with Enable off until processing is requested. A guarded job the queue drops unencoded (`EncodeQueue` `onDrop`), or whose commit is refused, also reports a registry change, so an open Texture Details offers the button once nothing will re-encode the Texture. While the Texture is read-only (`textureUsageBlockedReason`: a read-only root or plugin, or another user's lock until **Edit Anyway**) the button is disabled and Details changes do not re-encode, as the tab refuses every other edit. Only a Texture whose committed encode is still the one this project session wrote (the KTX2 chunk sha256 each commit records, or that a file this session created carries: an import, a `.babasset` import, Duplicate or Copy, the user's own re-encode, or the pass's own re-encode from while Enable was off) is still rechecked, such as an odd import a Tileset then picks; a git revert or pull that replaces that encode ends it, checked against the file on disk when a job writes, so a job queued before the revert writes nothing even before a rescan. A Texture the registry creates with an encode already committed (a `.babasset` import, including a bundle, or a Duplicate or Copy) is new work, not a shared file: the registry reports it as it is indexed (`setCreatedTextureListener`), so its encode counts as this session's, and `importFile` and `duplicateAsset` run the pass for it at once, whatever the setting, as an image import pads its first encode; a check that overlaps another for the same Texture skips it, so no second copy is queued, across remounts too (`ProjectService` hands every registry the same in-flight set, `alignmentRequeues`, as it does the queue). No source-control lock is taken for any of it. `ProjectService` reads the setting from `project.json` at load, and `DocumentProvider` reports in-session changes (`setSourceControlEnabled`, not through the debounced project save): turning it on stops guarded jobs it no longer permits; turning it off changes permissions without starting processing. The pass's re-encodes are guarded jobs (`EncodeJobGuard`, whose `canWrite` is `ProjectService`'s rule above): they write no `pending` or `encoding` state, so the Texture stays `compressed` on its old encode until the commit, and no partially queued state is left for a later explicit `requeueUncompressedTextures` pass. Each job asks `canWrite` again when it reaches the front of the queue (from the index) and before its commit or `encode_failed` write, inside the Texture's serialized write, with the header of the file on disk that write replaces (the index describes an external change only after a rescan), so turning source control on while it waits or encodes drops it with nothing written. A guarded job also carries its source's sha256 and writes nothing once the file's `pixels` chunk differs (`encodeJobMayWrite`), so an encode of replaced pixels never lands. The pass also asks per Texture, before and again after it reads the committed encode. `DocumentProvider` also reports an open Texture tab's Usage, saved or not (`ProjectService.setOpenTextureUsage`), which the pass checks and re-encodes with, so it never undoes an unsaved Details Usage such as Particle on an atlas. Atlas status changes (save, delete, duplicate, `.babasset` import, plugin mounts) run the pass for the affected Textures, and a committed encode rechecks its Texture with that Usage (a Tileset may have picked it mid-encode), unless another Usage chose the encode (an unsaved Details edit whose tab has closed). Encode callbacks rewrite the Texture (advancing the registry generation) and emit `ProjectService.onRegistryChange`, so `registryEpoch` changes and Content Browser badges refresh live. A hung worker fails the job on timeout (or `error` / `messageerror`) so the queue keeps pumping.

Loader prefers KTX2 when present (`selectTextureChunk`); self-hosted transcoder via `configureKtx2Transcoder(KhronosTextureContainer2)` in `createEngine`, URLs under `apps/editor/public/ktx2/` (vendored `babylon.ktx2Decoder.js`, MSC Basis, UASTC→ASTC/BC7/RGBA/R8/RG8, Zstd). Draco / meshopt glTF decoders are similarly self-hosted under `public/draco/` and `public/meshopt/` (`configureGltfMeshDecoders`). `probeKtx2TranscoderAvailable` HEADs/GETs **every** of those files (wasm included), not only the JS decoder. Silent fallback is forbidden — state must be explicit. Each vendored decoder/encoder directory (`ktx2/`, `basis/`, `draco/`, `meshopt/`, `havok/`) has a `README.md` recording the upstream release, source path, SHA-256 per file and the refresh steps.

**Encode path (source-first transferable):** the editor wires `createWorkerEncodeFn` with `editorEncodeWorkerUrl()` (`publicAssetUrl("basis/encode-worker.js")` so GitHub Pages `/BabylonSlate/` and Capacitor `/` both resolve) plus vendored Basis encoder wasm under `apps/editor/public/basis/` into `EncodeQueue`. The host posts a transferable `source` `ArrayBuffer` plus MIME (`SourceEncodeRequest`); the worker decodes, clamps and block-aligns (a plain-JS mirror of `textureEncodeSize`, pinned by `apps/editor/src/lib/encode-worker.test.ts`), then Basis-encodes. Worker init errors clear the cached `ready` promise so the next job can spawn a new Worker. If the worker cannot decode (`decode_unavailable`), the host runs Safari / odd-MIME `Image.decode()` (`decodeSourceToRgba`) and posts a transferable RGBA job (`RgbaEncodeRequest`) — encode stays off the main thread. `encode_failed` persists `payload.encodeError` (Output Log + Texture Settings); a later successful `commitCompressedTexture` clears it. Source `pixels` stay on the asset; `selectTextureChunk` still returns `kind: "source"` when there is no usable KTX2, so `encode_failed` does **not** make the texture unusable. Thumbnails pass the source chunk MIME into `createImageBitmap` (`generateThumbnailBytes(..., mime)`); JPEG sources keep JPEG output; other image sources use PNG to preserve alpha. Existing JPEG thumbnails from alpha-capable sources regenerate lazily when first displayed. Unit tests keep `stubEncodeKtx2` as the default when no Worker is injected. CI runs a real Basis encode smoke (`a16-encode-smoke.test.ts` / `createNodeBasisEncodeFn`) against checked-in A16 wall envelopes in `@babylonslate/test-kit`. On project enter, `probeKtx2TranscoderAvailable(editorKtx2PublicBase())` marks compressed textures `fallback_uncompressed` when **any** decoder/wasm file is missing. Editor `createEngine` passes the same KTX2 base. Packed Preview/export textures use `playerFilesHaveKtx2Transcoder` on the player file map before choosing KTX2 vs `pixels`. The file list (`KTX2_TRANSCODER_RELATIVE_FILES`) lives in `@babylonslate/assets` so `loadPlayerDistFiles` / export can spread it without importing `@babylonslate/render`.

**Model ingest is GLB/glTF only.** `MODEL_EXTENSIONS` is `glb`/`gltf`. Parse must succeed (GLB magic / glTF JSON `asset`); failure throws — there is no stub Model. `importByExtension("mesh.obj")` / `.fbx` / `.stl` throw. Stored `source` MIME is `model/gltf-binary` or `model/gltf+json`. Play and preview load only `@babylonjs/loaders/glTF/2.0`.

**Editor binding is `MeshComponent.assetGuid`.** There is no `ModelComponent`. A Model (or Mesh) asset on a MeshComponent wins over `meshKind`. Inspector hides **Mesh Kind** while that guid is set so the row is not a Box primitive. The editor keeps a hidden unpickable named root; picking, outline, and (unlocked) gizmos follow the instantiated GLB. When a collider or extra visual forces an origin hierarchy, the GLB parents under the MeshComponent child (`editorActor:<id>|<componentId>`), not the origin.

**OBJ convert-on-import:** Content Browser `accept` is registered importer extensions **plus `.obj`, `.fbx` and `.stl`**. `convertObjToGlb` in `@babylonslate/render` loads OBJ (+ optional MTL/maps grouped in the same pick) on a throwaway Scene, exports GLB, then `importFile(..., "Hero.glb", glbBytes)`. Consumed sidecars are not also imported as Textures. Missing MTL is fine. Conversion failure is a per-file import error. OBJ has no skins or clips — the resulting Model has no Skeleton/Animation. Multi-object OBJ groups become multiple static glTF meshes.

**STL convert-on-import:** `convertStlImportBatch` in `@babylonslate/render` loads binary or ASCII STL with Babylon's `STLFileLoader` on a throwaway Scene and exports GLB (`exportConvertedSceneToGlb`, shared with OBJ), after OBJ conversion in the same batch. STL is geometry only: the Model gets the default material slot, no Skeleton and no Animation. A file with no facets is a per-file import error.

**FBX convert-on-import:** A disposable worker loads the FBX with Babylon's FBX loader (`@babylonjs/loaders` 9.29, PBR materials, `unitScale: "meters"`) on a NullEngine scratch scene, which converts source units and axes to meters/Y-up, then exports GLB through the serializer step shared with OBJ/STL and uses the existing Model, Material, Skeleton, and Animation importer. External texture paths resolve to the selected image sidecars by basename (with a suffix fallback for Babylon 9.29's ASCII parser, which drops the `\` in `Textures\albedo.png`); the sidecar bytes are embedded unchanged. Select external texture images alongside the FBX; missing or ambiguous sidecars produce per-file errors. Conversion is local; Play and exported games only need canonical GLB data. Proprietary shader graphs and DCC constraints are not preserved as editable authoring data.

The converter is exposed through `@babylonslate/render/fbx-import`, keeping the FBX loader out of the player bundle. Consumed FBX image sidecars remain available to other models in a mixed import batch, then are excluded from standalone Texture imports.

**Clip ranges:** Duration is the source take's maximum time minus its minimum time. Names are deterministic and unique, including unnamed takes. Play and the exported player repair legacy absolute-end-time durations from available model sources.
**GLB/glTF import:** Content Browser import batches GLB/glTF with image (and `.gltf` `.bin`) sidecars the same way OBJ groups MTL/maps (`groupGltfImportSidecars` / `embedGltfImportBatch`, after OBJ convert). Shared pack atlases (Kenney Holiday `Textures/colormap.png`, Mannequin `Textures/texture-d.png`) match by URI or basename and are **consumed** — not also imported as standalone Textures. `importModel` / `registry.importFile({ sidecars })` run `ingestGltfForImport`: `embedGlbExternalImages` into the stored BIN, then `stripUnmatchedGltfImageUris` so leftover relative URIs cannot 404 from a blob URL. A `.gltf` whose `buffers[0].uri` is a relative path with no matching `.bin` sidecar throws (`MISSING_GLTF_BIN`) instead of storing an empty-BIN GLB. Content Browser `embedGltfImportBatch` catches that per model (keeps the original `.gltf` so `importFile` reports it in the import-error alert) and always clears Import busy in `runWithContentBrowserImportBusy` — a missing BIN is a per-file alert, not a stuck Import button. Other files in the same pick still import. Picker `.bin` / images that grouping missed (FAB `buffers/Foo.bin` vs `Foo.bin`) are still passed into ingest’s sidecar map. `parseGlbForBrowse` extracts materials, embedded images, clip names/durations, and rig classification. glTF `bufferView.byteOffset` defaults to **0** when omitted; image bytes are **copied** out of the BIN (`slice`, not a view that aliases Model `source`). Empty image bytes write no `pixels` chunk and **must not** set `compressionState: "pending"` (encode would never start). `KHR_materials_unlit` sets browse `unlit: true`; import seeds that slot’s Material with `shadingModel: "unlit"` (otherwise `"pbr"`). Import uniquifies every dependent name in the batch (`nextCopyName`) so a Texture and Material that share a glTF stem do not collide. It creates a Material per glTF slot (albedo Texture Sample → Base Color), **auto-applies** those Materials on named `materialSlots`, and a Model with `{ materialSlots, clipNames, skeletonGuid, importScale }`. New imports stamp `importScale` from Engine Settings **Model Import Default Scale** (default 10). Missing `importScale` on existing assets normalizes to **1**. Play/editor apply it on a `__importScale` child under the actor placeholder so scene/nodegraph scale stay independent. A valid GLB with no materials still becomes a Model (default/empty slot). Static / no-clip files stay `rigKind: "none"` (no Skeleton). Clearing a slot to Default/None restores the glTF construction material. Header-only save keeps the `source` GLB chunk; slot Material guids go in `header.dependencies[]`. `layout.json` `asset-settings:…` Model / Animation tabs reopen as `model:…` / `animation:…`.

**Skeleton and Animation dependents:** `rigKind` is `"skin"` when `skins[]` is non-empty; `"hierarchy"` when there are no skins and clips target parented **Mesh** parts that share an ancestor; else `"none"` (root-only object clips, two independent animated meshes, static meshes). Hierarchy `boneNames` is that ancestor tree (targeted meshes + parents), not every mesh in the file. `importModel` creates one Skeleton when `rigKind !== "none"` (`kind` + `boneNames` = skin joint names or hierarchy node names; catalog names are glTF JSON names, not `__root__`). One Animation per glTF animation (`clipName`, `modelGuid`, `skeletonGuid` null only for object clips, optional `durationMs` from sampler input accessor `max`, optional `sourceAnimationGuid` after Retarget). Do not invent `JOINTS_0` weights. Morph targets are not a Skeleton. New Asset does not create blank Skeleton / Animation.

**Content Browser Retarget…:** enabled when every selected asset is an Animation with `skeletonGuid` (skin **or** hierarchy). Picks a target Skeleton and duplicates Animation rows onto that Model (`sourceAnimationGuid` set). Name-match only (no Mixamo map UI). Zero channel matches → no file + `Alert` `content-browser-retarget-errors`. Skin↔hierarchy retarget works only when names overlap. Match probing runs in `@babylonslate/render` on a throwaway Scene (`animationRetargetHasMatches`); Content Browser does not construct Babylon `Scene`s.

## Rectangular area emission

Rectangular emitters reference an ordinary Texture GUID. Explicit processing
uses `AssetRegistry.prepareAreaEmission` and the existing single-job EncodeQueue,
including its Preview/background pause policy. A dedicated worker owns decoding
and the pinned native-compatible filter; cancellation terminates that job's
worker. Processing progress distinguishes queued, decoding, filtering and saving.
The separable filter accumulates RGB together to reuse each mirrored sample and
kernel weight, while preserving per-channel order, RGBA8 rounding and exact alpha.

The original `pixels` chunk remains intact. A versioned `area-emission` chunk
stores lighting data beside it, keyed by original source SHA-256 and processor
version. Cached representations are validated and survive project reopen. Commit
rechecks the current source under the Texture write queue and rejects stale
results. Explicit reprocessing can recover a missing/corrupt derived chunk;
gameplay never performs preprocessing. Texture assets expose **Prepare Emission**
with progress and cancellation; closing the project cancels its jobs. Document
saves, renames and derived commits share one per-asset write queue.

Editor and Play consume validated prepared chunks. Export carries each reachable
prepared Texture as an `AreaEmission` sidecar while retaining its independent
visual representation. Missing required preparation blocks export with the
Texture GUID and the preparation action. The player validates the version and
pixel hash before engine creation. Native GPU filter/orientation comparison and
textured receiver browser qualification remain pending.
