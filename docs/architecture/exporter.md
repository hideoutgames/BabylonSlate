# Exporter and packaged player (P14)

The internal export option is `renderSettings: RenderProjectSettings`; the serialized contract remains `game.json.render`. Project loading, export, and manifest parsing share `normalizeRenderProjectSettings`, preserving backend/path, PBR/CEL, quality, shadows, environment, effects and output dimensions. Unknown/editor-local fields are discarded, missing legacy fields receive project defaults, and the artifact owns its normalized values. Capability fallback is resolved separately at engine creation without rewriting the saved request. Boundary tests do not certify rendered parity or device performance.

The same boundary normalizes the separate `playFrameCap` through `normalizePlayFrameCap`: finite positive rates are preserved, malformed rates use the 60 fps project default. Positive fractional output dimensions round to at least one pixel.

Spec: [engineplan.md](../engineplan.md) §15, §15.1, §15.2. Implementation: `@babylonslate/exporter` (headless packer), `apps/player` (Vite canvas host), editor **Export Game** and **Preview Build**.

Overlay Play (shared Engine, `registerView`) stays the default. Packaged **itch zip / Export Game** always starts from `project.json` `startupSceneGuid` (asset guid). Overlay Play and Preview Build seed that guid when Debug **Play from Scene** is off, or when it is on and no scene tab is open; otherwise they seed the open scene for that session only. Do not boot or tree-shake from `BabprojectManifest.startupScene` or `assets/main.scene.babasset`.

Preview Build and the standalone player resolve the saved GPU backend before starting runtime logic. One private constructor canvas owns the graphics context; the visible game canvas uses the shared-view path. Material compatibility includes packed Material Functions, and decoder URLs remain local to the player. A WebGPU fallback preserves the authored request and reports its effective backend and reason. Stop is received before pack/font/backend startup completes; a cancelled completion releases its engine without starting the player. Loading-dialog Stop, fatal loading failure, external Stop and startup rollback share one release path: all runtime/view cleanup is attempted before the page listeners are released. The backend Engine is disposed only after the view's deferred Scene release settles, confirmed or quarantined, so that release never runs on a disposed Engine. Meanwhile the player keeps empty frames running on that private Engine, because WebGPU frees released textures and buffers only at the end of a frame. When frames cannot complete the release (context loss, a hidden page), the Engine is disposed after 5 seconds anyway as the final native owner. Failed disposal is reported (a late one as a `player.cleanup.failed` diagnostic) and never retried. This startup gate is separate from per-Scene and SceneLayer asset/shader/presentation readiness.

## Project identity

- Project Settings > General edits `project.json` > `metadata.version` as a free-form string; new projects start at `1.0.0`. This is separate from the project file's schema version.
- Every export includes `game.json` > `project: { name, version }`, including release builds without the debugger. External packaging tools can read this without unpacking assets or executing scripts.
- Play, Preview Build, and the packaged player pass identity into the runtime load message. **Get Project Name** / **Get Project Version** return these strings; the player refuses a `game.json` without identity. No native build conversion or version-dependent runtime behavior is attached to this metadata.

## Package (`@babylonslate/exporter`)

No React, Babylon, or Capacitor. Callers compile graphs and load payloads; the package tree-shakes, packs, and emits files. It uses `@babylonslate/object-model` for subsystem class-ancestry helpers.

## Export closure

Not `header.dependencies` alone — scene saves often leave those empty.

The editor serializes RenderTarget and RenderTargetTexture documents into export bytes, retaining their payloads for dependency traversal. Header-only Skeleton documents also ship as JSON, preserving the Model/Skeleton required-dependency cycle in the player catalog. Asset-typed variable defaults and Set Variable literals participate for every asset kind (including Audio, Material, Model and Font), with scalar, array and typed Map key/value handling in class and function graphs. Cleared canonical pin defaults mask legacy values; ordinary string variables do not create dependencies. Saved Class headers use the same asset-default collector for reference browsing and deletion guards.

1. Apply export-preset `pluginOverrides` (layer 3) **before** the walk so disabled plugin roots are absent.
2. Seed with `startupSceneGuid` (must be a Scene asset) **and** Project Settings `audioMixerGuid` the same way `gameInstanceClass` is seeded. Pack `occlusionEnabled` and reverb wet/decay/damping scales from Project Settings Audio.
3. Walk only typed reference fields in `SerializedScene` actors/components (guid fields, Mesh/Model `assetGuid`, textures, Font, Class ids); the project `gameInstanceClass` is a startup root. A reference resolves as an asset guid, or else as the compile class id of a Class (its file stem, `classIdForAssetPath`). Display names never resolve. Ordinary authored strings are never searched for GUID text.
4. Load Class/Sprite/Tilemap/**SceneLayer** documents; pull asset-typed pin values, `header.dependencies`, payload fields such as sprite `textureGuid` and overlay `2DTexture` / `2DMaterial` / `2DPanel` / `2DText` / `2DRichText` guids (including `[img]` texture guids parsed from markup). Change Scene targets are Scene guids. SceneLayer overlay actors pack the same closure as a 2D scene. Player `activeScene` still swaps **world** only.
5. Include Class-variable constraints and defaults (scalar, array, and typed map keys/values, including function locals) and Class pin defaults (`default:classId`), so a prefab referenced only by a Class variable or Spawn Actor's dropdown remains available at runtime. Follow Class `parentClass` metadata even when dependency headers are empty, retaining unplaced ancestors and their prefab resources. Recurse to a fixed point. Drop EditorUtilityObject / leftover EditorUtilityInterface / PluginSettings / SkyboxCreator (`isEditorOnlyAsset`). Generated skybox face Textures stay in the pack when a scene `SkyboxComponent` references them.
6. Scene library keys are **asset guids** in both the pack and overlay Play; display names remain aliases for `changescene`.
7. **Subsystems.** The startup-scene walk also roots every Class whose header parent chain reaches `GameSubsystem` or `SceneSubsystem`, including chains through user parents (`subsystemBaseClassIdOf` from `@babylonslate/object-model`, like the InputAction / InputAxis roots). These classes run without being referenced, so they and their user parents are marked as required startup systems. Roots pass the same filters: disabled-plugin subsystems drop out and editor-only classes stay stripped. A subsystem whose user parent lives in a disabled plugin is not rooted, since it would ship without its parent.
8. **Always Package Folders.** Every asset under a Project Settings `alwaysPackageFolders` entry (recursive, matched by storage path) is a root alongside the startup roots above, so it ships and its own references follow even when nothing else reaches it. A listed Scene starts its own closure. The editor-only and disabled-plugin filters apply to these roots like any other.
9. Reachability includes required and deferred references. The manifest separately records `requiredDependencies`; startup acquires only the entry Scene and declared project systems. Every included asset has its own path, byte length and content hash, so inclusion never implies startup loading.

Release zip compiles Class/Graph with `compileGraphDocuments` and `stripDevelopmentOnly` (skips Inspector **Development Only**), then merges `compileAnimGraphScripts` (`AnimGraph:{guid}` / `AnimRule:{guid}:{id}`). Preview Build and a preset with `bundleDebugger: true` keep Development Only nodes.

Export and Preview Build share one closure and compile path (`collectAndExportGame`), so both ship every subsystem Class. Each Class compiles under the class id of its file path (`classIdForAssetPath`), the id Play and the runtime catalog use, and a Class or Animation Graph whose codegen throws fails the export with its name instead of shipping without its script (Play keeps compiling the others). Empty subsystem Classes compile to metadata-only scripts ([scripting](scripting.md#subsystems)). There is no manifest or `load` field for subsystems: the player passes every script to `loadScripts`, and the runtime discovers subsystem classes from them.

Textures: pack `selectTextureChunk`’s chosen variant (KTX2 when present **and** the player file map contains the full self-hosted transcoder: JS decoder, MSC wasm, UASTC→ASTC/BC7/RGBA/R8/RG8, Zstd). If those files are missing, pack source `pixels` (`transcoderAvailable: false`) so itch zip does not bind KTX2 the player cannot decode. A Particle Texture whose selected KTX2 base size is not a multiple of 4 (an earlier Usage's encode, while the Particle re-encode is pending or after it failed) also packs `pixels` instead of that stale encode. A misaligned KTX2 of another compressible Usage (an atlas, or an encode not yet re-aligned) still packs as KTX2; a WebGPU player decodes it to RGBA ([render](render.md#project-lifetime-engine)). Uncompressed Usages (Pixel Art, UI, Skybox, Color Grading LUT) pack `pixels` even when a KTX2 from an earlier Usage is retained. **Preview Build always packs PNG/pixels** (`shouldPackKtx2ForPreviewBuild` / `transcoderAvailable: false`) so a cold iframe matches overlay Play on hardware GPUs — Playwright SwiftShader used to pack PNG while desktop Preview packed KTX2 and stayed on the error sampler. Itch **Export Game** still packs KTX2 when the transcoder files exist. Packed Texture index entries also record authored payload `width`/`height` (import pixels, not LOD/GPU bytes) so overlay `2DTexture` layout in the player matches the SceneLayer object. `ResourceCache` tags KTX2 blobs as `image/ktx2` with `forcedExtension: ".ktx2"` and an unmodified object URL so Babylon does not treat a `blob:` URL (or IPv4 host) as a generic image, and passes byte-array inputs as `buffer`; immutable Blob inputs load from their retained object URL through the selected KTX2 loader. The player then `configureKtx2DecoderRuntime`: main-thread wasm (blob Workers under COEP often fail) and `forceRGBA` for packed play so software GL cannot upload ASTC/BC7. Scene `navmesh` extra chunks pack as sidecar assets (`type: "NavMesh"`, guid `navmesh:<sceneGuid>`) so they do not collide with the Scene JSON guid. Scene `audioReverb` extra chunks pack the same way (`type: "AudioReverb"`, guid `audioReverb:<sceneGuid>`). Packed Audio assets are a **BSAU** envelope (JSON payload + source bytes). Packed Model assets are a **BSMO** envelope (JSON `ModelPayload` including `importScale`, `materialSlots` and `autoLod` + GLB source); the player peels that into `modelBytes` + `modelPayloads` so Preview Build and itch export match editor/Play scale. Closure walks Scene mesh `assetGuid` → Model `materialSlots` / `payload` / `dependencies` → Material graph `textureGuid` → Texture (same `payloadByGuid` string walk as Sprite `textureGuid`). Play/player slim embedded GLB rasters **only** when every slot Material’s sampled texture guids exist in packed `textureBytes`; otherwise construction mats keep authored PNG/JPEG instead of the 1×1 red stub. Font `facetype-glyphs` packs as `FontFacetype` (`font-facetype:<fontGuid>`) for `Text3DComponent`; Font MSDF JSON/PNG pack as `FontMsdf` / `FontMsdfAtlas` (`font-msdf:<fontGuid>` / `font-msdf-png:<fontGuid>`) for overlay 2D Text. `bytesForAsset` skips those sidecar chunks so the Font guid stays woff/ttf for GUI `FontFace`. A reached asset whose document or packed bytes failed to load (`loadExportDocuments` keeps the read error) fails the export with that asset's name instead of shipping a game without it; Audio and Model fall back to their header settings. An asset whose stored format version is not current is recorded the same way before its document loads, so a reached one fails Export Game and Preview Build with its `AssetFormatVersionError` message, Audio and Model included ([schema migration](containers.md#schema-migration)). The Scene reverb bake that export awaits beforehand skips any Scene it cannot load and reports the reason (`collectAudioReverbFlushScenes` → `loadExportDocuments` `audioReverbBakeFailures`). An unreached one does not block the export; a reached one fails with `<Scene> could not be read for its audio reverb bake: …` unless export's own read already failed on it, and its earlier `audioReverb` chunk is never packed. A Scene whose fresh reverb result the bake could not save (writes locked during Simulation Play, or a write error) is reported the same way with that result: its saved chunk packs only if it equals the result, and otherwise a reached Scene fails with `<Scene>'s audio reverb bake could not be saved: …` ([audio](audio.md#reverb-bake)). An edit or Auto-Save during export never supersedes export's flush; its bake waits until the flush settles. Each flushed Scene's saved chunk is therefore refreshed, or the Scene is reported. A Scene saved with new geometry in the meantime carries the chunk that Save reconciled with that geometry.

## Runtime file layout

World `OutlineComponent` records travel with normal scene/Class component data
in every export. Player hydration emits actor-bound outline
contributions through the runtime bridge, including late model realization and
spawn/despawn. Normalized `render.cel` defaults include global outline enable,
RGB color and output-pixel width; scene overrides and session Scalability use
the same settings contract as Play. Selection, gizmos and editor membership are
view state and are never exported. Outlines require no extra asset preprocessing.
The [qualification report](../design/renderer-qualification.md) distinguishes
implemented wiring from independently served player acceptance.

```
index.html          # CSS inlined; itch requires this at zip root
player.js           # Vite `codeSplitting: false`; workers stay separate files
game.json           # small catalog: required dependencies, paths, sizes and hashes
assets/data-0.bin   # independently addressable asset or sidecar
assets/data-1.bin
coi-serviceworker.js
havok/HavokPhysics.wasm   # 3d world
assets/rapier-*.js        # 2d world or physics-enabled SceneLayers
ktx2/…              # transcoder files the player needs
draco/…             # glTF Draco decoder (KHR_draco_mesh_compression)
meshopt/…           # glTF meshopt decoder (EXT_meshopt_compression)
```

`GameManifest` records `startupSceneGuid`, optional `gameInstanceClass` (project field), `render`, `playFrameCap`, project `twoD.pixelsPerUnit` / `pixelPerfect` (defaults 100 / false), Engine Settings `touchMinTargetPx` (default 44), `physicsWorld`, and `assets[]`. `parseGameManifest` rejects a manifest without `assetCatalogVersion: 1` or without any field every export writes (such as `project`, `render`, `focusNavigation`, `sortingLayers`, or the debugger loop settings below) and asks for a rebuild; present fields with invalid values are still normalized. Audio fields: optional `audioMixerGuid`, `occlusionEnabled` (default on), and reverb scales (default 1). Font index entries include `name` (authored `family`, else the asset name) so the player can `FontFace(family, bytes)`. The player boot reads the Game Instance from `manifest.gameInstanceClass` only. When `bundleDebugger` is true the manifest also carries `infiniteLoopDetection` and `loopCount` from Project Settings (defaults on / 1_000_000); release packs omit those keys. `parseGameManifest` ignores those fields on release manifests. `GameManifest` does not include HUD keys. Every exported project or plugin asset's index entry also records `assetPath`, its authored storage path (`assets/Weapons/Rifle.class.babasset`; `path` stays the exported file). Generated entries (compiled scripts, navigation, Font and emission sidecars) have none. The player builds the Asset Registry catalog from the entries that have it and sends it in the `load` control; a Font entry's `name` is its family, as for `FontFace`.

Every export writes tree-shaken `assets/data-<index>.bin` files and `assetCatalogVersion: 1`; export presets have no packed or loose choice, and `game.json` has no `mode`; ZIP remains a delivery format, not a runtime archive. The manifest maps unchanged asset IDs to these portable filenames, including namespaced emission and audio sidecars. Names remain distinct on case-insensitive filesystems and cannot introduce path separators or Windows reserved names. Content hashes overlap (up to four assets ahead); files and catalog entries are still written in asset order, and the first failing asset fails the export. Wasm, transcoder, and `coi-serviceworker.js` stay real files.

`exportGame` retains Rapier for a 3D world only when a `SceneLayer` in the exported asset closure enables physics (`settings.physicsEnabled`, read with `normalizeSceneLayer` as the player does); only those layers get a separate 2D world. A 3D export whose layers all leave physics off omits Rapier, and the runtime never loads it for them. An unreadable layer payload keeps Rapier. A 2D export omits Havok.

New players fetch `game.json`, the entry Scene and required dependencies. Deferred Scene documents, compiled Class code, textures, models, fonts and audio remain unread until acquired. Each compiled module is a required sidecar of its owning Class or AnimationGraph; multiple animation-rule modules retain distinct identities. Class identity and console-command metadata live in the catalog without code. Runtime source replacement waits for module registration before publishing the requesting Scene or completing its preload, and eviction removes unowned source modules. Length and SHA-256 checks reject mismatched deployed files. Static hosting does not need HTTP Range support. `getReadMetrics()` reports actual response bytes.

Font catalog names, fallback edges and the project's `defaultFontGuid` select the same representation as Play: Bitmap reads the original font, MSDF reads its JSON/atlas pair, and geometry Text3D reads Facetype. Selected Scene/Class documents and later text commands supply those modes before binary reads. Different consumers can retain different representations of the same Font. BDebugCommand metadata remains available in the catalog; command Classes and their deferred resources ship in the closure without becoming startup sources.

HTTP asset bodies are bounded by catalog lengths while reading, and bytes received before a rejected body remain in storage metrics. Script load handles read Loaded only after native preparation succeeds; native failures report failed and can be retried while prior valid resources remain owned.

`AssetLoadingService` owns compatible source reads and decoding across Scene instances and script load handles. Sources publish only after the complete required closure succeeds. Streaming acquires and installs the prepared source scope before the existing runtime/render readiness transaction. Unload releases runtime objects first, then scoped renderer sources and otherwise-unowned source maps. Shared consumers remain valid. Failed requests remain retryable. `packedContentFromGame`, `packedSourceControls`, and `GameSourceContent` are shared with editor Play; complete content replacement controls also remove released data, clip, SceneLayer and navigation catalogs. Source and CPU budgets are independent of the existing renderer resource cache.

Preview Build still performs an explicitly reported build step, then hands the iframe only `game.json`. `createPreviewAssetClient` requests each selected file from the host using the same source-loading contract as HTTP. Stop cancels pending requests and late responses cannot restart the session. Included deferred files remain in build storage until requested.

File-count report: warn 800 / fail 1000 (preset-overridable). Export smoke asserts count.

## `apps/player`

Asynchronous Worker startup/runtime failures and unreadable Worker messages report `player.worker.failed` and stop the session through the shared cleanup path. A failed module fetch cannot leave the player pumping input indefinitely without simulation.

The player loads current exports only. Every catalog entry needs its SHA-256 `revision`, Model and Audio entries must be BSMO / BSAU envelopes, and sidecars need their prefixed ids (`navmesh:`, `audioReverb:`, `font-facetype:`, `font-msdf:`, `font-msdf-png:`); anything else fails the load. Startup reads the entry Scene's closure plus the startup-required assets. The `load` control's Class lookup is keyed by class id only (the catalog `classId`, else the `assetPath` stem), as in Editor Play. Startup-required render sources hold their own lease once the startup Scene's initial sources are released; a failed upload is retried by the next Scene acquire. An acquire or release that leaves every loaded source in place skips the content rebuild and the source union post.

Vite canvas host: `@babylonslate/runtime` + `@babylonslate/render` + bridge/physics/debugger. No Dockview, editor chrome, or React shell. Dedicated Engine (do not `registerView` onto the editor Engine). Boot `startupSceneGuid`; apply `render.customResolution` via the shared `play-preview-aspect` math in `@babylonslate/core` (`playFramebufferSize`): Black Bars on locks WxH and the host **letterboxes** with `fitContainedRect` (never `object-fit: fill`); Black Bars off fills `#player-root` and `resize()` follows the element. Re-layout on `#player-root` resize.

`includeDebugCommands: manifest.bundleDebugger`. Release player uses `createCommandRegistry({ includeDebug: false })`; core commands (`changescene`, …) stay. When the debugger is bundled, a small vanilla DOM HUD (not the editor `PlayOverlay`) shows fps / scriptMs / physicsMs / publishMs / draws, and boot forwards `infiniteLoopDetection` / `loopCount` on the `load` control message. **Print** (`data-testid="print-overlay"`) and **Draw Debug** always apply — they are not gated by `bundleDebugger`. Stats HUD stays debugger-only. Packed fonts use `FontFace(family, bytes)` — family from the manifest `name`, falling back to the guid; not blob URLs. Facetype sidecars hydrate into `createEngine` `fontFacetypeBytes` for 3D Text. MSDF JSON/PNG sidecars hydrate into `fontMsdfJson` / `fontMsdfPng` for overlay 2D Text. Inline RichText `[img]` textures pack through the SceneLayer closure, not `collectStrings` on the markup string.

Boot hydrates packed **Sprite / Sprite Animation / Tilemap / Tileset / AnimationGraph / Animation / BehaviourTree / Blackboard / Material / Material Function** payloads into `createEngine` and the worker (`loadScripts` when present, then `loadAnimGraphs`, `loadSprites`, `loadTilemaps`, `loadNavMesh`, …) **before** `play`. Packed Texture index `width`/`height` become `texturePixelSizes` on `createEngine` so overlay `2DTexture` planes match the SceneLayer object instead of sniffed GPU/LOD bytes. Packed Model **BSMO** bytes peel into `modelBytes` (GLB) and `modelPayloads` (`importScale`, `materialSlots`, `autoLod`) on `createEngine`. Auto LOD Models start generating their levels in the `model-lod.worker` module worker (main-thread fallback) once the model loads; the levels attach after the instance publishes, and readiness does not wait for them ([Automatic LOD](render.md#automatic-lod)). Packed Animation JSON fills clip names/durations and stamps Play groups with Animation guids (`modelClipAnimationGuids` / `retargetAnimationLoads`). Material documents, functions, and the startup scene `postProcessStack` go to the Engine; `assignMaterial` is forwarded with mesh/camera commands. After the first `assignMesh`, the player waits for GLB instances (`whenEditorModelsReady`) then sample-ready library textures (`whenMaterialTexturesReady`) then `prewarmSceneMaterials` — the editor viewport already does this; the iframe Engine did not. `activeScene` looks up the packed scene guid and calls `loadScene` / `applySceneEnvironment` so a later `changescene` replaces that stack. Engine Settings `postProcessingEnabled` is editor/Play-only and is not read by the player. In-process fallback registers the same content and runs a rAF `advance` pump; a throwing tick is reported as a diagnostic and the pump continues, and a Scene, Scene Layer or stream realized marker whose pose copy misses waits for the next complete pose, as over the worker transport. Both paths capture canvas input into the input ring. The packaged player does not hydrate a game HUD. EUI assets are never packed.

`?preview=1` waits for a same-origin metadata handoff and requests asset files on demand; it ignores a handoff that carries no trace budget. Repeated packs are ignored while a launch runs or after it started; a failed launch accepts a later pack. Destroying the iframe drops that WebGL context.

## Preview Build

The Preview handshake carries the Engine Settings **Trace Memory Budget (MiB)** for that session in both Worker and in-process modes. It is separate from the packed files and game manifest, and a Preview handoff must carry it; standalone games use the runtime's 128 MiB default. Settings changes apply to the next session.

Debug-dropdown checkbox only (`debuggerDefaults.previewBuild`, default **off**). Always visible; disabled while Play or prepare is running. **Session** also has **Play from Scene** (`debuggerDefaults.playFromScene`, default **on**). **Off Preview Build:** overlay Play; chrome launch reads **Play**. **On:** chrome launch reads **Preview**; always `bundleDebugger: true`; Preparing Preview modal (Saving → Collecting Assets → Compiling → Writing Pack → Launching); same-origin iframe of the hosted player. Cancel only before the iframe exists. **Stop** is a labeled 44px control layered above the iframe (not a 28px ghost X in a chrome strip). Clicking it posts `PREVIEW_STOP_MESSAGE`, drops the in-memory pack, unmounts the overlay immediately, and shows the session report if diagnostics were posted. A posted diagnostic with `code: "runtime.infinite_loop"` closes Preview the same way without tapping Stop; the player also cancels rAF and stops the worker so the iframe is not left running. Preview diagnostics now carry `code` (and optional `bodyLine`); the editor no longer hardcodes `code: "preview"` when the player sent a real code. The player keeps at most 1000 diagnostics for the posted list and `stop()`: past that it drops the oldest after the first 100, so a per-tick error cannot grow memory or the per-diagnostic post without bound, while `onDiagnostic` still runs once per diagnostic. `canSendPreviewPack` refuses handshake replies after Stop so a dying iframe cannot relaunch. The packaged player HUD samples fps on the rAF pump (same idea as overlay Play) so fps is not stuck at 0 while ticks climb. Preview Build packs an in-memory `startupSceneGuid` override from the open scene when Play from Scene is on; Export Game never uses that override.

**Player URLs follow the Vite base.** The iframe `src` and `loadPlayerDistFiles` both go through `playerHostBase()` / `playerPreviewSrc()` (`apps/editor/src/lib/player-host-url.ts`), which prefix `import.meta.env.BASE_URL`. `loadPlayerDistFiles` fetches only `player-files.json` names that are relative paths inside the player root (no leading `/`, `..`, `\` or URL scheme), since each name becomes an exported file. Hardcoding `/player/` broke every non-root deployment — GitHub Pages serves the editor from `/BabylonSlate/`, so the iframe fetched the domain root and showed nothing but its own black background. `playerHostVitePlugin` mounts at the same base in dev.

**The pack handover is a handshake, not a single post.** The player posts `PREVIEW_REQUEST_PACK_MESSAGE` once its listener is installed and the editor replies with the pack, resending on each request; posting only on the iframe `load` event raced module evaluation and silently dropped it. Repeated packs are ignored while a launch runs or after it started; a failed launch accepts a later pack. Boot failures post `PREVIEW_ERROR_MESSAGE`, which the overlay renders as an `Alert` (`preview-build-error`) so a failed boot is never an unexplained black frame. A locked framebuffer (Black Bars on, or a live Set Render Resolution override) stays WxH; CSS contain letterboxes it in the iframe so circles stay round. Without a locked framebuffer the player resizes its canvas to the element and observes it for changes (Black Bars off, or Follow System when custom resolution is off). The iframe uses `outline-none` / `focus-visible:outline-none`, and the packaged player sets `canvas:focus { outline: none }`, so a click does not draw a browser focus ring. AudioV2 is created suspended at player boot; the first canvas gesture only resumes / unlocks (no `CreateAudioEngineAsync` on the click turn). When the debugger is bundled, the player shows the same **Click the game view to enable audio** hint while play commands are queued.
