# UserInterface runtime (P9)

Shared surface for the widget tree, Babylon GUI layout fields, font-stack compilation, and edit-time cycle checks (engineplan §11). Implementation is split like `debugger` so React and Babylon never share a package.

Agents working on this surface must follow [`.cursor/skills/BabylonJS/SKILL.md`](../../.cursor/skills/BabylonJS/SKILL.md) before implementing. Designer chrome around the canvas stays React ([components.md](components.md)); the widget document itself is Babylon GUI.

| Layer | Package | Imports |
| --- | --- | --- |
| Widget tree, layout fields, `previewRect`, font-stack compiler, cycle check | `@babylonslate/ui-runtime` | no React / Babylon / Capacitor |
| Injectable GUI apply, `FontFace` load, sprite quads, shader compile | `@babylonslate/render` | Babylon, no React |
| Designer / Logic chrome (`UiEditorModeBar` + dual DockView catalogs), Font / Sprite editors, graph hosts, Play HUD host | `apps/editor` | `@babylonslate/ui`, `editor-kit`, `graph-ui` |

UI mutations travel on the **command channel** ([bridge.md](bridge.md)), not the snapshot. The game worker drives widget properties; the main thread applies an injectable GUI host. Worker code never calls `document.fonts`.

v1 Play applies viewport-layer HUD through **`BabylonUiApplyHost`** (`AdvancedDynamicTexture` on the Play scene). Layout fields copy onto nested Babylon controls (no RectTransform solver in the Play path). `devicePresetForViewport` supplies SafeArea insets. The overlay starts **empty**: Play and the exported game do **not** auto-apply a UserInterface. A class graph must call **Apply User Interface** (`ui.applyToViewport`) with a `classRef(UserInterface)` (asset guid or `UserInterface:<guid>`); the node returns an `objectRef(UserInterface)` instance, not an opaque string. **Remove User Interface** (`ui.removeFromViewport`) takes that object. The worker emits `uiApply` (`instanceId`, `classId`, `assetGuid`) / `uiRemove` (`instanceId`); the host looks up documents from a Play UI library (every UserInterface asset, open documents first). Overlay Play (`PlayHudOverlay`) and `apps/player` (`createPlayerUiHost`) share `attachFullscreenGui` + the same commands. **Later `uiApply`s append** onto one fullscreen Layer ADT (`flatMap` in apply order) so a second HUD paints and picks above the first — there is no authored z-index. Overlay and player both merge Engine Settings designer presets for Safe Area, register Font assets onto the HUD ADT (`applyFontRegistryToHost`), and keep the Layer interactive. Canvas POINTERMOVE still reaches the HUD (`attachFullscreenGuiPointerMoves`) so enter/exit fire while `skipPointerMovePicking` stays on; pointerdown is not captured so Button clicks stay on the scene GUI path. Packed Preview Build / Export copy `uiDesignerPresets` onto `game.json`. **Apply / Remove are one-shot:** the overlay attaches the fullscreen ADT once per Play scene and reconciles widgets on that host (`applyUiControls`). It must not dispose/recreate the ADT when `uiApply` / `uiRemove` or viewport size changes — remounting dropped HUD that was not re-applied every Tick. Resize writes ADT ideal size in place (`applyAdtIdeal`). `applyUiControls` takes an injectable `UiApplyHost` (recorder in tests; `BabylonUiApplyHost` in the editor, Play, and player). jsdom Play HUD tests omit the scene and keep pointer handlers on testid markers.

## Layout (Babylon-native)

The document stores the same parameterization Babylon GUI uses (Y-down). Schema **v3**.

| Field | Babylon |
| --- | --- |
| `horizontalAlignment` / `verticalAlignment` | `left` \| `center` \| `right` / `top` \| `center` \| `bottom` |
| `width` / `height` + `widthUnit` / `heightUnit` | `"160px"` or `"50%"` |
| `left` / `top` + `leftUnit` / `topUnit` | always added after alignment |
| `padding` | `Control.padding*` (stretch insets live here, not on `style.padding`) |
| `transformCenter` | `transformCenterX/Y` in 0–1 |

`style.padding` is not layout. If a widget needs both stretch insets and inner padding, nest: outer control gets layout padding, inner control gets visual chrome.

- **3×3 + stretch presets** (`applyAnchorPreset`) are macros that write the fields above. They do not store a parallel RectTransform.
- **Safe area:** Canvas hosts a synthetic `__safeArea` container padded by the device preset. Default-add parents into it. `ignoreSafeArea` parents to the full-bleed canvas. Nested instance slots never get a second Safe Area. Designer uses the unscoped id. Play and the player `scopeUiControlIds` **id and parentId**, so children parent to `ui-N:__safeArea`. `BabylonUiApplyHost` keeps a Safe Area per instance prefix (stacked HUDs do not share one box).
- **Containers:** `StackPanel` (`isVertical`); Grid → `Grid` with row/col defs (`value` + `isPixel`) and per-child `gridRow` / `gridColumn`; `ScrollViewer`. Details Columns/Rows resize `gridColumns` / `gridRows` (keep existing defs; new tracks are star `1`). Apply maps `gap` to cell padding between tracks (Babylon Grid has no column/row spacing API) and updates column/row defs **in place** so cells stay parented. Apply uses `parent.addControl` / `grid.addControl(child, row, col)`. Never `adt.addControl` for non-roots. StackPanel children must author pixel size on the stack axis.
- **One project design space.** Play/player ADT ideal (`idealWidth` / `idealHeight` / `useSmallestIdeal`) comes from Project Settings → User Interface (`designResolution` default 1920×1080, `scaleRule` default `shortestSide`) via `resolveUiAdtIdeal` / `applyAdtIdeal`. Viewport-layer designer device presets change the **ADT bitmap** and Safe Area only; ADT ideal stays the project design resolution. Widget prefabs (`viewportLayer: false`) match bitmap 1:1 (no adaptive scale, no Safe Area). Per-document `designResolution` / `scaleRule` are deprecated echoes; Play ignores them. First viewport-layer document seeds project settings when `settings.ui` was omitted (`seedUiProjectSettings`). Export copies project UI settings onto `game.json` next to `uiDesignerPresets`.
- **`previewRect`** mirrors Babylon’s published alignment/%/padding formulas for **absolute** children only (jsdom designer hit-tests). It must not invent Stack/Grid geometry. Production apply never calls `layoutUserInterface`. `describeUiControls` walks `children[]` (nested skip-Canvas, ids `slotId/innerId`). When a live Engine exists the designer prefers ADT `measureControls()`. Play apply copies layout fields onto controls and does not feed canvas-mapped `guiRect`s as the source of truth. Overlay and player both `scopeUiControlIds` **id and parentId**.
- Legacy `anchorMin/Max` + `offsetMin/Max` payloads migrate via `migrateUserInterfacePayload` (schema v2). v2 kind aliases, left/top units, Grid tracks, stack-axis px, and `style.padding` → `layout.padding` migrate via `migrateUserInterfaceV3` (schema v3). `normalizeUserInterfaceDocument` (used by `asUiDocument`) always produces a Canvas root plus layout/style/props/children, so a missing widget never throws on `widgets[id]!`.

Device presets: built-ins (`desktop-4-3` 1600×1200, `desktop-16-9` 1920×1080, `desktop-21-9` 2560×1080 Widescreen) plus designer **Desired** (`desired` canvas id). All built-ins use zero Safe Area. Desired has no Width/Height fields: the frame is `contentDesiredSize` (alignment-aware AABB of canvas children so center/right/bottom + offsets stay inside the frame; empty documents keep `DEFAULT_DESIRED_SIZE` 400×300). Custom sizes live in Engine Settings `uiDesignerPresets` and merge after the built-ins (`mergeDevicePresets`); reserved ids (`desired` and built-in ids) cannot be overridden. The designer dropdown, Play overlay, and packaged player (`devicePresetForViewport`) all consume the merged list so a custom 390×844 row can supply matching safe-area insets. Preview Build / Export copy Engine Settings `uiDesignerPresets` onto `game.json`. Switching a designer preset does not rewrite the widget tree.

Text measurement is injected (`TextMeasurer`). Golden tests use a deterministic stub; the live host uses Canvas / `document.fonts` on the main thread. Production layout is Babylon’s.

## Widget payload

A `UserInterface` asset stores the widget tree in the `document` chunk. Nested UserInterface widgets (`kind: "UserInterface"`, `nestedUiGuid`) are **instance slots**, not a flatten. **Edit-time cycle check** (`nestedUiPickableGuids`) excludes self and cycle partners from the designer picker. TouchJoystick / TouchButton / TouchDPad may use `nestedUiGuid` as a skin; worker logic mounts only for `kind === "UserInterface"`. v2 `visualOverrideGuid` migrates onto Button image/style or a Touch skin.

Nested **visuals** stay one tree (layout prefixes inner ids `hostSlot/innerBtn`). Nested **logic** runs as a worker-only child instance (`UserInterface:<nestedGuid>` at id `hostInstance/slotId`) — no second `uiApply`. Prefixed widget events dispatch to that child with the local remainder. Nested graphs tick while the host is mounted. Cycles are skipped.

Placement:

- **Viewport layer** — `ctx.applyUserInterface(classIdOrGuid)` creates a typed `UserInterface` (`classId` `UserInterface:<guid>`, instance ids `ui-1`, `ui-2`, …) plus concrete `*Widget` children. Not auto-hosted on Play.
- **WidgetComponent** — world-space 2D prefab (`CreateForMesh`). Class id exists; Add Component and Search hide it until a runtime `CreateForMesh` path exists. Viewport-layer HUD is the v1 Play path.

`ctx.getWidget(widgetId)`, `ctx.setWidgetVisible(widget, visible)`, `ctx.applyUserInterface(classIdOrGuid)`, and `ctx.removeUserInterface(instance)` are real worker helpers: they emit UI commands; Play and the player apply them. `getWidget` is scoped to `ctx.self` when self is a `UserInterface`. Scripts never touch Babylon GUI.

## Typed instances

Engine bases `UserInterface` and `Widget` are `BObject`s (`kind: "object"`), not Actors. Concrete subclasses match authored kinds (`ButtonWidget`, `ImageWidget`, `MaterialWidget`, …; `widgetClassIdForKind`). Asset class ids are stable `UserInterface:<assetGuid>` — not the file stem.

- **Apply** registers the asset class, constructs the `UserInterface`, then widgets from `loadUserInterfaces` metadata (`guid` `ui-N:widgetId`, `owner` = the instance). Nested `UserInterface` widgets with `nestedUiGuid` mount a child instance (`ui-N/slotId`) without emitting `uiApply`. Widgets then the UI run `onCreation`; interfaces bind; the worker emits `uiApply` for the host only.
- **Remove** tears nested children first (no `uiRemove`), then widgets in reverse (`onDestroyed`, `owner = null`) then the UI, and emits `uiRemove` for the host. Change-scene and Play stop tear down every mounted UI.
- **Tick** calls `onTick` only while mounted. Two applies of one class are independent (variables, widgets, visibility).
- **Events** (`click` / `value` / `checked` / `text` / `pointerEnter` / `pointerExit` / `pointerDown` / `pointerUp`) travel main → worker as `uiWidgetEvent` and invoke `onWidgetClick` / `onWidgetValue` / `onWidgetChecked` / `onWidgetText` / `onMouseEnter` / `onMouseExit` / `onMousePress` / `onMouseRelease` on the owning UI with `{ widget, widgetId, value }`. Prefixed ids (`chip/inner-btn`) route to the nested instance with local `inner-btn`. Catalog nodes: **Event On Mouse Enter/Exit/Press/Release** and **Event On Widget Click**. Empty Canvas hits do not emit widget events.
- **Visibility** is instance-scoped (`uiSetVisible` `{ instanceId, widgetId, visible }`). Hosts prefix control ids `instanceId:widgetId`.
- UI / Widget class ids are **not** spawned as Actors (`shouldSpawnScriptedActor`).

## Designer / Logic

Chrome **Designer | Logic** `ToggleGroup` (`UiEditorModeBar`; testids `ui-editor-mode-bar`, `ui-editor-mode-designer`, `ui-editor-mode-logic`) sits **outside** DockView. Below it, two stacked DockView surfaces persist separately in `layout.json` `{ uiEditorMode, designer, logic }` (raw old snapshots migrate to Designer). **Windows** and Focus follow the **active mode**. Leftover `ui-logic` panels close on restore. **P18** (`p18-inactive-documents`) mounts only the active mode’s DockView; the inactive mode unmounts immediately. Designer canvases freeze while Logic is open (`documentActive` requires designer mode). This mode bar is the documented exception to “all document chrome is DockView” ([dockview-editor-tabs.mdc](../../.cursor/rules/dockview-editor-tabs.mdc)).

Play and the player compile `payload.logic` with Class graphs as `UserInterface:<guid>` / parent `UserInterface` (authoring `parentClass` still defaults to BObject so Actor stubs are not seeded). Built-in canvases are read-only. If the selected custom id is deleted, the designer falls back to `desktop-16-9`. Undo via `@babylonslate/edit`. Compose from [components.md](components.md) (`PanelFrame`, `TreeView`, `NestedMenu`, `PropertyGrid`, `AssetPicker`, `CatalogDialog`, `NamePromptDialog`, `GraphEditor`, `ToggleGroup`).

| Mode | Windows catalog | Primary panel |
| --- | --- | --- |
| **Designer** | Design, Hierarchy, Details. Not Graph/Class. | `ui-design` |
| **Logic** | Same as BObject Class: Graph, Class, Inspector, Compiler Results. Graph is `payload.logic`. | `graph` |

- **Design canvas** (`ui-design-viewport` / `ui-design-canvas`): `touch-none` wrapper. Game widgets paint through `BabylonUiApplyHost` on a standalone `CreateFullscreenUI` on the shared app Engine (`interactive: false`). **Happy path:** the ADT Canvas2D backing store is hosted in the device frame (`tryHostAdtBackingCanvas` / `presentHostedAdt`) — **not** `registerView`, which would blit the last 3D framebuffer onto the tab. Invalidate-rect stays on for a hosted canvas. Blit fallback (`presentAdtToCanvas`) keeps invalidate-rect **off**. `presentAdtToCanvas` throws if the 2D context or ADT backing store is missing (hard failure → **Babylon GUI Preview Unavailable**); other present errors are retried. A 0×0 ADT size is skipped so a hidden or unmeasured panel does not empty the canvas. Hidden Design tabs call `UiSurface.setFrozen(true)` so present, `markDirty`, and pointer picks skip (`freezeLiveUiSurface` / `blitIfUnfrozen`), and `applyUiControlsIfUnfrozen` skips control rebuilds. Returning to Designer unfreezes and always `resize → apply → measure → show`. Close disposes the Scene + ADTs. Viewport / scale-rule / design-resolution changes call `resizeDesign` instead of disposing the Scene. Viewport-layer ADT **ideal** is the project design space; **bitmap** is the device/Desired frame. Transparent hit rects keep `data-testid={`ui-widget-${id}`}` from `measureControls()` when an Engine exists (jsdom uses `previewRect` for absolute widgets). No second gizmo ADT (`paintDesignerGizmos` stays unused). Selection (`border-2 border-primary`) and 14px handle glyphs stay visible while the GUI preview is live; 44px hits sit **outside** the box so a fitted 36px control still has a move interior. `UiDesignerSession` (`apps/editor/src/lib/ui-designer-session.ts`) is the layout stroke: pointermove does not `setState`; a locked host skips `resizeDesign` / apply; `patchLiveLayout` writes alignment, size, and padding, then rAF `present`; the overlay follows the **preview** rect, not stale `liveRects`. Pointer-up (and Details numeric blur) commit once with `ui-design-stroke:` (`uiHostStats.commit`). Details unmount, selection change, Designer→Logic, and canvas unmount **commit** an in-progress scrub so the session cannot stay locked. Details Width seeds the committed layout as the first preview so `cancel()` can restore it. `cancel()` restores that first preview (canvas `lockGesture` does the same), then unlocks. **Fit** / device preset may reset pan/zoom; dock panel resize does not (`uiDesignerCanvasFitKey`). Nested hits map to the **slot** for transform. Apply **reconciles** unchanged Babylon controls instead of clearing the ADT. Resize/present is rAF-coalesced (`createUiFrameScheduler`). Test-mode `window.__babylonslateUiHostStats` exposes `apply` / `create` / `present` / `commit`.
- **Image widgets:** Details Texture picker writes `props.imageGuid`. Designer, Play HUD, and the player pass `resolveImageUrl` into `createUiSurface` / `attachFullscreenGui`. `collectImageGuidsFromUiDocuments` walks nested UserInterface documents. Overlay Play `resolveUiImages` loads Texture `pixels` (then `source`) as blob URLs with the chunk `image/*` MIME (fallback `image/png`) and records `missing-asset` / `missing-chunk` / `wrong-type` issues (`UiImageIssueAlert` on Design). Blob URLs are cached **by texture guid**: a later `ui` / registry tick reuses the same URL when the guid is still referenced, so Babylon GUI `Image.source` is not reassigned (a new URL would decode blank and flicker through the designer checkerboard). Unused guids are revoked after resolve; remaining URLs are revoked on project close / Play teardown. Packed Preview Build / Export keep GPU KTX2 on the Texture guid and pack a `UiImage` sidecar (`uiimage:<textureGuid>`) from `selectGuiImageChunk` (pixels then source). `createPlayerUiHost` builds blob URLs only from browser-decodable bytes (`mimeForGuiTextureBytes`); KTX2 is never labeled `image/png`. Reconcile still assigns `Image.source` only when the URL string changes.
- **Material widgets:** Details Material picker writes `props.materialGuid` and lists Interface-domain Materials only (`isInterfaceMaterialForPicker`; open-document domain wins over a stale header). Hit Testable defaults **Disabled** (same as Image). Babylon GUI has no `Control.material`; `createInterfaceMaterialPresenter` compiles the Interface NodeMaterial onto a widget-sized RTT, blits to a 2D canvas, and drives a GUI `Image` (`domImage`). Designer, Play HUD, and the player share that presenter. `collectMaterialGuidsFromUiDocuments` walks nested UI; Play `collectPlayMaterialLibrary` unions those guids with scene materials. Export packs `materialGuid` the same way as `imageGuid`. Surface and post-process materials are out of scope on HUD widgets.
- **Per-project UI/font library cache:** designers share one UserInterface + Font library load per project (`rememberProjectUiAssets`). Close or switch project resets it so identical paths (`assets/HUD.ui.babasset`) cannot reuse another project's documents.
- **Add Widget** is a `CatalogDialog` (Containers / Controls including Material / Touch). Vertical Stack / Horizontal Stack presets create `StackPanel` with `isVertical`. Cycle-filtered UserInterface assets insert as bound slots (`nestedUiGuid`), not empty rectangles. New widgets use `defaultAddLayout` (center align + preferred px size, staggered 48px per Canvas sibling; stack-axis px when the parent is a StackPanel). **Frame Selection** (`ui-design-frame`, next to Fit) zooms the selected control so it is not a speck on a fitted 16:9 canvas; Add Widget does **not** change pan/zoom. **New Asset → UserInterface** seeds `createDefaultUserInterface` (Canvas root only, `viewportLayer: true`). `createDefaultPlayHud` (title + joystick) is a test fixture, not the create path.
- **Hierarchy** is a collapsible `TreeView`: collapse, immediate drag-to-reparent (cycle/root rejected). Drop on a row **middle** nests; the **top/bottom 8px** insert as a sibling in the parent `children[]` (same-parent reorder is allowed). Trailing ⋯ `NestedMenu`: **Visible**, **Ignore Safe Area** (Canvas children), **Open Asset** / **Extract** (instance slots), Duplicate / Rename / Delete. Nested instance expand is read-only names; select/transform maps to the slot; double-click / Open Asset opens the nested document. The Canvas root cannot be duplicated, deleted, or extracted. `duplicateWidget` copies descendants. Extract writes a `viewportLayer: false` prefab next to the host and replaces the selection with a slot.
- **Details** expose identity and kind props plus **Hit Testable** (Enabled / Disabled enum) and **AnchorPresetPicker** (pin/stretch macros). **Size** uses `authoringFieldsFromLayout`: Width/Height when that axis is pinned; Left/Right or Top/Bottom insets when stretched (not a raw `100%`). Switching px/% converts via the parent extent (`convertLayoutSize`). Numeric scrubs share `UiDesignerSession` so Width drag does not reconcile every tick; leaving Details without blur commits the preview. The first Width preview is the committed layout so `cancel()` can restore it. Grid Columns/Rows also write `gridColumns` / `gridRows` track arrays (`resizeGridTracks`). **Layout** still has alignment, Left/Top + unit, and padding on pinned axes. Rectangle `props.width` / `props.height` (Box Width/Height) are hidden so layout size is the only size. Canvas children can **Ignore Safe Area**. Stack/Grid children show that the parent slot owns layout (stack-axis size stays). Instance slots show exposed nested overrides. Touch* show a Skin (`nestedUiGuid`) picker. **Material** widgets pick an Interface-domain Material (`props.materialGuid`). Widgets can opt in `exposed: { key, label }` for host overrides.
- **Desired** sizes the authoring frame to `contentDesiredSize` (alignment-aware content AABB). Nested layout uses that same size as the nested document’s design resolution inside the host slot. The payload may still store `desiredSize` for compatibility; the designer does not edit it.
- Unspecified Text / Button / InputText `style.color` applies as `#ffffff` (Babylon’s empty color would `fillText` with the canvas default black). TouchJoystick without a background uses `#e5e5e5`, not `#000000`. Canvas Rectangle background stays authored — no implicit fill. **New** Buttons get `style.background` `#333333` at create time only (`defaultStyleFor`); a loaded Button that omits background stays unset (no invented fill). Details color rows use `ColorField` `null` for that unset/transparent state.
- **Nested UserInterface** is an instance slot. Add Widget lists cycle-filtered assets; Content Browser insert is the same bound slot. Designer preview and Play present share `describeUiControls` (skip nested Canvas, no nested `__safeArea`) via one resolver: the document under edit, then an open usable payload, then the loaded UI library / document chunk, then a **usable** header payload (`widgets` and/or `rootId`). Empty `{}` headers are ignored so they cannot hide the library. Image and Interface-material walks use that same order. Nested save / `rememberProjectUiAssets` re-applies **that slot**. Slim `loadUserInterfaces` meta includes `nestedUiGuid`, `exposed`, and slot `overrides` (`widgetRuntimeMeta` in `@babylonslate/ui-runtime`). Overlay Play and the packaged player both ship that mapper — nested **graphs** mount from `meta.nestedUiGuid`, not from visuals alone.

## Hit Testable and input mode

`WidgetNode.hitTestable` is authored next to `visible`. Details shows **Hit Testable** Enabled / Disabled. Missing field on load uses `defaultHitTestableFor(kind)`:

- **Enabled:** Button, TouchButton, TouchJoystick, TouchDPad (default Play HUD sticks/buttons keep working).
- **Disabled:** Image, Material, Text, ProgressBar, Spacer, Slider, CheckBox, TextInput, containers, nested UserInterface, Canvas.

Runtime maps that to Babylon `isHitTestVisible` / `isPointerBlocker` only when the host is interactive, the control is visible, Hit Testable is Enabled, and input mode is not Game. Disabled Hit Testable lets the pick walk through to widgets/HUDs/game behind; children with Enabled still receive hits. Pointer / click handlers bind only on controls that can be hit; Canvas still must not emit widget events on empty hits. Designer ADT stays `interactive: false` (paint-only).

**Set Input Mode** (`input.setInputMode`, engine enum `engine:InputMode`: All / Interface / Game) is session-scoped (Play stop / player boot reset to All).

| Mode | HUD | Game (input ring, look, actions/axes) |
| --- | --- | --- |
| All | Authored Hit Testable | On |
| Interface | Authored Hit Testable | Off (no key/pointer/gamepad into the resolver). HUD TextInput and Touch* still use GUI. Touch axes may still emit because they are interface controls. |
| Game | Force no GUI hits (`isHitTestVisible` / skip pick) | On. HUD still paints. |

## Touch → P6 input

TouchJoystick / TouchButton / TouchDPad emit `{ kind: "touchAxis", controlId, value }` into the Play ring buffer. Default `Move` bindings include `joystick-x` / `joystick-y` **alongside** gamepad. `GetAxis2D("Move")` is unchanged. Not the editor camera stick (`viewport-joystick.tsx`). TouchDPad is a `Rectangle` with composed `Ellipse`s; TouchButton is a `Rectangle`. Slider `props.min` / `props.max` copy onto the Babylon slider. Play does not show a stick until a HUD is applied; an unlabeled TouchJoystick reads as **Stick**.
